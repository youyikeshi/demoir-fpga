## 0. 一句话

**E1E2 现在直接读 conv 的 int8 C8 OUT 缓冲（零拷贝、零反量化、零量化），
cat 在物理上不存在。** 256² 整网（默认 24 槽、热内核基线）：

## 1. 交付物 ①：C8 布局的反推结论（不猜）

### 1.1 反推（从两个**互逆**的函数读出来的）

```python
# bin_ref_numpy.py
def to_c8(x):                       # (C,H,W) int8 → 板上 bin_conv_core 的写口布局
    out = np.zeros((cg, H, W, 8));  out[c//8, :, :, c%8] = x[c]
def from_c8(raw, C, H, W):          # 逆
    a = raw.reshape(cg, H, W, 8);   x[c] = a[c//8, :, :, c%8]
# bin_engine.from_c8_deq：a.transpose(0,3,1,2) == (cg,H,W,8) → (cg,8,H,W)
```

⇒ 内存下标 **`((c//8)·H + y)·W·8 + x·8 + (c%8)`**

$$\Rightarrow \textbf{组主序，组内像素主序，像素内 8 通道交错}$$
- 先是 `ceil(C/8)` 个"8 通道组"，每组一块连续的 `H*W*8` 字节；
- 组内按像素 `p = y*W + x` 递增，每个像素 8 字节 = 通道 `8g..8g+7`；
- **通道号 `c%8` 是最快变化维**（不是"8 组交错"、也不是"通道主序"）。

⇒ 与 E1E2 描述符的关系：一条 lane 读 `H*W` 个连续 64-bit 字 =
   该 8 通道组的整块 C8 ⇒ **`src_pa = out_pa + (ch//8)·H·W·8`
   （`ch = 64·group + 8·lane`）**，正是交付 `desc.bin` 的生成公式。

### 1.2 用真实数据验证（不是只对公式）

| 验证 | 结果 |
|---|---|
| `bin_engine --selftest`：`from_c8(to_c8(x)) == x`（(40,5,7)） | ✅ |
| golden `expected_c8.bin` 逐字节（5 个 xsim golden，selftest 里） | ✅ |
| `ps/tools/verify_e1e2_direct.py` A：227 层、1,191,712 B（64²）/ 19,067,392 B（256²） **0 差异** | ✅ |
| 同上：与交付 `thr.bin` 的 **40304 个真实通道 THR** 逐一对照 **0 差异** | ✅ |
| 整网 4 组合 × 64²/256² 的 sha1 == 冻结基线 | ✅ |

## 2. 交付物 ②：三层改动的实现

### ① E1E2 的 src 直接指向 conv 的 OUT 缓冲

`E1E2Engine.prepare_segments(segs, L)`（新增）把"一层输入"表示成**段表**：

```python
segs = [dict(kind="i8",  C=48, H=64, W=64, fs=<该 buffer 标度>, pa=<C8 基址>),
        dict(kind="f32", C=96, H=64, W=64, data=<f32 张量>), ...]
```

- i8 段：**零拷贝**。描述符 `src = pa + (ch-off)//8·H·W·8`，THR 用闭式
  `closed_form_thr(d=fs_in-fs, t_q)`（`sat8(rint(x·2^d)) + t_q > 0 ⟺ x + THR > 0`），
  与交付物 `gen_e1e2_desc.py` 逐字一致（§1.2 的 40304 通道对照就是它）。
- f32 段：`q8.c8_into()` **一趟完成 量化 + C8 转置**（见 §3），THR 用 d=0。
- 段边界必须 8 通道对齐；不满足 ⇒ 返回 None ⇒ 调用方回落（**不会静默错**）。
- cin=544 的第 9 组照旧用 `cfg_group=7` 变通；全掩码 lane 的 THR 指向哨兵 −127，
  src 沿用上一条合法 lane（RTL 仍会发读，哨兵保证 bit=0）。
- **cat 免费**：一条 lane 可以指向任意生产者段 ⇒ 嵌套 cat 全部在描述符里融合。
  本网 110 个 conv 的输入是 cat（有的 11 段），全部零拷贝。

```diff
+ for (s, off, C) in lay:
+     if kind == "i8": src = s["pa"] + ((ch-off)//8)*hw*8      # 直读 conv OUT
+     else:            src = vin_pa + (ch//8)*hw*8             # 现量化段
+ desc[g*8+k] = (thr_pa + ch*2) << 32 | src
```

### ② 跳过不必要的 `read_out` 反量化（惰性句柄）

`bin_engine.C8Tensor`（新增）：conv OUT 的**惰性 int8 C8 句柄**。

```python
read_out(out_buf, L, lazy=True)   # 不反量化，返回 C8Tensor（pa + C8 + fs）
h.materialize()                  # 只有真要 f32 时才反量化（= 旧 read_out）
np.asarray(h)                    # __array__ 也物化 ⇒ 未适配的消费者拿到的仍是正确 f32
h.release()                      # 引用计数（nuse = 会读它的 conv 层数）归零才还槽
```

- `BinNet._analyze_lazy()`（构建期一次）算出 `needs_f32`：**只有** add/interp/
  sam/eca/convfp/shuffle 消费者、或网络输出、或被这样 cat 吃掉的张量才必须物化。
  其余 198 个 conv 张量保持 int8（**省掉 198 次反量化**）。
- `_PlBackend.finish`：`needs_f32` 之外的 conv 输出返回 `C8Tensor`，并**钉住**它
  所在的 OUT 槽；槽数由 `BIN_LAZY_SLOTS`（默认 24）控制；槽不够时把最老的句柄
  **物化**再复用它的槽（正确性不依赖槽数，只影响速度）。
- `_exec_ps(cat)`：cat 的输出若只被 conv 消费 ⇒ 返回 `_CatLazy`（**不 concat**），
  叶子可以是 `C8Tensor` 或 f32 数组 ⇒ 110 个 cat 全部零拷贝。
- E1E2 的 start/wait 推迟到 `_PlBackend.kick()`（`prepare` 只造描述符 + 量化 f32 段）：
  上一层 conv 已收完 ⇒ done 位不会打架，**prologue 只剩真正的 PS 工作**。

### ③ convfp 那 4 层的量化：`q8.py`（4× → 7×）

`quantize_int8` 的 C 内核（逐字节自检 + 自动回落），见 §3。

## 3. 交付物 ④：`quantize_int8` 的优化 + 逐字节验证

旧实现（`e1e2_sim.quantize_int8`）：`isfinite` + 布尔花式索引 + float64 升格
⇒ 544×24² **140 ms**。

新实现 `q8.c`：
- 语义：`q = clamp(rint(x·2^fs), -128, 127)`，NaN→−128，+inf→127，−inf→−128
  （与旧版**逐字节相同**）。
- 板端 ARMv7 NEON 路径（ARMv7 没有 VRINT）用"加 1.5·2^23 再减回去"实现
  round-half-to-even；NaN 用 `vceq` 掩码置 −128。
- **`q8_c8` 再融合一步**：边量化边按 C8 布局写（省掉旧的转置拷贝）。

| 板端实测（cin×H×W） | 旧 `quantize_int8` | `q8_quant` | `q8_c8`（含量化+转置） |
|---|---:|---:|---:|
| 544×24²（1.25 MB 输入） | 186.8 ms | 26.4 ms（**7.1×**） | **5.4 ms（232 MB/s，34×）** |
| 544×64²（8.4 MB） | 1339.7 ms | 191.9 ms（7.0×） | — |
| 192×16² | — | — | 1.1 ms（175 MB/s） |
| 96×32² | — | — | 2.1 ms（190 MB/s） |

逐字节验证：
- `q8.py` 自检（每次加载必跑，板端 0.24 s）：全 256 个 int8 取值 × fs 0..12、
  平局点两侧各 1 ULP、±0、±inf、NaN、次正规数、越界大值；**q8_quant 与 q8_c8
  两个入口**都与 numpy 参考逐字节比，0 差异才加载。
- `bin_engine --selftest`：`quantize_int8 == e1e2_sim.quantize_int8`（8 个 fs）。
- 整网 A/B 的 sha1 证明（见 §4）。

16 槽 → 24 槽：提前物化 38–48 次 → 10 次，prologue 2.12 → 1.61 s。
512² 时单槽 ×4，建议把槽数降到 8~12。

## 5. 不确定项 / 没做的

1. **64² 上净亏**（§4.2）。不是 bug，是小层上"PL 往返 + MMIO"贵于 C 内核。
   若必须兼容 64²，加一个按层字节数的阈值（> ~0.5 MB 才走直读）。
2. **prologue 仍有 2.1 s**（16 槽）：f32 段量化 0.83 s（123 MB = 30.8 M 元素）、
   `pack_input` 回落层 0.99 s、`_ensure_cfg` 0.37 s、其余 0.2 s。要把 prologue
   压到 1 s 需要把"f32 段的量化"搬到生产者算子（add/interp/sam/convfp）里，
   让它在 PL 忙时重叠——那是 S2 的 `qcache` 方向。
3. **PL 计时口径**：`pl` 是 Σ 每层 `poll` 看到 done 的时刻差；`NET_TPOLL=0` 时
   会被 PS 轮询延迟污染（本报告的数字就是 TPOLL=0）。用 TPOLL=1 复测：
   基线 12.69 / 直读 9.95，趋势一致（PL 分别 3.61/4.61）。
4. **板端两次跑之间基线有 5~6% 抖动**（11.91~12.84），直读 8.79~10.17。
   同一次进程内的四种组合可比；跨次比较请以同一次的冷/热对照为准。
5. **未跑 512²**：arena 44 MB（16 槽）在 1 GB 板 / CMA 147 MB 下没问题，但
   512² 的 `max_in/max_out` 会 ×4（~176 MB），需要按 `BIN_LAZY_SLOTS` 调小。
6. **E1E2 的 job 现在在 `kick` 里同步跑**（PL 串行）。如果以后要"打包与 conv 真重叠"，
   需要双实例或 RTL 改动——本版没做，也不在本次判据里。
