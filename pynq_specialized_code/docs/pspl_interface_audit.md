## 4. 性能实测：为什么 5 秒超时一定会炸（v3.2 历史基线）

**实测来源**：`pl/proj/engine_cosim/cosim1/sim/report/conv2d_engine_cosim.rpt`
（C/RTL cosim，Verilog，Pass）——`Total Execution Time = 4,694,784` 拍。
对应数据集 `testdata_c352_o192_k1_h2`：cin=352、cout=192、k=1、H=W=2（4 个输出像素）。

一个"单元" = 一个输出像素 × 一个输出通道 × 一个输入通道。
这里单元数 = 2×2×192×352 = **270,336** → **17.4 拍/单元**。

| 量 | 数值（按 17.4 拍/单元、150MHz 外推） |
|---|---|
| 最贵层 `decoder_1...conv_proj`（320², cin=224, cout=64） | 1.468G 单元 → **≈170 s** |
| 640 整网 247 个卷积 | 15.14G 单元 → **≈29 分钟** |

也就是说：**功能对、但慢**。5 秒超时会在第一层大卷积上直接抛 `TimeoutError`；
即使不抛，整网也是"半小时级"，离"秒级"两个数量级。

**为什么慢**：`for (ic…)` 上写了 `PIPELINE II=1`，但实测 17 拍/单元，
说明循环携带依赖没被打开——每个 `ic` 迭代里 25 个抽头的乘加链（DSP latency=3）
串成一条长链；`acc_even/acc_odd` 的拆分没有改变 II。

**建议的优化顺序**（每步都要按 README 的"电路改动＝全链重验"走）：

1. **给 1×1 单独一条快路径**：249 个卷积里 **132 个是 1×1**，现在它们和 5×5 走同一条
   25 抽头通路（24/25 的乘法被谓词掉），白白耗掉同样拍数。
2. 抽头求和改**树形归约 + 寄存器打拍**，把 `part` 的串行链打断。
3. 再做通道维并行（OC_BLOCK 内多通道并行），此时才谈得上 25~50 MAC/拍。

## 5. 优化尝试：1×1 专用快路径（2026-10-17 晚，v3.3）

**动机**：640 网络里 **132/249 个卷积是 1×1**，却和 5×5 共用同一条 25 抽头谓词通路
（24/25 的乘法被 `if` 掉，但拍数照付）。

**改法**：在 `src/conv2d_engine.cpp` 的 `(x2, i)` 循环里加 `if (ksize == 1)` 分支，
只做一次乘加；`src_cosim` 同步（见 §7 的同步检查）。

**实测（全部重跑，不是估计）**：

| 项 | v3.2 | v3.3（+快路径） |
|---|---|---|
| cosim 周期（cin=352 cout=192 k=1，2×2 输出） | 4,694,784 | **4,142,592（−11.8%）** |
| cosim 结果 | PASS | **PASS（768 输出逐位一致）** |
| csynth | 165 BRAM / 56 DSP / 14450 FF / 19265 LUT | 165 / **56** / 14818 / 19748（+483 LUT, +368 FF） |
| 实现 | WNS +0.107ns | **WNS +0.087ns**；BRAM 82 块(86.3%) / DSP 59(36.9%) / LUT 11699(25.3%) |

**为什么这个形状只有 12%？** 说明瓶颈不在抽头链。拆账（同一形状，H=W=2）：

- 计算循环：4 像素 × 24 个 OC 块 × 8 通道 × 352 输入通道 = **270k** 次迭代；
- **权重重装**：每个 (行, 列块, OC 块) 都重读 `ocbl × cin × k²` = 8×352×1，
  ×24 块 ×2 行 = **135k** 次迭代，且每次要写进分区化的 `wgt_buf`（实测这部分吃掉了
  4.14M 里的约 3.4M 拍，即 **~82%**）。

> ⚠️ **这个 82% 是"2×2 小画幅"的放大效应，不能直接套到真实层**：
> 权重重装次数 ∝ `Hout × ceil(Wout/64) × ((cout/8)×8×cin)`，而计算单元数 ∝
> `Hout × Wout × cout × cin`。比值 = `ceil(Wout/64) / Wout`：
> - 2×2：ceil(2/64)=1 → 比值 1/2（权重装载被放大 32 倍）；
> - 320 宽真实层：ceil(320/64)=5 → 比值 **1/8**。
>
> 所以 **12% 是这个形状下的下限**。按真实宽度的比值重算：k=1 层每单元
> ≈ 计算 1.5 拍 + 权重 (25 拍 × 1/8 ≈ 3.1 拍) ≈ **4.6 拍/单元**（原 17.4）→
> 640 整网从 ~29 分钟降到 **~9–10 分钟**。这是**解析估计**，要确认得跑一次
> 宽画幅（如 H=8/W=320）的 cosim 或上板计时。

**结论**：下一刀不是继续抠乘法，而是**把权重装载从"每行每块"提出来**：

1. 提到 (行, OC 块) 级（去掉列块维的重复，320 宽能省 5×）；
2. 或整层一次装载 —— 最坏层权重 352×192×1×1 ≈ 67 KB，约 30 个 BRAM18K，
   而当前 BRAM 已用 86.3%，**放不下**，必须先换循环顺序或降 `OC_BLOCK` 的常驻策略；
3. 每改一次都要 `check_src_sync.py` + csim/cosim + 重综合（本轮已按此走完）。

## 10. 2026-10-21 晚：PS 侧优化落地，以及"下一刀砍哪里"的实测证据

### 10.1 PS 侧：176 s → 85 s（六处改动，全部逐位等价）

| 项 | 改动 | 为什么结果不变 |
|---|---|---|
| `_req` 标度重定标 | float64 乘 + rint + clip → **256 项查找表** | int8 只有 256 个取值，表项用同一算式逐值算好 |
| `cat` | 每图 224 次整块读写（535 MB）→ **零拷贝**（204 个 cat 折叠成"一块缓冲 + 通道切片视图"） | 叶子生产者都是同 H/W 同形状的写者；30 个"之后还要被读"的输入保留复制 |
| `interp` | 权重 float64 → **float32** | 比例只有 1/2、1/4、2/1、4/1，权重落 1/8 网格；中间值分母 ≤64、量级 ≤127，float32 精确 |
| `add` | 两份 float32 → **int16 + 饱和** | 整数和的 rint 恒等 |
| `sam_sum` | 整块 float64（≈200 MB 临时）→ **按 16 通道分块** | 逐元素运算不变 |
| `eca` | 两次整块 float32 临时 → 原地乘 | 同上 |

验证：`ps/tools/test_ps_opt.py`（每项与旧实现逐位对拍，含 int8 全值域穷举）+
`check_pack_ref.py` **0 / 1,228,800** + 板端输出 **md5 与 `ref_out.bin` 相同**。
池 84.8 → **66.8 MB**。板端 PS 176 → **85.3 s**（125 MHz）。

### 10.2 conv 258.8 s 的分解（247 层逐层计时 + 最小二乘，R² = 0.99）

| 分项 | 秒 | 占整网 | 单位成本 |
|---|---:|---:|---|
| 行缓冲填充（逐字节从 DDR 搬） | **102.0** | 29.6% | 15.9 拍/字节 |
| 权重重装（每行×每列块重复搬） | **87.5** | 25.4% | **142 拍/字节** |
| k=3 乘加 | 59.0 | 17.1% | 3.60 拍/单元 |
| k=5 乘加 | 4.9 | 1.4% | 10.3 拍/单元 |
| k=1 乘加 | 0.6 | 0.2% | 0.006 拍/单元 |
| 每层固定 | 4.8 | 1.4% | — |

搬运总量 0.88 GB / 190 s ≈ **4.6 MB/s**（HP0+DDR 预算 ≥500 MB/s）。
**结论：瓶颈已经从"乘加吞吐"变成"搬运延迟没被流水掩盖"。**

### 10.3 int8 打包（B）为什么不做：三条硬证据

1. **位宽算不动**：DSP48E1 是 25×18→48 位。两个权重打包 `A = w0 + w1·2^17`
   （间隙只能 ≤17 位：17+8=25）；`|p·w| ≤ 16384`，低 17 位要无溢出装下
   `Σ p·w0` ⇒ **每 3 个输入通道就必须拆一次包**（3×16384 = 49152 < 65536）。
   每 3 拍乘加后面跟 4 个通道对的拆包（1 减 + 2 加），乐观摊到 **4.8 MAC/拍**，
   而现在 k=1 已经 **4.34**。
2. **要加速的部分已经没了**：A 做完后 k=1 乘加只剩 **0.6 s（整网 0.2%）**，
   k=3 乘加 59 s 也受 line_buf 端口限制（不是 DSP）。B 的天花板 ≈ **8~12 s（3%）**。
3. **8 路并行读实测不成立**：把 `K1_OC_UNROLL` 从 4 提到 8，
   C/RTL cosim **功能失败（4110/8192 输出不一致，csim 通过）**——
   LUTRAM 权重缓冲撑不住每拍 8 次读，"再加并行"这条路要先改存储。

> 所以 B 不是"没时间做"，是**做完了也只有 3%**，而 73% 在两个搬运循环上。

### 10.4 已实施的一刀：两条搬运循环加流水

| 位置 | 改动 |
|---|---|
| 行缓冲填充 | 原来 `(r, ic, j)` 三层都没有流水，最内层是"算地址→发 AXI 读→等返回→写 BRAM"的串行 FSM。改成**每行一条 `PIPELINE II=1`**，补零段用谓词选择（地址始终合法） |
| 权重重装 | 原来 `k` 分支在循环体内、步长是运行期 `kk`、无流水 → 每次读各自等 AXI。改成**按 k 拆成三个分支**（步长 9 / 25 变编译期常量）+ 内层 `ic` 循环 `PIPELINE II=1`，地址用指针递推（`wp += 9`），避免 `off + ic*k²` 的 32 位乘加链 |

**注意一个陷阱**：这两个改动用 C/RTL cosim **测不出收益**。cosim 的 AXI 内存模型
延迟≈0，所以"流水"只剩 prologue 开销（同一形状 1,314,252 → 1,940,226 拍，−47%）。
板端 15.9 / 142 拍/字节全是真实 AXI 往返延迟，只有板子能给结论。
资源变化：LUT 21,491 → 24,853（54%）、FF 15,630 → 17,629、BRAM 165 不变，
`Estimated Fmax` 172.97 MHz 不变。

## 11. 当晚的最优版本与"不要再试"的清单（2026-10-21 收尾）

**最佳已上板版本**：`conv2d_engine.cpp` = 1×1 并行化（`K1_OC_UNROLL=4` + LUTRAM 权缓）
+ 权重重装按 k 拆分支（常量步长 + II=1）；PS 侧 = 256 项查找表重定标（`bytes.translate`）
+ cat 零拷贝 + 整数 interp + 分块 eca。

| 指标 | 实测（125 MHz，640 单张） |
|---|---|
| 整网 | **313.96 s**（原始 749 s，**2.39×**） |
| conv | 257.5 s（其中填充 105 / k=3 乘加 101 / k=1 乘加 31 / k=5 9 / 其它 12） |
| PS | 56.4 s（sam_sum 24.4 / interp 17.1 / eca 7.7 / cat 5.6 / add 1.5） |
| 逐位对拍 | 0 / 1,228,800 |
| 时序 | WNS +0.217 ns @150 MHz |

**已经证明无效或有害的改法（不要再重复）**：

1. 把补零用谓词折进搬运循环的流水 → 破坏 burst，整网慢 4~5 倍。
2. 只给拷贝段加 `II=1` → 中性。
3. 把 (ic, j) 压平成一条长循环 → 慢 12%（循环携带的 j 回绕依赖堵死预取）。
4. `K1_OC_UNROLL=8`、3×3 的"oc 展开 ×4 + 抽头复用" → **RTL 功能错误**（cosim 抓出）。
5. 6 项拟合模型里的"权重重装 142 拍/字节" → 过参数化假象（改动后 conv 不变）。

**下一刀的正确形态**（要么少搬、要么搬得宽）：
- 64 位宽读 + 对齐修正（逐字节 → 8 字节/事务）；
- 离线预置输入/权重布局，让搬运变成线性大块；
- 层间算子整体搬进 PL（见 `docs/设计_v2_层间算子加速器.md`）。

> 瓶颈归因（为什么是"并发度"而不是带宽）、以及七条可行方向的 成本/收益/风险，
> 见 [`部署/记录_20261021` §4.10](../../docs/部署/记录_20261021_PS端验证与BOOT重建.md)，
> 不在这里重复第二份清单。
