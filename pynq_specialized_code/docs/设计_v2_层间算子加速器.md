# v2 设计：层间算子加速器（一块 IP 覆盖五个 PS 算子）

> 状态：**设计稿**（2026-10-21 晚定方向，未开工）。
> 前置读数：[`../docs/pspl_interface_audit.md`](../docs/pspl_interface_audit.md) §10
> （PS 侧实测分解）、[`部署/记录_20261021`](../../docs/部署/记录_20261021_PS端验证与BOOT重建.md) §4.8。
> 目标：把单图 **56 s 的 PS 层间算子**压到 **< 2 s**，且**一次改完**（不留半套）。

---

## 0. 为什么合并成一块

板端 125 MHz 实测（640×640，conv 257.5 s 之外的部分）：

| 算子 | 秒 | 次数 | 特征 |
|---|---:|---:|---|
| `sam_sum` | 24.4 | 6 | 3 源 + 逐通道权重（1/4096 网格）+ 加法源，纯流式 |
| `interp` | 17.1 | 26 | 双线性，比例只有 2/1、1/2、4/1、1/4 |
| `eca` | 7.7 | 6 | 逐通道空间均值（3C×(H×W) 归约） |
| `cat` | 5.6 | 224 | 通道拼接 + 重定标（已是零拷贝，只剩重定标） |
| `add` | 1.5 | 6 | 两源加权相加 |
| shuffle | 0.2 | 4 | 纯重排 |

**它们的共同点**：都是"读 1~5 个 CHW int8 张量 → 逐元素（或逐通道）线性组合 →
一个定点重标 → 写 1 个 int8 张量"。只有 `interp` 需要横向邻域、`eca` 需要归约。

所以**不做五块小 IP**，而做一块**流式多源加权引擎**，用"算子码 + 操作数表 + 通道系数表"
把五种形态统一掉。这样：一份驱动、一份验证、一次 BD 改动。

## 1. 数值契约（先定这个，否则后面全要返工）

现在 PS 侧混着 float64（`sam_sum`）、float32（`eca`/`add`）、256 项查找表（重定标），
这是跨平台（x86 SIMD vs ARM 标量）反复出问题的根源。v2 统一成 **Q16 定点**：

| 量 | 表示 | 说明 |
|---|---|---|
| 每个源的比例系数 `a/b`（标度比） | `int32`，Q16（`round(ratio × 65536)`） | 导出端算好，写进 DDR 系数表 |
| 逐通道权重（`sam_sum` 的 attn、`sam_sum` 的 1/4096 网格） | `int32`，与比例系数相乘后仍是 Q16 | 现在 attn 已在 1/4096 网格上，正好整数 |
| 累加 | `int64`（每通道一次乘加后累加） | 5 源 × 128 × 65536 ≈ 4.2e7，int32 也够，但留 int64 余量 |
| 输出 | `round_half_even(acc >> 16)` + 饱和到 `[-128,127]` | 与 numpy `rint` 半偶一致 |
| `interp` | 权重只落 1/8 网格 → 两段 ×8，最后 ÷64 | 与现有 `ops_numpy.interp` 整数路径完全一致 |
| `eca` 归约 | 每通道 int64 求和 + 比例，回传 float32 均值 | PL 只做归约，Sigmoid/Conv1d 仍在 PS（只有 576 个值） |

> **这条会改变线上数值语义**：`ref_out.bin` 必须用新语义重生成，且**独立参考要用
> `export_network.py` 的浮点前向**（不要再拿同一套代码自证）。PSNR 只要不明显掉
> （现在 22.39 dB），就说明定点化没有实际损失。

## 2. 指令与 ABI

### 2.1 寄存器（s_axilite，独立基址，例如 `0x4002_0000`）

| 偏移 | 名称 | 含义 |
|---|---|---|
| `0x00` | AP_CTRL / AP_RETURN | bit0=start，bit1=done；返回码 0/2/3/4 |
| `0x08` | OP | 算子码，见 2.2 |
| `0x10` | N | 元素总数（`C*H*W`） |
| `0x18` | C / H / W | 形状（`interp` 另需 out_H/out_W） |
| `0x20` | SRC0..SRC3 | 四个源张量地址（64 位，写低位后写 0 到 +4） |
| `0x40` | DST | 目标张量地址 |
| `0x48` | COEF | 比例系数表地址（Q16 int32 数组） |
| `0x50` | DST_CH_OFF | `cat/rescale` 的通道偏移（写入目标第几通道开始） |
| `0x58` | NSRC | 参与运算的源个数（1~4） |

### 2.2 算子码

| 码 | 算子 | 语义（全部按 §1 的 Q16） |
|---|---|---|
| 1 | `RESCALE` | `dst = sat(round(SRC0 × k0) >> 16)`（可带通道偏移，覆盖 `cat` 的重定标） |
| 2 | `ADD` | `dst = sat(round(SRC0×k0 + SRC1×k1) >> 16)` |
| 3 | `SUM3W` | `dst[c] = sat(round((SRC0[c]×k0[c] + SRC1[c]×k1[c] + SRC2[c]×k2[c] + SRC3[c]×k3) >> 16))` |
| 4 | `INTERP` | 双线性，比例由 `out_H/out_W` 推出（只能是 1/2、1/4、2、4） |
| 5 | `REDUCE_MEAN` | 逐通道 int64 求和写到 `DST`（3C 个 int64），比例由 PS 算 |

> `cat` 不需要单独指令：调用方把每个源的 `DST_CH_OFF` 指到目标缓冲的通道切片，
> 一次 `RESCALE`（k=1 时就是纯搬运）即完成；这与 PS 侧现有的"零拷贝 cat"完全对齐。

## 3. 微架构

```
            ┌──────────── 单条主流水（8 字节/拍） ────────────┐
DDR ──m_axi─▶ 源装载 FIFO ─▶ 解包 int8×8 ─▶ 系数(per-channel) ─▶ int32 乘加
                                   │                              │
                         (interp)  │ 2 行行缓冲 + 1/8 权重        ▼
                                   └────────────────────▶ int64/32 累加
                                                              │
                                              round>>16 + 饱和 │ 打包 int8×8
                                                              ▼
DDR ◀──m_axi──────────────────────────────────────────── 写回 FIFO
```

- **源个数可变**：`SUM3W` 用 4 个 m_axi 读通道（或一个通道 + 轮转地址），
  每个源一个"比例系数寄存器组"（逐通道时从 BRAM 读，`COEF` 只装当前 C 块）。
- **系数存储**：逐通道系数最多 576 个 int32 = 2.3 KB → 一块 BRAM，随 op 装载一次。
- **`interp`**：比例固定 → 只保留 1 行输入缓冲 + 1 行输出暂存，横向 2 抽头、
  纵向跨两行；`out_H = H/2` 这类直接按半行步进读。
- **`REDUCE_MEAN`**：累加器 C 个 int64（576×8 B = 4.6 KB，LUTRAM/BRAM），
  结束时一次性写回。
- **资源预估**：BRAM ≈ 6~10 块，DSP ≈ 8（8 个 int8 乘加/拍），LUT 约 3~5 k。
  当前引擎占 165 BRAM / 71 DSP / 54% LUT，v2 加进来 **BRAM 会到 ~175/190（92%）**
  → 需要注意：**要么先做 §4 的"填充分块"腾 BRAM，要么把 `BWCOL_MAX` 从 76 降到 68**。

## 4. 与现有卷积引擎的关系

| 项 | 处理 |
|---|---|
| DDR 通路 | 复用 `S_AXI_HP0`，两个引擎挂同一个 AXI SmartConnect（PL 内部仲裁，不会同时跑） |
| 地址映射 | 新增 `s_axi_pp = 0x4002_0000`（`0x4000/0x4001` 已被 conv 占用） |
| 驱动 | `ps/pynq/pp_engine.py`，风格照抄 `conv_engine.py`（.hwh 发现地址 + 超时估算） |
| 调度 | `runner.py` 里五种非卷积算子的分支换成一次 `pp.run(op=…)`；`RefEngine` 走 numpy 实现，保证本机可测 |
| 清单 | `build_manifest.py` 给每个非卷积算子加 `pp_op` 字段 + 系数表；`index.json` 增加 `coef_blob` |

## 5. 验证（三级，全部可离线完成前两级）

1. **单算子逐位**：`ps/tools/test_pp_vs_numpy.py` —— 对 5 种算子、随机形状、边界形状
   （奇宽、小图、单通道）与 numpy 定点参考逐位对拍；`interp` 另外覆盖 4 种比例。
2. **整网**：`check_pack_ref.py` 必须 **0 / 1,228,800**；同时用浮点前向算 PSNR，
   与当前 22.39 dB 对比（允许 ±0.05）。
3. **上板**：`test_on_board.py` 增加 pp 的 5 个用例（含 `SUM3W` 全形状）→ 整网 →
   与 `ref_out.bin` 逐位一致 + `--profile` 里非卷积项应归零。

## 6. 分期落地（一次交付，可分三次提交）

| 期 | 内容 | 开启后能省的 |
|---|---|---|
| v2.0 | IP 骨架 + `RESCALE` / `ADD`（顺带把 `cat` 的重定标吃掉） | cat 5.6 + add 1.5 ≈ **7 s** |
| v2.1 | `SUM3W`（含逐通道系数） | sam_sum **24.4 s** |
| v2.2 | `INTERP`（行缓冲）+ `REDUCE_MEAN`（回传均值） | interp 17.1 + eca 7.7 ≈ **25 s** |
| 合计 | | **≈ 56 s → <2 s** |

**建议顺序**：v2.1 先做（单算子收益最大、结构最简单），然后 v2.0 的 `RESCALE`
（顺带统一 `cat` 语义），最后 v2.2（行缓冲和归约器是真正的额外复杂度）。

## 7. 风险与前置条件

1. **BRAM 预算**：当前 86%，加 pp 会顶到 92%+。前置动作二选一：
   - 把 `BWCOL_MAX` 76 → 68（列块 64 → 56，BRAM 约降 10%），代价是 k=3 的填充量略增；
   - 或先把 `line_buf` 的 7 行 bank 按 `span` 实际值拆分（k≤3 时只有 3 行）。
2. **验证成本**：这块 IP 的寄存器/系数表比 conv 引擎简单，但**系数表的语义**（逐通道、
   Q16、与标度比相乘）最容易错——必须用"单算子逐位"这一关兜住。
3. **数值语义变更**：`sam_sum`/`add` 从 float64 改成 Q16 会让 `ref_out.bin` 变，
   必须重生成 + 独立浮点参考对 PSNR。
4. **不要和 conv 引擎抢 HP0**：两者串行执行，驱动层保证不并发。

---

## 8. 一句话

**把"层间算子"从 5 个 numpy 分支收敛成 1 块流式定点引擎 + 1 张系数表**，
用一次 ABI 改动换掉 56 s 和全部跨平台浮点隐患。
