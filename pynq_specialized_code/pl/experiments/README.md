# 实验分支（不进主流程）

## `conv2d_engine_th2.cpp` —— 行批处理（TH=2）：**功能已 30/30，但板上更慢，不采用**

**动机**：填充是延迟受限（0.4 GB 用了 90 s ⇒ 8 MB/s，而 HP0+DDR 能力 ≥500 MB/s，差 60 倍），
说明每读一行（68 B）就是一次完整往返。思路：一次装 2 行（两个独立 burst → MLP×2），
把"一次等待"摊到 2 个输出行上。

**实现要点（三个 bug 都已修）**
1. 行缓冲从 `SPAN_MAX` 加到 `SPAN_BUF = SPAN_MAX+1 = 8` 行；
2. 位移步长必须用**上一批的推进量** `prev_adv`（末批 th=1 时若用当前 th 会错位）；
3. k=1 路径的行索引写死成 `line_buf[ic][0][cb]`，必须改成 `[jbase][cb]`；
4. `wide1`（k=1 宽列块把行维当列 bank）与行批处理互斥 → 该模式 `ystep=1` 退化；
5. 守卫：`(k-1)*dil+1+stride > SPAN_BUF` 直接 `ERR_SIZE`（只有 k=5,d=3 会超，网络里不存在）。

**验证结果**
| 项 | 数值 |
|---|---|
| 形状回归（g++） | **30/30 PASS** |
| 综合 | DSP 131 / **BRAM18K 182（190）** / Fmax 172 MHz |
| 时序 | **WNS −0.782 @150 MHz** ⇒ 只能跑 140 MHz |
| 板上整网（140 MHz） | 198.19 s，conv **141.7 s**，0/1,228,800 |

**结论：不采用。** 折算到同一时钟：TH=2 的 conv 132.3 s vs 原引擎 129.8 s（150 MHz），
**慢 2%**，且时序退化 0.7 ns 使其只能跑 140 MHz。提高 MLP 的收益被
"额外行偏移寻址 + 时序损失"完全抵消。

**为什么填充没改善**（事后分析）：瓶颈不是"一次等几行"，而是**每行一次往返本身**；
TH=2 只是把两行的等待合并，但行缓冲地址计算变复杂（`jbase + rdoff[t]` 多一级加法、
buffer 变大导致布线变长），净抵消。真正的解法是双缓冲（BRAM 不够）或
把跨层的生产者-消费者流水化（融合）。

### 追加：同频对比（决定性）

| 引擎 | 时钟 | conv | 整网 |
|---|---:|---:|---:|
| 原引擎 | 150 MHz | 129.8 s | **187.41 s** |
| **原引擎** | **140 MHz** | **140.6 s** | 197.03 s |
| **TH=2** | **140 MHz** | **141.7 s** | 198.19 s |

同频下 TH=2 慢 1.1 s（0.8%）⇒ 结论不变。
另外得到一个修正：150→140 MHz 使整网 +5.1%（187.41→197.03），
说明当前**大部分是计算受限**，不是"90 s 纯延迟"——这修正了对填充占比的估计。

## `conv2d_engine_fuse.cpp` —— 融合出口（out_lut / chsum）：**已实现，但 ABI 风险未解决**

**动机**：把 cat 的重定标（5.7 s）和 ECA 的通道均值（7.8 s）搬进卷积写回路径，
省掉两遍 DDR 往返；同时若能把 pp 引擎整个去掉，集成版的"布局容量墙"也一并解决。

**已实现**：三处写回点都加了可选 `out_lut`（256 项表，写回时直接落到目标张量标度）。
指针为 0 时行为与旧版完全一致（形状回归 30/30 通过）。

**意外发现（需先解释再做）**：加了出口之后 HLS 综合变成
DSP **131 → 47**、FF 17.0k → **8.9k**、BRAM 163 → 115，Fmax 仍 172 MHz，
功能（csim 3072/3072）正确。资源降这么多不像是"免费"，
**很可能是 HLS 把多条乘法链串行化（II 变大）**，必须先拿到 cosim 拍数才能判断。

> 留档报告（`/data/work/hls_fuse`）的实测是 DSP 47 / FF 12,209 / LUT 14,038 / BRAM 115，
> 与上面记的 "FF 8.9k" 有出入，以报告为准。

**卡点**：新增的两个指针端口没有 `depth=` 声明，
`check_cosim_dims.py` 直接拒绝 cosim（"depth 与数据集不一致"）；
而要加 depth 就得改 AXI-Lite 寄存器表 ⇒ 存在"驱动没写新寄存器、引擎解引用垃圾指针"的风险。

**已解决（2026-10-22）**
1. 用 `#if FUSE_OUT` 宏把出口隔离；默认构建（FUSE_OUT=0）**逐字不变**：
   DSP 131 / LUT 15,351 / FF 16,985 / BRAM 166 —— 与交付版完全一致；
2. `FUSE_OUT=1` + 正确 `depth=` 声明后，DSP 131 / BRAM 166 不变，但 FF/LUT 确实增加
   （最终实测 FF 25,870 / LUT 37,752，相对 FUSE_OUT=0 的 25,347 / 36,958 是
   **+523 FF / +794 LUT**）；
3. 之前"加出口后 DSP 131→47"的怪现象，根因是**新端口没声明 `depth=`**：
   HLS 在未约束的 AXI 端口下重新调度、把乘法链串行化了。声明 depth 后恢复正常。

> **修正（2026-10-23）：融合不是零成本，原文这条结论作废。**
> 这里曾写"融合在 FPGA 侧是零成本的"—— 那是基于一次空操作的误测（`synth_only.tcl`
> 没把 `EXTRA_DEFS` 传给编译器，两轮对比的 csynth 报告逐字相同，见 §"同一类错误"）。
> 板上实测：**`out_lut` 让 conv +7.9~9.8 s**（142.5 → 150.4 s），关键路径拖慢 0.64 ns
> （WNS −0.067 → 约 −0.71），只能跑 140 MHz ⇒ **不便宜**；
> 而 **`chsum`（FUSE_SUM）才便宜**：DSP 131 / BRAM 166 不变，同频 conv 只 +1.9 s
> （140.6 → 142.5 s）。
> 详见 `docs/部署/记录_20261022_三版引擎全量技术纪要.md` §9.3。

**剩余工作（纯 PS 侧）**
- 驱动要给每次 conv 传一张 256 项的 `out_lut`（本层标度 → 目标张量标度），
  并在启用 ECA 融合时读回 `chsum[cout]`；
- manifest 需要在 conv 算子条目里带上 `out_lut`（打包时生成）；
- 完成后 cat 的重定标（5.7 s）与 ECA 的均值遍历（7.8 s）都可以不再单独走一遍 DDR。

## ⚠️ 事故记录（2026-10-22 21:50）：FUSE_OUT=1 的 bit 把板子挂死了

**现象**：把 `FUSE_OUT=1` 的 bit 部署到板上、用**旧驱动**跑 `test_on_board.py`，
5 个用例全部 `rc=0 但大量不一致`；随后整网跑了几秒，板子直接失联（ping 不通、SSH 无路由，
主机网口正常），需要断电重启。

**根因**：`FUSE_OUT=1` 的 bit 多出 `out_lut`（0x40）和 `chsum`（0x4C）两个 AXI-Lite
基地址寄存器。旧驱动**根本不写**这两个寄存器 ⇒ 它们保持复位后的未定义值 ⇒
RTL 里 `if (out_lut != 0)` 判真 ⇒ 引擎拿垃圾地址去读 256 字节 LUT ⇒
对未映射地址发起 AXI 访问 ⇒ HP 口/互连死锁 ⇒ PS 侧后续访问挂死。

**为什么之前的验证没抓到**：主机侧 A/B 用的是 `RefEngine`（纯 numpy），
根本走不到 AXI；而 bit 的 ABI 变化只有真跑硬件才暴露。

**两条改进（下次必须做）**
1. **RTL 侧改用魔法值使能**，而不是 `!= 0`：
   `if (out_lut == (const data_t*)0x5AFE0000ULL || ...)` —— 未初始化寄存器几乎不可能撞上；
   或干脆加一个 s_axilite 的 `fuse_en` 标量，默认 0。
2. **驱动侧初始化即写 0**：`Conv2dEngine.__init__` 在拿到 `fuse_offsets` 后立刻把两个
   寄存器写 0，而不是等到第一次 `run()`。这样即使中途异常也不会留垃圾。

**部署纪律**
- `FUSE_OUT=1` 的 bit **必须**配"会写这两个寄存器"的驱动一起部署；
  当前驱动需要 `--fuse-offsets 0x40,0x4c`（来自导出 IP 的 `xconv2d_engine_hw.h`）；
- 板子重启后加载的是 `/home/xilinx/demoir_new/design_1.bit`（现在还是 fusion 版），
  要么带 `--fuse-offsets` 跑，要么把交付版 bit 重新拷回去。

**权威寄存器偏移（FUSE_OUT=1，取自 `xconv2d_engine_hw.h`）**
| 寄存器 | 偏移 |
|---|---|
| in_fm / wgt / bias / out_fm | 0x10 / 0x1C / 0x28 / 0x34 |
| **out_lut** | **0x40** |
| **chsum** | **0x4C** |
