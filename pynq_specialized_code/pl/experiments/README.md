## `conv2d_engine_th2.cpp` —— 行批处理（TH=2）尝试，**未完成**

**动机**：填充是延迟受限而非带宽受限。反推：填充流量 ~0.4 GB（每字节只读 1.06 次，
已是理论最小），耗时 ~90 s ⇒ 实际 **8 MB/s**，而 HP0+DDR 能力 ≥500 MB/s，差 60 倍。
说明每读一行（68 B）就是一次完整往返、相邻行完全不重叠。
思路：一次装 2 行（两个独立 burst → MLP×2），把"一次等待"摊到 2 个输出行上。

**BRAM 账（这是硬约束）**
| | 行数 | 容量 | 增量 |
|---|---:|---:|---:|
| 现在 TH=1 | 7 | $7\times76\times352=183$ KB | — |
| **TH=2** | 9 | $9\times76\times352=240$ KB | +53 KB = 24 块（剩 27 块 ✓） |
| TH=4 | 13 | $13\times76\times352=348$ KB | +72 块 ✗ 装不下 |

**已完成的改动**
1. `line_buf` 行数 `SPAN_MAX` → `SPAN_BUF = SPAN_MAX + 2`；
2. y 循环步长 `THB`，`th = min(THB, Hout-y)`，`yspan = span + (th-1)*stride`；
3. 填充范围 `[keep, yspan)`，BRAM 内位移步长改为 `th*stride`；
4. 计算区外面包一层 `for (j2 = 0; j2 < th; ++j2)`，行下标统一 `jbase + rdoff[t]`
   （`jbase = j2*stride`），输出行号改为 `y + j2`；
5. `wide1`（k=1 宽列块把行维当列 bank 用）与行批处理互斥 → 该模式 `ystep = 1` 退化。
