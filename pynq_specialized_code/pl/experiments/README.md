# 实验分支（不进主流程）

## `conv2d_engine_th2.cpp` —— 行批处理（TH=2）：**功能已 30/30，但板上更慢，不采用**

**动机**：填充是延迟受限（0.4 GB 用了 90 s ⇒ 8 MB/s，而 HP0+DDR 能力 ≥500 MB/s，差 60 倍），
说明每读一行（68 B）就是一次完整往返。思路：一次装 2 行（两个独立 burst → MLP×2），
把"一次等待"摊到 2 个输出行上。

**实现要点（三个 bug 都已修）**
1. 行缓冲从 `SPAN_MAX` 加到 `SPAN_BUF = SPAN_MAX+1 = 8` 行；
2. 位移步长必须用**上一批的推进量** `prev_adv`（末批 th=1 时若用当前 th 会错位）；
3. k=1 路径的行索引写死成 `line_buf[ic][0][cb]`，必须改成 `[jbase][cb]`；
4. `wide1`（k=1 宽列块把行维当列 bank）与行批处理互斥 → 该模式 `ystep=1` 退化；
5. 守卫：`(k-1)*dil+1+stride > SPAN_BUF` 直接 `ERR_SIZE`（只有 k=5,d=3 会超，网络里不存在）。

**验证结果**
| 项 | 数值 |
|---|---|
| 形状回归（g++） | **30/30 PASS** |
| 综合 | DSP 131 / **BRAM18K 182（190）** / Fmax 172 MHz |
| 时序 | **WNS −0.782 @150 MHz** ⇒ 只能跑 140 MHz |
| 板上整网（140 MHz） | 198.19 s，conv **141.7 s**，0/1,228,800 |

**结论：不采用。** 折算到同一时钟：TH=2 的 conv 132.3 s vs 原引擎 129.8 s（150 MHz），
**慢 2%**，且时序退化 0.7 ns 使其只能跑 140 MHz。提高 MLP 的收益被
"额外行偏移寻址 + 时序损失"完全抵消。

**为什么填充没改善**（事后分析）：瓶颈不是"一次等几行"，而是**每行一次往返本身**；
TH=2 只是把两行的等待合并，但行缓冲地址计算变复杂（`jbase + rdoff[t]` 多一级加法、
buffer 变大导致布线变长），净抵消。真正的解法是双缓冲（BRAM 不够）或
把跨层的生产者-消费者流水化（融合）。

### 追加：同频对比（决定性）

| 引擎 | 时钟 | conv | 整网 |
|---|---:|---:|---:|
| 原引擎 | 150 MHz | 129.8 s | **187.41 s** |
| **原引擎** | **140 MHz** | **140.6 s** | 197.03 s |
| **TH=2** | **140 MHz** | **141.7 s** | 198.19 s |

同频下 TH=2 慢 1.1 s（0.8%）⇒ 结论不变。
另外得到一个修正：150→140 MHz 使整网 +5.1%（187.41→197.03），
说明当前**大部分是计算受限**，不是"90 s 纯延迟"——这修正了对填充占比的估计。

## `conv2d_engine_fuse.cpp` —— 融合出口（out_lut / chsum）：**已实现，但 ABI 风险未解决**

**动机**：把 cat 的重定标（5.7 s）和 ECA 的通道均值（7.8 s）搬进卷积写回路径，
省掉两遍 DDR 往返；同时若能把 pp 引擎整个去掉，集成版的"布局容量墙"也一并解决。

**已实现**：三处写回点都加了可选 `out_lut`（256 项表，写回时直接落到目标张量标度）。
指针为 0 时行为与旧版完全一致（形状回归 30/30 通过）。

**意外发现（需先解释再做）**：加了出口之后 HLS 综合变成
DSP **131 → 47**、FF 17.0k → **8.9k**、BRAM 163 → 115，Fmax 仍 172 MHz，
功能（csim 3072/3072）正确。资源降这么多不像是"免费"，
**很可能是 HLS 把多条乘法链串行化（II 变大）**，必须先拿到 cosim 拍数才能判断。

**卡点**：新增的两个指针端口没有 `depth=` 声明，
`check_cosim_dims.py` 直接拒绝 cosim（"depth 与数据集不一致"）；
而要加 depth 就得改 AXI-Lite 寄存器表 ⇒ 存在"驱动没写新寄存器、引擎解引用垃圾指针"的风险。

**正确的下一步**
1. 用编译期宏把融合出口隔离（`#if FUSE_OUT`），默认构建**不产生任何新端口**，
   保持交付版 ABI 与资源完全不变；
2. 在 `FUSE_OUT=1` 的构建里给 out_lut/chsum 声明 `depth=`（256 / cout），跑 cosim 拿拍数；
3. 只有拍数不退化（相对 369,236）才值得继续做驱动侧接线。
