## 3. 路径 A：OpenDataLab 国内镜像（不耗 VPN）

**平台**：OpenDataLab（上海人工智能实验室），国内站，实测 **0.6 秒响应，无需代理**。

**数据集标识**：`OpenDataLab/UHDM`

**实际结构**（已用 `openxlab dataset info` 验证）：
```
OpenDataLab/UHDM                    总计 82.0 GB
├── README.md                        516 B
├── metafile.yaml                    279 B
├── raw/
│   └── UHDM.tar.gz                  80.00 GB   ← 完整数据集，单文件
└── sample/
    └── image/sample_0000.jpg ...    497 张，约 2 GB
```

**步骤**：

```powershell
# 1. 装 CLI（已在 tools/requirements_pdnet.txt 中）
pip install openxlab -i https://pypi.tuna.tsinghua.edu.cn/simple

# 2. 注册并登录（国内站，无需代理）
#    先到 https://openxlab.org.cn/ 注册，在"个人中心 → 密钥管理"获取 AK/SK
openxlab login

# 3. 先看信息确认体积
python tools/download_uhdm_opendatalab.py --info

# 4. 可选：先下 497 张样例图（约 2GB）验证链路
python tools/download_uhdm_opendatalab.py --samples

# 5. 下完整数据集（80GB）
python tools/download_uhdm_opendatalab.py
```

**注意**：
- 提供本仓库的辅助脚本 `tools/download_uhdm_opendatalab.py`，封装了上述命令
- `openxlab dataset ls` 有上游 bug（`NameError: rprint` is not defined），
  用 `info` 代替即可列出文件

## 4. 路径 B：Google Drive 分卷（可只下一部分）

⚠️ **这条路走 VPN，会消耗流量**，但优点是**可以只下一部分**。

官方文件夹里训练集是 **18 个分卷**：
```
train_split/train_split00.tar.gz ... train_split17.tar.gz
```

**部分下载的思路**：如果这些分卷是 `split` 切割出来的（同一 gzip 流被切段），
那么只下前 N 卷、拼接后仍可解压出**前面那部分数据**（gzip 允许在任意点截断，
`tar` 会提取截断前已完整的文件，末尾报 "unexpected EOF" 但前面的文件是好的）。

这样**下 4 卷（约 16 GB）就能拿到约 1000 对图**，是可用的训练子集。

⚠️ **但这个假设尚未验证**。分卷命名是 `train_split00.tar.gz`（带 `.tar.gz` 后缀），
既可能是切割段，也可能是**18 个独立压缩包**。两种情况下载策略不同：
- 若是切割段 → 只下前几卷即可（省流量）
- 若是独立包 → 每卷都能单独解压，也只需逐卷解压想要的

**验证方法（只需下一卷，约 4 GB）**：
```powershell
# 下载第一卷后尝试列出内容，不实际解压
tar -tzf train_split00.tar.gz | Select-Object -First 20
```
能列出文件 → 独立包（更简单）；报错但能列出部分 → 切割段。

## 5. 路径 C：在训练机（B 机）下载 —— 最推荐

理由：
1. **不占本机 VPN 流量**
2. 训练本来就在 B 机进行，数据在 B 机落盘最省事——否则还要再搬 80 GB 硬盘
3. B 机的网络条件可能更好（校园网/实验室网络通常不限量）

**做法**：把本仓库的 `tools/` 目录同步到 B 机（走 git 即可），然后在 B 机执行
路径 A 或 B 的步骤。

## 6. ⚠️ 战略提醒：真的需要完整训练集吗？

在下 80 GB 之前，值得先想清楚这个问题。**两条理由**：

### 理由一：最终部署目标是小画幅，与 4K 训练域不同

`交接文档` 第 1 节已明确：
> 摩尔纹频率与采集分辨率绑定。**不能把 4K 图降采样后训练/推理**
> 采集分辨率 = 训练分辨率 = 部署分辨率

本项目最终要部署 **600×400** 到 Zynq。而 UHDM 是**4K 拍屏**数据。
所以：
- UHDM 训练集 → 只能用来做 **Phase 1 基线复现**（验证能复现论文）
- **最终模型**需要**目标分辨率的真实数据**（相机在 600×400 采集，或合成）

换句话说，UHDM 对最终 FPGA 模型的价值是**有限的**（可作为预训练起点）。

### 理由二：交接文档的第一个未决问题还没回答

> **输入源**是相机拍屏幕还是已有图片库？若是相机，其输出分辨率是多少？

这个问题**决定了需要什么数据**。在它明确之前下 80 GB，有下错数据的风险。

### 建议的顺序

1. **先确认输入源与采集分辨率**（这是 Phase 2 的前提）
2. 若确定要做 Phase 1 基线复现 → 再下 UHDM 训练集
3. 若要直接做最终模型 → 优先采集**目标分辨率的真实数据**，体积会小得多
   （600×400 的数据量是 4K 的约 1/35）
