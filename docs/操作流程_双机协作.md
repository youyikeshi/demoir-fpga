# 操作流程：双机协作（代码走 Git，大文件走移动硬盘）

> 场景：机器 A（当前这台，无 GPU 训练条件）↔ 机器 B（训练机，有 GPU）
> 目标：代码和文档通过 GitHub 同步，权重/数据集通过移动硬盘搬运。
> 相关文档：`docs/交付说明_20260910.md`、`_hd_transfer/README.md`

---

## 1. 核心原则：什么走哪条路

| 内容 | 体积 | 走哪条路 | 原因 |
|---|---|---|---|
| 代码 `.py` / 配置 `.yaml` / 文档 `.md` | 小 | **Git** | 需要版本管理和双向同步 |
| 小结果 `curve.csv` / 日志 / 对比图 | <2 MB | **Git** | 属于实验记录，值得留痕 |
| teacher 权重 `checkpoint_000150.tar` | 50.8 MB | **移动硬盘** | 接近 GitHub 100MB 单文件上限，且官方只在网盘提供 |
| UHDM 数据集 `uhdm_data/` | GB 级 | **移动硬盘** | 远超仓库合理体积 |
| 合成数据 `synth_data/` | 1.4 MB | **移动硬盘** | 可脚本重生成，不必入库 |
| Python 虚拟环境 `.venv-pdnet/` | ~7 GB | **哪都不走** | 目标机器重建即可，见第 3 节 |
| VGG16 / LPIPS 权重缓存 | 761 MB | **哪都不走** | 首次运行时自动下载 |

一句话：**Git 只管"能看懂的东西"，硬盘只搬"跑起来需要的东西"。**

---

## 2. 为什么必须分开：GitHub 的硬限制

| 限制 | 阈值 | 后果 |
|---|---|---|
| 单文件大小 | 100 MB | 超过**直接拒绝推送**。teacher 权重 50.8MB 虽然没超，但已接近，且属二进制不适合管理 diff |
| 仓库建议体积 | 1 GB | 超了克隆会非常慢；数据集 GB 级必定超 |
| 推送请求体积 | 2 GB | |

`uhdm_data/` 若误提交，仓库会瞬间膨胀到数 GB，**且 git 历史无法轻易删除**（需要 `filter-repo` 重写历史）。
所以 `.gitignore` 里的这几条**不要删**：

```gitignore
uhdm_data/
_hd_transfer/
pdnet_smoke/synth_data/
*.tar
*.tar.gz
*.pth
out_dir/
```

## 3. 机器 B 首次搭建（从零开始）

### 3.1 拿代码

```bash
git clone <你的仓库地址> demoir-fpga
cd demoir-fpga
```

### 3.2 建 Python 环境

**不要**从 A 机拷贝 `.venv-pdnet`（跨机器不可靠、体积 7GB、路径写死）。按下面重建：

```bash
python -m venv .venv-pdnet
# Windows:
.venv-pdnet\Scripts\activate
# Linux:
source .venv-pdnet/bin/activate
```

装 CUDA 版 torch：**必须按目标机器的显卡架构选 cuXXX**：

```bash
# 本机实测可用（RTX 4060, sm_89, Windows）
pip install torch==2.7.0 torchvision==0.22.0 --index-url https://download.pytorch.org/whl/cu118

# 其余依赖（国内建议加清华镜像加速）
pip install -r tools/requirements_pdnet.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

> ⚠️ 常见坑：如果目标机器装的是 CPU 版 torch，代码会在 `.to(device)` 时报错或退化成 CPU 训练。
> 装完务必验证：
> ```bash
> python -c "import torch;print(torch.__version__, torch.cuda.is_available(), torch.cuda.get_device_name(0))"
> ```
> 输出里 `is_available()` 必须是 `True`。

### 3.3 还原大文件（从移动硬盘）

把硬盘上的 `_hd_transfer` 整个目录拷进仓库根目录，然后：

```bash
# 1. 校验拷贝完整性（CRC32 对比，能发现硬盘拷贝出错）
python tools/stage_hd_transfer.py --mode verify

# 2. 还原到仓库正确位置
python tools/stage_hd_transfer.py --mode restore

# 3. 确认关键文件就位
ls refer_code/PDNet/PDNet/Teacher_checkpoint/ghost_34large/UHDM/
```

校验失败（`[损坏] CRC32 不符`）说明文件在拷贝过程中出错，**重拷那一个文件**。
如果反复出现，说明移动硬盘或文件系统有问题——重拷那一个文件并校验。

### 3.4 首次运行前的检查

```bash
cd refer_code/PDNet/PDNet

# 1. 冒烟测试（用合成数据，几分钟，不需要真实数据集）
python train.py --config ./config/smoke_config.yaml

# 2. 若要通过辅助脚本看 PSNR/SSIM 曲线
python ../../pdnet_smoke/train_curve.py --config ./config/smoke_config.yaml --iters 300
```

跑通说明环境正确。首次运行会自动下载 VGG16（528MB）和 LPIPS alex（233MB），需要网络。

### 3.5 准备真实训练

**必须改数据路径**（原配置是作者机器上的绝对路径 `/home/data/...`）：

| 文件 | 行 | 改成 |
|---|---|---|
| `config/uhdm_config_distillation.yaml` | 10 | `TRAIN_DATASET: '../../../uhdm_data/Train'` |
| `config/uhdm_config_distillation.yaml` | 11 | `TEST_DATASET: '../../../uhdm_data/test'` |
| `config/uhdm_config.yaml` | 10–11 | 同上 |

> ⚠️ 关于 `../../../`：`train.py` 用 `from config.config import args`，所以**必须在
> `refer_code/PDNet/PDNet/` 目录下运行**（cwd 就是这里）。配置里的相对路径是按 **cwd**
> 解析的（`os.walk` 直接用传入字符串），不是按配置文件位置。从 `refer_code/PDNet/PDNet/`
> 退 3 层才是仓库根，所以是 `../../../uhdm_data/...`。
> 冒烟配置 `smoke_config.yaml` 里的 `../../../pdnet_smoke/...` 同理。

改动后**记得提交**，这样 A 机拉取时能看到（但注意：如果两台机器路径不同，
这个改动会互相冲突——见 5.1 的解决方案）。

## 4. 日常协作循环

### 4.1 在 A 机改代码 → 推到 GitHub

```bash
cd demoir-fpga

# 1. 先确认没有大文件混进来（关键步骤！）
git status --short

# 2. 如果看到 *_hd_transfer* / uhdm_data / *.tar 出现在待提交列表里，停下来检查 .gitignore

# 3. 提交
git add -A
git commit -m "描述这次改了什么"

# 4. 推送
git push
```

### 4.2 在 B 机拉取 → 跑训练

```bash
cd demoir-fpga
git pull

# 跑训练（后台 + 日志，避免终端断连导致误以为崩了）
nohup python train.py --config ./config/uhdm_config_distillation.yaml > train.log 2>&1 &

# 看进度
tail -f train.log
```

### 4.3 B 机的训练产物要不要回传

| 产物 | 建议 |
|---|---|
| 训练日志、指标曲线、loss 记录 | ✅ 提交到 git（小，是实验证据） |
| 对比图 / 可视化结果 | ✅ 提交（只要单张 <10MB） |
| 模型 checkpoint `.tar` | ❌ **绝不提交**（每个几十 MB，几十个就爆仓）→ 走硬盘或只保留最终那个 |

checkpoint 默认落在 `out_dir/<EXP_NAME>/net_checkpoints/`，`out_dir/` 已在 `.gitignore` 中。
**要回传具体某个 checkpoint 时**，用 `--mode stage` 前先把它挪到 `_hd_transfer` 的可搬运位置，
或直接手动拷到硬盘。

## 5. 常见坑与对策

### 5.1 两台机器路径不同导致配置冲突

**现象**：A 机改 `TRAIN_DATASET` 为自己的路径并提交，B 机拉取后路径失效，反复冲突。

**对策（按推荐度排序）**：

1. **用仓库内相对路径**（推荐）
   把数据集放在仓库根目录的 `uhdm_data/`，配置里按 cwd 写相对路径（cwd 是
   `refer_code/PDNet/PDNet/`，所以退 3 层到仓库根）：
   ```yaml
   TRAIN_DATASET: '../../../uhdm_data/Train'
   TEST_DATASET: '../../../uhdm_data/test'
   ```
   这样只要数据集放在仓库内、且从 `refer_code/PDNet/PDNet/` 运行，两台机器都能用。
   冒烟配置 `smoke_config.yaml` 用的就是这个写法。

2. **各自用本地覆盖配置，不提交**
   复制一份 `config/uhdm_config_distillation_local.yaml`，各自改路径，把 `*_local.yaml`
   加进 `.gitignore`。这样路径永远不会冲突。

3. 用环境变量（需要改代码，不推荐）

### 5.2 误把大文件 `git add` 了

**还没 commit**：
```bash
git restore --staged <大文件>
```

**已经 commit 但没 push**：
```bash
git reset --soft HEAD~1
git restore --staged <大文件>
```

**已经 push 了**：麻烦。需要在 `.gitignore` 忽略后，用 `git filter-repo`（或 BFG）
重写历史并强推，且**所有协作者都要重新克隆**。所以**在 commit 前检查 `git status`** 是最重要的习惯。

### 5.3 训练在后台被误判为"还在跑"

判断方法（Windows）：
```powershell
nvidia-smi --query-compute-apps=pid,process_name,used_memory --format=csv
Get-Process python | Select-Object Id,@{n='MemMB';e={[math]::Round($_.WorkingSet64/1MB)}}
```
如果 `nvidia-smi` 的 compute 列表里**没有 python**，就说明训练已停。
（桌面程序也会让显卡有占用，但那些是图形程序，不是 compute 进程。）

另外：Python 输出经 PowerShell 管道会被**块缓冲**，看起来像卡死。
调试时用 `python -u`（无缓冲），或让脚本自己写日志文件。

### 5.4 断点续传

大文件下载中断是常态（长时任务都可能被打断）：

- 数据集：`python tools/download_uhdm.py`（内部 `resume=True`，重跑即续传）
- 移动硬盘拷贝：`robocopy` 比资源管理器可靠
  ```powershell
  robocopy <源> <目标> /E /Z /R:3 /W:5 /NP /TEE /LOG:copy.log
  ```
  `/Z` 支持中断续传，`/R:3` 限制重试次数避免卡死

### 5.5 别忘了 `.gitattributes`（可选，但建议）

跨平台协作时，二进制文件（`.png`/`.tar`）应标记为二进制，避免 Git 尝试做行尾转换：

```bash
git config core.autocrlf false      # 两台机器都设，避免 CRLF/LF 来回改
```
