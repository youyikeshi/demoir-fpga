## 0. 这套设施解决什么

三个模块并行开发，必须用**同一套**判据，否则"我的 tb 过了"没有意义。本设施提供四件事：

| 层 | 文件 | 作用 |
|---|---|---|
| 向量 | `tools/make_golden.py` + `tools/golden_driver.cpp` | 用 `conv_ref_rt.cpp` 生成 `golden/<shape>/expected_c8.bin` |
| 激励/比对 | `tb/tb_common_tasks.vh` + `common/eq_checker.v` | tb 只写"参数 + 例化"，其余全包 |
| 单模块运行 | `tools/run_module.sh` | 编译 → 跑 → 判 → 写 `reports/<模块>_<时间戳>.md` |
| 全量看板 | `tools/regress_all.sh` | 遍历 `modules/*.v`，一行一个模块汇总 |

**不做什么**：不写模块本体、不综合、不上板、不 `git commit`。资源列只读取模块负责人提供的
`reports/<模块>_resources.json`，本设施不跑 csynth。

## 3. 黄金向量

### 3.1 生成链路（算术唯一来源）

```
input_c8.bin ──C8→CHW──┐
weight.bin ────────────┼──> conv_ref_rt.cpp ──CHW→C8（补零通道写 0）──> expected_c8.bin
bias.bin ──────────────┘        （pl/src，与 RTL 逐位一致的 C 参考）
```

`make_golden.py` **不做任何算术**，只负责复制/校验/调用。`golden_driver.cpp` 是
`conv_ref_rt()` 的薄封装：读 bin、转 CHW、调用、转回 C8。这样不会出现
"python 里再写一遍卷积，两边一起错"。

三套固定形状来自已有 cosim 数据集：

| shape | cin | cout | k | s | d | pad | H×W | shift | 来源 |
|---|---:|---:|---:|---:|---:|---:|---|---:|---|
| `k1_64x64` | 64 | 64 | 1 | 1 | 1 | 0 | 2×320 | 7 | `/data/work/tb_c8_k1_64x64` |
| `k3_32x16` | 32 | 16 | 3 | 1 | 1 | 1 | 2×320 | 7 | `/data/work/tb_c8_k3_32x16` |
| `k5_12x48` | 12 | 48 | 5 | 1 | 1 | 2 | 2×320 | 7 | `/data/work/tb_c8_k5_12x48` |

权重容器按契约 §2.2：k=1 每 (oc,ic) 1 B、k=3 12 B、k=5 28 B；输出物理通道
`ceil(cout/8)*8`，补零通道一律 0。

### 3.2 自检（0 差异才算生成成功）

生成后自动做一次独立交叉验证：用现有 HLS 引擎的 C-sim 构建
（`pl/tb/tb_engine_c8.cpp` + `-DC8_LAYOUT=1`）对同一组输入独立算一遍，输出转 C8 后
与 `expected_c8.bin` **逐字节**比对。任何差异都会直接 `FAIL` 退出，不会"改黄金迁就"。

当前结果（同时写在 `golden/INDEX.md`）：

| shape | expected 字节 | md5 | 交叉验证不一致 |
|---|---:|---|---:|
| `k1_64x64` | 40960 | `55126f35e9496e88cabf7f555d8d4677` | **0 / 40960** |
| `k3_32x16` | 10240 | `f9d8a9712fb085ec326f5d6693e7f15f` | **0 / 10240** |
| `k5_12x48` | 30720 | `61d0476a5170de44325d25f497da2a10` | **0 / 30720** |

> **关于"与现有 cosim 工程输出比对"**：`/data/work/hls_c8_cosim/*/cosim1/` 只保留了
> `C/RTL co-simulation finished: PASS` 日志，**没有落盘 RTL 输出**（tb 只有
> `TB_DUMP_OUT` 时才会写 C 侧 CHW 结果，历史运行没开）。因此这里用"同一份引擎的
> C-sim 构建"做交叉验证；该构建在
> `docs/设计/记录_20261023_C8RTL改造与验证.md` 与
> `docs/设计/记录_20261023_纯编译期C8与全8对齐.md` 里已由 HLS cosim
> 逐位验证过（10,240 / 30,720 输出全一致）。这是当前能拿到的最硬证据，标"存疑"的
> 部分只有"cosim RTL 输出未落盘"这一条。

### 3.3 fuzz 向量

```bash
# 每个选中形状生成 200 组：前 3 组固定为
#   全 0 / 全 +127（正饱和）/ 输入全 -128 + 权重 +127（负饱和、ReLU=0）
# 其余随机；种子固定可复现。
./tools/make_golden.py --random 200 --shape k3_32x16 --seed 20261023

# 生成结果
golden/fuzz/k3_32x16/case_000 ... case_199/
golden/fuzz/k3_32x16/manifest.txt     # 每行一个绝对目录，供 tb 一次仿真内循环
```

种子固定（默认 `20261023`），同样参数可复现同一批向量。fuzz 的 H/W/shift 默认从
**已生成的** `golden/<shape>/meta.json` 读取，所以三套固定 golden 生成后就不再依赖
`/data/work`。`run_module.sh --fuzz N` 会自动调用它，并把 manifest 传给 tb；
**一次 xsim 内循环 N 组**，不重复启动仿真器。

> 注意：全 127 边界用例的累加和会接近 26-bit 累加器上界。当前三套预设
> （cin=12/32/64）远低于红线；若以后新增 cin ≳200 的 k=5 形状，先按契约 §2.3
> 确认不会绕回，否则把该形状的边界用例改成随机/小幅值。

## 4. 通用 testbench 骨架 `tb/tb_common_tasks.vh`

### 4.1 它替你做了什么

- `ap_clk`（10 ns 周期，可用 `` `TB_CLK_HALF_NS `` 改）与 `ap_rst_n`；
- 契约 §3 的 `ctrl_*` 信号，并自动接 `ctrl_in_addr/ctrl_wgt_addr/ctrl_bias_addr/ctrl_out_addr`
  到四个内存区；`ctrl_shift/cin/cout/h/w` 从 golden 的 `meta.json` 自动驱动；
- **4 路 AXI4 从机内存模型**（in / w / b 三读 + out 一写，64-bit 数据宽），
  支持 burst、`arvalid/arready`、`rvalid/rready/rlast`、`aw/w/b`、`wstrb`；
- `byte` 动态数组加载 `input_c8.bin / weight.bin / bias.bin / expected_c8.bin`；
- 4 个 task（名字与任务书一致）：
  `load_bins(dir)`、`drive_start()`、`check_bytes(n_bad)`、`report_all(name)`；
- 自动入口 `tb_run(name)`：读 `+GOLDEN=<dir>` 或 `+FUZZ_MANIFEST=<file>`，跑完打印报告并
  以 `$fatal` 返回非 0（失败时）。

**不假设任何模块内部结构**：只认契约 §3 的顶层端口名。模块内部叫什么、几级流水、
状态机怎么编码，与 tb 无关。

**不要再写**：时钟 `always`、`initial` 里的复位、AXI 读写从机、`$readmemh`、比对循环。

> 不要在 tb 里自己覆盖 `TB_MAX_SIM_NS`。共享骨架已有默认值
> `64'd600000000000`（600 s）；写成未带位宽的 `60000000000` 会被截成 32 位负数，
> xsim 会把它当 0 延时，表现为"看门狗在 0 时刻触发"（k5 tb 踩过，已修）。

> 注意 `meta.json` 里的 H/W/shift 是**运行时**读入的；DUT 例化参数（CIN/COUT/H/W…）
> 必须与 `run_module.sh` 传入的 shape 一致。若不一致，第一个字节就会出现差异，
> 报错会给出 c/y/x 坐标，不会静默通过。

### 4.3 task 语义

| task | 行为 |
|---|---|
| `load_bins(input string dir)` | 读 `meta.json`、`shift.txt`、4 个 bin；按契约算 `cin_pad/cout_pad/Hout/Wout`；校验每个文件字节数；`out_mem` 初始化为 `8'hxx`（漏写会以 X 暴露） |
| `drive_start()` | 拉高 `ctrl_start` 一拍，然后在 `negedge` 采样 `ctrl_done`（避免单拍脉冲与 NBA 竞争），统计拍数；超时 `$fatal` |
| `check_bytes(output int n_bad)` | 调 `eq_byte_checker.compare()` 逐字节比 `expected_c8.bin`；打印前 200 处失配的 `byte / (c,y,x) / expected / actual`；同时累计逐 c / 逐 x 失配分布并打印 `[TB-PATTERN] c_top=[...] x_top=[...]` |
| `report_all(input string name)` | 打印统一验收表 + 机器可读 `[TB-SUMMARY]` 行；`run_module.sh` 解析后者 |

拍数口径：从 `ctrl_start` 拉高后的第一个上升沿起，到采样到 `ctrl_done` 的上升沿止
（不含 done 之后的 8 拍 drain）。实现上用 negedge 检查 done，兼容"单拍脉冲"的模块。

### 4.4 失败定位：`+DUMP_OUT` 与错误分布

tb 支持两个 plusarg（`run_module.sh` 分别用 `--dump-out` / `--fuzz 200` 传）：

| plusarg | 作用 |
|---|---|
| `+DUMP_OUT=<file>` | 把 DUT 实际输出按 `expected_c8.bin` 的**同一字节序与布局**（C8、物理通道数）落盘；**失败也写**。fuzz 模式写 `<file>.case_000`、`.case_001`…；X/Z（漏写）写成 0x00，并在报告里用 `unknown=` 单独计数 |
| `+FUZZ_MANIFEST=<file>` | 每行一个 golden 目录，一次 xsim 内循环 |

`[TB-SUMMARY]` 末尾带 `c_top=[c:count,...] x_top=[x:count,...] unknown=N`（前 5 个错得最多的
通道 / 列），可直接看出"某些 oc 全错"还是"某些列全错"。

用法（`--dump-out` 由 runner 转成 `+DUMP_OUT`）：

```bash
./tools/run_module.sh conv_k1_engine k1_64x64 --dump-out /tmp/dut_out.bin
# 即使验收 FAIL，/tmp/dut_out.bin 也会写出来（大小 = expected_c8.bin）
```

典型定位（在主控侧，不需要重跑仿真）：

```bash
python3 - <<'PY'
import json, numpy as np
m = json.load(open('golden/k1_64x64/meta.json'))
hout = (m['H'] + 2*m['pad'] - ((m['k']-1)*m['d']+1)) // m['s'] + 1
wout = (m['W'] + 2*m['pad'] - ((m['k']-1)*m['d']+1)) // m['s'] + 1
cpad = (m['cout'] + 7) // 8 * 8
a = np.fromfile('dut_out.bin', np.int8)      # DUT 实际输出（C8）
b = np.fromfile('golden/k1_64x64/expected_c8.bin', np.int8)
d = (a != b).reshape(cpad // 8, hout, wout, 8)
print("per-channel errors:", d.sum(axis=(1, 2)).ravel())   # 64 个 c
print("per-x errors      :", d.sum(axis=(0, 1, 3)))       # 320 个 x
PY
```

### 4.5 内存映射

| 区域 | 基址 | 内容 |
|---|---|---|
| `in` | `0x0000_0000` | `input_c8.bin`，大小 `cin_pad*H*W` |
| `wgt` | `0x1000_0000` | `weight.bin`，PAD 容器 |
| `bias` | `0x2000_0000` | `bias.bin`，int32 小端 |
| `out` | `0x3000_0000` | 输出 C8，大小 `cout_pad*Hout*Wout` |

地址是**字节地址**，读侧每拍 8 字节（`rdata` 64-bit），写侧按 `wstrb` 逐字节落内存。
一次只支持一个 outstanding burst（AW/AR 各一个）——现有 HLS 引擎与手写模块都是这个形态；
若某个模块要发多 outstanding，需要扩展 BFM（标"存疑"，不要私改共享文件，先提出来）。

### 4.6 与 `eq_checker.v` 的分工

- `eq_checker`：有**黄金 RTL** 可同时例化时，做逐拍指纹比对（`SKEW` 参数可容忍流水级差；
  本轮顺手修了原实现 `SKEW` 空转的 bug，见文件内注释）。
- `eq_byte_checker`（同文件第二个 module）：只有 `expected_c8.bin` 时，做逐字节比对。
  `tb_common_tasks.vh` 例化一份，`check_bytes()` 直接调它。两个比较器共用同一份文件，
  模块 tb 不需要自己写比较逻辑。

## 5. `tools/run_module.sh`

```text
./tools/run_module.sh <模块名> [golden 形状] [选项]

选项：
  --shape S          等价于第二个位置参数
  --golden DIR       直接指定 golden 目录（自测用）
  --dut FILE         默认 modules/<模块名>.v
  --tb FILE          默认 tb/tb_<模块名>.v
  --top NAME         默认 tb_<模块名>
  --fuzz N           跑 N 组随机向量（生成 fuzz manifest，一次 xsim 内循环）
  --fuzz-manifest F  直接使用现成 manifest（每行一个 golden 目录）
  --seed N           fuzz 种子（默认 20261023）
  --target N         覆盖 tools/targets.tsv 的目标拍数
  --max-cycles N     看门狗拍数
  --timeout S        单步超时秒数（默认 300；xvlog/xelab/xsim 各自 timeout）
  --dump-out FILE    落盘 DUT 输出（格式同 expected_c8.bin；失败也写）
  --define N[=V]     额外编译宏（可重复）
  --compile-only     只跑 xvlog 语法检查（安全，不 xelab/xsim）
  --clean            仿真结束后删除 build/run_* 目录
```

流程：`xvlog`（模块 + tb + `common/eq_checker.v`）→ `xelab` → `xsim`（一次或 fuzz 循环）
→ 解析 `[TB-SUMMARY]` → 写 `rtl_hand/reports/<模块>_<时间戳>.md`。

**所有子步骤都套了 `timeout`**（默认 300 s，`-k` 再兜底 5/10 s）：xvlog、xelab、xsim
各自超时；xsim 侧还有两道 tb 内看门狗：`MAX_CYCLES`（单组 `ctrl_start→ctrl_done`，
默认 20,000,000 拍）和全局仿真时间 `TB_MAX_SIM_NS`（默认 600 s 仿真时间，足以覆盖 200 组 fuzz）。正常情况下
会先 `$fatal`/`$finish`，不会走到墙钟超时；超时退出码 124，日志里会明确写"超时"。

runner 还会从 `golden/meta.json` 自动派生 `TB_CIN/TB_COUT/TB_K/TB_S/TB_D/TB_PAD/TB_H/TB_W/TB_SHIFT`
传给 xvlog，方便那些用 `ifndef TB_H` 参数化 DUT 的 tb；共享骨架本身在运行时读 meta，
不依赖这些宏。另会传 `+DIR=` / `+MANIFEST=` 作为 `+GOLDEN=` / `+FUZZ_MANIFEST=` 的兼容别名。

报告严格按契约 §5 的模板：

| 项 | 值 |
|---|---|
| 逐字节一致 | `N / N` |
| 随机 fuzz | `M / M` 组 |
| 每层拍数 | 实测 `X` vs 目标 `Y`（`X/Y`）|
| 资源（csynth） | 读 `reports/<模块>_resources.json`，没有则写"未提供（本设施不综合）" |
| 错误分布 top5 | `c_top=[...]` / `x_top=[...]` / `unknown=N` |
| 未达标的项 | 逐条列：字节、fuzz、AXI 越界、拍数比 >1.2、fuzz <200 |

**退出码**：`0` 全部过、`1` 仿真/比对失败、`2` 参数/文件缺失、`3` 环境问题。
任何一项不过都是非 0（包括 `$fatal` 的 xsim 退出码）。xvlog / xelab 失败也会写一份
"结论 FAIL"的简短报告（含日志 tail），不会静默退出。

目标拍数登记在 `tools/targets.tsv`（模块+形状 → 拍数）。默认值是**当前 HLS cosim 基线**：

| shape | HLS 基线拍数 | 出处 |
|---|---:|---|
| `k1_64x64` | 531,437 | `docs/设计/记录_20261023_k1十六车道与两处加宽证伪.md` |
| `k3_32x16` | 217,907 | `docs/设计/记录_20261023_写回宽写与填充零浪费.md` |
| `k5_12x48` | 2,106,401 | 同上 |

这些是"替换 HLS 的参照"，不是手写模块的最终目标；模块自己的目标写进
`docs/rtl_hand/<模块>.md`，再用 `--target` 或在 `targets.tsv` 里按模块覆盖。

## 6. `tools/regress_all.sh`（主控看板）

```bash
./tools/regress_all.sh
FUZZ_N=200 ./tools/regress_all.sh
./tools/regress_all.sh --only k5
```

遍历 `modules/*.v`，逐个调用 `run_module.sh`，输出：

```
| 模块 | 逐字节 | fuzz | 拍数比 | DSP/BRAM/LUT | 结论 |
|---|---|---|---|---|---|
| conv_k5_engine | 30720/30720 | 200/200 | 0.850 | 120/40/11000 | PASS |
| conv_k3_engine | 10240/10240 | 未跑 | —（217907 拍） | —/—/— | PASS*（fuzz 未跑）|
| conv_k1_engine | — | — | — | —/—/— | SKIP（无 tb）|
```

- `PASS*` = 逐字节过但 fuzz 没跑；**契约 §5 的正式验收要求 fuzz ≥200 组**，看板会显式标出。
- 拍数比 = 实测 / 目标；目标未登记时显示实测拍数。
- 资源列读 `reports/<模块>_resources.json`（可选，格式 `{"dsp":..,"bram":..,"lut":..,"fmax":..}`）。
- 每次看板写到 `reports/regress_<时间戳>.md`。
- 串行执行：`golden/fuzz/<shape>` 按形状共享，不能并行写；模块多时先跑 `--only` 分组。

## 7. 自测证据（假模块）

```bash
# 主控可直接跑这两个（最省事）
./tools/run_module.sh _selftest_ok      # 期望退出 0
./tools/run_module.sh _selftest_bad     # 期望退出 1，且打印 @byte=12345

# 一次跑完三条断言（PASS / FAIL / fuzz 循环）并落 evidence 文件
./tools/selftest.sh
```

假模块源文件是 `tools/selftest/fake_engine.v`；`modules/_selftest_ok.v` 与
`modules/_selftest_bad.v` 是它的两份拷贝（`_` 开头，`regress_all.sh` 默认跳过）。
它**不是卷积模块**，只是按 AXI 写全 0，对
`golden/_selftest_zero` 做三条断言：

1. **PASS 链路**：写全 0 → `run_module.sh` 退出 0，`bytes=30720/30720`；
2. **FAIL 链路**：`INJECT_ERROR=1` 在第 12345 字节写 1 →
   退出 1，打印
   `[BYTE-CHECK] ✗ ... @byte=12345 (c=17,y=0,x=263) 期望=0(0x00) 实际=1(0x01)`，
   汇总 `bytes=30719/30720 status=FAIL`；
3. **fuzz 循环**：同一 golden 目录重复 5 次 → 一次 xsim 内 `cases=5/5`、
   `bytes=153600/153600`。

自测证据写到 `reports/selftest_<时间戳>.md`。当前三条全部通过（2026-10-23）。

> `tools/selftest/fake_engine.v` 不在 `modules/` 下；`modules/_selftest_*.v` 虽然
> 在 `modules/` 里，但以 `_` 开头，`regress_all.sh` 默认跳过（`--include-selftest`
> 才跑）。所以它们不会被误当成真实模块合入看板。

## 8. 设计取舍与已知限制

1. **为什么用 `$fread` 而不是 `$readmemh`**：契约 §5 写的是 `$readmemh` 读 `.bin`，
   但 `$readmemh` 读的是文本十六进制，二进制必须用 `$fread`。本设施用
   `$fread(byte_array, fd)` 读原始字节；如果后续契约改成 `.hex`，再换。
2. **`meta.json` 解析**：为了不引入 JSON 库，`load_bins` 用 `$sscanf` 匹配
   `make_golden.py` 生成的固定键序/无空格格式。手改 `meta.json` 加空格/换序会导致
   解析失败（`$fatal` 并打印期望格式）。**始终用生成器**；旧 `meta.txt` 数据集先跑
   `make_golden.py --from-dir` 转换。
3. **tb 必须用共享骨架（或至少打印 `[TB-SUMMARY]`）**：`run_module.sh` 靠
   `[TB-SUMMARY] module=... bytes=ok/total cases=pass/total cycles=... status=PASS/FAIL`
   解析结果。并行开发中若某个 tb 自己写了一套输出格式、又不打印该行，runner 会按 FAIL
   处理（并打印 `[WARN] ... 没有 include tb_common_tasks.vh`）。这不是模块错误，是 tb
   未接入；按 §4.2 改造即可。runner 已尽量兼容旧 tb（`+DIR`/`+MANIFEST` 别名、形状宏），
   但**判据行必须统一**。
4. **AXI 模型是验收级，不是协议验证级**：不做 `ARSIZE/AWSIZE`、乱序 ID、多 outstanding、
   4 KB 边界拆分。判据是"功能/字节正确"，不是"AXI 合规"。如果模块时序问题出在这些
   边角，需要另加协议检查（或复用 HLS cosim 的 AXI checker）。
5. **拍数目标不是最终性能目标**：`targets.tsv` 里的 531,437 / 217,907 / 2,106,401 是
   HLS cosim 基线，用来判断"是否至少不比 HLS 差太多（≤1.2×）"。手写模块的真实目标
   （如 k=5 → ≤0.15 s）是整网口径，不能直接套到 2×320 的 cosim 形状上。
6. **fuzz 向量目录共享**：`run_module.sh --fuzz` 会重写 `golden/fuzz/<shape>/`，
   所以 `regress_all.sh` 串行跑；并行调用同一 shape 会互相踩。需要并行时按 shape 分目录
   或改 `--fuzz-manifest`。
7. **单拍 `ctrl_start` / `ctrl_done`**：`drive_start` 按"脉冲启动、电平/脉冲 done 均可"
   实现（negedge 采样）；若模块要求 `ctrl_start` 保持到 `ctrl_busy`，需要改 task
   并在模块文档里标注（当前契约没有这个要求）。
8. **资源红线不在这里判**：DSP/BRAM/LUT 必须由模块负责人跑 csynth 后提供
   `reports/<模块>_resources.json`；`run_module.sh` 只负责把它写进报告，不做综合。
9. **现有 cosim 输出未落盘**：见 §3.2 的"存疑"说明。若以后有人补跑 cosim 并 dump
   RTL 输出，建议把该文件拷进 `golden/<shape>/` 外层做一次性交叉验证，不要覆盖黄金。

## 9. 故障排查

| 现象 | 原因/处理 |
|---|---|
| `找不到 xvlog` | Vivado 没装或路径不在候选列表；`export XILINX_VIVADO=/path/to/Vivado` 后重跑 |
| `解析 meta.json 失败` | 手改了格式；重新跑 `make_golden.py`（旧 meta.txt 数据集用 `--from-dir` 转换） |
| `等待 ctrl_done 超时` | 模块没握手/状态机卡死；先看 `build/run_*/sim.log` 里最后一条 `[TB]`，再用 `--max-cycles` 放大看门狗 |
| 大量 `实际=xx`/`实际=x` | `x` 表示该字节从未被写（`out_mem` 初值 `8'hxx`）；查写回地址/`wstrb`/`wlast` |
| 失配集中在某些 c/y/x | 报告给出 C8 反解坐标；对照 `addr(c,y,x)` 公式查通道块/行/列边界 |
| fuzz 某组失败 | `golden/fuzz/<shape>/case_XXX/` 是完整可复现目录，用 `--golden` 单跑该组定位 |
| `regress_all` 显示 SKIP | `tb/tb_<模块>.v` 不存在；先按 §4.2 建 tb |

## 10. 加新形状 / 新模块

**新形状**（已有 cosim 数据集）：

```bash
./tools/make_golden.py --from-dir /data/work/tb_c8_kX_... \
    --name my_shape --cin 24 --cout 32 --k 3 --s 1 --d 1 --pad 1
# H/W/shift 默认读 --from-dir/meta.txt，可用 --H/--W/--shift 覆盖
```

**新模块**：

1. 写 `modules/<模块>.v`（端口严格按契约 §3）；
2. 按 §4.2 复制最小 tb 到 `tb/tb_<模块>.v`；
3. 在 `tools/module_shapes.tsv` 加 `模块名<TAB>形状`；
4. `./tools/run_module.sh <模块> <形状> --fuzz 200`；
5. 跑 csynth 后把资源写 `reports/<模块>_resources.json`；
6. `./tools/regress_all.sh` 看总表。
