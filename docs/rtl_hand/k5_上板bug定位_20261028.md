# k5 引擎上板 bug 定位记录（2026-10-28）

## 现象（单层 `encoder.conv_first`：cin=12 cout=48 320×320 k=5 pad=2）

```
总不符 21218 / 4915200  (0.43%)
出错列:  [3, 259]        ← 只有两列，且 259 = 3 + 256
出错通道: 全部 48
出错行:   320 行中约 70% 的 (c,y) 组合
```

## 已排除

| 假设 | 判据 | 结论 |
|---|---|---|
| 地址混叠（x 与 x+256 相撞）| `got[x=259]` vs `exp[x=3]` 仅 3798/15360 相同（随机水平）| ❌ |
| 缓冲容量不足 | `LB_DEPTH=324`、`WB_DEPTH=768`，无 256 深缓冲；`fill_col/lb_waddr/lb_raddr` 均 10 位 | ❌ |
| 时序竞争（不确定）| 同一输入连跑 3 次，**输出逐字节完全相同** | ❌ |
| 零输入有问题 | 零输入 → **0/4915200 不符** | ❌ |
| 常数输入有问题 | 常数 1 / 2 → **0/4915200 不符** | ❌ |
| 行列映射错误 | 单列脉冲：c=3/100/259/300 的输出**支撑集都恰好是 [c-2,c+2]** | ❌ |

## 决定性证据：列窗口右移 1

用"列间取值不同"的输入（各通道、各行相同），在 x=3 处做假设检验：

```
正常映射       与 got 相同 24 / 48 通道
列偏移 +1      与 got 相同 48 / 48  ★
```

$$\Rightarrow \textbf{x=3 处用了窗口 } [4..8] \text{ 而不是 } [3..7]$$

即该拍的 `lb_raddr` 比应为的多 1（`lb_raddr = x_cnt + 5`）。

## 结论与判据

**定性：`shift_pix` 滑动窗口在特定列多移了一拍**（不是地址线截断、不是容量、不是随机竞争）。

$$\text{触发条件与"列间数据是否变化"相关} \Rightarrow \text{触发点随输入变化（随机输入是 3/259，常数输入不触发）}$$

所以**不能靠"软件修补那两列"绕过**——坏列的位置不固定。

## 下一步（需要仿真环境）

1. 在 TB 里把 `stall`/反压注入到特定列（当前 TB 的总线模型不反压），复现"窗口多移一拍"
2. 重点看 `shift_en`：
   ```verilog
   assign shift_en = ((state==S_PRELOAD) && (pre_cnt>=1) && (pre_cnt<=5))
                  || ((state==S_COMPUTE) && (ic_cnt==IC_LAST) && (s_cnt==NG_LAST)
                      && (x_cnt != X_LAST));
   ```
   以及 `lb_raddr` 是**组合**产生（`x_cnt + 5`）却直接喂同步 RAM：
   ```verilog
   lb_rd[i] <= {lb_hi_i[lb_raddr], lb_lo_i[lb_raddr]};
   ```
   $$\text{组合地址 + 同步读 + 与 } \texttt{x\_cnt} \text{ 同拍变化} \Rightarrow \text{在硬件上是一条可疑的地址/使能竞态}$$
3. 建议改成：`lb_raddr` 打一拍再喂 RAM，并把 `shift_pix` 的采样点同步后移一拍
