# 操作流程：双机协作（代码走 Git，大文件走移动硬盘）

> 场景：机器 A（当前这台，无 GPU 训练条件）↔ 机器 B（训练机，有 GPU）
> 目标：代码和文档通过 GitHub 同步，权重/数据集通过移动硬盘搬运。
> 相关文档：`docs/训练/说明_交付_20260910.md`、`_hd_transfer/README.md`

---

## 1. 核心原则：什么走哪条路

| 内容 | 体积 | 走哪条路 | 原因 |
|---|---|---|---|
| 代码 `.py` / 配置 `.yaml` / 文档 `.md` | 小 | **Git** | 需要版本管理和双向同步 |
| 小结果 `eval_*.csv` / 日志 / 对比图 | <2 MB | **Git** | 属于实验记录，值得留痕 |
| 训练产物 `runs/` | —— | 部分 | 配置快照/日志/可视化图进 Git；`net_checkpoints/` 不进 |
| teacher 权重 `weights/teacher/*.tar` | 50.8 MB | **移动硬盘** | 接近 GitHub 100MB 单文件上限，且属二进制不适合管理 diff |
| student 权重 `weights/student/*.tar` | 18.3 MB | **移动硬盘** | 同上 |
| 数据集 `datasets/` | GB 级 | **移动硬盘** | 远超仓库合理体积 |
| 合成数据 `samples/synth/` | 1.4 MB | **哪都不走** | 可脚本固定种子重生成 |
| Python 虚拟环境 `.venv-pdnet/` | ~7 GB | **哪都不走** | 目标机器重建即可，见第 3 节 |
| VGG16 / LPIPS 权重缓存 | 761 MB | **哪都不走** | 首次运行时自动下载 |

一句话：**Git 只管"能看懂的东西"，硬盘只搬"跑起来需要的东西"。**

---

## 2. 为什么必须分开：GitHub 的硬限制

| 限制 | 阈值 | 后果 |
|---|---|---|
| 单文件大小 | 100 MB | 超过**直接拒绝推送**。teacher 权重 50.8MB 虽然没超，但已接近，且属二进制不适合管理 diff |
| 仓库建议体积 | 1 GB | 超了克隆会非常慢；数据集 GB 级必定超 |
| 推送请求体积 | 2 GB | |

`datasets/` 若误提交，仓库会瞬间膨胀到数 GB，**且 git 历史无法轻易删除**（需要 `filter-repo` 重写历史）。
所以 `.gitignore` 里的这几条**不要删**：

```gitignore
datasets/*          # 只放行 datasets/README.md（内容全部忽略）
runs/**/net_checkpoints/
samples/synth/
_hd_transfer/
*.tar
*.tar.gz
*.pth
```

## 3. 机器 B 首次搭建（从零开始）

### 3.1 拿代码

```bash
git clone <你的仓库地址> demoir-fpga
cd demoir-fpga
```

### 3.2 建 Python 环境

**不要**从 A 机拷贝 `.venv-pdnet`（跨机器不可靠、体积 7GB、路径写死）。按下面重建：

```bash
python -m venv .venv-pdnet
# Windows:
.venv-pdnet\Scripts\activate
# Linux:
source .venv-pdnet/bin/activate
```

装 CUDA 版 torch：**必须按目标机器的显卡架构选 cuXXX**：

```bash
# 本机实测可用（RTX 4060, sm_89, Windows）
pip install torch==2.7.0 torchvision==0.22.0 --index-url https://download.pytorch.org/whl/cu118

# 其余依赖（国内建议加清华镜像加速）
pip install -r tools/requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

> ⚠️ 常见坑：如果目标机器装的是 CPU 版 torch，代码会在 `.to(device)` 时报错或退化成 CPU 训练。
> 装完务必验证：
> ```bash
> python -c "import torch;print(torch.__version__, torch.cuda.is_available(), torch.cuda.get_device_name(0))"
> ```
> 输出里 `is_available()` 必须是 `True`。

### 3.3 还原大文件（从移动硬盘）

把硬盘上的 `_hd_transfer` 整个目录拷进仓库根目录，然后：

```bash
# 1. 校验拷贝完整性（CRC32 对比，能发现硬盘拷贝出错）
python tools/stage_hd_transfer.py --mode verify

# 2. 还原到仓库正确位置
python tools/stage_hd_transfer.py --mode restore

# 3. 确认关键文件就位
ls weights/teacher/
```

校验失败（`[损坏] CRC32 不符`）说明文件在拷贝过程中出错，**重拷那一个文件**。
如果反复出现，说明移动硬盘或文件系统有问题——重拷那一个文件并校验。

### 3.4 首次运行前的检查

```bash
# 1. 冒烟测试（用合成数据，几分钟，不需要真实数据集）
python src/train.py --config smoke --epochs 1

# 2. 若要通过辅助脚本看 PSNR/SSIM 曲线
python experiments/train_curve.py --config smoke --iters 300
```

跑通说明环境正确。首次运行会自动下载 VGG16（528MB）和 LPIPS alex（233MB），需要网络。

> 📌 **不需要 `cd` 到任何目录**。所有入口都以绝对路径解析数据集与权重，
> 从仓库根、从 `C:\`、从任何地方运行结果都一样。

### 3.5 准备真实训练

**不需要改任何路径。** 直接在配置里写数据集名字即可：

```yaml
DATA:
  DATASET: uhdm      # -> datasets/uhdm/{train,eval}
```

把数据放到 `datasets/<名字>/{train,eval}/`，具体布局要求见 `src/configs/README.md`。
上游那 9 份自带配置（`vendor/PDNet/config/*.yaml`）里仍然是作者机器的
`/home/data/...` 绝对路径，**不要用它们** —— 用 `src/configs/` 下的配置。

## 4. 日常协作循环

### 4.1 在 A 机改代码 → 推到 GitHub

```bash
cd demoir-fpga

# 1. 先确认没有大文件混进来（关键步骤！）
git status --short

# 2. 如果看到 *_hd_transfer* / uhdm_data / *.tar 出现在待提交列表里，停下来检查 .gitignore

# 3. 提交
git add -A
git commit -m "描述这次改了什么"

# 4. 推送
git push
```

### 4.2 在 B 机拉取 → 跑训练

```bash
cd demoir-fpga
git pull

# 跑训练（脚本自己会同时写日志到 runs/<run>/train.log）
python src/train.py --config uhdm_4k_s

# Linux/远程机器建议后台跑：
nohup python src/train.py --config uhdm_4k_s > train.log 2>&1 &
tail -f train.log
```

### 4.3 B 机的训练产物要不要回传

| 产物 | 建议 |
|---|---|
| 训练日志、指标曲线、loss 记录 | ✅ 提交到 git（小，是实验证据） |
| 对比图 / 可视化结果 | ✅ 提交（只要单张 <10MB） |
| 模型 checkpoint `.tar` | ❌ **绝不提交**（每个几十 MB，几十个就爆仓）→ 走硬盘或只保留最终那个 |

checkpoint 默认落在 `runs/<运行目录>/net_checkpoints/`，已被 `.gitignore` 挡住。
**要回传具体某个 checkpoint 时**，用 `--mode stage` 前先把它挪到 `_hd_transfer` 的可搬运位置，
或直接手动拷到硬盘。

```bash
# 看看一次训练到底用了什么（快照 + 可读记录）
cat runs/<run>/config.yaml
cat runs/<run>/run_info.yaml
```

## 5. 常见坑与对策

### 5.1 两台机器路径不同（**已从设计上解决**）

**旧问题**：配置里写的是相对 cwd 的路径（`../../../uhdm_data/...`），
两台机器路径不同就冲突，而且要 `cd` 到特定目录才能跑。

**现在**：配置里只写名字，`src/train.py` 把它们解析成**绝对路径**：

```yaml
DATA:
  DATASET: uhdm            # -> <仓库>/datasets/uhdm/{train,eval}
TEACHER_MODEL:
  TEACHER: ghost_34large   # -> <仓库>/weights/teacher/...
```

所以两台机器只需要各自把数据放在 `datasets/<名字>/` 下，**配置一个字都不用改**，
也不会产生冲突。

数据在仓库外时也不必改配置：

```bash
python src/train.py --config uhdm_4k_s --dataset-root /mnt/disk2/mydata
```

> ⚠️ 唯一仍需注意的是 `_hd_transfer/payload/` 是**按仓库路径镜像**的。
> 如果你改了 `datasets/` 或 `weights/` 的目录结构，必须在 A 机**重新 stage**，
> 否则 B 机 `restore` 会找不到文件。

### 5.2 误把大文件 `git add` 了

**还没 commit**：
```bash
git restore --staged <大文件>
```

**已经 commit 但没 push**：
```bash
git reset --soft HEAD~1
git restore --staged <大文件>
```

**已经 push 了**：麻烦。需要在 `.gitignore` 忽略后，用 `git filter-repo`（或 BFG）
重写历史并强推，且**所有协作者都要重新克隆**。所以**在 commit 前检查 `git status`** 是最重要的习惯。

### 5.3 训练在后台被误判为"还在跑"

判断方法（Windows）：
```powershell
nvidia-smi --query-compute-apps=pid,process_name,used_memory --format=csv
Get-Process python | Select-Object Id,@{n='MemMB';e={[math]::Round($_.WorkingSet64/1MB)}}
```
如果 `nvidia-smi` 的 compute 列表里**没有 python**，就说明训练已停。
（桌面程序也会让显卡有占用，但那些是图形程序，不是 compute 进程。）

另外：Python 输出经 PowerShell 管道会被**块缓冲**，看起来像卡死。
调试时用 `python -u`（无缓冲），或让脚本自己写日志文件。

### 5.4 断点续传

大文件下载中断是常态（长时任务都可能被打断）：

- 数据集：`python tools/download_uhdm.py`（内部 `resume=True`，重跑即续传）
- 移动硬盘拷贝：`robocopy` 比资源管理器可靠
  ```powershell
  robocopy <源> <目标> /E /Z /R:3 /W:5 /NP /TEE /LOG:copy.log
  ```
  `/Z` 支持中断续传，`/R:3` 限制重试次数避免卡死

### 5.5 别忘了 `.gitattributes`（可选，但建议）

跨平台协作时，二进制文件（`.png`/`.tar`）应标记为二进制，避免 Git 尝试做行尾转换：

```bash
git config core.autocrlf false      # 两台机器都设，避免 CRLF/LF 来回改
```

## 6. 完整流程速查（复制粘贴用）

### 机器 A（当前，无训练条件）

```powershell
cd G:\qiansaiFPGA2026\demoir-fpga

# 收集大文件到 _hd_transfer（数据集下完后重跑一次）
& "G:\qiansaiFPGA2026\.venv-pdnet\Scripts\python.exe" tools\stage_hd_transfer.py --mode stage

# 查看/校验清单
& "G:\qiansaiFPGA2026\.venv-pdnet\Scripts\python.exe" tools\stage_hd_transfer.py --mode list
& "G:\qiansaiFPGA2026\.venv-pdnet\Scripts\python.exe" tools\stage_hd_transfer.py --mode verify

# 提交代码
git status --short          # 确认没有大文件
git add -A
git commit -m "..."
git push
```

### 机器 B（训练机）

```bash
git clone <repo> && cd demoir-fpga

# 环境
python -m venv .venv-pdnet && source .venv-pdnet/bin/activate
pip install torch==2.7.0 torchvision==0.22.0 --index-url https://download.pytorch.org/whl/cu118

python tools/stage_hd_transfer.py --mode verify
python tools/stage_hd_transfer.py --mode restore

# 冒烟验证
python src/train.py --config smoke --epochs 1

# 正式训练
nohup python src/train.py --config uhdm_4k_s > train.log 2>&1 &
```

> 全部命令**不需要 `cd` 到子目录**。
