# V2 行带流式融合（Row-Band Streaming Fusion）设计

> 状态：**设计稿**（2026-10-31）。本篇**不写 RTL、不起构建**，只给模块地图/数据流/预算/落地路径。
> 口径：所有数字标注来源——
> `[实测]` = 本机/板上直接量出来的；`[推算]` = 由实测数据按明确公式算的；`[估]` = 工程估计（有区间）。
>
> 基线 = v39（`design_1_150v39.bit`，md5 `602725b8…`）：整网 256² **8.096 s @150 MHz**（热态），
> PL 3.061 s，PS ≈ 5.03 s。PL 分解：**C(150 MHz) = 1.024 s（算力）+ M = 2.037 s（访存）**；
> 换算到 100 MHz 即 **C = 1.536 s + M = 2.037 s = 3.573 s**（PLAN §55.3，[实测]）。

## 0. 一页结论

| 项 | 现状 [实测] | V2 目标 [推算] | 判据/余量 |
|---|---:|---:|---|
| PL 访存时间 | **2.037 s（57% of PL）** | **0.7~1.1 s** | 中间 1-bit 激活不落 DDR |
| PL 总时间 | 3.061 s | 1.8~2.1 s | 算力 1.024(@150) + 访存 |
| 整网 | 8.096 s | 6.8~7.2 s（只做本篇）；再叠 PS 侧 V2 才可能到 2~3 s | 1 s 还需 PS 侧与更多并行度 |
| BRAM 峰值 | 35 / 95（37%） | **50 / 95（53%）**（B=8 + floatconv W5） | 余量 45 |
| LUT 峰值 | 20552 / 46200（44%） | **≈ 38.0k（82%）**（含 floatconv 16.2k） | 余量 ≈ 8k |
| DSP | 101 / 160（63%） | 117 / 160（73%） | 余量 43 |

**三条硬结论（先说，后面给推导）**
1. **BRAM 不是第一堵墙**——前提是"去掉 512 条线缓存（14.2 个 BRAM36）再放行带缓冲"：
   B=8 时行带最坏 15.1 个，净增 ≈ +0.9；加 floatconv（W5 后 14）仍只有 50/95。
   **若不做 floatconv W5（24 个）**，峰值 60/95（63%），也能活。
2. **LUT 才是墙**：20552 + V2 增量（估 0.8~2.5k）+ floatconv 16.2k ≈ **38k（82%）**，余量 ~8k；
   再上 16 lane（+13.4k）必爆 ⇒ 与 PLAN §54.6 结论一致：**16 lane 不可立项**。
3. **本篇单独到不了 1 s**：最乐观 PL = 0.83~0.91 s（算力理论地板）+ 0.3 s（访存）≈ 1.1~1.2 s；
   端到端 1 s 还要求 PS 侧 5.03 s 基本消失（prologue 1.6 + 非卷积 3.6）。
   V2 行带融合解决的是"**2.04 s 访存**"这一块，**它是必要条件，不是充分条件**。

## 2. 融合后的目标数据流

### 2.1 原则

1. **中间 1-bit 激活不落 DDR**：layer n 的输出直接写进 layer n+1 的"行带缓冲"（BRAM）。
2. **只有不可片上化的边界过 DDR**：输入/输出、**分辨率切换**、以及**跨段的 skip 叶子**（§2.6）。
3. **权重量级可忽略**（1.83 MB/帧）⇒ 按层从 DDR 流入 BRAM，不做全常驻。
4. 计算单元（8 lane XNOR+popcount）与写口**不改**；改的是"数据从哪里来、到哪里去"。

### 2.2 行带行数 B 怎么选

行带缓冲 bit 数（k=3 含上下各 1 行、d=2 含各 2 行；W 为全宽 + 左右 halo）：

```
band_bits(B) = cin × (B + halo) × (W + halo)      halo = k-1（d=2 时 2(k-1))，宽度 halo = k-1
```

| 最坏层型 | B=4 | B=8 | B=16 |
|---|---:|---:|---:|
| cin=544, W=128, k=1 | 7.6 | **15.1** | 30.2 |
| cin=448, W=128, k=1 | 6.2 | 12.4 | 24.9 |
| cin=256, W=128, k=3 | 5.4 | 9.0 | 16.3 |

（单位 = BRAM36，36864 bit/tile；`[推算]`，公式 + frame 的 cin/W）

选择依据：
- **B=4**：BRAM 最省（7.6），但每带只有 4 行 ⇒ 跨层握手/调度开销占比高；k=3 的上下 halo 占带宽 50%。
- **B=8（推荐）**：15.1 个 BRAM36；一条 128² 的带 = 8×128×8 lane 字 = 8192 个读字，
  按 E1E2 实测 ~9 拍/像素 ⇒ 单带 ~9.2k 拍 ≈ 61 µs @150 MHz —— 与"填一笔 burst ≈ 65 拍"相比足够长，
  握手可忽略。
- **B=16**：30.2 个 ⇒ 只剩 95−35−(V2 增量) 的余量；且每条带 1.1 Mbit，单带延迟 ~122 µs，
  调度粒度变粗，不利于和 interp/sam 的细粒度交错。

**结论：B = 8；B 作为参数，M1 阶段用 B∈{4,8} 做 A/B。**

### 2.3 相邻层如何跨层握手

融合段（fused segment）= 一串**同分辨率**的 op（conv/cat/interp/sam/add），由 PS 一次性下发
"段程序"（每层一条描述符，含 cin/cout/k/stride/dilation/thr 指针/段内源）。

- **行计数信用（row credit）**：生产者在行带缓冲里"写完一行"就 +1 信用；消费者"算完一行"就 −1。
  消费者只能推进到 `write_row − halo ≥ read_row`（halo = k−1 或 2(k−1)）。
- **带推进**：消费者算完第 y 行后，环缓冲的 y 行可被生产者覆盖（写指针回卷）。**不整体清缓冲**。
- **段结束**：消费者到达段末（输出整张 H×W）后，置 `seg_done`；生产者（下一段）在 `rd_quiet`
  （读通道静默）后启动 —— 沿用现有 `start_pend / rd_quiet / flush` 的语义，不新增"猜"。
- **背压**：与现在同一条 `u_ce`（读 miss / 写 FIFO 压力冻结），不新增握手 stall；区别只是
  "读 miss"从 DDR 填充变成"等上一层的行信用"。

### 2.4 k=3 / d=2 的边界重叠（最容易错的地方）

- k=3,d=1：输出行 y 需要输入行 y−1,y,y+1 ⇒ 环缓冲至少 **B+2** 行。
- k=3,d=2（`bin_3x32_48_d2` 等）：需要 y−2,y,y+2 ⇒ 环缓冲 **B+4** 行（不是 2B）。
- **交界处不重算**：第 n 带的最后 2（或 4）行输入行被第 n+1 带继续使用（环缓冲指针保留），
  所以"上下 halo"**只在段首付一次**，不是每带重读。
- **图像边界**：PAD=1 的层，y<0 / y≥H 的行读 0（不读 DDR）；带宽边界不需要特殊处理（宽度 halo 固定 2 列，
  在 BRAM 里置 0）。k=1 层不需要行 halo，但**仍用同一个环缓冲结构**（halo=0），避免两套数据通路。
- **数值等价**：每个输出像素的 term 序列与现在逐位相同（只是顺序由"逐带"变成"逐行"）；
  `sat8(rint(y·2^d))+t_q>0` 的定点路径一个字不改 ⇒ 见 §6-R1 的判据。

### 2.5 interp / cat 在融合下怎么"边算边拼"

| 算子 | 现状（PS，DDR 全张量） | 融合后（行带流式） | 行缓冲需求 |
|---|---|---|---|
| **cat**（116 op，688 叶） | 读所有叶子 → 写拼接张量（468.77 MB） | 变成**通道地址映射**：各生产者把结果写进消费者行带的对应通道区间；同段叶子片上直写，段外叶子按带从 DDR 读 | 0（就是消费方的行带） |
| **interp**（26 op，1.907 s） | 读整张 → 双线性 → 写整张 | 消费方行带按行流式：2× 上采样时 1 输入行产 2 输出行；1/2 下采样时 2 输入行产 1 输出行；比例只有 2/1、1/2、4/1、1/4 ⇒ 输入行数 ≤ 4 | 2~4 行 + 列系数 |
| **sam / add / eca** | PS 逐元素 | 同分辨率的逐元素加权：在行带上做（eca 需要列归约，用列累加器） | 1~2 行 + 列累加器 |

- interp 的**整数路径**必须原样搬：现有 `ops_numpy.interp` 的权重只落 1/8 网格、两段 ×8、最后 ÷64
  （见 `设计_v2_层间算子加速器.md` §1 的 Q16 契约），融合后按同一公式逐像素算，才可能 sha1 不变。
- cat 的 **6 个 needs_f32 回落 op** 保留在 PS（它们要 f32 语义），不强行融合。

### 2.6 分辨率切换与 skip：**不能全片上，必须如实承认**

- 网络在 5 个分辨率之间来回（128↔64↔32↔16↔8），**18 次切换**；每次切换必须把整张张量过一遍 DDR
  （或做一次片上重排，但需要整张驻留，放不下）。切换张量本身很小（最大 544×128²/8 ≈ 1.1 MB），
  18 次 ≈ 10~20 MB/帧，可接受。
- **DenseNet 的 skip（cat 的 688 个叶子）**：峰值活跃张量 33 MB @512²（= 8.2 MB @256²），
  远超片上 95×4.5 KB = 427 KB。⇒ **skip 叶子只能按带从 DDR 读**，这部分 cat 流量消不掉。
  能消掉的是"主链中间激活"（写 + 读），以及 cat 的**输出写**（写进行带）。
- 因此 §1.2 的 468.77 MB cat 里，保守估计 **40~50% 是跳连叶子读（保留）**，50~60% 可消。

### 2.7 目标字节账 `[推算]`

| 项 | 现状 | V2 | 说明 |
|---|---:|---:|---|
| 主链激活（C8 读 + packed 写） | 114 MB | **0** | 片上直传 |
| cat 输出写 / 主链叶读 | ~250 MB | **0** | 写成行带 |
| cat 跳连叶读 | ~220 MB | ~220 MB | 保留（放不下） |
| prologue f32 | 123 MB | 123 MB（M3 可降到 ~40） | 生产者侧量化 |
| f32 mixed / convfp / 非卷积 | ~120 MB | ~100 MB | 保留 |
| 权重 | 1.83 MB | 1.83 MB | |
| 分辨率切换 | 0 | ~15 MB | 新增 |
| **合计** | **≈ 841 MB** | **≈ 460 MB**（乐观 300） | |
| PL 访存时间 @413 MB/s | 2.037 s | **1.1 s**（乐观 0.73） | |

$$\Rightarrow\ \text{V2 把 PL 从 } 3.061 \to \mathbf{1.75\sim2.12\ s}\ \text{（省 }0.94\sim1.31\ \text{s）}$$
$$\Rightarrow\ \text{端到端 }8.096 \to \mathbf{6.8\sim7.2\ s}\ \text{——这是本篇的上限，1 s 还需要 PS 侧与更多并行度}$$

## 3. ★ BRAM 预算

### 3.1 现状（v39 post-route）[实测: `/tmp/v39_hier.rpt`]

| 归属 | LUT | FF | RAMB36 | RAMB18 | DSP |
|---|---:|---:|---:|---:|---:|
| `bin_unit_0` | 13425 | 10898 | 25 | 8 | 48 |
| `conv_uni_0` | 6210 | 6841 | 6 | 0 | 53 |
| 其它 | 917 | 750 | 0 | 0 | 0 |
| **合计** | **20552** | **18963** | **31** | **8** | **101** |

等价 tile 数：31 + 8/2 = **35 / 95（36.8%）**。
`bin_unit` 内部：直接映射线缓存 512×128 B = 64 KB ≈ **14.2 个 RAMB36**；转置缓冲 8×RAMB18 = 4；
其余是权重/FIFO/叶缓存。

### 3.2 行带缓冲公式与最坏层型

见 §2.2。**关键净账**：融合后线缓存不再需要（输入来自上一层行带）⇒

```
V2 峰值 = 35（现状）
        − 14.2（去掉 512 条线缓存）
        + band(B)（最坏层型）
        + floatconv（24 或 W5 后 14）
```

| 方案 | band | floatconv | 合计 tile | /95 |
|---|---:|---:|---:|---:|
| B=4 + W5 | 7.6 | 14 | 35−14.2+7.6+14 = **42.4** | 45% |
| **B=8 + W5（推荐）** | 15.1 | 14 | **49.9** | **53%** |
| B=8 + 不做 W5 | 15.1 | 24 | 59.9 | 63% |
| B=16 + W5 | 30.2 | 14 | 65.0 | 68% |
| B=16 + 不做 W5 | 30.2 | 24 | 75.0 | 79% |

### 3.3 权重：**不要常驻**

- 全网 1.83 MB；最大单层（cout=320, cin=320, k=3）**115 KB ≈ 25 个 BRAM36**。
- 但权重按层复用（同一层所有带用同一份），且每层只读一次 ⇒ **按层流式装入 4~8 个 BRAM36 的双缓冲**
  （与现在 `bin_conv_core8` 的 wmem 行为一致），不占 25 个常驻。
- 若哪天要把权重全常驻：最坏层 25 + band 15 + floatconv 14 + conv_uni 6 = 60/95（63%），仍可行，
  但会挤掉 band 的余量 ⇒ **不在 V2 首版做**。

### 3.4 floatconv 的 24 → 14（W5）

- floatconv 现状 24 个 BRAM36（tbuf ≈12 + wbank ≈8 + obuf ≈4，[实测: floatconv 报告]）。
- W5（tbuf 改 k 行环形缓冲）目标 24 → 14。**这是 V2 的前置条件之一**（不做也能活，见 §3.2 的 63%）。
- V2 的 band 与 floatconv 的 tbuf **在时间上不重叠**（不同层、串行执行）⇒ 可做成"物理复用同一块 BRAM"
  再省 ~10 个 tile；但需要 PS 调度保证不并发，**标注为 M3 的可选优化**，不计入首版预算。

### 3.5 余量与红线

$$\Rightarrow\ \text{推荐方案 } 50/95 = 53\% \Rightarrow \textbf{余量 } 45\ \text{个}$$
$$\Rightarrow\ \text{红线：任何单个层型的 band + floatconv + 权重双缓冲 不许超过 } 70/95（74\%）$$
$$\Rightarrow\ \text{触发重估的条件：出现 cin>544 或 W>128 的层 / B 被迫 >8 / floatconv 不做 W5}$$

## 6. 风险清单（触发条件 / 症状 / 判据）

| # | 风险 | 触发条件 | 症状 | 判据（怎么抓） |
|---|---|---|---|---|
| **R1** | **行带交界数值不等价** | k=3/d=2、H 不是 B 的整数倍、PAD=1 边界 | 整网 sha1 变，或只在带缝（每 B 行）出现 1~2 像素错 | ① `B=4/8/16` 三次跑同一网，输出**逐字节相同**；② 227 层 E1E2 直接 TB（H=128/64/32/16/8 全覆盖）；③ 板端 54/54 sha1 |
| **R2** | skip 叶子放不下 | 688 个 cat 叶子 / 峰值活跃 8.2 MB | 以为省了 469 MB，实际只省一半；或频繁重填 | 统计每个段的叶子里"同段产生"的比例；目标 ≥50% 流量消除；不达标就改"按 band 读 skip"的调度 |
| **R3** | 跨层握手死锁/饿死 | 生产者等消费者、消费者等行信用 | 整网挂住（watchdog 触发） | 形式不变式：`write_row − read_row ≥ halo`；TB 加行信用断言；板上先跑单段样板 |
| **R4** | interp/sam 定点路径变了 | 把 PS 的 float64/float32 直接搬进 PL | sha1 变，PSNR 略降 | interp 必须用现有整数公式（1/8 网格、×8、÷64）；先做离线 FakePL A/B，再上板 |
| **R5** | 面积超墙 | floatconv 集成后 >36k LUT 或 V2 增量 >3k | 布局失败 / WNS 崩 | 集成前先做 OOC 综合；红线 42k LUT（91%）；超了先砍 cat 片上 mux |
| **R6** | BRAM 超墙 | 不做 W5 且 B=16 | place 失败 | 用 §3.5 的红线 70/95；B=8 + W5 是默认 |
| **R7** | 时序回退 | 新状态机/地址生成进 10 ns 关键路径 | WNS < −2.0（现在是 −1.998） | 综合后 WNS/TNS/端点集与 v39 对比；新逻辑必须在 `u_ce` 锥之外 |
| **R8** | PS 接口漂移 | 段程序格式与现有 `frame.json` 不兼容 | 老描述符不能跑 / 两套驱动 | 新字段只在 `0x2xx` 扩展页；旧 `cmds.bin` 仍可跑（向后兼容） |
