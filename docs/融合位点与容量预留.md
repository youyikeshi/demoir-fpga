## 0. 与《V2 行带流式融合》的合并关系

| | 本篇（PS 吞并） | V2 行带（PL 侧） |
|---|---|---|
| 目标 | 把 PS 的 8 类非卷积算子搬到数据流上，**同时消灭 DDR 往返** | 把二值 conv 的中间 1-bit 激活留在片上 |
| 手段 | 融合位点：生产者写口 / 消费者读口 / 行缓冲 / 地址映射 | B 行环缓冲 + 跨层行信用 |
| 共享资源 | 行带缓冲、BRAM、读带宽、AR 在飞 | 同左 |
| 关系 | **PS 吞并的输出缓冲 = 行带缓冲的"多源输入"** ⇒ 同一块 BRAM | 行带是 PS 吞并的物理载体 |

$$\Rightarrow\ \text{合并后的目标流水线：}\ \text{conv(PL)} \to [\text{cat / interp / sam / add / eca / quantize 在同一条行带上}] \to \text{conv(PL)}$$
$$\Rightarrow\ \textbf{冲突点只有一个：额度}。\text{§3 给出"先保 10\% 余量"的分配；若冲突，明确放弃哪个位点（§3.4）}$$

## 2. ★ 融合位点

### 2.1 判据与位点表

| 类型 | 类型学 | 搬去哪 | 接口 | 缓冲 | 延迟 | 可省流量 | 风险 |
|---|---|---|---|---|---|---|---|
| **quantize / pack**（prologue 123 MB + f32 段 33 MB） | 逐元素 | **生产者写口**（convfp/interp/sam 的输出直接量化为 C8/THR） | 写口 +32 bit THR 通道 | 0 | 0 拍 | **~150 MB** | 量化语义必须与原 q8 逐位（已有 THR 等价证明） |
| **cat**（116，468.8 MB） | 重排 | **通道地址映射**：生产者把各自通道写进消费者的行带区间；段外叶子按带读 | 多源写口（3~11 源） | 0（就是行带） | 0 | **~250 MB**（主链部分） | 6 个 needs_f32 回落保留 PS |
| **interp**（26，14.4 MB int8） | 邻域（2~4 行） | **行带流式**：消费行带 → 双线性 → 写下一层行带 | 行缓冲 2~4 行 + 列系数 | 2~4 行 × C | 2~3 拍/像素 | **14.4 MB + 1.907 s PS** | 整数路径必须原样（1/8 网格 ×8 ÷64） |
| **sam**（6，13.8 MB） | 逐元素 5 源 | **消费者读口**（conv 读带时做 5 源加权） | 5 源读 + attn 系数 | 0 | 1~2 拍 | **13.8 MB + 0.247 s** | 5 源地址表；系数 Q16 |
| **eca**（6，8.3 MB） | 归约（列均值） | **生产者写口旁路**：PL 做列累加，PS 只做 sigmoid/conv1d（576 值） | 列累加器 + 576 值回传 | 1 行/列 | 0 | **8.3 MB + 0.081 s** | 归约顺序影响舍入？用 int64 累加 |
| **add**（6，8.3 MB） | 逐元素 2 源 | **消费者读口**或生产者写口 | 2 源 | 0 | 1 拍 | **8.3 MB + 0.068 s** | 无 |
| **shuffle / unshuffle**（4，0.9 MB） | 纯重排 | **地址映射**（改读写地址，不搬数据） | 地址发生器 | 0 | 0 | **0.9 MB + 0.019 s** | 分辨率变化点必须与 cat 的通道序对齐 |
| **convfp**（4，10.5 MB f32） | f32 卷积 | **留在 PS**（或未来 PL floatconv） | — | — | — | 0 | 与 1-bit 行带精度不同，不能直接融合 |
| **epilogue**（0.265 s） | 输出 | 必须落 DDR | — | — | — | 0 | 最终输出 |

### 2.2 ★ 输出根本不需要落 DDR 的算子（字节直接归零）
| 算子 | 现在 | 融合后 | 省 |
|---|---|---|---:|
| shuffle ×3 + unshuffle ×1 | 读写 0.9 MB + 0.019 s | 地址映射，0 字节 | 0.9 MB |

| **合计** | | | **≈ 380 MB + ~2.2 s PS 时间** |

### 2.3 每个位点的"数据从谁到谁 / 缓冲 / 延迟"
```
conv_n (PL) ──写口──> 行带 B 行（cin 通道，1-bit 或 int8）
   ├─ cat：多个生产者的通道区间直接写进同一行带（地址偏移 = 通道号）
   ├─ interp：读行带 2~4 行 → 双线性 → 写下一层行带（行缓冲 2~4 行 × C）
   ├─ sam/add/eca：读行带（多源）→ 加权/归约 → 写行带或 576 值寄存器
   └─ quantize：在写口把 f32/int8 换成 C8+THR（E1E2 已支持 THR 直读）
conv_n+1 (PL) ──读口──> 同一条行带（零 DDR 往返）
```
- 缓冲 = 行带（V2 的 B 行环缓冲）+ interp 的 2~4 行 + eca 的列累加器（C 个 int32）
- 延迟 = 逐元素 1 拍；interp 2~3 拍/像素；cat 0 拍；无 DDR 往返

### 3.2 LUT 是唯一"贴线"的资源
$$\Rightarrow\ \text{base } 36725 + 3500..5000 = 40225..41725 \Rightarrow \text{余量 } 4475..5975 = 9.7\%..12.9\%$$
$$\Rightarrow\ \textbf{如果 floatconv 集成本身再涨 10\%（+1617）} \Rightarrow 41842..43342 \Rightarrow \text{余量降到 } 6.2\%..9.4\%$$
$$\Rightarrow\ \textbf{结论：10\% 余量不能"默认"成立} \Rightarrow \text{必须二选一：}$$
$$\Rightarrow\ \text{(a) floatconv 的 W5/面积优化先落定（省 1~2k LUT）} \Rightarrow \text{余量回 10\%+}$$
$$\Rightarrow\ \text{(b) PS 吞并只做"地址映射类"（cat/shuffle/quantize）+ interp，放弃 eca/sam 的独立硬件}$$

### 3.3 BRAM 余量成立的前提（与 V2 一致）
- 去掉 512 条线缓存（−14.2）后，V2 行带 +15.1（B=8）→ 净 +0.9
- PS 吞并的行缓冲（interp 2~4 行 × C=544 × 128 px ≈ 2~4 个 BRAM36）可**复用行带的同一块**（不同时）⇒ 实际净增 0~2
- 所以 BRAM 峰值 ≈ 49.9 + 2 + 14(floatconv 已在上面) ≈ 52~57 / 95（55~60%）✓

### 3.4 若额度不够，必须放弃哪个（不假装都装得下）
| 放弃项 | 省 LUT | 代价 | 建议 |
|---|---:|---|---|
| eca 的 PL 列累加 | ~300~600 | eca 仍 PS（0.081 s，8.3 MB） | 可放弃 |
| sam 的 5 源硬件 | ~800~1200 | sam 仍 PS（0.247 s，13.8 MB） | 可放弃（优先级最低） |
| interp 的 PL 引擎 | ~2000~3000 | interp 仍 PS（1.907 s，14.4 MB）——**但这是最大的 PS 桶** | **不建议放弃** |
| cat 的片上通道映射 | ~300~500 | cat 回落 PS（468.8 MB） | 不建议放弃 |

## 4. ★ 访存不卡的自证（每级带宽/延迟预算）

> **⚠ 2026-10-31 19:40 前提已变**：旧前提"PL 访存 2.037 s"作废 —— TPOLL 实测 **PL 总忙时只有 1.707 s**（pack 0.965 + conv 0.742）。
> 因此下面"峰值 ≤700 MB/s"的判据不再用于"PL 带宽"，只剩一条硬约束：
> **pack 的读 miss 冻结 48.4% × 0.965 = 0.47 s 是 PL 侧唯一可回收的访存时间**；
> PF_AHEAD 只需把在飞从 1.2 提到 ≥2.0（Little's law：`N = BW/347.8`，700 MB/s ⇒ N=2.0），
> 就能把这 0.47 s 拿回，不需要 800 MB/s 的满带宽。以下各级预算的"字节"部分仍有效（流量口径），
> "时间"部分按 1.707 s 的新分母理解。


### 4.1 融合后每级 DDR 需求（只列"还会碰 DDR"的）

| 级 | 数据 | 字节/帧 | 时机 | 峰值需求 |
|---|---|---:|---|---:|
| 输入 | 3×256² f32 → 量化 | 0.8 MB | 帧首 | 可忽略 |
| 分辨率切换 ×18 | 整张张量 | 10~20 MB | 段边界 | 544×128²/8=8.9 MB/次，按 0.5 ms 摊 ≈ **17 GB/s 瞬时？** |
| skip 叶子读（cat 段外） | 468.8 MB 的 40~50% | 190~235 MB | 每个带 | 与主链交错，≤ **400 MB/s** |
| prologue f32（M3 前） | f32 段 | 33.3 MB | 段首 | ≤100 MB/s |
| convfp | f32 in/out | 10.5 MB | 4 次 | ≤50 MB/s |
| 输出 | 最终张量 | 0.2 MB | 帧尾 | 可忽略 |
| **合计** | | **≈ 250~300 MB** | | **峰值 ≈ 500~600 MB/s** ✓ ≤700 |

$$\Rightarrow\ \text{唯一需要小心的是"分辨率切换那一次"：}8.9\ \text{MB 集中读} \Rightarrow \text{按 }55.2\ \text{拍/线、在飞 }2.3 \Rightarrow 800\ \text{MB/s} \Rightarrow 11\ \text{ms/次}，18\ \text{次} = 0.2\ \text{s}$$
$$\Rightarrow\ \text{可接受，但要把它排进"不与非卷积抢带宽"的调度窗口}$$

### 4.2 在飞需求（判据：≤ AR_SLOTS / NSLOT）
```
要 700 MB/s：N = 700 / 347.8 = 2.01 条线在飞
AR_SLOTS = 4（≥2.01 ✓）；NSLOT = 16（✓）；PF_MAX = 4（≥2 ✓）
⇒ PF_AHEAD = 2 是"够用且不过冲"的最小值
```

### 4.3 自证结论
$$\Rightarrow\ \text{融合后 DDR 峰值 } 500\sim600\ \text{MB/s} \le 700（12\%\ \text{余量}）✓$$
$$\Rightarrow\ \text{在飞 } 2.0 \le AR\_SLOTS=4 ✓；\text{不需要加宽 AXI ID/端口}$$
$$\Rightarrow\ \textbf{不卡访存的前提是 PF\_AHEAD ≥ 2（当前 1）} \Rightarrow \text{这就是 §5 的第 1 项}$$
