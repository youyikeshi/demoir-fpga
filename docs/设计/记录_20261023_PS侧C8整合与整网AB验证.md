## 1. 开关（默认关，可一键回退）

| 方式 | 说明 |
|---|---|
| 环境变量 `C8_LAYOUT=1` | 板端/本机通用。**默认 0**（未设置 / 空 / `0` / `false` / `off` / `no` 都算关） |
| `run_network_on_board.py --c8` | 等价于 `C8_LAYOUT=1`；必须在构造 arena **之前**生效（脚本已在 `parse_args` 后立刻设置） |
| 一键回退 | 不设环境变量/不加 `--c8` ⇒ 全 CHW：`c8_in=c8_out=0`、层间算子走 `ops_numpy` |

关（默认）时的三条保证：

1. 所有张量按 CHW 分配、视图 `(C,H,W)`；
2. 引擎 `relu_en` 只写 bit0（值仍是 0/1，与整合前**逐位一致**）；
3. 层间算子全走 `ops_numpy`，`c8lib` / `ops_c8` **根本不会被 import**（惰性导入）。

> 引擎侧还有编译期开关 `C8_LAYOUT`（`pl/src/conv2d_engine.h`，0/1）。PS 的
> `C8_LAYOUT=0` 可以在 `C8_LAYOUT=1` 的 bit 上跑（bit2/bit3 全 0 = 走 CHW 通路），
> 所以"同一 bit、两个 PS 开关"就能做板端 A/B。

## 3. 布局判定与分配（规范 §1/§3）

唯一规则：`int8 且 C % 8 == 0 ⇒ C8`，否则 CHW。

```python
buf_bytes(c,h,w,is_c8) = ceil(c/8)*8*h*w  if is_c8 else c*h*w
视图  C8: (c/8, h, w, 8)    CHW: (c, h, w)
addr(c,y,x) = (c//8)*H*W*8 + y*W*8 + x*8 + (c%8)
```

- **本网络 C8 张量的 C 都是 8 的倍数 ⇒ `ceil(C/8)*8 == C`，字节数与 CHW 完全相等**：
  实测池 66,764,800 B 两种模式一致、522 个张量的池偏移逐一相同（"零额外内存"）。
  `nbytes()` 仍按通用式写，只是为"万一被强行置成 C8 的非对齐张量"留出补零区。
- 补零区必须为 0：`NumpyArena` 用 `np.zeros`；`PYNQArena` 在 C8 模式**整池清零一次**
  （`~50 MB`，板端可忽略）。本网络没有补零通道（C 都是 8 的倍数），但引擎的
  `ceil(cin/8)*8` 读法一旦遇到非对齐张量就会读补零区，所以这条防线必须留着。
- **cat 零拷贝不受影响**：`off_c*H*W == (off_c/8)*H*W*8`，字节偏移公式一行没改；
  只把组的 numpy 视图换成 `(total/8,H,W,8)`、成员换成
  `buf[off_c/8 : (off_c+c)/8]`（要求 off_c、c 都对齐 8 —— 实测 454/454 段满足）。

## 4. 引擎参数（规范 §2）

驱动唯一公式（`conv_engine.relu_flags`）：

```python
flags = (1 if op['relu'] else 0) | (4 if in_is_c8 else 0) | (8 if out_is_c8 else 0)
```

- 布局由 **arena 的布局表逐张量查**（`PYNQEngine.conv` → `arena.is_c8(张量名)`），
  不按层硬编码；
- 三个位**互相独立**，两个典型不匹配层已核对：
  `encoder.conv_first` = **cin=12(CHW) → cout=48(C8)**，`decoder.decoder_1.out_conv`
  = **C8 → cout=12(CHW)**；
- C8 关时 `flags ∈ {0,1}`，与旧驱动写的值完全相同（旧 bit 也会忽略 bit2/bit3）。

## 5. 层间算子分工（复用 `ps/c8/ops_c8.py`）

| 算子 | 个数 | C8 下的做法 | 是否转换 |
|---|---:|---|---|
| `cat` | 224 | **块级拼接**（段通道数全对齐 8）；别名组仍是零拷贝 + 256 项 LUT 重定标 | 否 |
| `add` | 6 | 逐元素 `sat16(a+b)`，直接 C8 | 否 |
| `sam_sum` | 6 | 逐元素（无归约），直接 C8；`Runner._sam_sum_c8` 按 2 个通道块（16ch）分块 | 否 |
| `rescale`（标度重定标） | 每段 cat | `bytes.translate` 逐字节映射 ⇒ 布局无关 | 否 |
| `interp` | 26 | 转 CHW 调用 `ops.interp`（按 3-D 写死），再转回 | **是**（89.8 MB） |
| `eca` | 6 | **必须转 CHW**：按 32 通道分块 `from_c8` 后照搬旧的分块均值公式 | **是**（51.6 MB） |
| `pixel_shuffle/unshuffle` | 1+1 | 例外张量（3ch/12ch）本来就是 CHW，路径不变 | 否（0 MB） |
| `slice` | 0 | 起止对齐 8 → 块级切片，否则回退（适配器已实现并自测） | — |

**v2 层间算子加速器（`--pp-ops`）在 C8 模式自动旁路**：`pp_ops` 按 `(C,H,W)` 拆形状、
按 `c*H*W` 步长做 DMA，是纯 CHW 地址语义。C8 下打印一行 INFO 后全走 `ops_c8`
（正确性优先；要恢复 pp 得先把它的 DMA 改成 C8 语义）。

## 8. 板端预期收益（事务数模型，`ps/c8/txn_model.py`）

```
标定口径（wide1=0 + 行复用，与板端实测 8.76 M 笔 / 90 s 吻合到 0.5%）：
  读（填充）: CHW 8.807 M (57.1 B/笔) → C8 1.118 M (450.2 B/笔)   ÷7.88
  写        : CHW 2.510 M            → C8 0.331 M                 ÷7.59
  读写合计  : CHW 11.317 M           → C8 1.448 M                 ÷7.81
  填充耗时  : 90.7 s → 11.5 s；读写都算 116.6 s → 14.9 s
当前 bit（K1_WIDE_COLS=1 + 行复用）：
  读 3.592 M → 0.466 M；写 2.510 M → 0.331 M；合计 6.102 M → 0.796 M（÷7.66）
  填充 37.0 s → 4.8 s
```

对上板基线 **187.41 s** 的推算（只算 DDR 事务，10.3 µs/笔）：

| 口径 | 省下的事务时间 | 整网预估 |
|---|---|---|
| 标定口径 | 读 −79 s、写 −22 s | **≈ 86 s**（−54%） |
| 当前 bit | 读 −32 s、写 −22 s | **≈ 133 s**（−29%） |

再叠加 PS 侧的代价：真机 PS 只需转换 141.4 MB/张（A9 上按 x86 的 1/5~1/10 估 ⇒ 0.3~0.6 s），
相对收益可忽略。另外 AXI 4 KB 边界会把 544 B 的逻辑 burst 拆成 2 笔（概率约 13%），
实际会再打 ~7% 折扣（÷7.4 左右），结论不变。

> **⚠️ 与 RTL 侧文档交叉核对后必须加的一条风险**：`记录_20261023_运行期layout位与上板回归.md`
> §4.4 的 cosim 证据显示，**运行期版 bit 的 C8 填充可能被 HLS 拆成 3 笔**（64+64+24）而不是
> 1 笔 608 B（该层 C8 路径比"编译期 C8"多 16,720 拍）。若上板后确实如此，读侧事务只降到
> `1.118 M × 3 ≈ 3.35 M`（**÷2.6**，不是 ÷7.9），填充 90.7 s → ~34 s，整网 ≈ **109 s**
> 而不是 86 s。所以：
> **本表的 ÷7.88 是"burst 合成成功"时的上限**，实际介于 86~133 s 之间；
> 上板第一件事就是量 `conv` 的填充时间（`--profile`），若明显没到 11 s 档，
> 先让 RTL 侧把 C8 填充抽成独立函数 / 把 `if (c8_in)` 提到列块循环外（他们文档 §4.4 已给思路）。

> 设计文档里"conv 130 s → ≤60 s"的量级与上表一致；**具体数字必须上板实测**
> （尤其 K1_WIDE_COLS 那一档的填充基线到底是多少）。

## 9. 坑

1. **`fp32` 张量的字节数要乘 itemsize。** `nbytes()` 返回的是**元素个数**（对 int8 恰好等于字节数），
   把 `plan_pool` 里的 `meta["bytes"]` 换成 `nbytes()` 后，6 个 `attn`（fp32）只分到 1/4 空间，
   `PYNQArena` 直接报 `cannot reshape array of size 48 into shape (144,1,1)`。
   现在统一走 `c8_layout.bytes_of(meta, is_c8)`。
2. **C8 视图的 `shape[0]` 是通道块数，不是通道数。** `Runner` 里所有 `v.shape[0]`、
   `nc, hh, ww = v.shape`、`attn.reshape(3, C)` 都必须显式换算（`_logical_c()`/`c8_layout.channels()`）。
3. **sam_sum 的权重广播**：C8 视图是 `(Cb,H,W,8)`，权重必须按 `(块,1,1,8)` 广播
   （`w[0][bs][:, None, None, :]`）。写成 `[:, None, None, None]` 会把 8 顶到新轴上，
   得到 `(块,块,H,W,8)` → broadcast 报错。
4. **ECA 必须转 CHW**，且要**按 32 通道分块转**（与旧代码的分块一致）：
   整块转会把 14.7 MB 的临时数组放大，分块转的均值公式与旧代码逐字相同 ⇒ 逐位不变。
5. **`hashlog` 会污染 PS 开销**：逐算子 sha1 要把每个输出都从 C8 转回 CHW（单张多搬 ~756 MB），
   实测把"纯转换"从 0.32 s 抬到 0.52 s。测 PS 开销一律用 `--timing`（关 hashlog 的那一轮）。
6. **别拿本机墙钟当性能结论**：CHW/C8 两路的差在 −3.6 s…+0.1 s 之间跳、符号会翻转
   （机器上有并行的 Vivado/回归在跑）。唯一稳的是每秒转换字节数。
7. **v2 加速器（pp_ops）是 CHW 地址语义**，C8 下必须旁路，否则它会拿 `(Cb,H,W,8)` 去拆
   `(C,H,W)`（`ValueError`）或按 `c*H*W` 步长搬错数据。已在 `Runner.run` 里自动关掉并打印 INFO。
8. **`--c8` 必须在构造 arena 之前生效**：布局表是 arena 的一部分（分配/视图都由它决定），
   事后改环境变量只会造成 "runner 说 C8、arena 是 CHW" 的分裂——`Runner` 现在会检测
   arena 的布局表与环境变量不一致并**直接抛异常**（不静默跑错）。
9. **上板包别漏文件**：`runner.py` 在 import 期就依赖 `lut_util`/`pp_ops`/`c8_layout`，
   C8 还要 `c8lib`/`ops_c8`。`make_board_bundle.py` 原本漏了 `pp_ops`/`pp_engine`/`lut_util`
   （旧包能跑是因为它来自更早的快照），已一并补上。
10. **补零区清零**：C8 的 `ceil(cin/8)*8` 读法会读到最后一块的补零通道，必须为 0。
    本网络没有补零通道（C 都是 8 的倍数），但 `PYNQArena` 仍在 C8 模式整池清零一次，
    且 `NumpyArena` 用 `np.zeros` —— 这条是留给"将来出现非对齐张量"的防线。
11. **C8 的收益上限受 "HLS 是否把 8·lb 字节折成一笔 burst" 约束**：运行期版 cosim 显示
    C8 填充疑似被拆成 3 笔（见 §8 的 ⚠️）。PS 侧已按规范把 `c8_in=1` 传下去，但"传对了位"
    不等于"板上事务数就 ÷8"——这一条只能在板上量，PS 侧无法自证。
