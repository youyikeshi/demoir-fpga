## 1. 问题与账

`encoder.conv_first` 是整网唯一的 5×5 层（cin=12（C8 补齐后）、cout=48、320×320），
**5.40 s，占 conv 的 10%**。它的权重装载量按 manifest 精确统计是 **23.0 MB**
（列块 5 × hout 320 × cout 48 × cin 12 × 25 B），而每个 `(oc,ic)` 是 **25 字节**：

* 25 不是 4 的倍数 ⇒ `(oc·cin+ic)·25` 不保证 4 字节对齐；
* 于是 HLS 只能按 **1 字节/笔** 访问（`ARLEN=1`），板端 16.3 拍/字节 ⇒
  23.0 MB × 16.3 / 125 MHz ≈ **3.0 s**（另外约 2.4 s 是计算）。

k=3 那轮已经验证过解法：**只补容器、不动读侧 bank 划分**。k=5 照抄：

```
offset(oc, ic, ky, kx) = (oc*cin + ic)*28 + ky*5 + kx        # 25 个抽头紧排 + 3 个零
```

28 = 7 个 32-bit 字，起点恒 4 字节对齐 ⇒ 一笔读出 7 个字；写侧仍是 25 个
**编译期常量** bank（`wgt_buf` 的 dim3/dim4 完全拆分，与改造前逐字相同）。
代价只有体积 ×28/25（1.83 MB 量级）。

## 2. 改了什么

### 2.1 导出侧（`ps/pynq/ref_numpy.py`）

```python
W_LAYOUT_K5_PAD28 = "k5_pad28"     # 仅 k=5：[oc][ic][28]（25 个抽头 + 3 个零）
K5_PAD, K5_PAD_BYTES = 28, 25
def k5_to_pad28(w):   ...   # (cout,cin,5,5) -> (cout,cin,28)
def k5_from_pad28(w): ...   # 逆；顺带校验 3 个补零字节必须为 0
```

`wgt_as_ocic()` / `conv_ref_numpy(w_layout=…)` 增加 `k5_pad28` 分支，语义路径与
改造前逐字相同（只是容器补齐）。`index.json` 里该层变为
`w_shape=[48,12,28]`、`w_len=28·cout·cin`、`w_layout="k5_pad28"`。

### 2.2 PL 装载循环（`pl/src/conv2d_engine.cpp`，`src_cosim/` 同步）

```cpp
#if K5_PAD28
const int cin28 = cin * 28;
int off = off_ocb28;                        // = ocb*cin*28（逐块递推，不再乘 ocb）
for (int i = 0; i < ocbl; ++i, off += cin28) {
    const w32_t *pw = reinterpret_cast<const w32_t *>(wgt + off);
    HLS_PRAGMA(HLS PIPELINE II=1)
    for (int ic = 0; ic < cin; ++ic) {
        HLS_PRAGMA(HLS UNROLL)
        for (int ky = 0; ky < 5; ++ky) {
            HLS_PRAGMA(HLS UNROLL)
            for (int kx = 0; kx < 5; ++kx) {
                const int kk = ky * 5 + kx;                  // 编译期常量
                const w32_t wv = pw[7 * ic + (kk >> 2)];
                wgt_buf[i][ic][ky][kx] = (data_t)(wv >> (8 * (kk & 3)));
            }
        }
    }
}
#else
   … 原逐字节路径（K5_PAD28=0 的对照构建）…
#endif
```

* `K5_PAD28` 是**编译期**宏（默认 1），与 `K3_PAD12` 同一个风格：没有运行期 mux；
* `kk>>2` 与 `kk&3` 都是常量 ⇒ 字节抽取是静态移位，不是桶形移位器；
* 新增 `off_ocb28` 递推，避免每迭代做 `(ocb+i)*cin*28` 的乘法链（v3.1 时序教训）。

## 4. 资源：意外的大幅下降

同一套 tcl、同一份源码，只切 `K5_PAD28`：

| 资源 | 基线 `K5_PAD28=0` | 本轮 `K5_PAD28=1` | 说明 |
|---|---:|---:|---|
| LUT | 35,261 (76%) | **30,676 (66%)** | −4,585 |
| DSP | 104 (65%) | **100 (62%)** | −4 |
| FF | 23,046 (24%) | **21,177 (22%)** | −1,869 |
| BRAM18 | 172 (90%) | 172 (90%) | 不变 |
| Fmax | 172.97 MHz | 172.97 MHz | 不变 |

为什么反而更省：基线的 k=5 装载是 **25 个动态地址的 8 位读**（`wp[ky*5+kx]`，
每个都要一套地址算术 + 一个 AXI 读槽），RTL 里那一坨组合逻辑就是 4.6k LUT；
新写法只有 **7 个 32 位字地址** + 常量移位抽取。
⇒ 本轮不仅省时间，还给布线腾出 10% 的 LUT 余量（对后续 FUSE_OUT 之类很关键）。

## 6. 坑

1. **`src_cosim` 的 `depth=` 会被覆盖**：用 `cp` 复制 `src/` 到 `src_cosim/` 图省事，
   会把 cosim 专用的 `depth=` 注释掉（`check_src_sync.py` 只比较规范化后的逻辑，
   不查 `depth=` 是否存在）。改完源码后要么两边一起手改，要么复制后**立刻**
   把 `depth=` 那段补回来再跑 `check_src_sync.py`。
2. **cosim 的 `SRC_DIR` 必须绝对路径**：tcl 里先 `cd $here`，相对路径会被解析成
   `pl/scripts/<相对路径>`，报 `FileNotFoundError` 后又被 `catch` 包成
   "AXI depth= 与数据集不一致"（极具误导性）。
3. **HLS 工程不能放在源码树外**：`SRC_DIR=/data/work/...` 时 HLS 把文件记成
   `../cosim_k5_src/conv2d_engine.cpp`，csynth 阶段报 `Cannot find source file`
   并**静默跳过设计文件**（只剩 TB）。正解：副本放在 `pl/build/`（仓库内、
   已被 .gitignore 覆盖）。
4. **C8 测试台的 depth 要按补零后的通道数算**：见 §5.1。
5. **bit 与权重包必须成对**：`K5_PAD28=1` 的 bit 只能配 28 字节容器的包
   （`weights.bin` md5 见 §7）；混用不报错，只会算出"看起来正常"的错数据。
   `check_consistency.py` 上板前拦一道。
6. 本轮改动**只碰 k=5**：k=1、k=3 的容器与装载路径一个字节都没动（A/B 里
   k=3 的 12 字节容器层在 repack 时原样搬运），所以 k=3 那 16.15 s 不受影响。
