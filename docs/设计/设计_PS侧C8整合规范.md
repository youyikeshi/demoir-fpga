# PS 侧 C8 整合规范（runner / 驱动）

> 2026-10-23　|　前置：C8 RTL 已通过 23/23 形状验证（提交 `b9f976e`），运行期 `c8_in/c8_out` 位在实现中
> 目标：让整网在板上真正按 C8 布局跑，且与当前 CHW 路径**逐位一致**

---

## 1. 布局判定（唯一规则）

对每个 int8 张量 $T$（形状 `(C,H,W)`）：

$$T \text{ 用 C8} \iff C \bmod 8 = 0$$

据此实测分布（manifest_640，516 个 int8 buffer）：

| 类别 | 数量 | 处理 |
|---|---:|---|
| C8 对齐 | **508** | 按 `ceil(C/8)*H*W*8` 分配，按 C8 地址读写 |
| 例外（3ch / 12ch） | **8** | 保持 CHW |

8 个例外的名字（来自 C8 软件侧报告）：
`t0`(3)、`t1`(12)、`t520`(12)、`t521`(3)、`t342`(12)、`t343`(3)、`t431`(12)、`t432`(3)。

> 注意：后 4 个属于 `decoder_2/3` 的尾巴，不在 needed 子图内；
> 实际执行面上只有 4 个例外会被碰到。

## 2. conv 的调用参数

引擎的 `relu_en` 字段现在承载三位：

| 位 | 含义 |
|---|---|
| bit0 | ReLU 使能（原有） |
| bit2 | **输入缓冲区是 C8** |
| bit3 | **输出缓冲区是 C8** |

驱动侧：

```python
flags = (1 if op['relu'] else 0) | (4 if in_is_c8 else 0) | (8 if out_is_c8 else 0)
```

必须**逐张量**判定，不能按层硬编码——典型不匹配：

| 层 | cin | cout | c8_in | c8_out |
|---|---:|---:|---|---|
| `encoder.conv_first.0` | 12 | 48 | **0** | **1** |
| `decoder.decoder_1.out_conv` | 对齐 | 12 | 1 | **0** |
| 其余 246 个 conv | 对齐 | 对齐 | 1 | 1 |

## 3. 缓冲区分配

```python
def buf_bytes(c, h, w, is_c8):
    if is_c8:
        return ((c + 7)//8) * 8 * h * w        # 通道补零到 8 的倍数
    return c * h * w
```

- 补零通道的**数据内容必须是 0**（引擎会读它们，写回时靠 `cout` 上界保护不写脏）；
- 现有 `plan_pool` 的**字节偏移公式在 C8 下不用改**：
  $\text{off}_c \cdot H W = (\text{off}_c/8)\cdot H W \cdot 8$（已在 20 个真实 cat 组验证），
  只需把 numpy 视图形状换成 `(total/8, H, W, 8)`。

## 4. 层间算子

复用已归档的 `pynq_specialized_code/ps/c8/ops_c8.py`（已证明 517/517 逐位无损）：

| 算子 | 做法 |
|---|---|
| `cat`（224 个） | **块级拼接，直接 C8**（454 个段全部 8 对齐） |
| `add`、`sam_sum` | 逐元素，可**直接 C8** |
| `rescale` | 256 项 `bytes.translate`，**逐字节映射 ⇒ 布局无关** |
| `interp`、`pixel_shuffle/unshuffle` | 转 CHW 处理 |
| `eca` | **必须转 CHW**（float32 空间均值对累加顺序敏感，是唯一"必须"的例外） |
| `slice` | 起止对齐 8 走块级，否则回退 |

**性能提醒**：真机上转换是有成本的。C8 软件侧实测 48×320×320 转换 3.81 ms / 1.52 ms（x86），
需转 CHW 的张量总量约 165 MB/张 ⇒ **ARM 上必须实测**，若转换开销超过收益，
就把 `interp`/`sam_sum` 也改成原生 C8 实现（`C8_SAMSUM_DIRECT=1` 已验证可直算）。

## 5. 验收阶梯

| 阶段 | 判据 |
|---|---|
| 1. 主机侧 | 用 `RefEngine` 跑整网，CHW vs C8 **0 / 1,228,800**（软件侧已完成 ✓） |
| 2. 板端单测 | `test_on_board.py` 5/5，且 `layout=0` 时耗时与旧版一致（152.6 / 40.2 / 7.9 / 152.6 / 119.5 ms） |
| 3. 板端整网 | `run_network_on_board.py`，**0 / 1,228,800 不一致**，整网耗时对比 187.41 s |
| 4. 回归 | 若 C8 无收益或更慢，能一键切回全 CHW（`c8_in=c8_out=0`） |

---

## 6. 风险

| 风险 | 对策 |
|---|---|
| 补零通道未清零 → 引擎读到脏数据 | 分配时 `memset` 0；且权重对补零通道无对应项，乘加不参与 |
| `cat` 的段缓冲视图形状写错 | 用 `(total/8,H,W,8)`；字节偏移不变，只改视图 |
| 转换开销吃掉收益 | 先量 ARM 上的转换耗时；必要时把 interp/sam_sum 改原生 C8 |
| `layout` 位与 relu 位冲突 | 引擎内必须用 `(relu_en & 1)` 判 relu（已要求） |
| 与 FUSE_OUT 宏交互 | 两者独立；`FUSE_OUT=1` 时写回路径也要走 `c8_out` 分支（实现时注意三处写回都要覆盖） |
