## 0. 结论速览

| 问题 | 答案 |
|---|---|
| 填充/权重/计算/写回各占多少 | **权重 57.4 s(45%) / 填充 35.3 s(27%) / 计算 22.7 s(18%) / 写回 13.1 s(10%)**，合计 128.5 s（实测 128.44 s） |
| 一句话根因 | HLS 生成的 RTL 里 `m_axi_gmem0_0_ARLEN = 1`（**字节**）：每一次 DDR 访问都是**单 beat、1 个有效字节**的事务，口径 1.26 GB 的流量因此要 105.8 s（=82% 的 conv 时间），有效带宽只有**读 14.3 / 写 10.7 MB/s**，而 HP0 32bit@150MHz 峰值 600 MB/s |
| C8 为什么只换来 1.6 s | C8 减的是**逻辑行读笔数**（÷7.88），但 RTL 从来就没形成 burst，真实事务数 ≈ **字节数**（1.2 G 笔），CHW/C8 的字节数一模一样 ⇒ 该省的 50 s 根本不存在。1.6 s ≈ 被消掉的 7.66 M 笔 AR 握手/地址计算的固定开销（≈30 拍/笔） |
| 权重提升（ocb 外提） | **净亏 50 s**：省 56.8 s 权重，但填充要按 ocb 组重做 ×3.98 ⇒ 填充 35.3 → 140.4 s。**不要做** |
| 下一个改动 | 把 DDR 访问从 1 字节加宽到 4 字节：填充循环 `src/conv2d_engine.cpp:256-278`，配套写回 `:450/:518/:612`。保守估计 conv **128.4 → 49 s**、整网 **144.9 → 66 s** |

## 1. 实验设计：为什么没用 HLS 计数器，用了什么

### 1.1 HLS 层确实插不进可靠计数器
- Vitis HLS 的 C 代码里**没有读取自由运行计数器的 API**（`ap_wait()` 只用于 dataflow，
  `#pragma HLS LATENCY` 是约束不是观测）。任何"按已知 II × 迭代数累加"的写法都是猜测。
- 可行的是 C/RTL cosim（拍数精确），但 **1 s 的 RTL 仿真要跑几小时**（实测 cosim
  ≈4~8 k 拍/秒），只够做小形状。
- 备选方案"在 `tb_engine_c8.cpp` 里给 AXI 读注入 N 拍延迟"**也做不到**：cosim 的 AXI
  从设备是 HLS 自动生成的 autotb（`conv2d_engine.autotb.v` + axi_vip），C 测试台根本
  不实现 AXI，注入延迟没有入口。

### 1.2 实际用的三重测量（全部是板上实测，无假设）
1. **逐层实测 247 个卷积**：板上已有 `layers.json`（`--profile-layers`，纯 C8 bit，
   conv 合计 128.445 s）。这是 247 条方程。
2. **33 个新形状扫描**（本轮新测，`phase_split{,2,3}.json`）：320² 上做
   `(cin,cout)` 互换、面积/通道扫描、`cout%8 != 0`、`1×1` 极小图，共 **33 个点**。
   关键是把四个相位做成**正交**的：
   | 手段 | 打破了哪条共线性 |
   |---|---|
   | `(cin,cout)` 互换（8/64 ↔ 64/8） | compute 与 weight 字节**完全相同**，fill 与 write 成反比 ⇒ 直出 `aF − aW` |
   | 固定 cout、扫 cin | weight **装载次数**不变、字节数 ∝ cin ⇒ 分离"每笔固定"与"每字节" |
   | `cout%8 != 0`（1/2/4/12/20） | `weight_bytes/iters` 随 cout 变（0.0625~0.125）⇒ 分离 `aT` 与 II |
   | `1×1` 图 + `cout: 1→8` | fill/write ≈ 0，而 weight 字节 ×8、迭代数不变 ⇒ 单独量出 `aT` |
3. **生成的 RTL 直接查证**（`/data/work/hls_c8_cosim/pure11/cosim1/sim/verilog/`）：
   把事务形态从"推断"变成"读代码"。

### 1.3 精度
- 单点重复性：同一形状 7 次重复**最大值与最小值差 < 0.2%**（如 5425.30 / 5425.34 / 5425.28 ms）。
- 320² 的 17 点联合拟合：**RMS 0.4 ms、最大 1.0 ms**（对 88 ms~6.1 s 的样本）。
- 247 层：用 8 个系数拟合，R²=0.9997、RMS 20.9 ms。

## 2. 根因：每笔 AXI 事务只有 **1 个有效字节**

```
$ grep "assign m_axi_gmem0_0_ARLEN" conv2d_engine_conv2d_engine_Pipeline_VITIS_LOOP_267_13.v
assign m_axi_gmem0_0_ARLEN = 64'd1;      // 填行缓冲（写 line_buf 的那条流水）
$ grep ... Pipeline_VITIS_LOOP_343_16_VITIS_LOOP_345_17.v
assign m_axi_gmem0_0_ARLEN = 64'd1;      // k=1 权重装载（写 wgt1_buf）
$ grep ... Pipeline_VITIS_LOOP_438_30.v / 506_35.v
assign m_axi_gmem1_0_AWLEN = 32'd0;      // 写回（每个 oc 一次单字节写）
```
- 端口本身是 32 bit（`C_M_AXI_GMEM0_DATA_WIDTH = 32`，`ARSIZE = BUS_ADDR_ALIGN = 2`），
  所以**每个 beat 硬件搬 4 字节，但我们只用 1 个**。
- `max_read_burst_length=256 / num_read_outstanding=16` 这两条 pragma 因此**都没有生效**：
  请求长度只有 1 字节，压根没有 burst 可合，outstanding 也只是把 1-byte 请求排个队。
- 实测代价：**读 10.5 拍/字节、写 14.0 拍/字节**（`fill_heavy_192_8` 与 `write_heavy_8_192`
  两点的斜率，见 `phase_split.json`）。等价于"每字节一笔、单笔往返 ≈ 42 拍、约 4 笔在途"。

> 这也解释了 2026-10-21 那条"行缓冲填充只有 16 拍/字节（≈8 MB/s）、反推每搬一行要等
> 一次完整往返"的观测——当时的归因（"并发度不够"）方向对了一半，但真正的原因是
> **请求只有 1 字节**，不是"每行的第一笔要等往返"。

| 系数 | 值 | 来源 |
|---|---|---|
| 填充 `aF` | 10.5 拍/B | `swap_64_8` − `swap_8_8` 差分；`fill_heavy_192_8` 斜率 9.8；`1×1` cin 扫描 11.4 |

| 权重 `aT`(k=3) | 16.3 拍/B | k=3 组总时间 − 计算项倒推；`1×1` 上 `k3_c1→k3_c8` 独立测得 20 拍/B（9 字节散读更贵） |

**误差棒**：填充/写回是直接测出来的（±10%）。计算与权重的切分依赖 `aT`，
而 `weight_bytes` 与 `iters` 在 247 层里几乎完全共线，只能靠 `1×1` 与 `cout%8` 两个
杠杆分开。若 `aT`(k=3) 取 10.5 而不是 16.3，则权重 44 s / 计算 36 s；若取 20，
则权重 66 s / 计算 14 s。**"内存 82%、计算 18%"这条结论在 ±8% 内稳定**，
但"权重 57 / 计算 23"的切分应理解为 45±10 s / 30±12 s。

## 4. C8 为什么只换来 1.6 s

三条独立证据互相对上：

1. **RTL 层面**：C8 与 CHW 的请求都是 1 字节/笔（`ARLEN=1`），C8 只改了**地址**
   （连续 vs 跨步 880 B），没改事务粒度。
2. **字节数不变**：CHW 填充 0.59 GB，C8 填充 0.504 GB（C8 把 cin 补到 8 的倍数，
   `lb` 也从 68 收到 64）——量级完全相同，只是把"同字节数"换个顺序读。
3. **量化对账**：C8 消掉 8.76 M − 1.118 M = 7.66 M 笔**逻辑行读**。实测省 1.6 s
   = 240 M 拍 ⇒ **≈31 拍/笔**，正好是"每笔的 AR 握手 + 地址递推"的固定开销。
   也就是说：**逻辑行读的"笔数"只占填充成本的 4%**（240 M / 5.3 G 拍），
   另外 96% 是"每个字节一笔"的字节级事务。

⇒ 判据：**`max_read_burst_length` / `num_read_outstanding` / C8 布局这三件事全都
在优化"笔数"，而瓶颈是"字节级事务"。** 只要 C 代码里的 m_axi 指针还是
`data_t*`（`ap_int<8>`），HLS 就只会发 1-byte 请求，改布局/改 pragma 都没用。

## 5. 权重提升（ocb 移到 y 外面）的净收益与风险

前提数据：权重读 **612.8 MB / 57.4 s**（占 conv 44.7%）；填充 **503.7 MB / 35.3 s**。

### 5.1 直接外提：净亏 ≈ 50 s
- 权重按 `(x0, ocb)` 装一次 ⇒ 612.8 MB ÷ 平均输出行数 ≈ 几乎归零，省 ~57 s。
- 但 `y` 进到 `ocb` 里面以后，**每个 ocb 组都要把输入行重新填一遍**：
  `Σ fill·⌈cout/8⌉ / Σ fill = 3.98`（不是 12——大部分层的 cout 是 16~64），
  填充 503.7 MB → **2 005 MB**，35.3 s → **140.4 s**。
- 净：conv 128.4 → **≈178 s**（+50 s）。**否决。**

### 5.2 想保住填充就必须多占 BRAM，而 BRAM 已经没余量
唯一不重填的办法是把 `span+B-1` 行留在片内（B = 一次权重装载覆盖的行数）。
`line_buf` 现在是 `[CIN_MAX=352][SPAN_MAX=7][BWCOL_MAX=76]` = 187 KB ≈ 94 块 BRAM18；
`span=3 → 3+B-1` 每加一行就是 +27 KB ≈ +13 块，而当前已用 82/95 块。B=2 都紧张。

### 5.3 不重填的替代：`OC_BLOCK` 8 → 16
权重装载字节数**减半**（613 → 306 MB，57.4 → 28.7 s），填充/写回/计算量**完全不变**，
不需要任何额外填充。代价：
- `wgt3_buf` 25.3 KB → 50.6 KB（LUTRAM；当前 LUT 已 76~79%）；
- 累加器/加法树 8 → 16 路，DSP 不变（lane 数不变，II 翻倍但迭代数减半，计算总拍数不变）；
- **C8 地址公式假设 `OC_BLOCK == C8_CH == 8`**（`conv2d_engine.h` 里有 `#error` 守卫），
  写回要改成每像素 16 字节 = 4 个 32-bit 写；PS 侧布局也要跟着从 8 改到 16。
- 收益：conv 128.4 → **99.7 s**。

**建议顺序**：先做第 6 节的宽访问（省 79 s，且不碰 ABI），做完之后权重只剩 14 s，
`OC_BLOCK=16` 只值 7 s，就不值得再冒 LUTRAM/LUT/布局改动的风险了。

## 6. 下一步最值得做的一个改动（具体到行）

**把 DDR 访问从 1 字节加宽到 4 字节（32 bit，正好一个 beat）。**

位置（`pynq_specialized_code/pl/src/conv2d_engine.cpp`，同步 `src_cosim/`）：

1. **填充（收益最大，35.3 s）** `C8_LAYOUT` 分支的填充循环，`:256-278`：
   ```cpp
   const int nwide = lb * C8_CH;
   for (int t = 0; t < nwide; ++t)
       line_buf[cinb + (t & 7)][r][la + (t >> 3)] = in_fm[iob + t];
   ```
   改成按 32-bit 字读：C8 布局下连续 4 字节 = **同一像素的 4 个通道**，正好落 4 个
   不同 bank（`line_buf[cinb+0..3][r][la+j]`），一拍可以并行写 4 个 bank：
   ```cpp
   const ap_uint<32> *in32 = reinterpret_cast<const ap_uint<32>*>(in_fm + iob);
   HLS_PRAGMA(HLS PIPELINE II=1)
   for (int w = 0; w < nwide / 4; ++w) {          // nwide 恒为 4 的倍数：lb*8
       ap_uint<32> v = in32[w];
       const int j = la + (w >> 1);
       const int c0 = cinb + ((w & 1) << 2);
       line_buf[c0 + 0][r][j] = v(7, 0);
       line_buf[c0 + 1][r][j] = v(15, 8);
       line_buf[c0 + 2][r][j] = v(23, 16);
       line_buf[c0 + 3][r][j] = v(31, 24);
   }
   ```
   注意 `iob` 必须 4 字节对齐（C8 下是 `io_row*8 + (cinb>>3)*hw8`，恒为 4 的倍数）。
2. **写回（13.1 s）** 三处 `out_fm[OUT_ADDR(ocb,i,y,x0+x2)] = v8;`
   （`:450`、`:518`、`:612`）：C8 下同一像素的 8 个 oc 是连续 8 字节，
   把 `for (i<ocbl)` 里算好的 8 个 `v8` 打包成一个 `ap_uint<64>`（或两个 32-bit）存。
3. **权重装载（57.4 s）** `:340-395`：k=1 分支换成 32-bit 读（cin 是 8 的倍数）；
   k=3 的 9 字节步长不是 4 对齐，先只改 k=1（237 MB / 16.6 s），k=3 另行处理。

**验证台阶（不要直接上板）**：
1. `fuzz_shapes.py` + `fuzz_c8_shapes.py` 逐位回归；
2. **cosim 跑同一个 2×320 / cin=32 / cout=16 / k=3 数据集：拍数应从 339,120 明显下降**
   （这一步同时验证"事务变宽"是否真的发生了——再 grep 一遍 `ARLEN` 应为 `4`/`8`）；
3. `check_src_sync.py`、`check_regmap.py`（ABI 不变，应无改动）；
4. 再出 bit（bit+hwh 成对）上板。

**预期**（保守，W=4：一笔仍是 1 beat，事务形态与现在完全相同）：
| 相位 | 现在 | 改后 |
|---|---|---|
| 填充 | 35.3 s | 8.8 s |
| 权重 | 57.4 s | 14.4 s |
| 写回 | 13.1 s | 3.3 s |
| 计算 | 22.7 s | 22.7 s |
| **conv** | **128.4 s** | **≈49 s** |
| **整网** | **144.9 s** | **≈66 s** |

W=8（每笔 2 beat，一次搬一个像素的全部 8 个通道）是上限：conv ≈ 36 s、整网 ≈ 52 s。

## 7. 坑

1. **`max_read_burst_length` / `num_read_outstanding` / C8 全是"笔数优化"，对 1-byte
   请求全都不生效**。以后任何"事务数"模型都必须先确认 RTL 里的 `ARLEN`，
   否则会像这次一样把 8.76 M 当成真实事务数（真实值 ≈1.2 G，差 140×）。
2. **`80 s 填充` 那个结论是错的**：它把"10.3 µs/笔"标定到"8.76 M 笔"上，
   而 8.76 M 是**逻辑行读笔数**，不是 AXI 事务数。C8 的 A/B 是反证：÷7.88 笔只省 1.6 s。
3. **cosim 的 8 MAC/拍不能外推到板上**：cosim 的 AXI 从设备零延迟，计算与访存完全重叠；
   板上 82% 的时间在等 DDR。任何用 cosim 拍数 × 频率估板端时间的做法都偏乐观 3~6 倍。
4. **`(cin,cout)` 互换时 compute 与 weight 字节完全同步变化**，单靠形状扫描分不开；
   必须用 `cout%8 != 0`（1/2/4/12/20）或 `1×1` 图才有一个不变的量做杠杆。
5. **1×1 微基准的 0.1 ms 是 PS 侧开销**，不是引擎拍数：`eng.run()` 从写寄存器开始计时，
   每次调用有约 1.1~1.7 万拍（≈0.1 ms）的寄存器写/轮询开销。做差分可以消掉，别当绝对量。
6. **同一个形状，网络里跑比单独跑快 14%**（`decoder.preconv_1`：网络内 15.32 s，
   微基准 17.79 s）。原因是 DDR 行/体局部性与缓冲区基地址不同。用微基准标定整网时要
   预留这份偏差，别把微基准的绝对值直接乘上去。
7. **`OC_BLOCK` 改 16 会撞 `#error` 守卫**（`C8_LAYOUT && OC_BLOCK != C8_CH`），
   而且 C8 写回公式和 PS 侧布局都写死了 8，不是改一个宏的事。
8. **板端要 `sudo -i` 再跑 `board_safe_run.sh`**：`/tmp/board_run.lock` 之前是 root 建的，
   `xilinx` 用户直接跑会 `flock` 失败并报"另一个板端任务占着锁"。本次用
   `echo xilinx | sudo -S chmod 666 /tmp/board_run.lock` 修好；PYNQ/`/dev/mem` 也要 root。
