## 1. 为什么是**两位**而不是一位

网络里输入/输出的 8 对齐状态**不是同时成立**的：

| 层 | cin | cout | 输入 | 输出 |
|---|---:|---:|---|---|
| `encoder.conv_first.0` | 12 | 48 | **CHW** | C8 |
| `decoder_1.out_conv` | 对齐 | 12 | C8 | **CHW** |
| 其余 246 个 conv | 多数对齐 | 多数对齐 | 按 `c%8` | 按 `c%8` |

一位 layout 会让 `conv_first`（cin=12）或 `out_conv`（cout=12）其中一层跑错。
所以输入缓冲和输出缓冲各一位，PS 侧按每个张量的 `C % 8 == 0` 独立决定。

位定义（`conv2d_engine.h`）：

```cpp
#define RELU_EN_RELU_BIT  0
#define RELU_EN_C8IN_BIT  2
#define RELU_EN_C8OUT_BIT 3
```

- `C8_LAYOUT=1` 编译（硬件有两套通路）：bit2/bit3 决定走哪套；
- `C8_LAYOUT=0` 编译（旧硬件）：**bit2/bit3 被忽略**，行为与改造前逐字一致。

### 1.1 ⚠️ `relu_en` 不再是布尔

三处写回原来都是 `if (relu_en != 0 && v < 0) v = 0;`。设了 bit2/bit3 后
`relu_en != 0` 恒真 ⇒ **线性层会被误开 ReLU**（depthwise 方案踩过的同类隐患）。
现在统一成：

```cpp
const int relu_on = (relu_en >> RELU_EN_RELU_BIT) & 1;
...
if (relu_on && v < 0) v = 0;
```

全仓库 `src/` 与 `src_cosim/` 已无 `relu_en != 0`（`pl/experiments/` 的
历史单文件实验不参与构建，未改）。

### 2.1 填充：两套循环体，一个运行期选择

C8 与 CHW 的**循环顺序本质不同**（C8 必须 `ic` 在内层才能折成 8·lb 长 burst；
CHW 是 `ic` 外层、列内层），所以不能只 mux 一个下标：

```cpp
#if C8_LAYOUT
    if (c8_in) {
        // 8 通道 × lb 列 = 连续 8*lb 字节 ⇒ 一笔长 burst（ceil(cin/8) 笔/行）
        for (int cinb = 0; cinb < cin; cinb += C8_CH) {
            const int iob = io_row * C8_CH + (cinb >> 3) * hw8;
            HLS_PRAGMA(HLS PIPELINE II=1)
            for (int t = 0; t < lb * C8_CH; ++t)
                line_buf[cinb + (t & 7)][r][la + (t >> 3)] = in_fm[iob + t];
        }
    } else
#endif
    {
        // 原 CHW 填充（逐字保留）
        for (int ic = 0; ic < cin; ++ic) { ... in_fm[io_row + ic*hw + j] ... }
    }
```

`C8_LAYOUT=0` 时 `#if` 把 `if (c8_in)` 整段剪掉，只剩原 CHW 体。

### 2.2 写回：**布局判断放在循环外**

```cpp
#if C8_LAYOUT
if (c8_out) {                       // C8 写回：地址式与旧版逐字相同
    const int obase = ((((ocb >> 3) * Hout + y) * Wout + (x0 + x2)) * C8_CH);
    for (int i = 0; i < ocbl; ++i) { ...; out_fm[obase + i] = v8; }
} else
#endif
{                                   // CHW 写回
#if C8_LAYOUT
    int oaddr = ((ocb * Hout + y) * Wout + (x0 + x2));   // 运行期版：递推（省 14 DSP）
    const int ostep = Hout * Wout;
#endif
    for (int i = 0; i < ocbl; ++i) {
        ...;
#if C8_LAYOUT
        out_fm[oaddr] = v8;  oaddr += ostep;
#else
        out_fm[((ocb + i) * Hout + y) * Wout + (x0 + x2)] = v8;   // 旧式，逐拍 369,236
#endif
    }
}
```

**为什么不能只写"一个 mux"**（这是本次最重要的教训）：写回循环没有流水，
地址在关键路径上。把 `c8_out ? ... : ...` 或 `i * 运行期步长` 放进循环体，
每个输出通道会多 1~2 拍 ⇒ C8 侧 339,120 → 355,840（+4.9%）。改了两版都不行，
最后只能把布局判断**提到循环之外**（复制一份小的后处理循环；MAC 不复制）。
代价：engine LUT 38,076 → 39,485（+1,409），DSP 111 → 117。

### 4.4 拍数差异的归因（做了一轮对照实验，结论与最初猜测不同）

| 实验 | C8 拍数 | CHW 拍数 | 结论 |
|---|---:|---:|---|
| 旧源码（`b9f976e`）+ **新测试台** | **339,120** | — | 测试台/缓冲区分配无关 |
| 运行期版（布局 select 在写回循环内） | 355,840 | 360,416 | 起点 |
| 同上，`if (c8_in)` 改成 `if (1)`（只剩 C8 填充体） | **355,840** | — | **双填充循环/运行期分支本身 0 拍代价** |
| 同上，写回用单条完整表达式 + 循环内 mux | 362,240 | 366,816 | 更差，否决 |
| **最终版：布局判断提到写回循环外** | **340,500** | **361,716** | **+0.41% / +0.67%** ✓ |
| 旧源码 `C8_LAYOUT=0`（单 CHW 循环） | — | 369,236 | 基线 |

**根因是写回，不是填充 burst**。最初怀疑"运行期分支让 C8 填充被拆成 3 笔"，
但把两次生成的填充循环 RTL 逐行对比（`..._Pipeline_VITIS_LOOP_235_13.v` 旧 vs
`..._258_13.v` 新）**除符号名外完全相同**（ARLEN 仍是一笔 152 拍），且"只剩 C8 体"
的对照拍数一点没变 ⇒ 假设被证伪。

真正原因：写回循环没有流水，旧 C8 的地址是纯移位、每通道独立；运行期版把
`c8_out ? ... : ...`（或 `i*运行期步长`）放进循环体后，地址进了关键路径，
10,240 次写回 × 1~2 拍 ≈ +16.7k。把布局判断提到循环外（复制后处理、不复制 MAC）
后回到 340,500。

剩余 +1,380 拍（+0.41%）来自每个 (x2, ocb) 一次的分支判断（2,560 次 × ~0.5 拍），
不可避免；`c8_in=0` 侧同理 +0.67%。

## 5. 资源（csynth，xc7z015clg485-2，6.667 ns）

| 构建 | DSP | BRAM_18K | FF | LUT | Fmax |
|---|---:|---:|---:|---:|---:|
| 改造前 CHW（`b9f976e`） | 131 | 166 | 25,347 | 36,958 | 172.18 MHz |
| `C8_LAYOUT=0`（本次源码） | **131** | **166** | 25,315 | 36,926 | 172.18 MHz |
| `C8_LAYOUT=1` 编译期 C8（`b9f976e`） | 104 | 172 | 22,200 | 35,383 | 172.97 MHz |
| 运行期版（写回 select 在循环内，已否决） | 111 | 172 | 24,913 | 38,076 | 172.18 MHz |
| **`C8_LAYOUT=1` 运行期版（最终）** | **117** | **172** | **26,060** | **39,485** | **172.18 MHz** |

- 相对"同一份源码的 CHW 构建"：**−14 DSP / +6 BRAM18 / +2,559 LUT**；
- 相对"改造前 CHW 硬件"：**DSP −14、BRAM +6、LUT +2,559（+6.9%）**。

LUT 增量主要来自"两套填充循环体 + 两套写回循环"（HLS 不会把它们合并）。
39,485 LUT = 85.5%（x7z015 共 46,200）。上一版（38,076 LUT）整合后 impl 为
38,963 LUT(84.3%)、WNS −0.589 ns @150 MHz；本版整合后约 40.4k(≈87%)，
**150 MHz 不收敛是常态，板子实际跑 125 MHz**（见 §7）。
若 impl 放不下，回退"写回按布局复制"两处 hunk 可回到 38,076 LUT，代价是 C8=355,840。

## 8. 坑

1. **`relu_en` 不能当布尔**：bit2/bit3 一设，`relu_en != 0` 就恒真 ⇒ 线性层被误开 ReLU。
   本仓库 `pl/src`、`pl/src_cosim` 已清零；`pl/experiments/` 的旧单文件实验仍有，不参与构建。
2. **`EXTRA_DEFS` 是假的**：脚本只认 `EXTRA_CFLAGS`。判断宏是否生效别信"退出码 0"，
   要看 csynth 的 BRAM（172 vs 166）和 `component.xml` 的 `MAX_READ_BURST_LENGTH`（256 vs 64）。
3. **HLS 的源码路径依赖**：把 `SRC_DIR` 指到工程根目录**同一文件系统**下的兄弟目录
   （如 `/data/work/...`）时，HLS 把源文件记成相对路径 `c8_old_src/...`，解析时按
   **`scripts/` 当前工作目录**找 ⇒ `Cannot find source file`，报出来是
   `[HLS 200-70] Cannot find any design unit to elaborate`。跨文件系统（如 `/tmp`、
   `/media`）时才会保留绝对路径。做 A/B 对照时把旧源码放 `/tmp/c8_old_src` 即可。
4. **A/B 时测试台会和"旧源码"打架**：新 tb 引用了头文件里的 `RELU_EN_*_BIT`，用旧头文件
   编不过。对照实验要用"旧 .cpp + 新 .h"（头文件只加宏和注释，不影响旧 RTL）。
5. **`input_chw.bin` 必须显式生成**：`tb_engine_c8` 在 `c8_in=0` 时读它，
   `fuzz_c8_shapes.py` 会写；手工跑 cosim 时要先用 `c8lib.from_c8` 生成。
6. **写回地址用递推，不要 `i * 运行期步长`**：后者会给每个写回生成运行期乘法。
   虽然本次实测拍数不变（不在关键路径），但在 DSP 更紧的构建里是隐患。
7. **`C8_LAYOUT=1` 仍然强制 `K1_WIDE_COLS=0`**：所以运行期版在 `c8_in=0` 时 k=1 层
   没有 wide1。小图（16×16，1 个列块）不受影响；大幅宽 k=1 层如果要 `c8_in=0` 会慢。
8. **拍数不是唯一判据**：运行期版 C8 比编译期版慢 4.9%（§4.4），但功能逐位一致；
   本阶段只用 CHW 分支，实测比旧 CHW 基线还快。
