## 1. 为什么必须回到编译期：运行期 mux 的实测代价

| 运行 | 总 | conv | 说明 |
|---|---:|---:|---|
| 黄金 bit（CHW，无 mux） | 186.7 s | **129.8** | 交付基线 |
| 运行期双布局位（CHW 模式） | 197.3 s | **139.6** | mux 代价 **+7.5%** |
| 运行期双布局位（C8 模式） | 195.4 s | 138.0 | C8 收益没兑现 |

上一版为了"8 个例外张量保持 CHW"而引入运行期选路，代价是三重的：

1. **拍数**：写回循环没有流水，地址在关键路径上；`c8_out ? ... : ...` 放进循环体
   让每通道多 1~2 拍（C8 侧 339,120 → 355,840）。把判断提到循环外仍余
   +0.41%/+0.67%（每次 (x2,ocb) 一次分支）；
2. **资源**：两套填充循环 + 两套写回后处理，HLS 不会合并 ⇒ **LUT +2,559、DSP +13**；
3. **板上**：conv 直接慢 7.5%，把 C8 的全部账面收益吃光。

去掉 mux 后（本版）三项全部回到编译期水平：**LUT 35,359（−4,126）、DSP 104（−13）、
FF 22,201（−3,859）**，数据通路与 `b9f976e` 的编译期 C8 版逐字相同。

## 2. RTL：怎么去 mux（`pl/src/conv2d_engine.cpp`、`pl/src_cosim/` 同步）

### 2.1 地址：编译期常量选择（`OUT_ADDR` 宏）

```cpp
#if C8_LAYOUT
#define OUT_ADDR(ocb_, i_, y_, x_) \
    ((((ocb_ >> 3) * Hout + y_) * Wout + x_) * C8_CH + i_)
#else
#define OUT_ADDR(ocb_, i_, y_, x_) (((ocb_ + i_) * Hout + y_) * Wout + x_)
#endif
```

三处写回（k=1 快路径 / k=3 快路径 / 通用路径）都只剩**一份**后处理循环：
`out_fm[OUT_ADDR(ocb, i, y, x0 + x2)] = v8;`。C8 侧是纯移位/加法，CHW 侧是旧的
双乘法链，两者都在编译期定死 —— **循环体内没有任何运行期 select**。

### 2.2 填充：`#if` 选循环体，不是 `if (c8_in)`

```cpp
#if C8_LAYOUT
            {   // 唯一一份：C8 长 burst（8 通道 × lb 列 = 连续 8*lb 字节）
                for (int cinb = 0; cinb < cin; cinb += C8_CH) {
                    const int iob = io_row * C8_CH + (cinb >> 3) * hw8;
                    HLS_PRAGMA(HLS PIPELINE II=1)
                    for (int t = 0; t < lb * C8_CH; ++t)
                        line_buf[cinb + (t & (C8_CH - 1))][r][la + (t >> 3)] =
                            in_fm[iob + t];
                }
            }
#else
            {   // 唯一一份：原 CHW 逐通道填充（逐字未改）
                ...
            }
#endif
```

`c8_in`/`c8_out` 两个运行期变量**已经不存在**（`grep` 只剩注释）。

### 2.3 `relu_en` bit2/bit3 → 声明位 + `ERR_LAYOUT`

编译期 C8 的构建没有 CHW 通路可退，所以"PS 忘了声明"必须**响亮地失败**，
否则会把 CHW 数据按 C8 读、算出一堆"看起来正常"的垃圾（板上表现为整网精度崩、
引擎却不报错 —— 最难查的一类）：

```cpp
const int relu_on = (relu_en >> RELU_EN_RELU_BIT) & 1;
#if C8_LAYOUT
    if ((relu_en & ((1 << RELU_EN_C8IN_BIT) | (1 << RELU_EN_C8OUT_BIT)))
        != ((1 << RELU_EN_C8IN_BIT) | (1 << RELU_EN_C8OUT_BIT))) {
        return ERR_LAYOUT;          // 新增错误码 4（conv2d_accel.h）
    }
#endif
```

- 这是**入参校验**，不是选路：每层一次 32 位比较，不进任何循环；
- `relu_en` 仍然**不能当布尔**（`relu_en & 1`），上一版的这个坑继续保留修好的状态。

### 2.4 测试台与脚本

| 文件 | 改动 |
|---|---|
| `pl/tb/tb_engine_c8.cpp` | 编译期布局：`-DC8_LAYOUT=1` 时 `c8_in=c8_out=1` 并把声明位无条件置进 `relu_en`；新增**负向测试**（清掉声明位必须得到 `ERR_LAYOUT`） |
| `pl/scripts/fuzz_c8_shapes.py` | 组合从 4 种减到 1 种（`(1,1)`）；判据改成"**两个独立构建逐字节相同**" |
| `pl/scripts/hls_run_engine.tcl` | 新增 `TB_SRC`（C8 构建要换成 `tb_engine_c8.cpp`）与 `SKIP_CSIM`；默认行为不变 |

`-DC8_LAYOUT=1` 的 csim 必须换测试台：CHW 测试台喂纯 C8 引擎会被 `ERR_LAYOUT`
拦住。本次 csim 用 `TB_SRC=tb_engine_c8.cpp TB_DATA=/data/work/tb_c8_k3_32x16 TB_RELU=13`，
日志 `PASS: 10240 个输出全部一致（c8_in=1 c8_out=1，补零输出通道 0 个）`。

## 3. PS 侧：让所有张量都是 8 的倍数

### 3.1 判定规则（`ps/pynq/c8_layout.py`）

```python
table(manifest, on, pad=True)   # pad=True：int8 ⇒ 全部 C8；fp32 ⇒ CHW
```

`pad=False` 保留上一轮"只让 C%8==0 走 C8"的规则，仅供历史对照
（**不能配纯 C8 的 bit**）。实测 manifest_640：**C8 516 / int8 例外 0 / fp32 6**。

配套改动：
- `view_shape()`：C8 视图 = `(ceil(C/8),H,W,8)`，**不再对非 8 倍数抛错**（补零块存在，
  块内尾部 `8-C%8` 个通道恒 0）；
- `to_chw(arr, is_c8, c=逻辑通道数)`：只转换需要的那几个通道块，再切掉补零通道；
- `from_chw()`：C8 目标时**补零到 8 的倍数**（对齐张量行为逐字不变）；
- `chw_chunk()`：允许非 8 对齐的分块边界（`eca` 的 32 通道分块碰到 12ch 张量时）；
- `ch_slice()`：仍然要求 8 对齐（只用于 cat 别名组的块级切片）；
- `compute_cat_alias()`：判据从"两边布局标志相同"（全 C8 后恒真）改成
  **"段通道数真的是 8 的倍数"**。实测 224 个 cat / 454 个段全部对齐 ⇒ 不触发。

### 3.2 四个例外张量怎么办

| 张量 | 角色 | 原 C | 补到 | 做法 |
|---|---|---:|---:|---|
| `t0` | 网络输入（RGB） | 3 | 8 | 输入注入时 `to_c8(pad=True)`，补 5 个零通道（拷贝 8/3 倍，仅此一处） |
| `t1` | `encoder.conv_first` 的输入 | 12 | 16 | 缓冲区 16 通道、尾部 4 个恒 0；引擎按 C8 读满 2 个通道块，乘加仍只跑 `ic<12` |
| `t520` | `decoder_1.out_conv` 的输出 | 12 | 16 | 引擎只写前 12 个通道，尾部 4 个保持 0（测试台逐用例断言"补零通道没被写脏"） |
| `t521` | 网络输出（RGB） | 3 | 8 | `pixel_shuffle` 结果补零后落盘；读出时只取前 3 个通道 |

`decoder_2/3` 的尾巴（`t342/t343/t431/t432`）不在 needed 子图内，同样补零。

### 3.3 `cin=12` 那一层：**零打包改动**

采用任务书里的"引擎侧方案"：

- manifest 里 `cin` 上界**仍然是 12**，权重张量 `w_shape=(48,12,5,5)` 一字未动；
- 缓冲区按 `ceil(12/8)*8 = 16` 通道分配并清零；
- 引擎 `for (cinb = 0; cinb < cin; cinb += 8)` 跑 2 次（读满 16 个通道位），
  但乘加循环是 `for (ic = 0; ic < cin; ++ic)` ⇒ **补零通道的 4 个权重根本不存在，
  也不参与累加**；
- 权重装载的 `cin_kk = cin*kk = 300` 依然是 12 通道的跨度，`w_off/w_len` 不变。

代价：这一层多读 4 个零通道（填充字节数 +33%），全网络只此一层，可忽略。
**导出侧（`ps/tools/export_network.py` / 权重包）零改动。**

### 3.4 算子层（`ps/c8/ops_c8.py`、`ps/pynq/runner.py`）

只有 3 类算子会碰到补零张量，全部显式传**逻辑通道数**：

| 位置 | 改动 |
|---|---|
| `pixel_unshuffle` / `pixel_shuffle` | 新增 `c_in`/`c_out`：入口按 `c_in` 切掉补零通道再重排，出口按 `c_out` 补零后放回 |
| `RefEngine.conv` | 输入按 `op["cin"]` 取逻辑通道（补零区不进乘加，与 RTL 的 `ic<cin` 一致）；输出补零到 8 的倍数 |
| `Runner._verify_chsum` / `record` / `hashlog` / 最终输出 | `to_chw(..., 逻辑通道数)`，保证与 CHW 路的形状/sha1 可直接 diff |
| `PYNQArena` | 视图元素数改成 `ceil(C/8)*8*H*W`（按 `c*h*w` 切会 reshape 失败） |

内存池：**66.76 → 67.17 MB（+0.41 MB）**，来自 4 个补零张量（3ch→8、12ch→16 各两张：
`t0 640×640` 多 2.05 MB、`t521 640×640` 多 2.05 MB、`t1/t520 320×320` 各多 0.41 MB，
生命周期复用后池只涨 0.41 MB）。PYNQ CMA 128 MB 充裕。

### 3.5 板端 PS 转换量（解析式，**不是** A/B 日志里那个数）

`test_c8_ab.py` 的日志会打印"真机 PS 实际要转 ≈ 921.7 MB"，那个数**被 hashlog 撑大了**
（A/B 要逐算子 sha1，把 517 个算子输出全转了一遍 CHW）。真实执行路径上只有
"必须在 CHW 里算"的算子才转换：

| 算子 | 个数 | 转换量/张 |
|---|---:|---:|
| `eca` | 6 | 51.6 MB |
| `interp` | 26 | 89.8 MB |
| `pixel_shuffle` / `unshuffle` | 2 | 4.9 MB |
| **合计** | 34 | **146.3 MB** |

`cat`（224 个）/ `add` / `sam_sum` / `rescale` 在 C8 上**零转换**（块级或逐元素），
`conv` 由 PL 直读直写 C8 ⇒ 也 0。换算下来：事务模型给出的填充收益约
**37.0 s → 4.6 s**（wide1+行复用口径），而 146 MB 的 PS 转换在 Cortex-A9 上量级是
几秒 —— 收益面仍然占优。**但这必须板端实测**（`interp` 其实也能在 C8 上原生算：
它只动 H/W、通道维零重排，是后续最容易摘掉的 89.8 MB）。

## 7. 坑

1. **`-DC8_LAYOUT=1` 不能再跑 `tb_engine.cpp`**：纯 C8 引擎没有 CHW 通路，
   会直接返回 `ERR_LAYOUT`。csim 要 `TB_SRC=tb_engine_c8.cpp` + 含 `input_c8.bin` 的数据集
   + `TB_RELU=13`（声明位）。`hls_run_engine.tcl` 已加这两个环境变量支持。
2. **声明位不是选路位**：旧 PS（`C8_LAYOUT=0`）配新 bit 会拿到 `rc=4`，
   `run_network_on_board.py` 会抛 `RuntimeError`。这是**故意的**，比静默算错强。
   反过来，新 PS（`C8_LAYOUT=1`）配旧 bit（双布局位版）也不会立刻错：
   它恒传 bit2/bit3=1，旧 bit 会走 C8 通路、行为正确 —— 但**不要依赖**这一点。
3. **`view_shape` 的 `shape[0]` 是通道块数**：补零后 `shape[0]*8 != 逻辑通道数`
   （12ch 张量是 2 块 = 16）。所有取通道数的地方一律走 manifest 的 `c`。
4. **`PYNQArena` 的视图切片**：按 `c*h*w` 切会 reshape 失败（补零张量更大），
   必须用 `bytes_of()/itemsize`。
5. **cat 别名组的判据要跟着改**：全 C8 之后"两边布局标志相同"恒真，
   必须改成"段通道数都是 8 的倍数"，否则补零张量一旦进 cat 就会错位。
6. **HLS 源码路径**：`SRC_DIR` 指同一文件系统内的兄弟目录会让 HLS 记相对路径而
   找不到设计文件（`[HLS 200-70] Cannot find any design unit`）。用 `/tmp` 或绝对路径。
7. **唯一保留的"运行期"开销**：`relu_en` 的声明位校验（每层一次比较）。
   cosim 上它就是 0 拍代价（不在循环里），不要为省它去掉安全检查。
