### 4.1 ★ 合并检查清单（**任何 patch 合并后必跑，三条全绿才许 commit**）

```bash
bash pynq_specialized_code/ps/tools/merge_gate.sh
# 想看细节/复核别人的合并（不改清单）：加 --no-gen
# 判冻结点/板端目录：--src <目录> --file <清单>
```

| # | 判据 | 命令（脚本内部就是这三条） | 挂掉的含义 |
|---|---|---|---|
| ① | `--gen` rc=0 | `deps_closure.py --gen` | 源码树里有 **DECL 未声明的模块**（合并带进了新 `.py`/`.c` 而没补 DECL）⇒ 门禁坏掉 |
| ② | `md5sum -c` rc=0 | `cd ps/pynq && md5sum -c deps_closure.txt` | 清单与磁盘文件不符（没重生成 / 文件被改 / 缺文件） |
| ③ | `--check` rc=0 | `deps_closure.py --check` | 清单**结构不完整**（漏行 / 依赖图变了 / 缺文件） |

**⚠ 为什么是三条而不是两条（实测，不是理论）**：`md5sum -c` 只对**清单里列到的**文件负责。
T-44 负例实测：把 `mmio_batch` 两行从清单里删掉，`md5sum -c` **仍然 rc=0**，
只有 `--check` 报「清单只有 17 行 md5，闭包应有 19 个文件」。
**这就是 2026-11-02 事故（手挑 7 个 `.py`、漏 `q8/c8deq/bpack`、md5 全过、静默回落 numpy、两天假数）的机械形态。**

**为什么这条必须是脚本而不是纪律**：同类"闭包缺口"已是**第三次**——
① 2026-11-02 手挑 7 个 `.py` 漏 `q8/c8deq/bpack`；② T-41 事后补 `convpf_c`（随 `613a117`）；
③ T-44 事后补 `mmio_batch`（随 `b2cfd23`，新增 `ps/pynq/mmio_batch.c`）。
②③ 是**同一个形态**："合并带了新模块进来，DECL 没同步" ⇒ 判据物理上不可能 rc=0。
⇒ 见 `PLAN_1second.md` 第 82 条：**这不是记性问题，是流程缺环**（每次合并都会带进新模块，概率是 1）。

> 合并动作的完整顺序（缺一步都不算合并完）：
> ① `git merge`/`cherry-pick` → ② **`merge_gate.sh` 三条全绿** → ③ `git add`（显式清单）→ ④ `git commit`。
> 先 commit 再补门禁 ⇒ 历史里留下一个"main 上 `--check` 不可达"的 commit（本项目已有两个）。
