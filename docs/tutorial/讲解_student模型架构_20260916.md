## 第 0 课：这个模型在做什么事？

**去摩尔纹（demoireing）**：手机拍屏幕时，照片上会出现彩色波纹（摩尔纹）。模型输入
一张有摩尔纹的图，输出一张干净的图。

- 输入：一张 RGB 图像，形状是 `(1, 3, H, W)` —— 依次是 **批大小(1张)、通道数(红绿蓝3)、高、宽**
- 输出：同样形状的一张干净图

## 第 1 课：三个你必备的基础概念

在看代码前，先建立三个词的直觉，后面全程要用：

**① 张量（tensor）**：就是一个多维数组。图像在 PyTorch 里是 4 维的：
`(批, 通道, 高, 宽)`。你可以把"通道"理解成**叠在一起的多张同大小的图**——RGB 是
3 张（红图、绿图、蓝图），模型内部会有 48 张、96 张……每一张叫一个**特征图
（feature map）**，可以粗略理解为"从原图里提取出的一种模式的存在强度图"。

**② 卷积（Convolution, `nn.Conv2d`）**：整个模型 90% 的计算量都是它。做的事：拿一个
小的"模板"（比如 3×3 的权重窗口），在特征图上**从左到右、从上到下滑动**，每到一个
位置就做一次"窗口内数字 × 对应权重再求和"，输出一个新的格点。滑完整个图，就得到
一张输出特征图。

- 一个 `nn.Conv2d(in_channels=48, out_channels=96, kernel_size=3)` 的意思是：用 96 组
  不同的 3×3 模板，每组模板对全部 48 张输入特征图加权求和，产出 96 张输出特征图。
  **权重就是模型"学"到的东西**——训练就是在调这些数字。
- **stride（步幅）**：窗口每次滑几格。`stride=2` 就是每次跳 2 格 → 输出图**尺寸减半**。
  这是模型"缩小图片"的方式。
- **padding（补边）**：在图边缘补一圈 0，让输出尺寸不变。`padding=1` 配 3×3 卷积就是
  "尺寸不变"。
- **dilation（空洞）**：窗口里的权重之间隔开几个格。`dilation=2` 的 3×3 窗口实际"看到"
  的是 5×5 的范围，但只用 9 个权重——**花小钱看大视野**，对摩尔纹这种有空间周期的
  花纹很有用（`d_list=(1,2,1)` 就是一层看 3×3、一层看 5×5、一层看 3×3）。

**③ ReLU（`nn.ReLU`）**：最简单的非线性，`负数→0，正数→保留`。没有它，一百层卷积
叠起来数学上等价于一层，网络就"深"不起来。

> Python 语法扫盲（读这个文件只需要这些）：
> - `class X(nn.Module):` 定义一个网络构件；`__init__` 里的代码在**建房子**（声明有
>   哪些层、多少参数），`forward` 里的代码是**水流过管道**（数据怎么算）。
> - `nn.Sequential(A, B, C)` = 把 A、B、C 串成一根管子，数据依次流过。
> - `torch.cat([...], dim=1)` = 沿通道维度把几张图**拼**在一起（48 张 + 32 张 → 80 张）。
>   `dim=1` 就是指"通道"那一维。

## 第 2 课：鸟瞰全局 —— 一个"先压缩、再还原"的 U 形结构

看顶层 `my_model`（`nets_student.py:13`）：

```python
self.encoder = Encoder(...)   # 压缩：提取特征，图越来越小、通道越来越多
self.decoder = Decoder(...)   # 还原：把特征变回干净图像
```

```text
原图 (3通道, H×W)
   │
   ▼ pixel_unshuffle ×2  ──► (12通道, H/2 × W/2)     ← 第87行
   ▼ conv_first
┌─ Encoder_Level 1 ──── 48通道  ── y_1 ─────────┐ (跳线)
│  ▼ 下采样stride=2                                 │
│ Encoder_Level 2 ──── 96通道  ── y_2 ────────┐   │ (跳线)
│  ▼ 下采样stride=2                             │   │
│ Encoder_Level 3 ──── 192通道 (最深处,1/4尺寸) │   │
│  ▼                                           │   │
│ Decoder_Level 3 ── 沿 y_3 还原               │   │
│  ▼ 拼接 y_2 ◄────────────────────────────────┘   │
│ Decoder_Level 2 ── 沿 y_2 还原                   │
│  ▼ 拼接 y_1 ◄────────────────────────────────────┘
│ Decoder_Level 1 ── 沿 y_1 还原
   ▼ conv → pixel_shuffle ×2 ──► 输出 (3通道, H×W)
```

**为什么要先缩小再放大？** 摩尔纹是**有空间周期的花纹**（条纹间距可大可小）。小图
（低分辨率）上每一点"看"到的原始范围更大，天然适合捕捉**周期大的粗纹**；大图适合
**细纹**。三级尺度 = 同时盯三种粗细的纹路。这个思想在后面的 `SAM` 模块里还会再
出现一次。

**为什么有跳线（skip connection）？** 编码器一路压缩会丢失细节。把 y_1/y_2 原封不动
接到解码器旁边（`Decoder.forward` 里 `torch.cat([y_2, feat_3], dim=1)`，第 64 行），
解码器就不用"凭空回忆"细节，直接抄旁边送来的原文。

## 第 3 课：Encoder 逐行走

`Encoder`（第 75 行）：

```python
x = F.pixel_unshuffle(x, 2)          # (87行)
```
**pixel_unshuffle**：不做任何乘法运算，纯粹**搬数据**——把每个 2×2 的像素块拆开摊平
成 4 个通道。3 通道变 12 通道，图缩小一半。作用：先用零计算量把分辨率降下来，后面
所有卷积都在半分辨率上算，**计算量直接省 4 倍**（FPGA 上这就是一个数据重排布线，
不需要任何算术单元）。

```python
nn.Conv2d(12, feature_num, kernel_size=5, ...)   # (79行) 12→48 通道
```
**开场卷积**：48 是配置文件 `uhdm_4k_s.yaml` 里的 `EN_FEATURE_NUM: 48`。从这一刻起，
模型不再处理"颜色"，而是处理 48 张各司其职的特征图。用 5×5 的大窗口开场，是为了
第一眼就看到稍大范围的内容。

接着进入三级 `Encoder_Level`（第 97 行），**每一级都是同一个配方**：

```python
self.rdb   = GhostModule(feature_num, inter_num, d_list=(1,2,1))   # 提特征（主力）
for _ in range(sam_number):                                        # SAM_NUMBER=1
    sam_block = SAM(...)                                           # 多尺度精修
self.down   = Conv2d(feature_num, 2*feature_num, stride=2, ...)    # 尺寸减半、通道加倍
```

三级的通道数：**48 → 96 → 192**（每降一级，通道翻倍——尺寸信息丢了，用更多通道
"记账"补回来）。第三级没有 `down`（第 107 行 `if level < 3`），到底了。

## 第 4 课：灵魂模块 GhostModule —— "一半认真算，一半走捷径"

这是模型能塞进 FPGA 的**关键设计**（第 148–188 行），细讲。

**问题**：普通卷积 `48通道→48通道，3×3` 需要 48×48×9 ≈ 2 万次乘法/每个像素位置。
**Ghost 的思路**：特征图之间是**高度冗余**的——第 49 张特征图往往和第 3 张长得差不多，
只是细节不同。那为什么要认真算满 48 张？

看 `GhostBlock.forward`（第 165 行）：

```python
x1 = self.primary_conv(x)        # 认真算：1×1 卷积，只产出 oup/2 张（比如只要24张）
x2 = self.cheap_operation(x1)   # 走捷径：对这24张做一个 3×3 卷积(带空洞)，
                                 #          得到"相似但有变化"的另外24张
out = torch.cat([x1, x2], dim=1) # 拼起来 = 48张
```

打个比方：要画 48 幅画，**先认真画 24 幅原作，再用复印机给每幅加个模糊/位移，得到
另外 24 幅"幽灵画（ghost）"**——效果接近 48 幅全手绘，但工作量接近一半。乘法量大约
省一半，这就是 "Ghost" 名字的由来。

`GhostModule`（第 171 行）再把这种块串成"**密集连接**"（来自经典的 DenseNet）：

```python
t = x
for ghost_conv in self.ghost_layers:      # 3 个 GhostBlock，dilation 依次 1,2,1
    _t = ghost_conv(t)
    t = torch.cat([_t, t], dim=1)         # 新产出不替换旧特征，而是"叠上去"
t = self.conv(t)                          # 1×1 卷积把堆高的通道压回原数
return t + x                              # 残差连接：输出 = 修正量 + 原输入
```

两个值得记住的技巧（后面反复出现）：
- **密集拼接**：每层的产出和之前的特征**全部保留**，网络自己决定用哪个（权重学出来）。
- **残差 `t + x`**（第 188 行）：不直接学"答案"，只学"对输入的**修正量**"。初始时
  修正量≈0，网络至少不比输入差，训练又稳又快。你会在 SAM（第 256 行）再见到它。

## 第 5 课：SAM —— 同一张图，三只眼睛看

`SAM`（Scale-aware Aggregation Module，第 232 行）：

```python
x_2 = F.interpolate(x, scale_factor=0.5, ...)    # 缩小到 1/2
x_4 = F.interpolate(x, scale_factor=0.25, ...)   # 缩小到 1/4
y_0 = self.basic_block(x_0);  y_2 = ...(x_2);  y_4 = ...(x_4)   # 三条路各跑一个 GhostModule1
y_2 = F.interpolate(y_2, scale_factor=2, ...)    # 都放大回原尺寸
y = torch.cat([y_0, y_2, y_4], dim=1)
attn = self.fusion(y)                            # ECA 打分
y = w0 * y_0 + w2 * y_2 + w4 * y_4               # 按分数加权混合
y = x + y                                        # 残差
```

三只眼睛分别看**原尺寸、1/2、1/4**——同一位置在三个尺度上对应不同的原始视野，
分别擅长不同周期的摩尔纹。关键在 ECA 打的那三个分数 `w0, w2, w4`：**网络自己决定
此刻该更信哪只眼**（是粗纹还是细纹主导），而且这个决定对图上每个位置可以是不同的
倾向。这是比"第三课的三级金字塔"更精细的第二次多尺度设计。

注意 `GhostModule1`（第 190 行）和 `GhostModule` **唯一区别是没有 `+ x` 残差**——
因为 SAM 外层已经做了 `x + y`，里面不用重复。

## 第 6 课：ECA —— 通道们的"裁判"

`ECA`（第 260 行）给上面三只眼打分：

```python
x = self.avg_pool(x)        # 全局平均池化：每张特征图压成 1 个数 = "这张图的平均激活强度"
x = self.conv2(...)         # 一维卷积(k=9)，在"通道排列顺序"上滑动，看相邻通道的关系
x = self.channelshuffle(x)  # 通道洗牌（纯数据重排，无计算）
x = self.conv1(...)         # 再来一次一维卷积
out = self.sigmoid(x)       # 压到 0~1 之间，作为每个通道的分数
```

直觉：48 张特征图各有一个"总体响度"，ECA 看一眼各通道的响度分布，输出 48 个 0~1
的权重——"这个位置，第 7 号特征图很响，多信它；第 30 号没动静，别理它"。
**这是全模型里唯一含"全局信息汇总"的模块**，也是 FPGA 实现时要单独照顾的
（见第 8 课）。

`ChannelShuffle`（第 332 行）纯是数组重排，目的是让一维卷积不会只看到"固定邻居"
的通道。

## 第 7 课：Decoder —— 倒着放一遍录像带

`Decoder`（第 47 行）三级，每级配方（`Decoder_Level`，第 124 行）：

```python
x = self.rdb(x)            # GhostModule 提特征（和编码器同款）
x = sam_block(x)           # SAM 精修
out = self.conv(x)         # 64通道 → 12通道
out = F.pixel_shuffle(out, 2)   # 12通道、半分辨率 → 3通道、全分辨率（unshuffle 的逆操作）
```

级与级之间（第 60–70 行）：拿编码器同级送来的 y_2（跳线）和解码器上一级上采样来的
feat_3 **拼在一起**，先用 `preconv` 压回 64 通道，再进下一级。第 70 行 `feat=False`：
最浅一级不再需要往下传特征了。

## 第 8 课：站在 FPGA 的角度看这个模型

把所有运算分个类，这基本就是你后续 HLS/RTL 工作量的地图：

| 类别 | 出现在哪 | 硬件难度 |
|---|---|---|
| **普通卷积 + ReLU** | conv_first、所有 GhostBlock、down、preconv、conv | ⭐ 你的主战场，MAC 阵列复用 |
| **数据重排（零计算）** | pixel_unshuffle/shuffle（87、140 行）、ChannelShuffle | ⭐ 只是地址映射，写好索引规律即可 |
| **空洞卷积** | GhostModule 的 d_list、SAM 内部 | ⭐⭐ 同一个 MAC，改的是**取数地址的间隔**（dilation=2 时输入指针每次跳 2 格） |
| **双线性插值** | SAM 的 0.5/0.25 缩放、feat 上采样（143、242–250 行） | ⭐⭐ 乘加系数固定，可以做简单乘法器或移位近似；**无参数** |
| **全局平均池化** | ECA 第 276 行 | ⭐⭐⭐ 需要整张图累加完才能出结果，是流水线里的一处**全局同步点**，得设计好累加器 |
| **1D 卷积 + sigmoid** | ECA 第 269–282 行 | ⭐⭐ 计算量极小，sigmoid 用查找表(LUT) |
| **加权求和 / 残差加** | SAM 第 255–256 行、GhostModule 第 188 行 | ⭐ 加法器和少量乘法器 |

三个对部署最重要的结论：

1. **算力大头**集中在 6 个 Level（3 编 + 3 解）里的 GhostModule 和 SAM，而它们全部由
   **1×1 卷积 + 带空洞的 3×3 卷积 + 拼接 + 1×1 融合**这四种原语组成——你 FPGA 上
   只需要做好**两种卷积核的引擎**，整个模型就能跑。
2. **模型尺寸**：卷积权重只有 `EN_FEATURE_NUM: 48` 一档就全定了（配合 `inter=32`），
   参数量很小，BRAM 放得下；想再省资源可以把 48 改小（需要重新训练/蒸馏）。
3. **训练和推理的差异**：`forward` 返回的 `out_2, out_3, feature_map`（第 35 行）是
   **给训练时蒸馏/监督用的**，FPGA 上只需要 `out_1` 一条主输出，后面那些直接扔掉不管。
