## 2. 前置条件：动手之前手上得有什么

### 2.1 工具链 PetaLinux 2025.2

```bash
ls -d /opt/pkg/petalinux && source /opt/pkg/petalinux/settings.sh && \
  petalinux-build --help >/dev/null && echo "✅ PetaLinux 可用"
```

装在 `/opt/pkg/petalinux`（约 12 GB）。Vivado / Vitis 2025.2 在 `/home/zheyang/AMD/2025.2/`，本流程只在建工程时需要 `Vitis/settings64.sh`（取 `xsct`）。

**版本为什么必须是 2025.2**：赛事要求工具链 ≥ 2025.2。这也是 PYNQ 官方 `sdbuild`（只声明支持 2024.1）走不通的原因 —— 但我们**不需要**它，见[附录 C](说明_机理与实测.md#附录-c为什么这样配机制)。

> PetaLinux **不是虚拟机**，是一个自带工具链的大目录；`source settings.sh` 只是把它的工具排到 `PATH` 前面。它不在家目录写任何东西，所有产出都在构建根里。

### 2.2 补全过的 XSA（含 SD 卡、网口、QSPI、USB、GPIO）

```bash
ls -la /home/zheyang/SRP/qiansaiFPGA/xilinx_project/moro_v1/design_1_wrapper.xsa
```

**这个 XSA 必须已经补全过 PS7。** 原始版本只开了 DDR 和 UART1，用它能构建成功，但设备树里
`ethernet` / `mmc` / `usb` 全是 `disabled`、`qspi` 节点根本不存在 —— **镜像上了板也起不来**（U-Boot 拿不到 MMC）。

30 秒自检（不用装任何工具）：

```bash
cd /tmp && rm -rf xsa_check && mkdir xsa_check && cd xsa_check
unzip -o -q /home/zheyang/SRP/qiansaiFPGA/xilinx_project/moro_v1/design_1_wrapper.xsa
grep -oE 'PCW_EN_[A-Z0-9_]+" VALUE="1"' design_1.hwh | sort -u | tr '\n' ' '; echo
```

**期望看到**：`PCW_EN_DDR` `PCW_EN_CLK0_PORT` `PCW_EN_RST0_PORT` `PCW_EN_QSPI` `PCW_EN_SDIO0`
`PCW_EN_SDIO1` `PCW_EN_ENET0` `PCW_EN_USB0` `PCW_EN_GPIO` `PCW_EN_UART1`。

**只看到 DDR/CLK0/RST0（或许加 UART1）= XSA 没补全，别往下走。**

要重做 XSA 时（改 PS 配置、换外设）：

```bash
source /home/zheyang/AMD/2025.2/Vitis/settings64.sh
/home/zheyang/AMD/2025.2/Vivado/bin/vivado -mode batch \
  -source demoir-fpga/deploy/xsa/ax7015b_ps7_complete.tcl -nojournal -log /tmp/ps7.log
```

脚本会覆盖工程里的 XSA（先备份）。**它绕过的两个 Vivado 坑**（`write_hw_platform` 导出缓存 HWH、
GPIO 抢走 ENET0 复位）写在 [`deploy/xsa/README.md`](../../../deploy/xsa/README.md)。

### 2.3 AMD 的 Ubuntu 根文件系统

```bash
ls -la /home/zheyang/SRP/qiansaiFPGA/peta_prj/downloads/pynq/jammy.arm.3.1.0.tar.gz
# 期望：2,063,101,601 字节
```

**从哪来**（AMD 官方，匿名可下，支持断点续传）：

```bash
cd /home/zheyang/SRP/qiansaiFPGA/peta_prj/downloads/pynq
curl -4 -L -C - -o jammy.arm.3.1.0.tar.gz \
  https://download.amd.com/opendownload/pynq/jammy.arm.3.1.0.tar.gz
```

**校验**（AMD 没给官方校验和，这是我们自己存的一份）：

```bash
cd /home/zheyang/SRP/qiansaiFPGA/peta_prj/downloads/pynq
sha256sum -c SHA256SUMS && gzip -t jammy.arm.3.1.0.tar.gz && echo "✅ 包完整"
```

期望哈希：`c3e99a9e8922b6be22955b58b09955fcbf8c3ea8ef7edec46f400bef80e4d00e`

它是什么（为什么能用到这块板上）、里面装了什么，见附录 B。

### 2.4 离线构建缓存

```bash
du -sh /home/zheyang/SRP/qiansaiFPGA/peta_prj/offline_cache/harvest
# 期望：约 12 GB（sstate-cache + downloads）
```

**从哪来**：把一次联网构建产出的 `ax_peta/build/sstate-cache` 和 `ax_peta/build/downloads`
复制出来即可（本机在 `offline_cache/harvest/`）。建工程脚本会把它写进 PetaLinux 配置，
后续构建**完全不碰网络**。

**没有它行不行**：行。把[第 4 节](流程_构建镜像.md#4-改工程配置)里的两行离线配置留空即可，首次构建会联网从
`https://petalinux.xilinx.com/sswreleases/rel-v2025.2/` 拉源码与 sstate（约 40 分钟）。

### 2.5 本地工具

```bash
which fakeroot mke2fs depmod gzip tar sfdisk debugfs fsck.fat
```

`fakeroot` 与 `mke2fs` 来自 `fakeroot`、`e2fsprogs` 两个系统包；`sfdisk`/`debugfs`/`fsck.fat`
在 `util-linux`、`e2fsprogs`、`dosfstools` 里，通常已装。

### 2.6 不需要的东西

**不用**给宿主机装 `pynq` / `pyxrt` / `grpcio` 等 Python 包。它们是给**板子（ARM）**用的，
装在目标 rootfs 里；而 PetaLinux 构建用的是它自带的 Python 3.12，与系统 Python 完全隔离。
实测证据见[附录 C](说明_机理与实测.md#附录-c为什么这样配机制).4。

## 附录 B：AMD 那个 Ubuntu 包是什么

| 项 | 值 |
|---|---|
| 官方发布页 | <https://www.pynq.io/boards.html>（"Build a PYNQ image" 一节） |
| 托管 | `download.amd.com`（AMD 自己的服务器） |
| 大小 / SHA-256 | 2,063,101,601 B / `c3e99a9e8922b6be22955b58b09955fcbf8c3ea8ef7edec46f400bef80e4d00e` |
| 是什么 | gzip 压缩 tar，Ubuntu 22.04 完整根目录树，**不是 Docker 镜像，也不是某块板子的镜像** |
| 解压后 / 条目数 | 5.15 GB / 204,510 |
| 谁做的 | AMD（原 Xilinx），PYNQ 是 AMD 项目，代码在 <https://github.com/Xilinx/PYNQ>（BSD-3-Clause） |

**为什么能用到 AX7015B 上**：AMD 官网自己用的词是 **`board-agnostic`（板卡无关）** ——
DDR 大小、SD 控制器编号、网口 PHY 全在**设备树和 `BOOT.BIN`** 里，不在这个包里。所以"通用 rootfs +
本板自己的启动三件套"是可以拼起来的。

里面**已经预装**（所以我们不用自己编 XRT 用户态）：

| 组件 | 路径 |
|---|---|
| PYNQ 3.1.0 本体 | `/usr/local/share/pynq-venv/lib/python3.10/site-packages/pynq/` |
| `pyxrt` | `/usr/lib/python3.10/pyxrt.so` |
| XRT 运行库 **2.17.0** | `/usr/lib/libxrt_core.so.2.17.0`、`/usr/bin/xclbinutil` |
| Ubuntu 22.04 + Python 3.10 | — |

**版本对齐是它能用的关键**：`zocl.ko` 和包里的 XRT 都是 **2.17.0**（同出 XRT 2024.1 分支）。
这就是[第 6 节](流程_构建镜像.md#6-装-zocl-配方)把 XRT 钉在 2024.1 的价值 —— **`zocl.ko` 与 `pyxrt.so` 必须同一版本**。

包里**没有** `lib/modules/`（一个内核模块都没有），因为 `zocl.ko` 属于板级内容，
所以直接把我们编的那份放进去即可，不用清理。

> ⚠️ AMD 没有提供官方校验和（`.sha256` / `.md5` / `.asc` 全是 404）。传输走 HTTPS，风险不高，
> 但不如有签名那样可验证。
>
> **不要**用 `jammy.aarch64.*`（那是 64 位 ARM，ZynqMP/Versal 用）；也**不要**直接烧
> `pynq_z1/z2_v3.1.1.zip` 这类官方板卡整镜像 —— 见[附录 C](说明_机理与实测.md#附录-c为什么这样配机制).5。
