## 11. 板上验收

宿主机把验收脚本拷上去，以 root 运行：

```bash
scp /home/zheyang/SRP/qiansaiFPGA/demoir-fpga/deploy/pynq/M1_acceptance_check.sh \
    xilinx@192.168.7.2:/tmp/
# 板上：
sudo bash /tmp/M1_acceptance_check.sh
```

> **别用 `ssh root@`**：sshd 用默认的 `PermitRootLogin prohibit-password`，root 只能用密钥登录，
> 密码会被拒。用 `xilinx`（密码 `xilinx`）登进去再 `sudo`。
>
> `192.168.7.2` 由 10.5 分配；如果板子还没配 IP，也可以只用串口
> （`cat > /root/M1_acceptance_check.sh` 直接把脚本粘进去）。

> ⚠️ **最容易误判成"板子坏了"的坑：`sudo` 会重置 PATH，把 PYNQ 的环境弄丢**
> （2026-10-06 实测踩到，当时第 6/7/8 项一起报红，看起来像 pynq 装坏了）。
>
> | 丢的是什么 | 谁提供的 | 丢了之后的症状 |
> |---|---|---|
> | `python3` = `/usr/local/share/pynq-venv/bin/python3`（`pydantic` 等依赖都在这个虚拟环境里） | `/etc/profile.d/pynq_venv.sh` 里那句 `source /usr/local/share/pynq-venv/bin/activate` | `python3` 落到系统 `/usr/bin/python3` → 第 7 项报 `ModuleNotFoundError: No module named 'pydantic'` |
> | `XILINX_XRT=/usr` | `/etc/profile.d/xrt_setup.sh` | 第 7/8 项必红：PYNQ 靠这个变量决定要不要去找 XRT 设备（第 8 项里那句 `No devices found, is the XRT environment sourced?`） |
>
> 这两样都**只在登录 shell 生效**，而 `sudo` 默认 `env_reset`。
> **验收脚本已自带环境自愈**（自己从上述两个路径把它们找回来），所以照上面命令跑就行。
> 但你手工敲 `python3 -c "import pynq"` 时若报 `No module named 'pydantic'`，
> 先想到这一条：改用 `sudo -i`，或先 `source /usr/local/share/pynq-venv/bin/activate`。
>
> 另外注意 `import pynq` 在本镜像上命中的是**工作目录里的源码** `/home/xilinx/pynq/`，
> 不是虚拟环境 `site-packages` 里那份 —— 所以在不同目录下跑，结果可能不一样。

脚本逐条检查 10 项，每项失败都给诊断提示：① 从 SD 启动 ② 网口有 IP ③ `pynq_board` 节点
④ FPGA manager ⑤ zocl + `/dev/dri` ⑥ `import pyxrt` ⑦ `from pynq import Overlay`
⑧ `pynq.allocate` 连续内存 ⑨ `xclbinutil` ⑩ 加载 `.bit`/`.hwh`。

**M−1 通过 = 10 项全绿。** 未通过的排查顺序建议：③ → ⑤ → ⑥ → ⑧。

**实测（2026-10-06，rootfs 修好、分区表修好、扩容完成之后）：12 通过 / 2 警告 / 1 失败。**
两个警告是 ② 的"没有默认路由"（直连没有网关，正常）和 ⑩（板上还没有 `.bit`）；
唯一的失败是 ⑧，**预期之内**，理由见下表。

**首轮有三项本来就该是红的，别当成失败**（2026-10-06 首次上板实测的结论）：

| 项 | 首轮表现 | 为什么 |
|---|---|---|
| ② 的"手工 DHCP" | 拿不到地址 | 直连没有 DHCP 服务器。脚本会 hint 一句"路由器没开 DHCP"——**忽略它**。只要 10.5 已配静态地址，② 的"有 IPv4 地址"就是绿的；网口硬件好不好看 `carrier` |
| ⑧ `pynq.allocate` | `RuntimeError: Overlay is not downloaded` | **PYNQ 的 `allocate()` 必须先下载一个 overlay**：它要从已加载的 xclbin 里读内存 bank 信息（`pl_server/embedded_device.py` 里那句 `raise RuntimeError("Overlay is not downloaded")`）。所以第 8 项**不可能**在没有 bitstream 的首轮变绿 —— 它要等 M2 的第一个 overlay。[附录 E](说明_机理与实测.md#附录-e上板实测结论与遗留问题) #5 里"M−1 用最小测试 overlay"说的就是这个 |
| ⑩ Overlay | WARN 跳过 | 同上：PL 里还没有逻辑，手上没有真实 `.bit`/`.hwh` |

**所以 M−1 的判定是：③ / ⑤ / ⑥ / ⑦ 绿、⑧ 与 ⑩ 先记为"待第一个 overlay"**，
等 M2 的第一个 `.bit`/`.hwh` 落地后**补跑一次**，那两项转绿即 M−1 收口。
