## 12. 故障排查

| 症状 | 可能原因 | 怎么处理 |
|---|---|---|
| 板子完全没反应，串口无输出 | ① 插错 MINI USB 口 ② 波特率不对 ③ SW1 没拨成 SD ④ brltty 抢了串口 ⑤ `BOOT.BIN` 的 DDR 参数不对 | 先排 ①–④（见 10.2 #2、10.3 ②、10.4）；都排除了再查 XSA 是否含正确的 DDR 配置（第 2.2 节） |
| `Kernel panic ... Unable to mount root fs` | **BOOT.BIN 里的 bootargs 还是 `ram0`** | 第 7.2 节的 `petalinux-package boot --u-boot --force` 漏了。用 `strings BOOT.BIN \| grep "root=/dev"` 确认 |
| 起不来，卡在 `Waiting for root device` | 根分区设备名不对（设备树里是 `root=/dev/mmcblk0p2`，但这张卡被枚举成了 `mmcblk1`） | **不用重编**：在启动分区（FAT32）放一个 `uEnv.txt`，写 `bootargs=console=ttyPS0,115200 earlycon root=/dev/mmcblk1p2 rw rootwait rootfstype=ext4 clk_ignore_unused` —— `boot.scr` 会先 import 它，设备树里的 bootargs 就不再生效。要固化再改[第 4 节](流程_构建镜像.md#4-改工程配置) `SDROOT_DEV` 后重编 |
| **第一次能开机、第二次开机 `Kernel panic … Unable to mount root fs`**（`No filesystem could mount root, tried: ext4`） | ⚠️ **PYNQ 原版 `resizefs.sh` 会把分区表平移约 1 MiB**：它用 `fdisk` 删掉分区 2 再重建、第一扇区取"默认值"，而 fdisk 把默认起点**向上对齐到 1 MiB**；本镜像 p2 起点是扇区 1048584（512 MiB + 8 扇区，不对齐）→ 新表把 p2 挪到 ~1050624，ext4 数据没跟着动。首次开机内核仍用内存里的旧表，所以"看起来正常"，**重启才炸**（2026-10-06 实测踩到） | **数据没坏，只是表错了**。修法（把卡插到电脑上，`/dev/sdX` 是那张卡）：`sudo sh -c 'echo "1048584, +" \| sfdisk -N 2 --force /dev/sdX'` —— 起点写回 1048584、大小撑到末尾（电脑若自动挂载了卡上的分区，先 `umount` 掉更稳）。插回板子开机后可以 `sudo resize2fs /dev/mmcblk0p2` 把文件系统也撑满，白拿回二十来 GB。想彻底避免：用 `deploy/pynq/files/resizefs.sh`（修正版，显式读回原起点再改大小，`build_pynq_rootfs.sh` 会自动装进去）重做镜像 |
| **根分区只有 8 GiB**（卡是 32 GB，`df -h /` 却是 8G），板上日志里有 `resize2fs: Filesystem has unsupported feature(s)` | 制卡用的 `mke2fs` 是 PetaLinux 2025.2 自带的 **e2fsprogs 1.47.0**（默认打开 `orphan_file` 特性），板上 Ubuntu 22.04 只有 **1.46.5**，不认识该特性，`resize2fs` 在特性检查那步就拒绝（证据在卡片 `/var/log/syslog`：`resize2fs 1.46.5` + `has unsupported feature(s)`） | **不用装任何东西** —— 那套 1.47.0 工具就在构建产物里。设 `E=<构建根>/ax_peta/build/tmp/sysroots-components/x86_64/e2fsprogs-native/sbin`，把卡插到电脑上（`/dev/sdX`，先 `umount`，并确认 p2 起点是 1048584）：`sudo $E/e2fsck -fn /dev/sdX2` 看一遍 → `sudo $E/e2fsck -fy /dev/sdX2` → `sudo $E/resize2fs /dev/sdX2` → `sudo $E/dumpe2fs -h /dev/sdX2 \| grep -E 'Block count\|Block size'`（Block count 应变成约 **7502335**，即 28.6 GiB）。根治见[附录 E](说明_机理与实测.md#附录-e上板实测结论与遗留问题).2 第 6 条 |
| 启动后根文件系统只读 | `rw` 没进 bootargs | 看[第 4 节](流程_构建镜像.md#4-改工程配置) `BOOTARGS_GENERATED` 末尾有没有 `rw` |
| `image.ub` 还是 20 MB | [第 4 节](流程_构建镜像.md#4-改工程配置) ext4 配置没生效 | 确认 `ROOTFS_INITRD` 已关、`ROOTFS_EXT4=y`，再 `--silentconfig` + build |
| `modprobe: FATAL: Module zocl not found` | `zocl.ko` 没进 rootfs，或 `modules.dep` 不对 | 跑第 8.3 节验证 |
| `insmod zocl` 报 `invalid module format` | vermagic 不匹配 | `zocl.ko` 必须对着**当前内核**编；对比 `modinfo zocl.ko` 和 `uname -r` |
| zocl 加载了但没有 `/dev/dri/` | 设备树节点没匹配上 | `dmesg \| grep -i zocl`；确认 dtb 里是 `xlnx,zocl`（[第 5 节](流程_构建镜像.md#5-补设备树)） |
| `import pyxrt` 报 `NameError` | 缺 `chosen/pynq_board` | [第 5 节](流程_构建镜像.md#5-补设备树)节点没进 dtb。**这是最容易误诊的一个**，见[附录 C](说明_机理与实测.md#附录-c为什么这样配机制).3 |
| `import pynq` 找不到模块 | 用了系统 Python | PYNQ 装在 venv 里：`source /etc/profile.d/pynq_venv.sh`，或用 `/usr/local/share/pynq-venv/bin/python3` |
| 网口不通（`carrier` = 0） | ① 网线插在 PL 端那个 RJ45 ② `phy-mode` 不对 | 先换 PS 端那个口（10.2 #1）；仍是 0 再把 `phy-mode` 从 `rgmii-id` 改成 `rgmii` 试（JL2121 的 TXDLY/RXDLY 上电都是延时） |
| 开机后 `ip a` 里 `eth0` 没有地址 | 镜像的 `/etc/network/interfaces.d/` 是空的（**预期行为，不是故障**） | 10.5 手工配；要一劳永逸见 10.7 |
| `ssh root@<板子IP>` 密码被拒 | sshd 用默认的 `PermitRootLogin prohibit-password`，root 只能密钥登录 | 改用 `ssh xilinx@192.168.7.2`（密码 `xilinx`）再 `sudo` |
| 分区太小写不下 | `--size` 根分区不够 | 根文件系统解压 5.15 GB，给 8 GB 以上 |
| `petalinux-package wic` 返回非零、提示 `bitbake wic-tools failed`，但日志里 `Tasks Summary: ... all succeeded` | 离线 sstate 缓存里缺某个 native recipe 的 `recipe_qa` 对象（实测是 `parted-native`），setscene 取不到就记一条 ERROR，而**真实任务随后成功** | **直接重跑一次**即可（缺的对象已写进本地 sstate）。`deploy/pynq/make_sdimage.sh` 已内置自动重试一次。判断成败看 `Tasks Summary ... all succeeded` 和有没有 `task .*: Failed`，**不要只看返回码** |
| 全量构建返回 255，有多条 `*_setscene: Fetcher failure ... .siginfo` | 同上，公开镜像/离线缓存缺 siginfo 的噪音，任务其实都成功了 | 同上：看 `Tasks Summary`，不看返回码。配好第 2.4 节离线缓存后噪音减少 |
| 建工程脚本报 `ax_peta 已存在` | 上次没删干净 | 见第 13 节回退 |

## 13. 回退与清理

### 13.1 从零重来（保留离线缓存与 AMD 包）

```bash
rm -rf /home/zheyang/SRP/qiansaiFPGA/peta_prj/ax_peta
cd /home/zheyang/SRP/qiansaiFPGA/demoir-fpga
bash deploy/peta/create_peta_project.sh
bash deploy/peta/build_peta.sh
```

### 13.2 只回退设备树

把 `project-spec/meta-user/.../system-user.dtsi` 换回 `deploy/peta/files/system-user.dtsi`
或删掉追加的节点，重跑 `petalinux-build -c device-tree` + `petalinux-build` + 重打 BOOT.BIN。

### 13.3 只回退 PYNQ 相关（回到纯 PetaLinux 镜像）

```bash
rm -rf /home/zheyang/SRP/qiansaiFPGA/peta_prj/ax_peta/project-spec/meta-user/recipes-xrt
# 并把 petalinuxbsp.conf 里 PREFERRED_VERSION_zocl 注释掉
```

### 13.4 按"删了有多大影响"回收空间

| 顺序 | 路径 | 大小 | 删掉的后果 |
|---|---|---|---|
| 1 | `peta_prj/pynq_rootfs/tree/` | 5.15 GB | **无影响**，纯解压中间态，重跑脚本能重建 |
| 2 | `peta_prj/ax_peta/build/` | 大部分 | 要重新构建（有缓存约 5–15 分钟） |
| 3 | `peta_prj/pynq_out/` | 8.5 GB | 要重出镜像（3 分钟） |
| 4 | `peta_prj/pynq_rootfs/` | 2.06 GB | 要重跑脚本（6 分钟） |
| 5 | `peta_prj/ax_peta/` | 14 GB | **工程没了**，从[第 3 节](流程_构建镜像.md#3-建-petalinux-工程并导入-xsa)重建 |

| 8 | `/opt/pkg/petalinux/` | 12 GB | **工具链没了**，要重装 PetaLinux 2025.2 |

**想快速回收空间又不想重做任何事：只删第 1 项。**
