## 10. 写卡与首次启动

> 本节按**没有路由器、用 USB 转网口和电脑直连**的实际条件写。
> 有路由器的差别只有一处：网线插路由器 LAN 口，10.5 的静态 IP 可以换成 DHCP。
> 但无论有没有路由器，**开机都不会自动拿到地址** —— 原因见 10.5，是镜像本身没配网络。

### 10.1 写卡（唯一需要 sudo 的一步）

```bash
# ① 找到 SD 卡设备名（千万别写错，会清掉你的硬盘）
lsblk -d -o NAME,SIZE,MODEL | grep -iE "sd|mmc"

# ② 写（把 /dev/sdX 换成你的卡）
sudo dd if=/home/zheyang/SRP/qiansaiFPGA/peta_prj/pynq_out/petalinux-sdimage.wic \
        of=/dev/sdX bs=4M status=progress conv=fsync
sync
```

### 10.2 连线：四根线 + 一个拨码

```text
      12V 电源 ──▶ 底板 DC 座
底板 USB Uart ──▶ 电脑 USB        （MINI USB，串口 console）
       SD 卡  ──▶ 底板 MicroSD 卡座
底板 PS 端 RJ45 ──▶ USB 转网口 ──▶ 电脑 USB
核心板 SW1：两位都拨到 OFF（SD 启动）
```

| # | 线 / 开关 | 从 | 到 | 注意 |
|---|---|---|---|---|
| 1 | 网线 | **底板 PS 端 RJ45（丝印 `ETH1`）** | USB 转网口 | 底板有**两个 RJ45**：`ETH1` = 接 PS（板子的"大脑"，就是 `eth0`），`ETH2` = 接 PL（FPGA 那侧，现在 FPGA 是空的，用不上）。**2026-10-06 实测确认 `ETH1` 就是 PS**。⚠️ **别用"宿主机显示有链路"来判断插对没插对** —— `ETH2` 那侧的网口芯片自己也有电、也会跟你电脑握手，所以电脑上看着"通"不等于插对了；**唯一判据是板子里 `eth0` 的 `carrier`**（10.5） |
| 2 | MINI USB | **底板** USB Uart | 电脑 USB | 板子上是 CP2102，走 PS UART1（MIO12/13）＝ 板上的 `/dev/ttyPS0`。核心板上**另有**一路 MINI USB 是 UART0，别插它 |
| 3 | 12V 电源 | 底板 DC 座 | 原装 12V 电源 | ⚠️ **不要同时用核心板 MiniUSB 供电**，手册写明会损坏 |
| 4 | SD 卡 | — | 底板 MicroSD 卡座 | 10.1 写好的那张 |
| 5 | 拨码 SW1 | **核心板** SW1 | 两位都 **OFF** | OFF/OFF = SD 卡启动；ON/ON = JTAG；OFF/ON = QSPI。最容易漏的一步 |

USB 转网口哪种都行（RTL8153 / AX88772 / CH397…），直连用**普通网线**即可：两端 PHY 都支持
Auto-MDIX，不需要交叉线。

### 10.3 上电前：宿主机准备

```bash
# ① 串口权限。用户不在 dialout 组时，串口工具会 Permission denied
sudo usermod -aG dialout $USER        # 之后必须注销重登（或新开登录会话）才生效

# ② brltty 会抢 CP2102（Ubuntu 22.04 已知坑），先停掉
sudo systemctl stop brltty-udev.service
sudo systemctl mask brltty-udev.service

# ③ 认出 USB 网口的接口名（新出现的那个）
ip -br link
dmesg | tail -5                       # 确认驱动认到：r8152 / ax88179 / asix

# ④ 给 USB 网口配静态 IP：宿主机 192.168.7.1，板子一会儿配 192.168.7.2
#    用 192.168.7.0/24 是因为本机 WiFi 在 10.197.x、docker0 在 172.17.x，不冲突
#    NetworkManager 通常已经为这块网卡自动建了一条连接，直接改它，不要再 add 一条
nmcli -f NAME,DEVICE,TYPE con show    # 看那条连接叫什么，通常是 "Wired connection 1"

nmcli con mod "Wired connection 1" ipv4.addresses 192.168.7.1/24
nmcli con mod "Wired connection 1" ipv4.method manual ipv6.method disabled
nmcli con up  "Wired connection 1"

# 验证
ip -br addr show enxec1ac300ce01       # 应看到 192.168.7.1/24
ip route                               # WiFi 的 default 路由必须还在
```

> ⚠️ **本文命令里的 `<IF>`、`<板子IP>` 都是占位符，必须替换成真实值再敲。**
> 把带尖括号的整行直接粘进 bash 会报 `IF: No such file or directory`
> —— bash 把 `<IF` 当成了"从文件 IF 读输入"。
>
> 网口名（`enxec1ac300ce01` 这种）由 NetworkManager 按网卡 MAC 生成，插哪个 USB 口都不变；
> 用 `ip -br link` 或 `ls /sys/class/net` 看一眼即可。
>
> **先设 `ipv4.addresses` 再改 `ipv4.method manual`**：反了 NM 会报
> `ipv4.addresses: this property is mandatory with method manual`。
>
> 两块网卡的地址互不影响：这条只加在 USB 网口上，WiFi 那条连接一个字没改；
> 而且**不设网关**，所以不会抢默认路由。改完 `carrier` 还是 0 时地址可能暂时挂不上，
> 正常（板子还没上电）——上电后 carrier 变 1 就生效；万一没生效，板上电后
> 再 `nmcli con up "Wired connection 1"` 一次。
>
> 不想动 NetworkManager 也可以：`sudo nmcli dev set <IF> managed no`，然后
> `sudo ip addr add 192.168.7.1/24 dev <IF>` + `sudo ip link set <IF> up`。
>
> 宿主机 ufw 处于 active 也不影响这个方向（宿主机 ssh 板子是出站，ICMP 默认放行）。

### 10.4 上电，先用串口看

```bash
# 串口工具二选一：screen 一般自带；picocom 更好用（退出 Ctrl-A Ctrl-X）
sudo apt install -y picocom

# 用 by-id 路径，别用 /dev/ttyUSB0 —— 编号会随插拔/设备增减变化
ls /dev/serial/by-id/                 # 确认哪个是你的板子那根
picocom -b 115200 /dev/serial/by-id/usb-Silicon_Labs_CP2102N_USB_to_UART_Bridge_Controller_*-if00-port0
```

`/dev/serial/by-id/` 下面那条长名字由芯片型号 + 序列号生成，**跟着设备走**，
换 USB 口、插拓展坞都不会变；`/dev/ttyUSB0` 则会变号。

> **串口打不开先看两件事**：① 用户不在 `dialout` 组 —— `id -nG | tr ' ' '\n' | grep dialout`
> 没有就 `sudo usermod -aG dialout $USER` 后**重登**，或当场用 `newgrp dialout` 开一个新 shell；
> ② `brltty` 抢口（Ubuntu 22.04 已知坑）—— `systemctl is-active brltty-udev`，
> 是 active 就 `sudo systemctl stop brltty-udev.service && sudo systemctl mask brltty-udev.service`。

然后接 12V 上电。要过三关：

| 关 | 期望输出 | 没有的话 |
|---|---|---|
| U-Boot | 有打印 | `BOOT.BIN` 或拨码不对（10.2 #5） |
| 内核 | `Starting kernel ...` | 看[第 12 节](说明_故障排查.md#12-故障排查) |
| 登录 | `AX7015B login:` | 串口没接对（10.2 #2） |

登录账号：**`root` / `xilinx`**，或 **`xilinx` / `xilinx`**（两个都能用；`xilinx` 在 `sudo` 组里）。

### 10.5 给板子配 IP（无路由器场景的关键一步）

**先说清楚为什么必须手工配**：镜像里的 `/etc/network/interfaces` 只 `source` 了
`/etc/network/interfaces.d/*`，而**那个目录是空的**，`networking.service` 因此不会碰 `eth0`，
开机后 `ip a` 看不到地址。这**不是故障**，跟有没有路由器无关 —— 没有路由器只是让
"插上路由器自动拿地址"这条退路也不存在了。

在串口里以 root 执行：

```bash
ip link set eth0 up
sleep 3
cat /sys/class/net/eth0/carrier          # ★ 1 = 链路通了；0 = 没通 → 先做下面的 10.5.1
ip addr add 192.168.7.2/24 dev eth0
ip -br addr show eth0                    # 应看到 192.168.7.2/24
```

`carrier` 这一行同时回答[附录 E](说明_机理与实测.md#附录-e上板实测结论与遗留问题) 的 #2 和 #3（PHY 复位 MIO7 的实际电平、`phy-mode` 该用
`rgmii-id` 还是 `rgmii`）。板上带 `ethtool`，也可以 `ethtool eth0 | grep -E "Link|Speed|Duplex"`。

#### 10.5.1 如果 `carrier` 是 0：先把速度降到 100M（**2026-10-06 实测必做**）

这是我们这块板上真实遇到、而且**已经解决**的问题：**千兆（1000M）握不上手**。
现象是"两边都说没插线"——板子 `carrier=0`，宿主机那边也是 `carrier=0`。

一行命令解决（把网口重新打开，并只广告 10M/100M 两种速度）：

```bash
# 板上（root）
ip link set eth0 down; sleep 1; ip link set eth0 up; sleep 3
ethtool -s eth0 autoneg on advertise 0x00f      # 0x00f = 只支持 10M/100M
sleep 8
cat /sys/class/net/eth0/carrier                 # 期望变成 1
```

实测结果：这条命令一跑，**两边同时 `carrier=1`，速率 100Mb/s Full，ping 通**。

**为什么这样就好了（白话）**：网线的两端在正式传数据前要先"商量"用多快（这叫自动协商）。
商量 1000M 时，两端还要额外决定谁当"主"、谁当"从"，而且对网线的质量要求更苛刻；
这一步在我们这根线 + 这颗芯片的组合上谈不成，于是两边都"谈崩了"、显示没插线。
把上限压到 100M 就没有"主从"这回事，立刻就谈成了。

> **副作用**：链路只能跑 100M（约 11 MB/s）。传日志、跑 Jupyter、传几 MB 的权重都够用；
> 等真要传大文件再回来查千兆那一环（见[附录 E](说明_机理与实测.md#附录-e上板实测结论与遗留问题) #3）。
>
> **注意**：这个设置**重启后会丢**，每次开机都要重来一次。想省事就在
> `/etc/network/interfaces.d/eth0` 里加一行 `post-up`（见 10.7 的写法），
> 开机自动执行。

**如果降到 100M 还是 0**，那时才怀疑插错口（见 10.2 #1 与下面的说明）。

### 10.6 开机后立刻确认这几件事

| # | 命令 | 期望 | 不对的话看 |
|---|---|---|---|
| 1 | `ls /dev/mmcblk*` | `mmcblk0`（SD 卡座）+ `mmcblk1`（eMMC） | 与[第 4 节](流程_构建镜像.md#4-改工程配置) `SDROOT_DEV` 对比；卡在 `Waiting for root device` 见[第 12 节](说明_故障排查.md#12-故障排查) |
| 2 | `findmnt /` | 根是 `ext4`、`rw` | [第 4 节](流程_构建镜像.md#4-改工程配置)的 `rw` 没生效 |
| 3 | `cat /proc/device-tree/chosen/pynq_board` | `AX7015B` | 设备树没编进去（[第 5 节](流程_构建镜像.md#5-补设备树)） |
| 4 | `cat /sys/class/net/eth0/carrier` | `1` | 10.5 |
| 5 | `modprobe zocl && lsmod \| grep zocl` | 有输出 | [第 12 节](说明_故障排查.md#12-故障排查) |
| 6 | `ls /dev/dri/` | 有 `renderD*` | zocl 没绑上设备 |

六项都过 → 去[第 11 节](说明_板上验收.md#11-板上验收)跑验收。

### 10.7 可选：让板子记住 IP / 让板子能上网

**记住 IP**（顺手把镜像缺的那块配置补上，以后开机自动有地址）：

```bash
# 板上
sudo tee /etc/network/interfaces.d/eth0 >/dev/null <<'EOF'
auto eth0
iface eth0 inet static
    address 192.168.7.2
    netmask 255.255.255.0
EOF
sudo ifup eth0        # 或重启
```

`/etc/network/interfaces.d/` 就是 10.5 说的那个空目录；放进去一个文件，
`networking.service` 开机就会执行它。

**让板子能 apt / pip**（借宿主机 WiFi 出去）：

```bash
# 宿主机：共享模式 = NetworkManager 自己起 DHCP + NAT，板子因此能借 WiFi 出去
nmcli con mod "Wired connection 1" ipv4.method shared
nmcli con up  "Wired connection 1"
# 板上：这回真有一个 DHCP 服务器了
dhclient -v eth0
```

改回直连（静态）就是把 10.3 ④ 那三条再跑一遍。
