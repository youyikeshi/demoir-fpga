# 流程：从 PetaLinux 构建到 PYNQ 镜像（AX7015B 全链路）

> **适用板卡**：ALINX AX7015B（XC7Z015，Zynq-7000，ARM32）
> **产出**：`petalinux-sdimage.wic`，`dd` 到 SD 卡即可启动 PYNQ
> **适用环境**：Ubuntu 22.04 · Vivado / Vitis / PetaLinux **2025.2**（赛事硬性要求 ≥ 2025.2）
> **本文覆盖**：从「手上有一个补全过的 XSA」到「写卡后可上板验收」的完整链路，全部手动命令 + 逐步验证。
> **不覆盖**：模型量化、HLS 加速器、PS–PL 推理调度（那是 M0–M5，见 [`对接文档_去摩尔纹PS-PL部署.md`](对接文档_去摩尔纹PS-PL部署.md)）。
>
> **不知道从哪开始？** 先读 [`README.md`](README.md)（部署线入口，按处境指路）。

### 1.3 时间与空间预算（本机实测，2026-09-30）

| 阶段 | 本机实测 | 无离线缓存（联网首次） | 新增占用 |
|---|---|---|---|
| 建工程 + 导入 XSA | 24 秒 | 同 | 约 200 MB |
| `petalinux-build`（全新工程首次） | **8 分 01 秒** | 约 40 分钟 | 约 14 GB |
| `petalinux-build`（再次运行，缓存全命中） | 55 秒 | — | — |
| `petalinux-build -c zocl` | 35–57 秒 | 约 5 分钟 | 小 |
| 组装 PYNQ 根文件系统 | 约 4 分钟 | 同 | 2 GB（+5.15 GB 中间态） |
| 出 SD 镜像 | 约 2 分钟（可能需重试一次，见第 12 节） | 同 | 8.5 GB |
| **合计（全新工程 → 可写卡镜像）** | **约 15 分钟** | **约 1 小时** | **约 32 GB** |

> 建工程和 `petalinux-build` 会从 `offline_cache/` 取源码与 sstate。**没有离线缓存也能做**，
> 只是首次要联网从 AMD 公开镜像拉约 7 GB（约 40 分钟）。
>
> 「全新工程首次」之所以要 8 分钟（而不是几十秒）：sstate 签名里含若干**绝对路径**
> （`plnxtool.conf` 的 `SYSCONFIG_DIR`、`EXTRA_FILESLIST` 等），工程换目录后
> 内核与 u-boot 需要真编一次；编完就进本地 sstate，再跑只要 55 秒。

### 3.2 导入后必须自检

```bash
cd /home/zheyang/SRP/qiansaiFPGA/peta_prj/ax_peta
grep -E "CONFIG_SUBSYSTEM_(ETHERNET|FLASH|PRIMARY_SD|MEMORY_PS7_DDR_0_SIZE)" project-spec/configs/config
```

| 看到什么 | 含义 |
|---|---|
| `..._MANUAL_SELECT=y` | ⚠️ 硬件里**没找到**该外设 → 回第 2.2 节补 PS，重导 XSA |
| `CONFIG_SUBSYSTEM_ETHERNET_PS7_ETHERNET_0_SELECT=y` + `..._USE_DHCP=y` | ✅ 认出了 PS 网口且会走 DHCP |
| `CONFIG_SUBSYSTEM_PRIMARY_SD_PS7_SD_0_SELECT=y` | ✅ 认出了 SD 卡座 |

## 4. 改工程配置

工程默认用 **initramfs**：整个根文件系统塞进 `image.ub`，开机解压到内存，只需要一个分区。
但 PYNQ 的 Ubuntu 根文件系统解压后有 **5.15 GB**，塞不进去。所以要改成 **ext4 独立分区**模式。

```text
改之前（一个分区）              改之后（两个分区）
──────────────────              ──────────────────────────────
FAT32                           分区 1 · FAT32 · 512 MB
  BOOT.BIN                        BOOT.BIN
  image.ub                        image.ub
    （里面含根文件系统）           boot.scr
  boot.scr                        system.dtb

                                分区 2 · ext4 · 8 GB
                                  Ubuntu + pynq + zocl.ko
```

编辑 `/home/zheyang/SRP/qiansaiFPGA/peta_prj/ax_peta/project-spec/configs/config`：

```diff
-# CONFIG_SUBSYSTEM_ROOTFS_EXT4 is not set
-# CONFIG_SUBSYSTEM_ROOTFS_INITRD=y
+# CONFIG_SUBSYSTEM_ROOTFS_INITRD is not set
+CONFIG_SUBSYSTEM_ROOTFS_EXT4=y
+CONFIG_SUBSYSTEM_SDROOT_DEV="/dev/mmcblk0p2"

-# CONFIG_SUBSYSTEM_FPGA_MANAGER is not set
+CONFIG_SUBSYSTEM_FPGA_MANAGER=y

-CONFIG_SUBSYSTEM_EXTRA_BOOTARGS=""
+CONFIG_SUBSYSTEM_EXTRA_BOOTARGS="rootfstype=ext4 devtmpfs.mount=1 clk_ignore_unused uio_pdrv_genirq.of_id=generic-uio rw"

-CONFIG_PRE_MIRROR_URL="https://petalinux.xilinx.com/sswreleases/rel-v${PETALINUX_VER}/downloads"
-CONFIG_YOCTO_LOCAL_SSTATE_FEEDS_URL=""
+CONFIG_PRE_MIRROR_URL="file:///home/zheyang/SRP/qiansaiFPGA/peta_prj/offline_cache/harvest/downloads"
+CONFIG_YOCTO_LOCAL_SSTATE_FEEDS_URL="/home/zheyang/SRP/qiansaiFPGA/peta_prj/offline_cache/harvest/sstate-cache"
```

每一项的作用：

| 配置项 | 作用 |
|---|---|
| `ROOTFS_EXT4=y` + 关掉 `INITRD` | 让 `image.ub` 只装内核，根文件系统独立成分区 |
| `SDROOT_DEV` | 告诉内核去哪找根文件系统（名字与第 7 节 bootargs 的 `root=` 对应） |
| `FPGA_MANAGER=y` | PYNQ 靠它加载 `.bit` 文件 |
| `EXTRA_BOOTARGS` | `clk_ignore_unused` 防止内核关掉 PL 时钟；`rw` 覆盖自动生成的 `ro`（Jupyter 要写盘） |
| `PRE_MIRROR_URL` / `YOCTO_LOCAL_SSTATE_FEEDS_URL` | 离线构建的源码镜像与 sstate 镜像 |

> ⚠️ **后两项是 Kconfig 字符串值，必须带双引号。** 少了引号 `--silentconfig` 会**静默忽略**，
> `build/conf/plnxtool.conf` 里 `SOURCE_MIRROR_URL` 变成空串，构建就悄悄去联网了。

### 让配置生效

```bash
cd /home/zheyang/SRP/qiansaiFPGA/peta_prj/ax_peta
unset http_proxy https_proxy all_proxy
source /opt/pkg/petalinux/settings.sh
petalinux-config --silentconfig        # ⚠️ 不要加 --get-hw-description
```

> **为什么不能加 `--get-hw-description`**：它会重新导入硬件、**重置外设选择**，把第 3 节刚
> 认对的网口/SD 配置打回 `MANUAL_SELECT`。硬件没换就不要重导。

### 验证

```bash
grep "BOOTARGS_GENERATED" project-spec/configs/config
grep -E "SOURCE_MIRROR_URL|offline_cache" build/conf/plnxtool.conf
```

期望（注意末尾的 `rw`，以及镜像指向构建根内的 `offline_cache`）：

```

SOURCE_MIRROR_URL = "file:///home/zheyang/SRP/qiansaiFPGA/peta_prj/offline_cache/harvest/downloads"
```

## 5. 补设备树

PetaLinux 从 XSA 生成的设备树**缺三样板级/PYNQ 需要的东西**，要手工加到
`project-spec/meta-user/recipes-bsp/device-tree/files/system-user.dtsi` 末尾。

### 5.1 要加什么

```dts
/* ① PS 网口 PHY 绑定（JL2121，MDIO 地址 1） */
&gem0 {
	phy-handle = <&ethernet_phy>;
	ethernet_phy: ethernet-phy@1 { reg = <1>; };
};

/* ② PYNQ 的板卡标识（缺了它 PYNQ 直接瘫痪，见附录 C.3） */
/ {
	chosen { pynq_board = "AX7015B"; };
};

/* ③ zocl 驱动节点 */
&amba {
	zyxclmm_drm {
		compatible = "xlnx,zocl";
		status = "okay";
	};
};
```

**权威文件**：[`deploy/peta/files/system-user.dtsi`](../../deploy/peta/files/system-user.dtsi)
—— 它是完整版，每一段都带"为什么"的注释；建工程脚本会把它原样拷进工程。**改设备树请改这个文件**，
不要只改工程里的副本，下次重建会丢。

### 5.2 三个容易写错的地方

1. **用 `&amba` 标签，不要写绝对路径。** 6.12 内核里这个总线容器的**节点名**从 `amba` 改成了 `axi`，
   但**标签 `amba` 保留**，用标签可以回避这个差异。
2. **不要写 `interrupt-parent` / `interrupts`。** 我们走 **poll 模式**（PL 里没有 `axi_intc`）。
   写了 `interrupts` 反而会加载失败。对照组见 `deploy/pynq/参考/`（PYNQ 官方的 poll 版与 intc 版）。
3. **`chosen` 里只加 `pynq_board`，不要加 `bootargs`。** `bootargs` 已由第 4 节的
   `EXTRA_BOOTARGS` 生成，这里再写会造成属性重复。

## 6. 装 zocl 配方

PYNQ 在 Zynq-7000 上，`pynq.allocate()` 走的是 **XRT**，需要一个内核模块 `zocl.ko`
提供 `/dev/dri/renderD*` 和缓冲区管理。

**为什么不能直接用 PetaLinux 自带的 zocl**：2025.2 自带的 `meta-xilinx` 里，每一个版本的
`zocl`/`xrt` recipe 都写着 `COMPATIBLE_MACHINE:zynqmp/versal/versal-net`，**不含 `zynq`** ——
我们的 `MACHINE = zynq-generic`，会被直接跳过。

**我们的做法**：照搬 PYNQ 自带的、没有任何机器限制的 `zocl_git.bb`，钉在 XRT `2024.1` 分支
（`SRCREV=a75e9843c875bac0f52d34a1763e39e16fb3c9a7`），并打两个内核 6.12 适配补丁。

```bash
# 手动做法
P=/home/zheyang/SRP/qiansaiFPGA/peta_prj/ax_peta/project-spec/meta-user/recipes-xrt/zocl
mkdir -p $P/files
cp /home/zheyang/SRP/qiansaiFPGA/demoir-fpga/deploy/pynq/zocl-kernel-6.12/zocl_git.bb $P/
cp /home/zheyang/SRP/qiansaiFPGA/demoir-fpga/deploy/pynq/zocl-kernel-6.12/files/*.patch $P/files/

# 配方与补丁的完整机理见：
#   demoir-fpga/deploy/pynq/zocl-kernel-6.12/README.md
```

然后在 `project-spec/meta-user/conf/petalinuxbsp.conf` 末尾加两行（**锁定版本**，否则 bitbake
会按最高 PV 选中 meta-xilinx 那份不兼容 zynq 的配方）：

```
PREFERRED_VERSION_zocl = "202410.2.17.0"
IMAGE_BOOT_FILES:zynq = "BOOT.BIN image.ub boot.scr system.dtb"
```

两个补丁各自解决什么：

| 补丁 | 解决的问题 |
|---|---|
| `0001-zocl-kernel-6.12-api.patch` | XRT 2024.1 的 zocl 是针对内核 6.6 写的，在 6.12 上有两类 API 漂移（缺 `<linux/vmalloc.h>`、`platform_driver.remove` 改返回 `void`） |
| `0002-zocl-aie-arm32-stubs.patch` | 补齐上游缺失的 2 个 AIE 空桩函数 —— **这是自建路线上唯一有实质技术风险的一环**，机理见附录 C.2 |

### 7.2 ★ 必须重新打包 BOOT.BIN（最容易漏的一步）

```bash

```

**为什么必须重打**：打包时会把一个**环境块**注入 u-boot，里面带着 `bootargs`，而
`petalinux-build` **不会**因为 `bootargs` 变了就自动重打 `BOOT.BIN`（依赖里没有这一项）。
u-boot 环境里的 `bootargs` 会**覆盖**设备树里的 `/chosen/bootargs` —— 所以即使设备树改对了，
板子照样会去找旧的 `ram0`，报 `Kernel panic - not syncing: VFS: Unable to mount root fs`。
**从设备树完全看不出问题。**

> 本 XSA 不含 bitstream（PL 尚未实现），所以**不加** `--fpga`。加了会报
> `WARNING: Empty file download-*.bit`。

## 8. 组装 PYNQ 根文件系统

### 8.1 为什么必须在 fakeroot 里做

Ubuntu 包里含 **root 属主**、**setuid 位**和**设备节点**。以普通用户解压会：

| 丢失的东西 | 后果 |
|---|---|
| 属主变成当前用户（1000） | 很多系统程序拒绝运行 |
| setuid 位消失 | `su`、`passwd` 等失效 |
| 设备节点被静默跳过 | 不报错，但文件不见了 |

`fakeroot` 让进程"以为"自己是 root。关键是**解压和重新打包必须在同一个会话里**，
否则伪造的属主信息会丢。

### 8.2 一键

```bash
cd /home/zheyang/SRP/qiansaiFPGA/demoir-fpga
bash deploy/pynq/build_pynq_rootfs.sh
```

脚本做的事（也可以照着手敲）：

```bash
OUT=/home/zheyang/SRP/qiansaiFPGA/peta_prj/pynq_rootfs
V=6.12.40-xilinx-g31626ef92ff1
Z=/home/zheyang/SRP/qiansaiFPGA/peta_prj/ax_peta/build/tmp/sysroots-components/zynq_generic_7z015/zocl/lib/modules/$V/updates/zocl.ko

rm -rf "$OUT" && mkdir -p "$OUT" && cd "$OUT"
fakeroot -- bash -c '
  set -e
  mkdir -p tree
  # ① 解压（本机 NVMe 约 1 分钟，机械盘可能 4 分钟以上）
  tar -xzf /home/zheyang/SRP/qiansaiFPGA/peta_prj/downloads/pynq/jammy.arm.3.1.0.tar.gz -C tree
  # ② 装入我们编的 zocl.ko（Ubuntu 的 /lib 是指向 /usr/lib 的软链，写 /lib 会落到 /usr/lib）
  mkdir -p tree/lib/modules/'"$V"'/updates
  cp '"$Z"' tree/lib/modules/'"$V"'/updates/zocl.ko
  # ③ 生成模块索引
  depmod -b tree '"$V"'
  # ④ 重新打包（属主保持 root）
  tar -czf pynq_rootfs.tar.gz -C tree .
'
```

耗时：本机实测 **约 4 分钟**（解压 + 打包），产出约 **2.06 GB**。

> `depmod` 会报 `could not open modules.order` 和 `modules.builtin` 两个 warning，**可以忽略** ——
> `zocl.ko` 的 `depends` 是空的（DRM 等依赖都编进了内核），`modules.dep` 内容是
> `updates/zocl.ko:`（冒号后为空）就对了。

### 8.3 验证

```bash

tar tzvf pynq_rootfs.tar.gz | head -3 | awk '{print $1, $2}'      # 属主应为 root/root
tar tzf pynq_rootfs.tar.gz | grep -E "zocl\.ko|modules\.dep$"
tar tzf pynq_rootfs.tar.gz | grep -E "pyxrt\.so$|site-packages/pynq/__init__\.py$"
```

四个都要在：`zocl.ko`、`modules.dep`、`pyxrt.so`、`pynq/__init__.py`（后两个是 AMD 包里原本就有的）。

## 12. 故障排查

| 症状 | 可能原因 | 怎么处理 |
|---|---|---|
| 板子完全没反应，串口无输出 | `BOOT.BIN` 的 DDR 参数不对 | 检查 XSA 是否含正确的 DDR 配置（第 2.2 节） |
| `Kernel panic ... Unable to mount root fs` | **BOOT.BIN 里的 bootargs 还是 `ram0`** | 第 7.2 节的 `petalinux-package boot --u-boot --force` 漏了。用 `strings BOOT.BIN \| grep "root=/dev"` 确认 |
| 起不来，卡在 `Waiting for root device` | 根分区设备名不对 | 确认 SD 是 `mmcblk0` 还是 `mmcblk1`，改第 4 节 `SDROOT_DEV` 后重编 |
| 启动后根文件系统只读 | `rw` 没进 bootargs | 看第 4 节 `BOOTARGS_GENERATED` 末尾有没有 `rw` |
| `image.ub` 还是 20 MB | 第 4 节 ext4 配置没生效 | 确认 `ROOTFS_INITRD` 已关、`ROOTFS_EXT4=y`，再 `--silentconfig` + build |
| `modprobe: FATAL: Module zocl not found` | `zocl.ko` 没进 rootfs，或 `modules.dep` 不对 | 跑第 8.3 节验证 |
| `insmod zocl` 报 `invalid module format` | vermagic 不匹配 | `zocl.ko` 必须对着**当前内核**编；对比 `modinfo zocl.ko` 和 `uname -r` |
| zocl 加载了但没有 `/dev/dri/` | 设备树节点没匹配上 | `dmesg \| grep -i zocl`；确认 dtb 里是 `xlnx,zocl`（第 5 节） |
| `import pyxrt` 报 `NameError` | 缺 `chosen/pynq_board` | 第 5 节节点没进 dtb。**这是最容易误诊的一个**，见附录 C.3 |
| `import pynq` 找不到模块 | 用了系统 Python | PYNQ 装在 venv 里：`source /etc/profile.d/pynq_venv.sh`，或用 `/usr/local/share/pynq-venv/bin/python3` |
| 网口不通 | PHY 配置 | 把 `phy-mode` 从 `rgmii-id` 改成 `rgmii` 试（JL2121 的 TXDLY/RXDLY 上电都是延时） |
| 分区太小写不下 | `--size` 根分区不够 | 根文件系统解压 5.15 GB，给 8 GB 以上 |
| `petalinux-package wic` 返回非零、提示 `bitbake wic-tools failed`，但日志里 `Tasks Summary: ... all succeeded` | 离线 sstate 缓存里缺某个 native recipe 的 `recipe_qa` 对象（实测是 `parted-native`），setscene 取不到就记一条 ERROR，而**真实任务随后成功** | **直接重跑一次**即可（缺的对象已写进本地 sstate）。`deploy/pynq/make_sdimage.sh` 已内置自动重试一次。判断成败看 `Tasks Summary ... all succeeded` 和有没有 `task .*: Failed`，**不要只看返回码** |
| 全量构建返回 255，有多条 `*_setscene: Fetcher failure ... .siginfo` | 同上，公开镜像/离线缓存缺 siginfo 的噪音，任务其实都成功了 | 同上：看 `Tasks Summary`，不看返回码。配好第 2.4 节离线缓存后噪音减少 |
| 建工程脚本报 `ax_peta 已存在` | 上次没删干净 | 见第 13 节回退 |

## 附录 C：为什么这样配（机制）

这一节解释"为什么"；操作步骤在上面各节。更深的论证分别在各工具自己的 README 里。

### C.1 XSA 为什么必须先补全 PS7

PS 里没使能的外设，PetaLinux 生成设备树时**连节点都不会有**。只配 DDR + UART 的 XSA
做出来的系统没有网口、没有 SD 卡、没有 QSPI，**镜像根本起不来**（U-Boot 拿不到 MMC）。

完整记录（26 个属性、两个顺序坑、逐节点证据）：[`deploy/xsa/README.md`](../../deploy/xsa/README.md)。

### C.2 zocl 的 AIE 符号问题（自建路线唯一的实质风险）

XRT 2024.1 的 zocl 是针对内核 6.6 写的。打完 API 兼容补丁后全部 `.c` 能编译，
但 modpost 链接时报 **10 个 `aie_*` 符号未定义**。

**根因**：这些符号由内核 AI Engine 驱动导出，而 AIE 是 Versal 专属硬件，其 Kconfig 是
`depends on ARM64 || COMPILE_TEST` + `depends on ZYNQMP_FIRMWARE` —— Zynq-7000 是 **ARM32**，
两条都不满足。**6.6 的 Kconfig 限制完全相同，这不是 2025.2 引入的问题。**

**解法**：用 XRT 上游自己为非 PetaLinux 构建预留的 `__NONE_PETALINUX__` 开关，它让
`zocl_aie.c` 改用 `include/zocl_aie.h` 里的 `static inline` 空桩（内联进 `zocl.ko`，
不产生外部符号）。上游空桩清单漏了 2 个函数，补丁 `0002` 补齐；配方加一行
`EXTRA_OEMAKE += "cflags_zocl=-D__NONE_PETALINUX__"`。

完整记录（含验证命令、回退方法）：[`deploy/pynq/zocl-kernel-6.12/README.md`](../../deploy/pynq/zocl-kernel-6.12/README.md)。

> **教训**：遇到"符号未定义"先找上游有没有预留开关，再考虑改代码。改代码之前把源码里
> 所有 `#ifdef` 和构建脚本读一遍。

### C.3 PYNQ 在 Zynq-7000 上靠什么跑（三个耦合点）

PYNQ v3.x 在 Zynq-7000 上是**混合方案**：**FPGA manager 配置器件 + `/dev/mem` 访问 PL 寄存器 +
XRT 分配内存**（`pynq.allocate()` → `pyxrt.bo()`）。**v2.7 起已无 CMA/xlnk 路径。**

三样东西必须同时对齐：

| # | 耦合点 | 我们怎么满足 | 缺了的症状 |
|---|---|---|---|
| 1 | `zocl.ko`（绑内核 vermagic） | 第 6/7 节：用本工程的内核编 | `insmod` 报 `invalid module format` |
| 2 | `pyxrt.so` / XRT 用户态（要同 XRT 版本） | AMD 包里预装的 2.17.0，与 zocl 同版本 | `import pyxrt` 失败 |
| 3 | 设备树 `chosen/pynq_board` 节点 | 第 5 节手工补 | **`NameError: name 'pyxrt' is not defined`** |

**第 3 点最容易误诊**：`pynq/ps.py` 用
`ON_TARGET = os.path.isfile('/proc/device-tree/chosen/pynq_board')` 判断是否在真板子上，
缺了这个文件 → `ON_TARGET=False` → `xrt_device.py` 根本不 `import pyxrt` → 报出看起来像
"XRT 没装"的错误。**论坛上有人把它误诊为"XRT 移除了 pyxrt"，实测源码后不成立。**

### C.4 宿主机不需要装 pynq / pyxrt

PetaLinux 构建用的是它**自带的 Python 3.12**，与系统 Python 3.10 完全隔离：

| | 系统 Python | PetaLinux 构建用 |
|---|---|---|
| 路径 | `/usr/bin/python3` | `/opt/pkg/petalinux/sysroots/x86_64-petalinux-linux/usr/bin/python3.12` |
| site-packages | `/usr/lib/python3/dist-packages` | `/opt/pkg/petalinux/sysroots/.../python3.12/site-packages` |

实测反证：完整跑过含内核、u-boot、zocl、wic 的构建，宿主机 `~/.local/lib/python3.10/site-packages/`
**一个文件都没变**。`pynq` / `pyxrt` 是给板子（ARM）用的。

### C.5 不要用 PYNQ-Z2 的官方镜像

镜像里的 `BOOT.BIN` 含 FSBL 的 **PS DDR 初始化参数**，按目标板 DDR 芯片写死。
PYNQ-Z2 是 512 MB/16-bit，AX7015B 是 **1 GB/32-bit** → DDR 初始化错误 → **连 U-Boot 都进不去**。
社区实证：一位 AX7020 用户"因为 SoC 相同"烧了 Z2 镜像，原话
**"my board doesn't even boot from it"**。

同理，**PYNQ v3.1 官方文档只声明在 2024.1 上测试过** —— 那是"他们测过的组合"，不是机制上的
硬要求。真正的限制写在 Kconfig 里（见 C.2），应该直接去读。
