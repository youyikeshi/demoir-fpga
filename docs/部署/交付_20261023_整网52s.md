> 一句话：**整网 187.41 s → 43.6 s（−76.7%），输出与 FP32 参考逐字节相同（零精度损失）。**

## 3. 怎么跑

```bash
cd /home/xilinx/demoir_new
printf 'xilinx\n' | sudo -S -p '' bash -lc \
  'C8_LAYOUT=1 ./board_safe_run.sh 900 run_network_on_board.py \
     --manifest manifest_640.json --pack weights_pack \
     --input weights_pack/input_q.bin --bit design_1.bit \
     --c8 --profile --profile-json /tmp/prof.json --dump-out /tmp/out.bin'
md5sum /tmp/out.bin      # 期望 97f5a094...
```

⚠️ `C8_LAYOUT=1` 与 `--c8` **缺一不可**：本 bit 是纯编译期 C8，配错会返回 `ERR_LAYOUT(4)` 并抛异常
（故意的，比静默算错好）。

## 4. 优化历程（每个节点都有板上实测 + md5 证据）

| 整网 | 手段 | 关键发现 |
|---:|---|---|
| 187.41 | （原始基线） | |
| 185.0 | 激活改 **C8 交错布局**（全 8 对齐、纯编译期、无运行期 mux） | 资源净赚 DSP 131→104；时间几乎没赚 |
| 144.89 | **层间算子改 ARM C 内核** | sam_sum/interp/eca 合计 48.7 → 8.7 s |
| 106.69 | **填充与 k=1 权重改 32-bit 读** | RTL 里 `ARLEN=1` 的真实含义是"抓 4 字节只用 1 个"——**每字节一笔事务**；此前所有 burst 参数都白设 |
| 68.40 | **k=3 权重 PAD12 容器** | **写 bank 号必须是编译期常量**，一旦变运行期值，HLS 不流水且 LUT 爆到 91~103% |
| 59.87 | **k=5 PAD28 + cat/interp/add 内核化** | k=5 对齐后 LUT 反而 −4,585；cat 瓶颈是 `tobytes+translate`（42.8 MB/s vs memcpy 183） |
| **52.4** | **写回改独立 64-bit 拷贝循环 + 修掉 C8 填充白写的零** | 写回瓶颈是 `AWLEN=0`（每像素一笔 1-beat），不是 II；补零白写 624.7 MB/4.2 s |

## 5. 精度结论（GPU 侧实验，均已归档）

| 方案 | ΔPSNR（400 块） | SSIM 中位 | 结论 |
|---|---:|---:|---|
| 当前交付：全 int8 权重 + int8 激活 | — | — | **与 FP32 逐字节相同** |
| 4 bit 权重（纯，group-64） | −1.50 dB | 0.7391 | 不可接受（文字肉眼可见糊） |
| **混合精度 E-g64**（k≥3 int4 + 全 k=1 int8 + 2 例外层） | **+0.24 dB** | 0.8135 | **可用但未启用**（38% 块变差、p05 −1.56） |
| 4 bit 激活（per-tensor） | **−6.10 dB** | 0.5507 | 否决 |
| 4 bit 激活 + QAT 800 步 | −11.13 dB | 0.2453 | 发散 |
| A6 + 32 元素块 scale | +0.22 dB | 0.8181 | 可行形态，但无收益（被 C8 覆盖） |
| 稠密→depthwise（裁非对角） | **−4.18 dB** | 0.7626 | 否决（非对角能量占 94.3%） |

## 6. 已知的剩余空间

| 方向 | 预期 | 风险 |
|---|---|---|
| 写回长 burst（`AWLEN>0`） | −4 s | 中（HLS 对局部数组只给 AWLEN=0；需 BD 侧抬 `USER_MAXREQS`） |
| **E-g64 + DSP 打包（2 MAC/DSP）** | −5~7 s | 高（LUT 78.8% → 逼近 90%，RTL 重写打包/偏置修正） |
| 填充与计算重叠 | ≤2 s | 否决（BRAM 93.2%，双缓冲超限 8×） |
| k=5 进一步优化 | −1~2 s | 低 |

计算天花板：引擎峰值 8 MAC/拍 ⇒ 32.9 GMAC 至少 **22.7 s**；要破这个天花板只能靠 DSP 打包（int4）。

## 7. 工程纪律（踩过的坑，务必遵守）

1. **板端任何 python 必须经 `board_safe_run.sh`**：精确清理残留（不误杀 ssh/bash）、CMA 预检（≥100 MB）、
   `timeout` 兜底、**flock 互斥锁**（两个任务不会互杀——真实发生过：跑到 150/247 被对方清理掉）。
2. **切 bit 必须 bit+hwh 成对**，且先归档到 `/data/work/bits_archive/`（有过一次删掉旧备份、回退要重跑 25 min）。
3. **板端 `cc` 默认不开 NEON**：标量兜底逐字节访问 CMA 只有 6.4 MB/s（cat 从 5.66 s 变 65.6 s）。
   必须显式 `-mfpu=neon -mfloat-abi=hard`，并**运行时自检** `i8_have_neon()`，不过就整体回落 numpy。
4. **CMA 非缓存内存必须按 64 字节（cache line）成块处理**：16 B/迭代 71 MB/s、64 B/迭代 163 MB/s。
5. **不要用"循环没流水"解释访存慢** —— 去看生成的 RTL 的 `ARLEN/AWLEN/WSTRB`。
6. **同一个"宽写"动作，放的位置决定成败**：放计算流水里 = 慢 5.6%；放独立拷贝循环 = 快 52%。
7. **`num_write_outstanding` 在本设计里空转**（AW 请求 FIFO `USER_MAXREQS=4`），改它只恶化 WNS。
