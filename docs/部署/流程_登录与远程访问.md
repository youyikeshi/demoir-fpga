## 1. 30 秒先决条件自检

在**宿主机**上敲（**按顺序看，第 ① 条最重要**）：

```bash
# ① 链路通没通 —— 这是唯一可信的"板子在不在"判据
cat /sys/class/net/enxec1ac300ce01/carrier    # 必须是 1
# ② 宿主机这侧地址对不对
ip -4 -br addr show enxec1ac300ce01           # 要有 192.168.7.1/24
# ③ 最后才用 ping 确认
ping -c 2 192.168.7.2
```

> ⚠️ **`ping 192.168.7.2` 通了，不代表板子在线！**（2026-10-06 实测踩到）
>
> 板子关机 / 拔线时，USB 网口 `carrier=0`，接口上的 `192.168.7.0/24` 路由随之消失，
> 于是发往 `192.168.7.2` 的包会**落到默认路由、从 WiFi 出去**：
>
> ```text
> $ ip route get 192.168.7.2
> 192.168.7.2 via 10.197.199.254 dev wlp0s20f3 src 10.197.197.16
>                                ↑ 走的是 WiFi，不是 USB 网口
> ```
>
> 而校园网里**恰好在 `192.168.7.2` 上有别的机器**。实测对方回 `SSH-2.0-OpenSSH_6.6`
> （2014 年的版本，板子是 OpenSSH 8.9）、80 端口回 `200`（板子的 80 是 `301` 跳 9090）。
> 结果就是：**你会连上一台陌生机器，还以为是自己板子** ——
> 表现是 SSH 报 `REMOTE HOST IDENTIFICATION HAS CHANGED`。
>
> **可靠的判据顺序**：① `carrier=1` → ② 串口设备 `/dev/ttyUSB0` 在 → ③ 对端 MAC 是
> `00:0a:35:00:1e:53`（`ip neigh show dev enxec1ac300ce01`）→ ④ 才是 `ping`。
> 只要 ① 不成立，后面全都不用看了。

> **⚠️ 必须走 USB 转网口那个网卡，不是 WiFi。** 板子只在 `192.168.7.x` 这个网段上，
> 而它挂在 `enxec1ac300ce01`（网卡名由 NetworkManager 按 MAC 生成，插哪个 USB 口都不变）。

## 3. SSH（命令行，最常用）

```bash
ssh xilinx@192.168.7.2          # 密码 xilinx
```

**三个必须知道的点**（都踩过）：

| 坑 | 说明 |
|---|---|
| **`ssh root@192.168.7.2` 一定失败** | 板子的 sshd 是 `permitrootlogin without-password`：root **只认密钥**，密码会被拒。正确做法是用 `xilinx` 登进去再 `sudo`（sudo 密码也是 `xilinx`） |
| **交互式登录进去，PYNQ 环境是自动配好的** | 登录 shell 会加载 `/etc/profile.d/pynq_venv.sh` 和 `xrt_setup.sh`，所以 `python3` = `/usr/local/share/pynq-venv/bin/python3`（带 `pydantic` 等依赖），`XILINX_XRT=/usr` 也已设好。**直接 `python3 -c "import pynq"` 就能用** |
| **非交互式（`ssh 板子 "命令"`）不会带这套环境** | 那种方式下 `python3` 会落到系统 `/usr/bin/python3` → `import pynq` 报 `No module named 'pydantic'`。要么加 `-t`，要么写绝对路径的 venv python |

免密登录（本文档作者配的专用密钥）：

```bash
ssh -i /home/zheyang/SRP/qiansaiFPGA/.agent-scratch/board_key xilinx@192.168.7.2
```

> 密钥放在 **`<课题根>/.agent-scratch/`** —— 那是 AI 助手的工作目录，**可以随时整个删掉**
> （删了就退化成用密码登录，不影响板子）。它不在任何 git 仓库里。

> 怎么自己配一份：把宿主机的公钥追加到板上的 `~/.ssh/authorized_keys` 即可
> （板子初始没有这个文件，`mkdir -p ~/.ssh && chmod 700 ~/.ssh` 先建目录）。

## 4. Jupyter（浏览器，PYNQ 的图形化入口）

**在宿主机的浏览器里打开：**

```text

```

80 端口上跑着一个转发服务，会自动 **301 跳到 `http://192.168.7.2:9090`**，所以不用带端口号。

**登录密码：`xilinx`**

> 这不是猜的：Jupyter 把密码存成 `sha1:盐:哈希`（`/root/.jupyter/jupyter_notebook_config.py`），
> 算 `sha1("xilinx" + 盐)` 与配置里的哈希逐字一致。

进去落在 **`/home/xilinx/jupyter_notebooks`**，里面**已经有现成示例**：

- `Welcome to Pynq.ipynb` ← 先点这个
- `getting_started/`、`common/`

能干什么：新建 notebook 直接跑 Python，`import pynq`、看设备、画图都行 ——
**这是 PYNQ 项目里最顺手的入口**，比敲命令行直观得多。

> ⏱️ **板子刚开机时 Jupyter 要等约 35 秒才就绪**（2026-10-06 重启实测：启动脚本从开机第 13 秒起

> **这不是故障** —— 这颗 666 MHz 双核 A9 起 Jupyter 就要这么久。刚开机就打不开页面，等半分钟再试。

> ⚠️ 一件事先有心理准备：`pynq.allocate()` 现在还会报 `Overlay is not downloaded`。
> 那是**设计如此**（PYNQ 必须先加载一个 xclbin 才知道内存怎么分），要等第一个 overlay 落地。

## 6. 图形界面：两条路，别一上来就装桌面

### 6.1 `ssh -X`：零安装，跑单个图形程序

板子上**已经装好了 X 客户端**（`xterm` / `xeyes` / `xclock` / `xcalc`），
而且 **tkinter 在系统 python 和 PYNQ venv python 里都能 import**，sshd 的 `x11forwarding` 也是 `yes`。

所以宿主机上一条命令就能看到板子的窗口：

```bash
ssh -X xilinx@192.168.7.2 xeyes        # 宿主机屏幕上弹出"眼睛"
ssh -X xilinx@192.168.7.2 xterm        # 板子的终端窗口
```

**这是零安装、零内存开销的方案**，适合"就想看一眼某个 GUI 程序"。
缺点是每个程序要单独起、窗口管理很原始。

### 6.2 VNC：完整桌面（**本文已经帮你配好了**）

**现状**：板子上已装 `tigervnc-standalone-server` + `tigervnc-tools` + `openbox`，
密码 `xilinx`，配置在 `~/.vnc/`。**但没有设成开机自启** —— 需要时手动开（理由见下面"成本"）。

```bash
# 板上：启动 / 停止（作为 xilinx 用户，不用 sudo）
vncserver :1 -geometry 1280x800 -depth 24 -localhost no
vncserver -kill :1

# 宿主机：连上去（这台机器已装 tigervnc-viewer）
vncviewer 192.168.7.2:1
```

端口是 **5901**（`:1` = 5900+1）。桌面是 openbox（右键出菜单，能启动 `xterm` 等）。

**已验证的事实**（2026-10-06 实测）：

| 项 | 结果 |
|---|---|
| 监听 | `0.0.0.0:5901`（`-localhost no` 是必须的，否则只允许板子本机连） |
| 协议握手 | 宿主机读到 `RFB 003.008` |
| 认证方式 | `VncAuth`（有密码）+ `VeNCrypt` |
| **密码正确性** | 用 `xilinx` 走完整 VncAuth 握手 → `SecurityResult=0` **通过**；用错密码 → `=1` **被拒** |

**说点实话：VNC 在这块板子上值不值得？**

| | 说明 |
|---|---|
| 好处 | 有个"真桌面"：能开多个窗口、能跑只有 GUI 的工具、感觉像在本地操作一台机器 |
| 代价 | 板子是 **666 MHz 双核 Cortex-A9 + 1 GB 内存（可用约 869 MB）**，桌面会明显发涩；而且 openbox 是**空桌面**，文件管理器/浏览器/编辑器都得另外装 |
| 装它花了多少 | 只有 **9 个包**（因为 X 库镜像里早就有）：`tigervnc-standalone-server`+`tigervnc-common`+`tigervnc-tools`+`openbox`+4 个库，合计约 1.4 MB |
| 更适合它的场景 | 想跑某个**只有图形界面**的工具时；或者你想有个"桌面环境"方便到处点 |
| **不适合替代 Jupyter** | PYNQ 的活（写 Python、看波形、试 API）用 Jupyter 更快更省 —— 浏览器渲染在你电脑上，不占板子 CPU |

> **建议**：平时别开 VNC。真要桌面时按上面两条命令开、用完 `-kill` 关掉，省内存。
> 想要更完整的桌面（面板、文件管理器、浏览器）就得装 `xfce4` 之类，那是几百 MB 的下载，
> 需要先让板子能上网（§8）。

## 7. NFS：让板子直接读写电脑上的目录（**已配好并验证**）

**用途**：代码在电脑上编辑，板子上直接跑，不用来回拷 —— 这是嵌入式开发最常用的姿势。

**它导出的是哪个目录**：宿主机上的 **`<课题根>/work/`**。那是一个**专门的中转站**，
不是随便挑的目录，约定如下：

```text
work/                      ← 唯一的 NFS 导出目录（板上挂在 /mnt/host）
├── to-board/              ← 电脑 → 板子：要弄上板的东西放这
│   └── pkgs/              ← 离线 .deb（板子没网时装的依赖包）
└── from-board/            ← 板子 → 电脑：从板上抄回来的东西放这
```

> ⚠️ **这个目录里的东西会直接出现在板子上**，所以别往里丢草稿。
> 目录里有一份 `README.md` 写着同样的约定 —— 但**那个文件不在 git 里**，
> 所以约定也抄在这里，免得哪天它被删掉就没人知道这个目录是干嘛的。
>
> **为什么专门强调**：2026-10-06 发现该目录被 AI 助手当成了草稿区（塞进抓包日志、
> 文档拆分脚本、备份等 17 项临时文件）。根因是**从未有人用文字声明过它的职责**，
> 而 `work` 这个名字又太通用 —— 谁看都像"临时工作目录"。
> 助手的草稿现在统一放在 `<课题根>/.agent-scratch/`（**可随时整个删掉**）。

### 7.1 宿主机侧（已配好，这里只说明现状）

宿主机的 `/etc/exports` 里有一行：

```text
/home/zheyang/SRP/qiansaiFPGA/work *(rw,sync,no_root_squash,no_subtree_check)
```

`nfs-kernel-server` 与 `rpcbind` 都在跑。从板上 `showmount -e 192.168.7.1` 能看到这条导出。

> ⚠️ **安全提醒：按现在的配置，这个导出对校园网是敞开的**（2026-10-06 实测确认）
>
> - `*` 表示**对任何来源**开放。而 `nfsd` 与 `rpcbind` 监听在 **`0.0.0.0`（所有网卡，含 WiFi）**，
>   这台机器的 WiFi 地址是 `10.197.197.16/21`（校园网）；同时 ufw 配置文件里是 `ENABLED=no`
>   （注意：`systemctl is-active ufw` 会显示 `active`，但配置里是关的 —— 别被它骗了）。
>   ⇒ 同网段的机器可以尝试 `mount -t nfs 10.197.197.16:/home/zheyang/SRP/qiansaiFPGA/work /mnt`。
>   修法只有一行，**板子仍是唯一客户端，收紧不损失任何功能**：
>
>   ```bash
>   sudo sed -i 's#^\(/home/zheyang/SRP/qiansaiFPGA/work\) \*#\1 192.168.7.0/24#' /etc/exports
>   sudo exportfs -ra && sudo exportfs -v      # 立刻生效并回显
>   ```
>
> - `no_root_squash` 表示**板子的 root 在宿主机上也是 root**（能改宿主机文件属主）。
>   中转站场景建议**留着** —— 否则从板上拖回来的文件属主会变成 `nobody`；知道含义即可。

### 7.2 板子侧（已装好客户端，且**开机自动挂载已实测有效**）

板上原本**没有** `nfs-common`，已用离线方式装好（见附录 B）。
**平时你不需要做任何事** —— 板子一开机就会自动挂上：

```bash
# 板上，验证用（平时不用敲）
findmnt /mnt/host      # 应显示 192.168.7.1:/home/zheyang/SRP/qiansaiFPGA/work nfs
ls /mnt/host           # 能看到宿主机 work/ 里的东西
```

**为什么能自动挂**（改配置时要知道这条）：`/etc/fstab` 里那行**没有写 `noauto`**，
于是 systemd 的 fstab 生成器造出一个 `mnt-host.mount` 单元，并把它挂到 `remote-fs.target` 下，
而那个 target 就在开机流程里 —— 所以每次开机都会挂一次。实测证据（2026-10-06）：

```text
/run/systemd/generator/remote-fs.target.wants/mnt-host.mount → ../mnt-host.mount
systemctl list-dependencies remote-fs.target   →   ├─mnt-host.mount
模拟开机：umount /mnt/host 之后 systemctl start remote-fs.target → 挂上了
```

改了 fstab 记得 `sudo systemctl daemon-reload`，否则生成的单元不会跟着更新。

**什么时候才需要你手动**：**板子开机时宿主机不在线**（比如先开板子、后开电脑）。
那次挂载会失败，等宿主机起来之后补一刀：

```bash
sudo mount /mnt/host                       # 补一刀（走 fstab 那行，不用写长参数）
sudo systemctl restart mnt-host.mount      # 或者让 systemd 重挂
sudo umount /mnt/host                      # 想卸就卸；下次开机还会自动挂回来
```

`/etc/fstab` 里那行（**改动前的原文件备份在 `/etc/fstab.bak-before-nfs`**）：

```text
192.168.7.1:/home/zheyang/SRP/qiansaiFPGA/work /mnt/host nfs _netdev,bg,soft,timeo=50,retrans=2,vers=3 0 0
```

这几个参数（每个都有理由，别随便删）：

| 参数 | 为什么 |
|---|---|
| `_netdev` | 声明这是网络文件系统，**等网络起来再挂**（否则可能卡在启动早期） |
| `bg` | 第一次连不上就转后台重试，**不让开机干等**。实测：宿主机不可达时 **3.3 秒**就返回（不是卡死） |
| `soft,timeo=50,retrans=2` | 宿主机中途掉线时**超时后返回错误**，而不是让板子上的进程无限期卡死 |
| `vers=3` | 用 NFSv3（板上内核 `CONFIG_NFS_FS=y` + `CONFIG_NFS_V3=y`，v3 最省事） |

> **⚠️ 三个概念别混**（2026-10-06 曾把前两个说成一回事，这里澄清）：
>
> | 概念 | 含义 | 这台板子上 |
> |---|---|---|
> | **开机挂载** | 每次开机自动挂一次 | ✅ **已配好、已实测有效**（就是上面那条链路） |
> | **访问触发自动挂载**（`x-systemd.automount`） | 你第一次访问那个目录时才挂 | ❌ 做不了 —— systemd 的 automount 依赖内核 `autofs4`，这个内核没编（`CONFIG_AUTOFS_FS is not set`，启动日志里 `systemd[1]: Failed to find module 'autofs4'` 就是它）。**但它不影响上一条** |
> | **手动挂载** | 敲命令挂 | ✅ 只在"宿主机当时不在线"时兜底 |
>
> 换句话说：**"开机自动挂"可以，"按需自动挂"不行** —— 而日常够用的恰恰是前者。
> 真要按需自动挂，得重编内核打开 `CONFIG_AUTOFS_FS`（额外工作，暂不做）。

| 吞吐 | 写 **约 9 MB/s**（已经贴着 100M 链路的上限 12.5 MB/s）；读那次 95 MB/s 是**缓存命中**，不作数 |
| **开机自动挂载** | ✅ 实测有效：fstab 那行 → 生成 `mnt-host.mount` → 由 `remote-fs.target` 在开机流程里拉起（见 §7.2） |
| 宿主机不可达时的耗时 | ✅ **3.3 秒**就返回（`bg` 把首次失败转后台），不阻塞开机 |

## 8. 让板子能上网（要 `apt install` / `pip install` 时才需要）

**现状**：板子**没有默认路由**，所以 `apt` / `pip` 都用不了。
（这也是为什么 NFS 和 VNC 的包是"离线装"的，见附录 B。）

**修法**：让宿主机做 NAT，把 WiFi 的网共享给板子。**三条命令，都要宿主机 sudo**
（`ip_forward` 这台机器已经是 `1` 了，不用改）：

```bash
# 宿主机
sudo iptables -t nat -A POSTROUTING -s 192.168.7.0/24 -o wlp0s20f3 -j MASQUERADE
# 板上：加一条默认路由 + 一个 DNS
sudo ip route add default via 192.168.7.1
echo 'nameserver 223.5.5.5' | sudo tee /etc/resolv.conf
```

验证（板上）：

```bash
ping -c 2 223.5.5.5 && sudo apt update && echo "✅ 板子能上网了"
```

> - 出口网卡是 `wlp0s20f3`（宿主机 WiFi）。**换了网络环境要改这一项。**
> - MASQUERADE 规则**重启宿主机后失效**，要用就重跑。想持久化得自己写进 iptables-persistent。
> - 别用 `nmcli con mod "Wired connection 1" ipv4.method shared`：那会把宿主机地址段改成
>   `10.42.0.1/24`，**破坏 192.168.7.x 这套静态约定**。手工 NAT 是更好的选择。
> - 板上 `/etc/resolv.conf` 原本指向 `127.0.0.53`（systemd-resolved），直连场景下解析不了域名。

## 附录 B：板上没网时怎么装包（离线装包法）

§8 的 NAT 不是必须的 —— **只要宿主机能上网**，就能把 armhf 的 `.deb` 下下来手动装。
本文的 NFS、VNC 就是这么装的。步骤（可复制）：

```bash
# ① 在板上问「我要装的东西需要哪些包」——apt 的索引镜像里是现成的，不用联网
ssh xilinx@192.168.7.2 "apt-get install -s --no-install-recommends <包名> | awk '/^Inst /{print \$2}'"

# ② 在板上问「每个包的 .deb 在哪」——直接读 apt 索引里的 Filename 字段
ssh xilinx@192.168.7.2 "for p in <包名列表>; do
  grep -h -A30 \"^Package: \$p\$\" \
    /var/lib/apt/lists/ports.ubuntu.com_ubuntu-ports_dists_jammy_*_binary-armhf_Packages \
  | awk -F': ' '/^Filename:/{print \$2; exit}'
done"

# ③ 在宿主机上下载（amd64 的 apt 装不了 armhf，所以直接按路径取）
curl -4 -sSL -o 包名.deb http://ports.ubuntu.com/ubuntu-ports/<Filename>

# ④ 传上去装
scp *.deb xilinx@192.168.7.2:/tmp/
ssh xilinx@192.168.7.2 'echo xilinx | sudo -S -p "" dpkg -i /tmp/*.deb'
```

**为什么这么绕**：板子是 32 位 ARM（armhf），宿主机的 apt 装不了它的包；
而板上又没有默认路由。用 `apt-get install -s`（模拟）在板上算出依赖闭包、
再从宿主机按索引里的真实路径下载，就绕开了这两个限制。

> ⚠️ `sudo -S` 是从 **stdin** 读密码的。所以**别**这样写：
> `echo "内容" | sudo -S tee -a /etc/某文件` —— 密码和数据会抢同一个 stdin，
> 结果是内容丢失、甚至把密码写进文件。正确写法是把内容放进 `sudo bash -c '...'` 里面。
