# 目录结构说明

> 本文档记录 2026-09-14 的**结构重构**：为什么这样分、从旧结构怎么迁移过来。
> 日常使用只需要看根目录 `README.md`。

---

## 1. 为什么重构

重构前有三个具体问题，都直接妨碍"换数据集重训"和"多机协作"：

| 问题 | 具体表现 | 后果 |
|---|---|---|
| **cwd 依赖** | 所有配置里的数据路径都是 `../../../uhdm_data/split_train` 这种相对路径，而 `os.walk` 直接拿字符串用 | **必须在 `refer_code/PDNet/PDNet/` 下运行**，换个目录就崩。换机器、换盘符都要改配置 |
| **我们的东西和上游混在一起** | 我们加的配置塞在 vendor 的 `config/` 里；训练产物埋在 `refer_code/PDNet/PDNet/out_dir/` 里；推理脚本叫 `pdnet_smoke/`（但已经不是"smoke"了） | 分不清哪些是上游、哪些是自己的，跟进上游会冲突 |
| **每个脚本各自造轮子** | 7 个实验脚本各自重复 `sys.path.insert` + `os.chdir` + 硬编码权重路径 | 改一次路径要改 7 个文件；`--out` 相对路径已经踩过一次坑 |

## 2. 五个分区

| 分区 | 谁的 | 进 git | 说明 |
|---|---|---|---|
| `src/` | 我们的代码 | ✅ | 唯一需要改的地方。入口脚本 + 配置 + 路径工具 |
| `vendor/` | 上游的代码 | ✅ | 原样快照，**不要动**（改动清单见 `vendor/README.md`） |
| `datasets/` | 数据 | ❌ | 只放 README |
| `runs/` | 训练产物 | 部分 | 配置快照/日志/可视化图进 git，checkpoint 不进 |
| `weights/` | 权重 | 部分 | `weights.yaml` 注册表进 git，`*.tar` 不进 |
| `samples/` | 输入图片 | 部分 | `phone/` 进 git，`synth/` 不进 |
| `experiments/` | 研究脚本 | ✅ | `out/` 只留被文档引用的精选产物 |
| `tools/` `docs/` | 运维与文档 | ✅ | |

## 3. 关键机制：命名解析 + 快照

配置里**不写路径，只写名字**：

```yaml
DATA:
  DATASET: uhdm            # -> datasets/uhdm/{train,eval}
TEACHER_MODEL:
  TEACHER: ghost_34large   # -> weights/ 下由 weights.yaml 登记的权重
```

`src/train.py` 负责：

1. 把名字解析成**绝对路径**；
2. 写一份快照 `runs/<run>/config.yaml`（全绝对路径）+ `run_info.yaml`（可读记录）；
3. 用**子进程**在 `vendor/PDNet/` 下跑上游 `train.py`，`--config` 指向那份快照。

于是上游看到的是它熟悉的形态（相对它自己的 cwd），而**我们的入口不依赖 cwd**。

### 为什么用子进程而不是 `runpy`

上游 `config/config.py` 在 **import 时**就执行 `parser.parse_args()`，
会去读我们自己的命令行参数，轻则吞参数、重则直接报错退出。
子进程让上游完整拥有自己的 `sys.argv`。

附带好处：上游训练出现过进程级崩溃（`0xC0000374` 堆损坏），子进程崩掉不会带走调用它的脚本。

## 5. 重构期间**没有**改动的东西

- `vendor/` 里的算法、模型、损失函数、数据加载逻辑（除了重构前那 9 处 torch 兼容修复）
- 任何**数值语义**：`crop 512`、batch、学习率、蒸馏权重、`USE_TEACHER` 默认值
- 评估口径（原生分辨率裁块、同一套 PSNR/SSIM 实现）

回归验证见 `runs/2026-09-10_uhdm4k_s512/README.md` 与 `experiments/out/README.md`：
重跑 student 评估应复现 Δ **+2.50 dB**，teacher 中位数应复现 **22.10 dB**。

## 6. 回滚

git checkout pre-restructure      # 看旧结构
git switch -c backup pre-restructure   # 从旧结构开分支
