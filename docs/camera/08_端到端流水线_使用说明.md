# 端到端流水线使用说明：拍照 → 握手传输 → 去摩尔纹 → 拼图显示

> **面向**：方案组（要把它跑起来、并且判断"结果对不对"的人）。
> **实现**：`pynq_specialized_code/ps/pynq/{cam_client,demo_pipeline}.py`（板端部署到 `ps/pynq/` 同目录，与 `bin_net.py`/`bin_engine.py` 并排）。
> **边界**：本文只讲 **PS 侧**。不涉及 PL 构建、不改 RTL、不改相机侧 app。
> **证据约定**：凡"已验证"都指 `tools/pipeline_selftest.py` 的判据号（如 `G3.2`）；完整索引用 `--ids` 现跑（同一 commit 内稳定）。


## ① 一页流程图

```
 MaixCAM Pro  10.13.148.1:8660
   │  TCP 一问一答（协议见 ⑨；一行 JSON 头 + 恰好 nbytes 载荷 + md5）
   │  USB NCM ── usb0 10.13.148.100/24
   ▼
 cam_client.CamClient.shot()                 → (256,256,3) uint8 RGB
   ▼
 demo_pipeline.Pipeline.run_once()
   ├─ to_float_tensor()                      → (3,256,256) float32 in [0,1]
   ├─ BinNet.run(x0, pipeline=True, nbuf=2, arena)   ← v57 引擎，75 MHz
   │                                         → {"out1","out2","out3"} float32
   ├─ sha1 门禁（**先**）→ 不符抛 Sha1Mismatch；to_uint8（**后**）→ (256,256,3) uint8
   ├─ compose(orig, proc, 1280, 720)         → (720,1280,3) uint8（上下各 40 px 黑边）
   └─ DisplayPipeline.show_frame()           → 写 buf = FRAME_ID & 1 → 翻 FRAME_ID → 等 vsync
   ▼
 hdmi_out_top @0x400A0000 → SIL9134 → 显示器（720p30）
```

| 环节 | 形状 / 字节数 | 说明 |
|---|---|---|
| 相机帧 | `(256,256,3)` uint8，`196,608` B | RGB888、行优先、无行尾 padding |
| 引擎输入 | `(3,256,256)` float32 | `img/255`，通道在前（与 `bin_net` 口径一致） |
| 引擎输出 | `out1` `(3,256,256)` float32 | 另有 `out2/out3`，只用于 sha1 判据 |
| 显示整幅 | `(720,1280,3)` uint8，`2,764,800` B | `compose()` 产出，黑边已烘进缓冲 |
| DDR 块 | 每块 `2,764,800` B，两块 | `buf = FRAME_ID & 1`；**先写块再翻帧号** |

时间预算（v57 @75 MHz，256² 板端实测；**本流水线未复测整链**）：

| 阶段 | 量级 | 依据 |
|---|---:|---|
| `capture` | 0.1~0.5 s | 精简相机 app（不开 RTSP） |
| `compute` | **≈6.2 s** | `runs/ACCEPT_v57/README.md`：256² 墙钟 6.198~6.234 s |
| `compose` | <0.05 s | 1280×720 fancy-index + 20% 拷贝 |
| `display` | <0.05 s | 2.76 MB 缓冲 + 2 次寄存器 |
| **一轮** | **≈6.3 s**（首次 +6.2 s 探针） | ≈0.15 fps，定位是"单次拍摄→出结果"，不是视频 |

## ③ `Pipeline(...)` 参数

```python
from demo_pipeline import Pipeline
pipe = Pipeline(net=None, cam=None, disp=None, *, fake=False, mode=3, slots=24,
                bit=..., pack_dir=..., overlay=None, verbose=False,
                log=print, strict_code=True, pix_tol=0.01)
```

| 参数 | 默认 | 什么时候要动它 |
|---|---|---|
| `net` | `None` | 注入自定义引擎（接口：`.run(x0, pipeline=True, nbuf=2, arena=...) -> (outs, stats)`）。主机测必用 |
| `cam` | `None` | 注入相机（接口：`.shot(w,h) -> (h,w,3) uint8`）。`None` 且非 fake ⇒ `CamClient()` |
| `disp` | `None` | 注入显示（接口：`.setup()`/`.show_frame(frame)`/`.wait(fid, timeout)`/`.pix_alive(ms)`）。`None` ⇒ 板端 `DisplayPipeline` |
| `fake` | `False` | `True` ⇒ 缺省装主机替身（本地图 + 假引擎 + 假 reg_io + 本地内存块），并且**跳过板端门禁** |
| `mode` | `3` | 显示模式：`3`=720p30（默认）/`0`=720p60/`1`=1080p60/`2`=1080p30。**板端默认用 3** |
| `slots` | `24` | 惰性槽数（`BIN_LAZY_SLOTS`）。板端实测 24；改小会让引擎多物化、变慢 |
| `bit` | `/home/xilinx/demoir/design_1_150v57.bit` | 位流路径。**v58 合并位流出来后换这里** |
| `pack_dir` | `/home/xilinx/demoir/deploy/bin_weights_new` | 权重包目录 |
| `overlay` | `None` | 已经加载过 overlay 时传进来，避免重复下载 |
| `strict_code` | `True` | 校验 `bin_net.py`/`bin_engine.py` 的 md5 == v57 定版；关掉会**打警告**（不推荐） |
| `pix_tol` | `0.01` | 像素时钟容差（±1%）。P3 若改了 MMCM 比例要重定这个值 |
| `log` / `verbose` | `print` / `False` | 日志出口（`list.append` 即可在测试里收集）；引擎详略 |

**注入优先级**：传了就一定用你传的（`fake=True` 也只补 `None` 的位置）。
所以"注入假引擎"和"引擎坏了自动降级"是两件不同的事 —— **后者不存在**（判据 `G6.18`/`G6.19`）。


## ④ `run_once()` 返回字典

```python
res = pipe.run_once(w=256, h=256)     # compose 契约只接受 256²，其他尺寸直接 ValueError
```

| 字段 | 含义 |
|---|---|
| `t_capture_s` / `t_compute_s` / `t_compose_s` / `t_display_s` | 四个阶段各自墙钟（秒） |
| `t_total_s` | 整轮墙钟，**≥ 四段之和**（判据 `G6.6`） |
| `frame_id` | 本轮提交的 `FRAME_ID`；块号 = `frame_id & 1` |
| `latched` | PL 是否在 1 个 vsync 内采纳（`False` 时本函数已经抛异常，不会返回） |
| `sha1_gate` / `frozen_verified` | 逐帧报告：`ok(frozen)`=这帧恰是冻结输入（`G6.15`）、`n/a(live)`=真实帧无基准（`G6.16`）、`skipped(fake)`；数值保证来自启动时**种子探针**（`frozen_verified=true`，`G6.24`） |
| `md5_orig` / `md5_proc` / `md5_frame` | 三张图（原图 / 处理后 / 整幅）的 md5，用于跨机对比 |
| `runpoint` | 本轮**实际生效**的 10 条开关 + stray + slots |
| `net_stats` | 引擎自己返回的统计（板端含 PL/PS 拆项；fake 模式是假值） |
| `log_line` | 本轮那行结构化日志的原文（便于直接进报告） |

判据：返回字段齐全且非负（`G6.1`~`G6.5`）、`md5_frame` 与 DDR 里的字节一致（`G4.3`）。


## ⑤ 日志怎么读（启动两行 + 每轮一行；示例是**板端**模式）

```
[PIPE] frozen phase=verify x0_sha1=cfc75bc3f15d out1=9b1940c8 out2=f86a7035 out3=025757a8 gate=ok(frozen)
[PIPE] stage capture=0.412 compute=6.203 compose=0.021 display=0.031 total=6.667 s | frame_id=1 latched=1 | md5 orig=ab12... proc=cd34... frame=ef56... | sha1_gate=n/a(live) out1=... | runpoint fake=0 switches=10 q8cache=1 slots=24 fclk=75->75 | 720p30 1280x720
```

| 片段 | 判读 |
|---|---|
| `capture=0.412` | 相机取帧。持续 >1 s ⇒ 相机侧在等 VI/停流，看相机 app |
| `compute=6.203` | v57 整网。**明显小于 6 s ⇒ 引擎可能没真跑**（看 `net_stats`/`ps_md5`） |
| `compose=0.021` | 构图。>0.1 s ⇒ 机器被别的东西占了 |
| `display=0.031` | 写块 + 等 vsync。>0.5 s ⇒ `wait()` 会超时抛异常（不会静默） |
| `latched=1` | PL 已采纳；`0` 不会出现（出现即抛） |
| `sha1_gate=n/a(live)` | 真实帧没有冻结基准（正常）；`ok(frozen)` 只在喂冻结输入时出现；`skipped(fake)` = fake 模式 |
| `q8cache=1` / `switches=10` | 运行点第 6 条 + 条数。**`q8cache=0` 是 v39 档；`switches` 少一条就不是 v57** |
| `fclk=75->75` | 目标→读回。**`->` 右边不是 75 就说明时钟没设上** |

启动时另有两行：`[PIPE] frozen phase=verify ...`（**种子探针**：只有它证明数值对，约 6.2 s，
一次）与 `[PIPE] runpoint phase=setup ...`（**10 条开关逐条** + `ps_md5`，与 §3.3 对齐）。
每次测量自带出处，不用靠时间戳猜。


## ⑥ 运行点：为什么是 75 MHz

| 运行点 | 板端 sha1 | 判定 |
|---|---|---|
| 150 MHz | — | ❌ 10 ns 口径 WNS −3.07，新临界路径是真实数据通路（无准静态豁免） |
| 100 MHz | **0/7**（7 次互不相同） | ❌ 不可用（WNS +0.206 看着能过，但**数值错**） |
| **75 MHz** | **3/3**（`9b1940c8`/`f86a7035`/`025757a8`） | ✅ 最终运行点（用户 2026-11-03 决定） |

- 代码里就一句 `Clocks.fclk0_mhz = 75`。**不要**套 HDMI 位流的"报数 = 真值 1.5 倍"口径：
  两个 BD 的 IO PLL 不同（HDMI `1000 MHz` vs v57 `1800 MHz / DIV0=4 / DIV1=3`）。
- `06_REPRODUCE.md` §3.1 里 `assert abs(Clocks.fclk0_mhz - 100) < 1` **已作废**（与实测矛盾）。
- 本流水线只**打印**目标/读回并要求读回≈目标；真实 ACLK 没有独立探针
  （像素时钟由 50 MHz 晶振驱动，与 FCLK0 解耦）⇒ 数值对不对**由 sha1 门禁裁决**。
  v59 候选：契约 §8.19 的 `0x34 ACLK_CNT`（`f_aclk = dcount / dt`）—— 有了它才能独立测 ACLK。

**10 条开关**（`demo_pipeline.RUNPOINT`，权威 `06_REPRODUCE.md` §3.4 + `--slots 24`）：
`BIN_PACK=e1e2`、`BIN_LAZY_DEQ=1`、`BIN_CAT_FUSION=1`、`BIN_BILINEAR_C=1`、`BIN_PRECOMP=1`、
**`Q8CACHE=1`**、`BIN_F32DIRECT=1`、`BIN_CAT_ECA_FUSE=1`、`BIN_EPI_NOINV=1`、`BIN_LAZY_SLOTS=24`。

- **这 10 条必须在 `import bin_net` 之前设好**（有开关是导入时读走的）；`demo_pipeline` 在**模块顶层**就调 `apply_runpoint()`（`G6.14`）。
- `Q8CACHE=1` 是 v57 档；写成 `0` 是 v39 档 —— 这条最容易抄错（判据 `G6.11`/`G6.13`）。
- 现场残留的其它 `BIN_*/Q8CACHE*/CATPACK*` 不会被强改，但会进日志的 `stray=`（能改数值 ⇒ 靠 sha1 门禁兜）。


## ⑦ 故障对照表（**先看证据，再谈动作**）

| 现象 / 异常 | 先看什么（证据） | 结论与动作 |
|---|---|---|
| `CamBadJson` | 异常信息里带回的原始字节（`raw[:96]`） | 相机回的包头不是合法 JSON ⇒ 相机侧 app 的问题，不是网络 |
| `CamChecksumError` | 异常里的「头=… 实算=…」 | 载荷与 md5 不符；已自动**同 seq 重发 1 次**，仍不符 ⇒ 线路或相机侧 bug（`G2.2`/`G3.2`/`G3.3`） |
| `CamShortPayload` | 「声明 N B，只收到 M B」 | 载荷被截断（半张图）⇒ 检查 usb0 链路/相机侧写满没有（`G2.7`） |
| `CamBusy` | `stats()["reasons"]` | 相机还在采上一张；已知退避 200 ms×3（`G3.14`）⇒ 拉大 shot 间隔 |
| `CamDisconnected` | `stats()["reconnects"]` | 已重连重发 1 次仍断（`G3.20`）⇒ usb0/相机进程 |
| `CamTimeout` | 异常里的「剩余预算」 | 8 s 总预算用尽；不是协议错 |
| `PipelineError: fclk0 没设上` | 日志 `fclk=目标->读回` | 写 75 读回不是 75 ⇒ **停**，别跑整网 |
| `PipelineError: 0x30 心跳 <5 沿` | `pix_alive(100 ms)` 的沿数 | 像素时钟没跑（50 MHz 晶振/MMCM/BUFGMUX）⇒ 按契约 §8.2 停，别再碰 AXI |
| `PipelineError: 像素时钟实测 …` | 日志 `pix=…MHz(design37.109)` | 显示时钟树不对（晶振/M 值）；±1% 门禁**只在板端跑**（本机无板，**未验证**） |
| `Sha1Mismatch` | 日志 `[PIPE] frozen` 那行的 x0/out 值 + `runpoint` | **数值错了**（种子探针不符，显示前就拦住）：先查运行点 10 条、fclk、PS 代码 md5、numpy 版本；**不是显示器问题**（`G6.24`） |
| `PipelineError: 位流里找不到 HDMI 从设备` | overlay 的 `ip_dict` | 用了 v57 而不是 v58 合并位流；**不许**对 `0x400A0000` 写寄存器 |
| `PipelineError: bin_net.py md5=…` | 异常里的 md5 | 部署的不是 v57 定版 PS 代码 ⇒ 冻结 sha1 无意义 |
| `FRAME_ID=… 没被 PL 在 vsync 采纳` | `frame_id` / `latched` | PL 没在扫（像素域死/模式没切）⇒ 画面还停在旧帧，已抛 |
| `ValueError: compose() 只接受 256x256` | 请求的 `w,h` | 本流水线**不做 resize**（协议 §2 硬约束）⇒ 改相机裁剪尺寸 |
| 显示器全黑但日志全绿 | `0x30` 心跳 + `STATUS[0] init_done` | AXI 通但像素侧没出图 ⇒ 查 `pix_clk` / `init_done`（契约 §6） |

**纪律**：上表任何一条都**不许**用"再跑一次试试"代替定位；本流水线所有失败都有唯一 reason 码。

## ⑨ 与相机侧的契约（唯一权威）

- 协议：**`docs/camera/07_端到端流水线_协议与模块图.md` §3**（请求/回包/校验/重试）。
  改协议必须**同时**改那份文档与本文件，否则两边会各说各话。
- 请求一行 JSON：`{"v":1,"cmd":"shot","seq":N,"w":256,"h":256,"crop":"center",...}\n`
- 回包：先一行 JSON 头（`v/ok/seq/w/h/fmt/nbytes/md5/t_cap_us/t_send_us`），紧跟**恰好 `nbytes`** 字节。
- 本仓库是**板子侧**实现；相机侧参考实现在相机仓库 `apps/pc/fake_camera.py`。

客户端把失败拆成**不同异常**（reason 码稳定，用来写判据/告警，别合并成"失败"）：

| reason | 异常 | 触发 |
|---|---|---|
| `bad_json` | `CamBadJson` | 包头不可解析 |
| `bad_field` | `CamBadField` | `v/seq/w/h/nbytes/fmt` 不符 |
| `md5_mismatch` | `CamChecksumError` | 重发 1 次后 md5 仍不符 |
| `short_payload` | `CamShortPayload` | 载荷不足 `nbytes` 就断（半张图） |
| `disconnected` | `CamDisconnected` | 读包头 EOF / 建连失败，重连重发 1 次后仍失败 |
| `busy` | `CamBusy` | `err:"busy"` 达 4 次 |
| `camera_timeout` | `CamRemoteTimeout` | `err:"timeout"` 重发 1 次仍超时 |
| `timeout` | `CamTimeout` | 客户端 8 s 总预算用尽 |

5 种坏包必须报**互不相同**的 reason（判据 `G2.56`）；md5 连错必须**同 seq 正好请求 2 次**（`G3.2`/`G3.3`）。

相机侧 `fake_camera.py` 的注入模式与本仓库异常的对应（`G1c.4`~`G1c.8` 实测）：

| 相机侧参数 | 产生的字节形态 | 本仓库异常 |
|---|---|---|
| `--corrupt md5` | 头里 md5 与载荷不符 | `CamChecksumError` |
| `--corrupt short` / `drop` | 载荷少 1 B / 发一半就关闭 | `CamShortPayload` |
| `--corrupt truncate` | 包头没写完就关闭（无 `\n`） | `CamDisconnected`（**不是** `bad_json`） |
| `--status busy` | `ok:false,err:"busy"` | `CamBusy`（200 ms×3 后退避耗尽） |

> "包头无 `\n` 就 EOF" 一律算**断连**；"有 `\n` 但 JSON 解析失败"才算 `bad_json`（`G2.12`）。
