# 显示构图规范（纯 PS 阶段）：左原图 / 右处理图，撑满宽度、上下填黑

> **范围**：本阶段**只做 PS 侧**——把 `256×256 原图` 与 `256×256 处理后` 拼成一张显示尺寸的 RGB 图，
> 输出 PNG 供验证，并写入一块可被后续显示通路直接扫描的缓冲区。
> **不碰 PL、不碰位流、不碰 `ps/pynq/` 里的推理代码。**
> **上板时机**：机器空闲时（当前有 Vivado 构建在跑），先主机自检通过再上板。

---

## 0. 一句话

画布 = `512×256`（左右各一张 256²），**按显示宽度等比放大**（因为 512:256 = 2:1 比任何常见显示都宽），
剩余高度**上下对称填黑**。默认显示模式 `1280×720`，可配 `1920×1080 / 1024×768 / 2560×1440`。

- 内容宽高比 = 512:256 = 2:1 ⇒ 比 16:9 (1.78) 和 4:3 (1.33) 都宽
- **永远先撑满宽度**，高度必然有余 ⇒ 上下填黑（letterbox）

---

## 1. 构图与缩放公式

设显示模式宽高为 $W_d, H_d$，内容为 $512\times256$：

$$s = \frac{W_d}{512}, \qquad H_c = 256\,s, \qquad y_0 = \left\lfloor \frac{H_d - H_c}{2} \right\rfloor$$

- 若 $H_c > H_d$（理论上不会发生，因为 2:1 比所有常见显示都宽）⇒ 回退为按高度适配 $s = H_d/256$，左右填黑。
- $y_0$ 与 $H_d - H_c - y_0$ 就是上下黑边（差 1 像素时上边少 1，取整向下）。

### 1.1 四种常见显示模式的实测取整

| 显示模式 | 缩放 $s$ | 内容尺寸 | 上下黑边 | 说明 |
|---|---:|---|---|---|
| **1280×720**（默认） | $2.5$ | $1280\times640$ | $40 / 40$ | 推荐，串行时钟低 |
| 1920×1080 | $3.75$ | $1920\times960$ | $60 / 60$ | 1080p 面板 |
| 1024×768 | $2.0$ | $1024\times512$ | $128 / 128$ | 4:3 老屏 |
| 2560×1440 | $5.0$ | $2560\times1280$ | $80 / 80$ | 2K 屏 |

- 1280 与 1920 的 s 分别是 2.5 与 3.75 ⇒ **都不是整数**

- **决定：**缩放用**整数倍最近邻 + 边界复制**，不用浮点插值
- 理由：① 去摩尔纹效果要看得清像素边界，插值会糊；② PL 以后照抄这段逻辑几乎免费；③ PS 侧也快
- 做法：预生成整数索引表 `idx` = x · 512 / W_d 与 y · 256 / H_c ，用一次 fancy-index 完成

- 若将来必须非整数倍且要平滑，再换双线性 ⇒ **先用最近邻，不改结论**

## 2. 像素格式与内存布局

| 项 | 选择 | 理由 |
|---|---|---|
| 颜色 | **RGB888**（3 字节/像素，行首无 padding） | 最简单；PL 侧以后直接按 3 字节吐像素即可 |
| 布局 | 显示尺寸整幅缓冲 `W_d × H_d × 3` | 上下黑边**已经烘进缓冲**，显示通路不需要懂 letterbox |
| 换帧 | **双缓冲 + 帧号** | 0.17 fps 下撕裂肉眼可见，必须避免 |
| 对齐 | 每行按 64 字节对齐（可选） | 以后 VDMA 突发更顺；PS 侧用 `np.ascontiguousarray` 即可 |

- 一帧 1280 × 720 × 3 = **2.76 MB**
- 一帧 1920 × 1080 × 3 = **6.22 MB**
- 每 6 s 更新一次 ⇒ 平均 1 MB/s ⇒ **带宽与 CPU 都可忽略**

## 3. 输入与输出契约

```python
def compose(orig: np.ndarray,   # (256,256,3) uint8，RGB，原图
            proc: np.ndarray,   # (256,256,3) uint8，RGB，去摩尔纹后
            W: int = 1280, H: int = 720) -> np.ndarray:
    """返回 (H, W, 3) uint8 的 RGB888 整幅画面（含上下黑边）。"""
```

**契约（写进代码 docstring，判据靠它）**
1. 输入必须 `uint8`、形状 `(256,256,3)`、RGB 顺序；形状不符直接 `ValueError`（**不许静默 reshape**）。
2. 输出必须 `(H,W,3) uint8`、`C` 连续。
3. **左右不镜像**：`x < W//2` 区域来自 `orig`，右侧来自 `proc`。
4. 黑边必须是 `(0,0,0)`。
5. 同一输入两次调用**逐字节相同**（纯函数，无隐藏状态）。

## 4. 本阶段能做什么、不能做什么（必须先说清）

### 4.1 能（纯 PS，当前镜像就能跑）
- 构图、缩放、letterbox、PNG 落盘、写共享缓冲。
- 用 `cv2`/`PIL` 把结果显示到**终端以外的任何地方**（文件、网络回传、Jupyter）。

### 4.2 不能（**纯 PS 上不了屏**，这是硬件/镜像事实）
- 当前 PYNQ 镜像只有 `/dev/dri/card0` = `zyxclmm\_drm`（ZOCL 加速器）
- **没有任何显示驱动**：无 `/dev/fb*`、无 HDMI connector、内核只有 `CONFIG\_DRM\_XLNX`
- AX7015B 的 HDMI-OUT 走 PL（TMDS 或 ADV7511 类芯片） ⇒ **PS 无法凭空产生**\Rightarrow\ \Rightarrow\ \textbf{"纯 PS" 阶段的事实是：能生成正确的画面，但还不能点亮显示器}- ### 4.3 因此本阶段的验收判据是"画面正确"，不是"上屏" 1. 4 种显示模式各生成一张 PNG，人眼确认：左原图 / 右处理图 / 上下黑边居中 / 无拉伸变形。 2. 像素级判据（脚本自检）： - 左上角像素 == `orig[0,0]`；右侧第一列像素 == `proc[0,0]`； - 第 0 行与第 `H-1` 行全黑；黑边高度 == 公式算出的 $y_0$； - 输出中不存在第三种来源（用"左右两张纯色图"当输入即可机械验证）。 3. 上板：同一份代码在板端跑通，产出 PNG 并 `md5` 与主机一致。 --- ## 5. 后续上屏的最小改动（不在本阶段做，只先定契约）\Rightarrow\ \text{PS 已经把整幅显示画面烘好} \Rightarrow \text{PL 以后只需要一个"拍缓冲"模块：}$$
$$\Rightarrow\ \text{DDR 帧缓冲 } \to \text{读成 AXI-Stream（按行）} \to \text{VTC 时序} \to \text{TMDS 编码 + OSERDES}$$
$$\Rightarrow\ \textbf{PL 里不需要缩放大器，也不需要懂 letterbox} \Rightarrow \text{比原方案 C 更简单}$$
$$\Rightarrow\ \text{代价：}DDR\ \text{每帧要读一整个显示缓冲}（1080p30 = 186\ \text{MB/s}）$$
$$\Rightarrow\ \text{而方案 C 只需 }6\ \text{MB/s} \Rightarrow \textbf{差别在于"谁来放大"}$$
$$\Rightarrow\ \textbf{结论：先按纯 PS 走通画面，}DDR\ \text{的 186 MB/s 在 46\% 余量内，够；}$$
$$\Rightarrow\ \text{若以后要 30 fps 实时刷新再考虑把放大搬回 PL。}$$
