## 2. 资源：三段拆分正好等于总量

- 20255 (v57) + 971 (HDMI 层次) + 483 (新增胶合) = **21709** ≤ 22000

| 项 | v57 | v58 | delta |
|---|---:|---:|---:|
| Slice LUT | 20255 | **21709** | +1454 |
| Slice FF | 18961 | 20668 | +1707 |
| BRAM (Tile) | 35 | **36.5** | +1.5 |
| DSP | 101 | **101** | 0 |
| `BUFGCTRL` | **2** | **8** | +6 |

- `BUFGCTRL` = 2（FCLK0 的 BUFG + 复位桥）+ 6（1 clkfb + 3 像素 + 2 `BUFGMUX`）
- **8 而不是 9** ⇒ 按"7+2"会把复位桥算两遍（此前的口径错误，已勘误）

## 3. ★ 本轮真正卡住的两个问题（都不是 HDMI 引起的）

### 3.1 v57 的 BD 源**本身不可 validate**
- 现象：`ERROR [BD 5-336] BD-design is locked`（`design_1_bin_unit_0_9` / `design_1_conv_uni_0_9`），
  `report_ip_status` 报 `Incompatible IP data detected`
- 根因：`pl/ip_repo` 里的 `bin_unit_axi_wrap_bd` / `conv_uni_axi_wrap_bd` **后来被重新打包成 AXI3 主口**
  （`m_axi_arlen` 4 bit + 新增 `m_axi_wid`），而两个 `_9` 的 xci 存的是 v57 时的 AXI4Lite(s_axi)/AXI4(m_axi, LEN 8)
- 为什么一直没暴露：**v57 位流用 `.gen` 产物 build，从不 validate BD**
- `upgrade_ip` 是死路（实测）：主口一改成 AXI3，`pc_conv_bin` 立刻 `ERROR [BD 41-241] MI_PROTOCOL AXI3 out of range`
- **解法**：把 **v57 自己生成的那层 wrapper**（`…/ip/design_1_<ip>_9/synth/*.v`，自带完整 `X_INTERFACE` 与
  `.AXI_ID_W(4)/(6)`）做成 **module reference** 使用 ⇒ cell 名/连接/地址全不变，接口与 v57 位流逐项一致
  - 产物：`pl/vivado/hdmi_v58/rtl/eng/{bin_unit_v57_wrap,conv_uni_v57_wrap}.v`
  - 只改三处：module 名 / 去跨工程 `CLK_DOMAIN` / 去 IP 专有属性
  - 附带档案：wrapper 的 `m_axi_arlen[7:0]` 接 RTL 的 `[3:0]`（高 4 位恒 0）是 **v57 既有行为**，刻意保留未"顺手修"

### 3.2 BD 内 IP（IPI core）不能单独 `synth_ip`
- `synth_ip` / `create_ip_run` 一律 `ERROR 12-3424`
- `pc_conv_*` / `auto_pc*` 的 DCP 只能由**整 BD 综合**产出 ⇒ 缺 DCP 时 merge 脚本跑一次工程 `synth_1`
- `auto_pc` 与 v57 **配置参数集合完全相同**（xml 归一化签名 60 项逐项相等）⇒ 按"配置同一性"借用 v57 的 DCP
- merge 脚本最后按 `design_1.v` **实际例化**的模块名生成 `bd_ip_index.txt`
  （7×dcp+stub / 4×wrap / 1×inline），build 只读索引，**不写死名字**（v57 的 build 就是写死了 6 个名字）

## 4. 关键决策回顾（为什么 HDMI 时钟不用 PS FCLK）

- HDMI 的 MMCM 由**板上 50 MHz 晶振（Y14，BANK13 MRCC）**驱动
$$\Rightarrow\ \text{VCO} = 50 \times 23.75 = 1187.5\ \text{MHz} \Rightarrow \div8 / \div16 / \div32 = 148.4375 / 74.21875 / 37.109375$$
- **彻底绕开两件事**：① PYNQ `Clocks` 报数与真值 1.5 × 偏差；② 本 BD 的 IO PLL=1800 与 HDMI 位流的 1000 不同
- HDMI 的 AXI 侧**共用 FCLK0**（不另起时钟域，免跨域）
- 带宽：扫描器行内需 111 MB/s；FCLK0 实跑 75 MHz ⇒ 225 MB/s ⇒ **2 × ** 余量
- **但 1080p60 需要 ** 445 MB/s ⇒ **合并后一定不支持** ⇒ 只做 720p30/720p60

## 5. 剩余风险（交给上板的人）

| 风险 | 判据 / 应对 |
|---|---|
| **50 MHz 晶振是否起振** | 这是**唯一没有本地证据的硬件假设**（手册已核实 Y14）。上板第一步读 `0x30[0]` 心跳，100 ms 窗口 ≥5 个沿；不足 ⇒ 立刻停，退回 PS FCLK 方案（MMCM 输入要重做） |
| `FCLK0` 余量只剩 **+0.100** | v57 是 +0.206。再往 BD 里加任何逻辑前必须先看这条 |
| `clk_pix_a` 余量 **+0.961** | p1 是 +1.500；少掉的 0.539 来自 v57 逻辑 + BUFG 级联（−0.295）。切 1080p60 时留意 |
| LUT 余量 **291** | 22000 − 21709。再加东西就会顶到上限 |
