# 演示握手协议 v1（相机 → 板端）

> 用途：演示视频里由相机制造"开始信号"，板端收到后以 **1 秒 1 帧**循环轮播"左右对比图对"。
> 这份文档可以直接发给相机侧的同事照做。**板端由我们实现，相机侧只需按本文发命令。**

---

## 1. 一句话

- 相机通过 TCP 连到板端 9999 端口 ⇒ 发一行 `START`
- 板端在 1 s 内开始播放 ⇒ 每对图停 1.000 s ⇒ 循环

## 2. 链路（**已实测确定，以 `11_相机连接与IP_权威参考.md` 为准**）

| 项 | 值 |
|---|---|
| 板端 | **TCP server**，监听 `0.0.0.0:9999` |
| 相机 | **TCP client**，主动连接 |
| **板端地址（相机要连的）** | **`10.13.148.100:9999`** |
| **相机地址** | `10.13.148.1`（同网段 `/24`） |
| 板端接口 | **`usb1`**（驱动 `cdc_ncm`）—— **不是 `usb0`** |
| 是否自动配好 | **是**：`usb-cam-net.service`（systemd，`enable` + 冷启动 2/2 验证） |
| 编码 | ASCII，每行 `\n` 结尾（`\r\n` 也接受）；**大小写敏感** |
| 空闲超时 | 连接建立后 10 s 无数据 ⇒ 板端关闭该连接 |

$$\Rightarrow\ \textbf{相机侧直接连 } \texttt{10.13.148.100:9999}\ \text{ 即可}$$
$$\Rightarrow\ \text{相机自己的 IP 是 } \texttt{10.13.148.1} \Rightarrow \text{同网段，无需网关}$$
$$\Rightarrow\ \text{实测 RTT } 2.0\sim2.6\ \text{ms}，0\%\ \text{丢包（板端 } \texttt{ping 10.13.148.1}\ \text{两次全通）}$$

$$\Rightarrow\ \textbf{接口名陷阱}：\text{NCM 被注册成 } \texttt{usb1}、\text{RNDIS 才是 } \texttt{usb0} \Rightarrow \textbf{不要按名字硬编码}$$
$$\Rightarrow\ \text{按驱动查找：}\texttt{/sys/class/net/usb*/device/driver} \text{ 软链指向 } \texttt{cdc\_ncm}\ \text{的那个就是 NCM 接口}$$
$$\Rightarrow\ \text{板端已把 RNDIS（}\texttt{usb0}\text{）}\textbf{压下并 flush} \Rightarrow \text{避免两条通道抢默认路由}$$

## 3. 命令表（相机 → 板端）

| 命令（整行） | 板端应答 | 含义 |
|---|---|---|
| `HELLO 1` | `ACK HELLO 1` | 建会话（可选，但建议发） |
| **`START`** | `ACK START <n>` | **开始/继续播放**；`<n>` = 当前已播帧计数 |
| `STOP` | `ACK STOP` | 停止播放，回到彩条 |
| `PING` | `PONG <ms>` | 保活；`<ms>` = 板端 uptime 毫秒 |
| 其他任何行 | `ERR BADCMD <原文>` | 非法命令，不影响现有状态 |

- **最小可用交互** = 连上 ⇒ 发 `START` 一行 ⇒ 收到 `ACK START` ⇒ 结束（可断连）
- 所以相机侧**只实现一条 ** `START` 也能跑通

## 4. 板端主动上报（可选接收）

- 板端在**第一帧真正上屏时**发一行：`EVT FIRST` （timeout 5 s，用于确认"真的开始了"）
- 相机侧可以忽略，也可以打印日志

## 5. 行为规则（避免演示中出现意外）

1. **`START` 幂等**：已在播放时再收到 `START`，回同一个 `<n>`，**不重置进度**
   - 语义澄清：`<n>` 是**已播帧计数**，幂等 ⇒ 同一会话连发两次 `START` 会拿到**相同的 `<n>`**
     （实测均为 `ACK START 27`），**不会递增**、也不会把播放进度打回 0
   - `STOP` 之后再 `START` 属于**新会话**：播放序列从 `order=000` 重新开始，帧计数继续累加
   - 重复 `START` 不会推进 `<n>`，这一点常被误读为"应该 +1"，以此为准
2. **断连不停播**：TCP 断开后板端**继续**轮播（演示中相机掉线不应黑屏）
3. **`STOP` 才停**：只有显式 `STOP` 或进程 `SIGTERM` 才回到彩条
4. **重复连接**：板端**只服务最新一个连接**；旧连接被关闭
5. **不会阻塞**：任何非法输入只回 `ERR`，不中断播放

## 6. 备选链路（相机侧按需选一种）

- **A. TCP（推荐）**：相机连 `<板IP>:9999` ⇒ 发 `START`
- **B. UDP**：相机向 `<板IP>:9999/UDP` 发 `START` ⇒ 板端回 `ACK START <n>` 到源地址
- **C. 文件触发**：相机无网络能力时，板端由人工 `touch /home/xilinx/demo/START.flag`

- USB 网卡的情况：板端需先启用 USB host（新镜像），届时板端 `usb0` 与相机在同一网段，
- IP 会在 `/etc/demo\_net.conf` 里给（默认板端 `192.168.10.2/24`，相机建议 `192.168.10.1/24`）
- **走网口最省事** ⇒ 现在就可用，不用等新镜像

## 7. 相机侧参考实现（Python / MicroPython 均可）

```python
import socket, time

BOARD_IP, BOARD_PORT = "192.168.7.2", 9999

def send_start():
    s = socket.create_connection((BOARD_IP, BOARD_PORT), timeout=3)
    s.sendall(b"HELLO 1\n")
    print(s.recv(64))          # b"ACK HELLO 1\n"
    s.sendall(b"START\n")
    print(s.recv(64))          # b"ACK START 0\n"
    s.settimeout(5)
    try:
        print(s.recv(64))      # b"EVT FIRST\n"（可选，可能超时）
    except socket.timeout:
        pass
    s.close()

send_start()
```

- 相机侧只需这一段 ⇒ 收到 `ACK START` 就说明板端已开始播放

## 8. 联调自检（相机同事照这个验收）

| # | 动作 | 期望 |
|---|---|---|
| 1 | `nc <板IP> 9999`，输入 `PING` | 回 `PONG <ms>` |
| 2 | 输入 `START` | 回 `ACK START <n>`，**屏幕 1 s 内开始出图** |
| 3 | 输入乱码 `XYZ` | 回 `ERR BADCMD XYZ`，**播放不中断** |
| 4 | 输入 `STOP` | 回 `ACK STOP`，屏幕回到彩条 |
| 5 | 断开连接 | **播放继续**（不黑屏） |
