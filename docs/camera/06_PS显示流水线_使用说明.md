# PS 显示流水线使用说明：左原图 / 右处理图 → HDMI（默认 720p30）

> **一句话**：`compose()` 把 `256²` 原图 + `256²` 处理图拼成 `1280×720`（撑满宽度、上下各 40 px 黑边），
> `DisplayPipeline` 把它写进双缓冲的**后台块**，再用 `FRAME_ID` 让 PL 在 **vsync 边界**换帧 ⇒ 无撕裂。
>
> ⚠️ **本支线当前不持有板子**（2026-11-03 起 `192.168.7.2` 已永久移交其他 agent）。
> 本文第 4 节的命令**仅备查、不执行**；等板子空出后由持板方照单执行。
> 判定故障时**优先用寄存器证据**（第 5 节），不要靠"上板试试"。
>
> ⚠️ **前置硬条件**：**需要 P2 位流**（P1 彩条 + `hdmi_fb_scan` 扫描器）。
> **P1 位流只有彩条**——`CTRL[2]=test_pattern` 之外没有扫描器，`enable=1` 也看不到 `compose()` 的画面。

契约来源：`docs/camera/05_HDMI输出_PS_PL接口契约.md`（§2 寄存器图 / §7.2 双缓冲 / §8.2+§8.9 心跳 /
§8.10+§8.11 720p30 / §8.13 PS 侧裁定）、`docs/camera/03_显示构图规范_纯PS.md`（构图）。

## 1. 模块图

```

                 │  pipe = DisplayPipeline(mode=3)        # 720p30                 │
                 │  pipe.setup()  → 预填黑 + 切模式协议 + enable=1                 │
                 │  fid = pipe.show(orig, proc)  → 写后台块 + FRAME_ID+=1          │
                 │  pipe.wait(fid, 0.5)         → 轮询 FRAME_ID_LATCHED            │
                 │  pipe.pix_alive(100)         → 心跳（先于一切 AXI 读，§8.2）     │
                 │  pipe.stats() / close()                                         │
                 └───────────────┬─────────────────────────────────────────────────┘
                                 │ 只调用，不改
        ┌────────────────────────┼───────────────────────────┬─────────────────────────┐
        ▼                        ▼                           ▼                         ▼
 display_layout.compose()   hdmi_out.HdmiOut           hdmi_out.REG / MODES      pynq.allocate
 256²+256² → 1280×720      configure/put/wait/         寄存器偏移 & 模式表        （默认 allocator，
 含 40/40 黑边（纯 numpy）  status/underflow            （几何唯一来源）           只有它 import pynq）
        │                        │                           │
        └────────── 帧字节 (1 280×720×3 = 2 764 800 B) ────────┘
                                 ▼
                    ┌────────────────────────────┐
                    │ 连续双缓冲（一次分配 2×FB_SIZE）│
                    │  块0 @FB_ADDR_LO            │ ← PL 扫  FRAME_ID[0]=0
                    │  块1 @FB_ADDR_LO+FB_SIZE    │ ← PL 扫  FRAME_ID[0]=1
                    └─────────────┬──────────────┘
                                  ▼  AXI-Lite
                    PL：hdmi_fb_scan → 行缓冲 → RGB + HS/VS/DE + pix_clk → SIL9134 → 显示器
```

**数据流（一帧，严格这个顺序）**

```
orig,proc (256,256,3) uint8
   → compose(orig, proc, W=1280, H=720)        # 黑边已烘进缓冲，PL 不懂 letterbox
   → 校验 shape/dtype/字节数                    # 不满足直接 ValueError
   → np.copyto(块[FRAME_ID&1])                 # ① 整帧先落地（+ flush）
   → write32(FRAME_ID, fid)                    # ② 再原子换帧
   → PL 在下一个 vsync 采纳 ⇒ 扫另一块          # 正在被扫的块永不与写入块相同
```

## 2. 地址与块布局（与 RTL 严格一致，改一边必须改另一边）

```
buf        = FRAME_ID & 1
addr       = FB_ADDR_LO + buf * FB_SIZE
FB_SIZE    = align64(FB_STRIDE * FB_H) = align64(3840 * 720) = 2,764,800 B
stride     = W*3 = 3840   （64 的整数倍 ⇒ 行尾无 padding，突发不跨 4 KB）
```

- ⇒ **两块必须一次连续分配**：`allocator(2 * FB_SIZE) = 5,529,600 B`。
  分两次分配会让 `buf=1` 指到别人的内存（现象：右半屏或整屏花）。
- 帧号从 **1** 起：`enable=1` 后 PL 立刻扫块 0，首帧若写块 0 就**边写边被扫**（撕裂）；
  故首帧写块 1 ⇒ 块序 **`1,0,1,0`**（`FRAME_ID` 严格递增）。
- `setup()` 会把**两块都预填黑**（5,529,600 B memset，毫秒级）：否则 `enable=1` 到首帧之间
  屏幕上是未初始化内存的垃圾（雪花）。

## 3. 模式表（`hdmi_out.MODES`，几何唯一来源）

| `VIDEO_MODE` | 分辨率 | 像素时钟（设计 / 板端实测） | H/V 总/有效 | 状态 |
|---|---|---:|---|---|
| 0 | 720p60 | 74.25 / **74.225 MHz** | 1650/1280, 750/720 | ✅ P1 已点亮 |
| 1 | 1080p60 | 148.5 / **148.450 MHz** | 2200/1920, 1125/1080 | ✅ P1 已点亮 |
| 2 | 1080p30 | 74.25 | 2200/1920, 1125/1080 | 未验证 |
| **3** | **720p30** | **37.109375 / ≈37.09 MHz** | 1650/1280, 750/720 | **P2 默认，待板端验证** |

- 720p30 的价值：像素域时序从 13.47 ns 放宽到 **26.94 ns**；行内瞬时带宽 **111 MB/s**
  ⇒ 100 MHz AXI（300 MB/s）余量 **63%**；平均 82.9 MB/s。
- 切模式必须走协议：`enable=0 → 写 VIDEO_MODE → 等 ≥2 整帧 → enable=1`（`_apply_mode()` 已实现，
  720p30 下停 68 ms、720p60 下停 34 ms；判据 6 用事件时间戳实测过）。

## 4. 等板子空出后可执行的命令清单（本支线不持有板子，以下命令**仅备查**）

> 这一节**没有在本支线执行过任何一行**。`192.168.7.2` 已永久移交，本支线不得 ssh/scp/ping/boardlock。

### 4.0 先啃掉交接陷阱：`Clocks.fclk0_mhz` 报数 = 真实值的 **1.5 倍**

本镜像 `hwh` 的时钟树是 IO PLL 1000 MHz、`DIVISOR0=5`、`DIVISOR1=2` ⇒ 真实 `FCLK0 = 100 MHz`，
但 PYNQ 的 `Clocks.fclk0_mhz` **读和写都是真实值的 1.5 倍**：

| PYNQ 报 | 真实 ACLK | 实测像素时钟（720p60） |
|---|---|---:|
| 150 | **100.0 MHz** | 74.23 MHz |
| 100 | **66.67 MHz** | ≈49.5 MHz（= 74.23 × 0.667） |

⇒ **要真实 100 MHz ACLK，必须写 `Clocks.fclk0_mhz = 150`**；写 100 只会得到 66.67 MHz。
⇒ 不要相信 `Clocks` 的报数，**用 `0x30` 心跳反推像素时钟来验证**（下表；720p30 设计 37.109375）：

| 反推的 720p30 像素时钟 | 真实 ACLK | 说明 |
|---:|---:|---|
| **≈37.1 MHz** | 100 MHz | ✅ 正确（`Clocks` 应写 150） |
| ≈24.7 MHz | 66.67 MHz | 写成了 100，带宽/时序全按错的值算 |
| ≈55.6 MHz | 150 MHz | 写成了 225，1080p60 才需要这一档 |

> 反推公式与窗口精度见 §4.3；`pix_alive(2000)` 的误差上限 ≈ ±0.09%，足够分辨上表三档（相差 50%）。

### 4.2 六步（§8.2 的顺序不可调换）

```python
# ---- 仅备查：本支线不持有板子，不要执行 ----
import sys, numpy as np
from pynq import Overlay, Clocks

sys.path.insert(0, "/home/xilinx/demoir/ps/pynq")     # 按实际部署改
import hdmi_out as ho                                  # 只为读 REG["PIX_HB"]
from display_demo import DisplayPipeline

# ① 先把 ACLK 设成真实 100 MHz（本镜像要写 150，见 §4.0），等 ≥100 ms
Clocks.fclk0_mhz = 150

# ② load（唯一 load 令牌）—— 与既有 P1 流程一致
Overlay("hdmi_p2.bit")

# ③ 心跳先行：先把 pipe 建起来，只做心跳，不读其它寄存器
pipe = DisplayPipeline(mode=3)          # 720p30
alive, mhz = pipe.pix_alive(100)        # 有界窗口 ≥100 ms、≥5 个翻转沿
if not alive:
    raise SystemExit(f"心跳不翻（{mhz:.2f} MHz）⇒ §8.2：立刻停，不要再做任何 AXI 访问")
print(f"像素时钟 ≈ {mhz:.2f} MHz（100 ms 只判活；要报精度用 2 s 窗口，见 §4.3）")
print("mmcm_locked(0x30[1]):", bool(pipe._io.read32(ho.REG["PIX_HB"]) & 0x2))   # 见 §5 第 1 行

# ④ 配置 + 预填黑 + enable=1（内部：enable=0 → VIDEO_MODE → 等 2 帧 → 几何 → enable=1）
pipe.setup()

# ⑤ 真画面：原图/处理图各 256²
orig = np.zeros((256, 256, 3), np.uint8)      # ← 换成你的原图
proc = np.zeros((256, 256, 3), np.uint8)      # ← 换成去摩尔纹后的图
fid = pipe.show(orig, proc)
print("adopted:", pipe.wait(fid, timeout=0.5))   # False = 超时（画面仍旧帧，无撕裂）

# ⑥ 诊断：先看寄存器证据，再看画面
print(pipe.stats())     # init_done / vsync / underflow / underflow_cnt / frame_id_latched

pipe.close()
```

> 上面读 `0x30` 用的是驱动的 `reg_io`（`pipe._io`），与 `pix_alive` 读的是同一个寄存器；
> 其余诊断项都在 `pipe.stats()` 里（`init_done` / `underflow` / `frame_id_latched`）。

### 4.3 如果要更准的像素时钟

| 窗口 | 720p30 沿数 | 精度 | 用途 |
|---:|---:|---:|---|

## 5. 故障对照表（**先读寄存器证据，再谈上板**）

寄存器偏移见 `hdmi_out.REG`；`0x30` 的读法见 §4.3。**右列标 ⚠️ 的才是"寄存器判不了、必须上板"的。**

| 现象 | 寄存器证据（读到什么 = 什么结论） | 处理 |
|---|---|---|
| **全黑** | ① `0x30[0]` 100 ms 内 <5 个沿 ⇒ 像素时钟没跑 ② 同时看 `0x30[1]`：0 = MMCM 没锁、1 = 锁了但不翻（拓扑/复位问题） | ①成立 ⇒ **立刻停**，不要再做任何 AXI 访问（§8.2）；先查 §4.0 的 ACLK 口径 |
| **全黑但心跳在翻** | `0x04[0] init_done`：0 = SIL9134 I2C 没配完；1 = 配置完了 | 0 ⇒ BD/复位/`sil9134_init` 问题，**不是 PS 驱动问题**（PS 驱动此时还没动过 `0x0C`~`0x1C`） |
| **全黑 + init_done=1** | `0x00[0] enable`：0 = 扫描器没使能；1 = 使能了。再看 `0x00[2]`：1 = 还在彩条模式 | 0 ⇒ `setup()` 没走完 / 被 `soft_reset`；`[2]=1` ⇒ 先 `test_pattern(False)`；两者都正常 ⇒ 见下一行 |
| **全黑 + enable=1 + init_done=1** | `0x24 FRAME_ID_LATCHED` 是否跟着 `0x20 FRAME_ID` 变：**不变** = PL 没在 vsync 采纳（P2 扫描器没出 vsync）；**变了** = 数据到了显示侧 | 不变 ⇒ 位流不是 P2 / 扫描器没起；变了仍黑 ⇒ P1 侧（时序/引脚/SIL9134）⚠️需上板 |
| **花屏 / 雪花 / 半屏垃圾** | `0x0C FB_ADDR_LO` 是否等于本次分配的 `pipe.fb_addr`；`0x14/0x18/0x1C` 是否 `3840/1280/720`；分配请求是否 `2×2,764,800` | 地址/几何不符 ⇒ 别处写过寄存器或分两次分配；`setup()` 未预填 ⇒ 首帧前是未初始化内存 |
| **撕裂（上下错开一条）** | 寄存器只能给**间接证据**：`0x24` 只在 vsync 变（说明采纳点对）、`0x20` 每次 `+1`（说明没跳号） | 直接证据是主机判据 3（写块 seq < 写 `FRAME_ID` seq + 换帧瞬间 md5）；顺序反了 / 只分配一块 ⇒ 必撕 |
| **只有左或右半屏有内容** | `0x18 FB_W=1280`、`0x14 FB_STRIDE=3840`、`0x1C FB_H=720`；`0x08 VIDEO_MODE` 与这些是否匹配 | 不符 ⇒ 写了别的模式；几何对 ⇒ 检查是否真调了 `compose(orig,proc,1280,720)` 而不是自己缩放 |
| **画面变形 / 黑边高度不对** | `0x08 VIDEO_MODE` ⇒ 期望几何：0/3 = 1280×720（黑边 40/40）、1/2 = 1920×1080（60/60） | 与 `0x18/0x1C` 不一致 ⇒ 配置没写完就 `enable=1` |
| **欠载：`0x2C > 0`** | `0x2C UNDERFLOW_CNT`（按行累加）与 `0x04[2]`（粘滞位）；配合 `0x08` 模式与心跳反推的像素时钟算行内带宽 = 3 B × f_pix | >0 ⇒ 带宽不够：1080p60 在 100 MHz AXI 下**必然** >0；降到 720p30（111 MB/s，余量 63%）或提 AXI 频率 |
| **切模式后花屏/闪黑** | `0x08` 是否已等于目标模式；心跳反推的像素时钟是否等于该模式的期望值（mode3≈37.1 / mode0≈74.2 / mode1≈148.45） | 反推值还是旧模式的 ⇒ BUFGMUX 没切（写了 `VIDEO_MODE` 但没先 `enable=0`）或模式号写错 |
| **`wait()` 一直 False** | 直接比 `0x20` 与 `0x24`：不等 ⇒ PL 没采纳；相等 ⇒ 已采纳 | 不等 ⇒ 扫描器没在 vsync（P2 未生效/位流错）；画面仍旧帧、**无撕裂** |
| **颜色错（红蓝互换）** | `0x28 PIXEL_FMT` 必须为 `0`（RGB888，字节序 R,G,B） | 非 0 ⇒ 写错；为 0 仍错 ⇒ 扫描器取字节序问题 ⚠️需看 RTL |
| **心跳反推频率偏差 >1%** | `pipe.stats()["pix_window_ms"]`：窗口多长决定该有多少误差（100 ms 就 ±1.8%） | 窗口够长仍偏 ⇒ 按 §4.0 表反推 ACLK 是否被 1.5× 口径坑了 |
| **彩条也没有（P1）** | `0x04[0]=1` 的情况下仍无彩条 ⇒ 寄存器已无信息量 | ⚠️**必须上板**：示波器看 `pix_clk` / HS/VS 极性 / 抓 I2C 确认 SIL9134 真收到配置（属 P1 范围） |

## 6. 交接事实（写清避免下一个人重踩）

   旧名 `MODE_640X480P60` 保留为兼容别名（值仍是 3，但语义已变，别再用旧名）。
3. **`0x30 PIX_HB` 已入 `REG`**（`REG["PIX_HB"]`），`hdmi_selftest.py` 的寄存器表同步到 13 条。
4. **几何/偏移只有一个来源**：`hdmi_out.MODES` / `hdmi_out.REG`；`display_demo` 里没有任何本地副本。
5. **`display_layout.compose()` 未改**（已板端验证）：黑边由它烘进缓冲，PS 侧不许自己缩放。
6. **板子不归本支线**：`192.168.7.2` 已永久移交（2026-11-03），本支线只做主机侧交付。

| 4 | 参数校验 | 18 种坏输入全部抛（ValueError/RegError），无静默降级 |

| 7 | 三图案 × 两模式 | 720p30/720p60 各 3 图案逐字节一致；1080p60 6,220,800 B 亦一致 |
| 8 | `setup()` 后两块全黑 | 5,529,600 B 全零，`prefill` 早于 `enable=1` |

> 判据 1~3 是"为什么这套实现可信"的核心：**字节全量比** + **块序交替** + **换帧瞬间快照**。
> 判据 5 用**物理自洽**的假 `0x30`（按真实流逝时间推进像素时间轴），否则"沿数 × 2¹⁶ / 墙钟秒数"
> 测出来的是假对象的读次数，不是像素时钟。
