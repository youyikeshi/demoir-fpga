## 1. 定点契约总览

| 量 | 格式 | 位宽 | 定义在哪 | 备注 |
|---|---|---|---|---|
| 激活 $x_q$ | **Q(5.10) int16**（研究默认）/ 逐层自适应 fx | 16 | `Fmt.fx` | 逐层指数是免费的（一个寄存器） |
| 阈值 $t_q$ | 与激活同标度 | 16 | `BinConvParams.t_q` | 逐输入通道，打包**前**加 |
| 权重 | 1 bit | 1 | `wbits` | bit=1↦+1，bit=0↦−1 |
| 激活位 | 1 bit × 64/字 | 1 | `pack_bits` | 沿通道打包 |
| 内层累加 | int | ≤17 | `xnor_inner` | 一个 tap 一个 popcount |
| $\beta_q$ | **Q0.5，5 bit**（0..31） | 5 | `Fmt.fb` | 实测 3 bit 太粗，见 §4 |
| $\alpha_q$ | Q1.15 尾数 + 逐层指数 `alpha_exp` | 16+5 | `BinConvParams.alpha_q/alpha_exp` | **块浮点**，见 §3.3 |
| $\alpha\!\cdot\!\text{bias}$ | 与输出同标度 | 24 | `bob_q` | 把 bias 折进输出域 |
| RPReLU $\zeta,\gamma$ | 与输出同标度 | 16 | `zeta_q/gamma_q` | |
| RPReLU slope | Q(7.8) | 16 | `slope_q` | 实测 6~12 位都没差别 |
| 累加器 | int32 | 24 够用 | — | 实测最坏 \|acc\|=23040=17 bit |
| 输出 $y_q$ | 同输入标度 | 16 | `BinConvInt` | 可直接串级 |

**舍入规则（全篇统一）**：

$$\text{round\_shift}(x,s)=\big(x+2^{s-1}\big)\gg s,\qquad \gg=\text{算术右移（向 }-\infty\text{）}$$

即"加半后算术右移"。`.5` 一律向 $+\infty$ 舍入（负数也如此：$-1.5\to-1$）。RTL 用一条加法 + 一条算术右移即逐位相同；numpy/Python 的 `>>` 对负数的行为与之一致（`tools/bin_ref_model.py: round_shift`）。

## 2. [BIN] 二值化：$t$ 阈值怎么加

$$\text{bit}(y,x,c)=\begin{cases}1\;(+1)&x_q(y,x,c)+t_q(c)>0\\0\;(-1)&\text{otherwise}\end{cases}$$

四条必须写死的细节：

1. **$t$ 是逐输入通道的**（`self.t` 形状 `(1,cin,1,1)`），所以是"每通道一个 int16 加法"，加在**打包之前**、$x_q$ 上，不是加在累加器里。
2. **顺序不可交换**：先 $x_q+t_q$ 再比较。若先比较再补偿，补不回来。
3. **零点归 −1**（判据是 $>0$）。torch 的 $\mathrm{sign}(0)=0$ 表达不出来——见 §5。
4. $t_q$ 与 $x_q$ 必须**同标度**：$t_q=\mathrm{round}(t\cdot2^{f_x})$，$x_q$ 先量化再相加。

```python
def binarize_bits(x_q, t_q):                     # tools/bin_ref_model.py
    z = x_q.astype(np.int32) + t_q.reshape(1, C, 1, 1)
    return (z > 0).astype(np.uint8)
```

## 3. [XNOR] 内层、外层、尾巴

### 3.1 XNOR-popcount 与 $\sum WX$ 的关系

位编码 $a,w\in\{0,1\}$ 表示 $a',w'\in\{-1,+1\}$，则

$$n_{\text{eq}}=\text{popcount}(a\ \text{XNOR}\ w),\qquad \sum_i a'_iw'_i=2n_{\text{eq}}-n$$

**三层修正，逐层叠上去**：

| 情形 | 修正 | 常数 |
|---|---|---|
| 恰好 $n=64$（`cin=64`，k=1） | 无 | $n=64$ |
| $n<64$（补位，§01 篇 4.3） | 补位恒"相等" ⇒ 多算 $2n_{\text{pad}}$ | $C_{\text{const}}=k^2(2n_{\text{pad}}+c_{\text{in}})$ |
| 空间越界（conv padding） | 界外 tap 白送 $-\sum_{ic}\beta_{ic}w$ | 查表 $W_\beta[oc,t]$，见 §3.2 |

```python
# 单 tap 的常数扣减；bypass 通路最后一次性减 C_const
sum_wx = 2 * popcount(~(a ^ w)).sum() - C_const
```

**验证**：T1（`--self-test`）在 `cin ∈ {8,48,64,65,96,160}` × 含补位 × 含边界修正上，与"直接按 ±1 求和"**逐位差 0**。

### 3.2 空间越界的修正表

$$W_\beta[oc,t]=\sum_{ic}\beta_{ic}\,w_{oc,ic,t}\quad(\text{gated}),\qquad S_w[oc,t]=\sum_{ic}w_{oc,ic,t}\quad(\text{bypass})$$

```python
acc = acc + (oob_mask @ W_beta.T).T      # oob_mask: (Ho*Wo, k²) bool
```

bypass 通路 $S_w$ 在权重量化时算好（**运行期零成本**）；gated 通路每图每层算一次，代价 $c_{out}k^2c_{in}$ 乘加 ≈ 一个输出像素。

### 3.3 外层：$\beta$ 与 $\alpha$

$$\text{acc}_{oc}=\sum_{\text{tap}}\Big[2\sum_{j=0}^{f_b}2^j\,\text{popcount}(m\&B_j)-B_{\text{tot}}\Big]\quad\text{（gated，等价于 }\sum_{ic}\beta_{ic}\text{inner}_{oc,ic}\text{）}$$

**为何用位平面而不用逐 ic 乘法**：见 01 篇 §5（便宜 4.7 倍，零 DSP）。**为何这是"等价"而不是"近似"**：$m$ 是 64 位"位相等"掩码，$\sum_{ic}\beta_{q,ic}m_{ic}=\sum_j2^j\text{popcount}(m\&B_j)$ 是恒等式（$\beta_q$ 的二进制分解）。T2 逐位验证：差 = 0。

**$\alpha$ 用块浮点**——这是踩过坑的地方：

$$\alpha=\alpha_q\cdot2^{-\alpha_{\text{exp}}},\qquad \alpha_{\text{exp}}=f_a-\big\lfloor\log_2\max_{oc}|\alpha|\big\rfloor$$

$\alpha_q$ 是 Q1.15 尾数，$\alpha_{\text{exp}}$ 是逐层指数（5 bit 寄存器）。这样最大的那个 $\alpha$ 用满 16 位量程，而 $\alpha$ 层内跨度 10 倍时最小通道仍有 13 位有效 ⇒ 相对误差 ≤0.01%。

> ⚠️ 我先写错过一次：`alpha_exp = fa + floor(log2(amax))` 少了 2 倍，导致实测层里出现 **2.7% 的纯 $\alpha$ 量化误差**（本该是 0.003%），一度被误判成"激活量化不够"。固定指数（不用块浮点）在 $\alpha\in[0.008,0.076]$ 这一档里必然犯这个错。**记录在此**。

### 3.4 [POST] bias 与 RPReLU 怎么并进累加器

三件事一件一件地并：

$$\text{out}=\alpha\Big(\sum_{ic}\beta_{ic}\text{inner}+\text{bias}\Big)\;\overset{\text{①}}{=}\;\alpha\sum_{ic}\beta_{ic}\text{inner}+\underbrace{\alpha\cdot\text{bias}}_{\text{预乘成 }bob_q}$$

$$\text{RPReLU: }f(y)=\begin{cases}y-\zeta+\gamma,&y>\zeta\\ \text{slope}(y-\zeta)+\gamma,&\text{otherwise}\end{cases}\;\overset{\text{②}}{=}\;\begin{cases}y+(\gamma-\zeta)&\\ \text{slope}\cdot y+(\gamma-\text{slope}\zeta)&\end{cases}$$

于是整条尾巴只有**一次乘法**（$\alpha$）和**一次比较**：

$$\boxed{\;z_q=\text{round\_shift}\big(\text{acc}_q\cdot\alpha_q,\;\alpha_{\text{exp}}+f_b-f_x\big)+bob_q\;}$$

$$d_q=z_q-\zeta_q,\qquad y_q=\begin{cases}d_q+\gamma_q&d_q>0\\ \text{round\_shift}(\text{slope}_q\cdot d_q,\,f_s)+\gamma_q&d_q\le0\end{cases}$$

**四个要点**：

1. `acc` 的单位是 $2^{-f_b}$（gated）或 1（bypass）⇒ 移位量里必须加 $f_b$。**这也是我踩过的坑**：漏了 $f_b$ 时输出整体放大 8 倍（相对误差 660%），而 T1/T2 全过——因为它们是纯整数比较，不看尾巴。
2. `bob_q = round(α·bias·2^{f_x})` 在导出时算好（PS 一次），**不需要在累加器里加 bias**。若硬把 bias 加进累加器，$f_b=3$ 时 bias 的最小分辨率是 1/8，而实测 |bias| ≤ 0.152 ⇒ 会被量化成 1，误差 40%。**这就是为什么要预乘**。
3. $d_q=0$ 时两分支同值（$\gamma_q$），与 torch 的 `where(d>0,...)` 无歧义。
4. RPReLU 作用在**$\alpha$ 缩放之后**的值上（模型里是 `conv(...)*alpha` 再 `act()`），所以比较点是 $z_q$ 不是 `acc`。

## 4. 误差预算（实测，全部来自 `tools/bin_ref_model.py`）

### 4.1 目标值怎么定的

论文的组件增益：MABG ≈ +0.8 dB、SGRA ≈ +1.3 dB、两者 +1.6 dB（`repro.md` §"五级阶梯"）。量化噪声必须**显著小于最小增益**，否则"L2 没达标"会分不清是门控没生效还是量化太粗。

$$\textbf{定：单层 RMS 相对误差} \le 2\%,\quad \textbf{单层最大} \le 10\%,\quad \textbf{整网 PSNR 掉点} \le 0.2\ \text{dB}$$

### 4.2 逐位正确性（这些必须是 0，不是"很小"）

| 测试 | 内容 | 结果 |
|---|---|---|
| T1 | popcount 恒等式：$\text{cin}\in\{8,48,64,65,96,160\}$ × 补位 × 边界修正 | **差 0** |
| T2 | $\beta$ 位平面通路 ≡ 逐 $(oc,ic)$ 乘加定义式 | **差 0** |
| T3 | numpy ±1 精确代数 ≡ PyTorch（fp64） | **0.00e+00** |

T3 为零不是巧合：±1 内积在 float64 里是**精确整数**，再乘同一个 $\alpha$ ⇒ 两路完全同位。这条给了"参考模型的浮点侧没有写错"的硬证据。

### 4.3 定点化误差（合成用例，`--self-test`）

| 配置 | 用例（$\text{cin}$,k,$\beta$） | 最大绝对 | 相对 | RMS |
|---|---|---:|---:|---:|
| fx=10,fb=3 | 48,3,无β | 1.00 | 2.55% | 2.85% |
| | 48,3,β | 1.75 | 7.71% | 7.12% |
| | 32,1,无β | 1.14 | 12.13% | 3.26% |
| | 64,3s2,β | 1.73 | 8.17% | 7.43% |
| | 96,3,β | 1.93 | 5.84% | 6.87% |
| **fx=12,fb=5（推荐）** | 48,3,无β | **5.3e-2** | **0.134%** | 0.118% |

### 4.4 位宽扫描（`--sweep`，3 用例的 相对误差 均值/最大）

| 扫的项 | 取值 → (均值 / 最大) |
|---|---|
| 激活 $f_x$ | 8: 7.92/9.99% · 10: 6.74/9.24% · 12: 6.59/9.24% · 14: 5.72/9.24% |
| $\alpha$ 小数位 $f_a$ | 10: 6.60/9.23% · 12: 6.59/9.24% · 15: 6.59/9.24% · 17: 6.59/9.24% |
| **$\beta$ 位数 $f_b$** | 2: 13.38/18.72% · **3: 6.59/9.24%** · **4: 3.56/4.19%** · **5: 2.11/2.80%** · 6: 1.47/2.80% |
| RPReLU $f_s$ | 6 / 8 / 10 / 12 全部 **6.59/9.24%**（无影响） |

（上表以 $f_x=10,f_b=3$ 为基准，只改一行的那一项。$eta$ 从 3 提到 5 位，误差减 3.1 倍；再提到 6 位只再减 0.4%，**边际收益在 5 位处拐弯**——这就是选 5 的定量依据。）

$$\Rightarrow\ \beta\ \text{是唯一的主导项};\quad \alpha\ \text{与 slope 几乎免费};\quad f_x\ \text{只在} \beta\ \text{修好后才显出作用}$$

（$f_x$ 那一行看起来"没用"是因为 $f_b=3$ 的误差盖住了它——把 $f_b$ 提到 5 之后，$f_x=10\to12$ 让无 β 层的误差从 2.6% 掉到 0.13%，跌了 20 倍。**先修 β，再调 $f_x$**。）

### 4.5 真实权重 + 真实激活（60 层，**5 epoch** 的 checkpoint）

`runs/bin_base/net_checkpoints/checkpoint_000005.tar`，每层取 64×64 子图（边界修正一起被验到），fmt 默认 $f_x=10,f_b=3$：

| 标度策略 | 相对误差 中位 | 最大 | 二值化位翻转率 最大 |
|---|---:|---:|---:|
| 固定 $f_x=10$（全局一个） | 4.43% | 9.83% | 8.86e-3 |
| **逐层自适应** $f_x$ | **1.70%** | **8.35%** | **1.15e-3** |

$$\text{逐层标度：}f_x=\mathrm{clip}\Big(15-\Big\lceil\log_2\frac{\max|x|}{0.9}\Big\rceil,\;6,\;14\Big)$$

227 层的自适应 $f_x$ 分布：**12 → 122 层，13 → 45，14 → 43，11 → 15，10 → 2**。

**两条结论**：

1. **误差几乎完全由"二值化位翻转"决定**——实测里位翻转率为 0 的层，误差是 0.002~0.004%（纯舍入）；有翻转的层，误差 ≈ 翻转数 × $2\alpha$。所以"定点化误差"= "阈值附近翻转了多少个元素"，不是"每一层都平滑地损失一点精度"。
2. **误差随 $f_x$ 提高而下降的机理就是翻转率下降**（8.86e-3 → 1.15e-3，掉 7.7 倍）。$f_x$ 给得越细，$|x+t|$ 落在 1 LSB 内的概率越小。

**最坏的 5 层**（自适应标度后）：都是 $c_{\text{in}}=48$ 的 k=1 `primary_conv`（8.35% / 6.39% / 5.66%）与 `encoder_1.down`（5.82%）。k=1 层的分母（$\max|y|$）小，同样的单个翻转占比就大 ⇒ **k=1 层要单独给更细的 $f_x$**，这是硬件上零成本的一条（层表里本来就有这个字段）。

### 4.6 零点（$x_q+t_q=0$）

$$\text{torch: }\mathrm{sign}(0)=0\;\Rightarrow\;\text{该 tap 贡献 }0;\qquad \text{硬件只有 }\pm1\;\Rightarrow\;\text{规定归 }-1$$

- 实测零点出现率 **1e-4 ~ 4e-4/元素**（合成用例 @$f_x=12$ 是 1/11520=8.7e-5，@$f_x=10$ 是 3.5e-4），随 $f_x$ 增大按 $2^{-f_x}$ 下降；比"位翻转率"低一个数量级（翻转只要求 $|x+t|<1$ LSB，零点要求恰好等于某一个整数）。
- 单个零点的代价是**半个翻转**（$\pm w$ 而不是 $\pm2w$）。
- 训练时 `sign(0)=0`、推理时归 −1 ⇒ 这是一个**系统性半 LSB 的阈值负偏**，学到的 $t$ 会自动补偿掉一部分。**不做特殊处理，已量化在此。**

### 4.7 累加器溢出

$$\max|\text{acc}|=2^{f_b}\cdot\max(c_{\text{in}}k^2)=8\times 2880=23040\;\Rightarrow\;17\ \text{bit}$$

取 **24 位有符号**（含符号位与增长余量）。$f_b$ 若提到 5，$\max|\text{acc}|=32\times2880=92160$ ⇒ 18 bit，24 位仍然够。（$f_b=6$ 且将来若做"$\beta$ 全层"的话要复查。）

## 5. 验证计划：五级阶梯

每一级都**只与上一级比**，判据是"逐位相同"，不是"误差很小"。这是 `docs/rtl_hand/00_SPEC_接口契约.md` 已经验证过有效的做法（k5/k3/k1 三个引擎都是这么上线的）。

| 级 | 对象 | 输入 | 判据 | 不过怎么办 |
|---|---|---|---|---|
| **L0** | 整数参考模型自身 | 随机小形状 | T1/T2 **差 = 0**；T3 = 0；T4 报告值落在 §4.1 目标内 | 改模型，不许改判据 |
| **L1** | 单个 64-lane 内核 + 行缓冲 | 单层激活 dump（覆盖 $k\in\{1,3\}\times$ stride$\in\{1,2\}\times$ pad$\in\{0,1,2\}\times$ dil$\in\{1,2,3\}$ $\times$ $\beta$ 有/无 $\times$ $c_{\text{in}}\in\{32,48,64,160,544\}$） | 与 `bin_ref_model` **逐字节 0 差异** | 99% 是补位常数 $C_{\text{const}}$ 或越界修正表的符号搞反 |
| **L2** | 两个引擎串联（二值 → 二值、二值 → int8） | 1-bit 打包→解包→再打包 | 位流逐位相同；中间不发生"补位被当真值" | 查打包时的 `cin` 尾部处理 |
| **L3** | 整网 227 层 | 一张真图（320²） | 与 numpy 金标准**逐位 0 差异**（比对全部 227 层输出，不只最后一层） | 用"逐层二分"定位第一个不一致的层 |
| **L4** | 板上 | UHDM 评估集 | ① 逐字节等于 L3 的板外结果；② PSNR 相对 PyTorch fp32 掉点 **≤0.3 dB** | ①②分开查：①是数据搬运，②才是数值 |

**L1 的用例集必须包含这三类"容易过不了"的**：

1. $c_{\text{in}}$ 不是 64 的倍数（48/32/160/544）——补位常数错就全错，而 `cin=64` 的层会"碰巧对"。
2. **dilation=2/3 的层**（SAM 的 `d_list=(1,2,3,2,1)`）——行缓冲深度按 3 行做的会静默错。**我写参考模型时就漏了 `dilation` 参数一次**（表现为输出尺寸 66 vs 64）。
3. stride=2 的层 + 一个角像素/一个边像素（验越界修正表）。

**L4 的 ②（掉点）需要训练完成的模型才有意义**。用 5 epoch 的 checkpoint 测出来的 PSNR 没有参考价值，只能验①。

## 6. 风险与未决项

按"会不会改变硬件设计"排序：

| # | 风险 | 影响 | 现在的处置 |
|---|---|---|---|
| 1 | **全部误差结论建立在 5 epoch 的 checkpoint 上** | 若最终模型 $\max\|x\|$ 更大 ⇒ int16 饱和；若激活更集中在 0 附近 ⇒ 翻转率更高 | `--real` 一条命令重跑；**这是唯一的前提性风险** |
| 2 | **MABG 的落点没定**（5 层 vs 1/3 层） | 外层 $\beta$ 从 0.472 G → 16.6 G；popcount 倍增 $(f_b+1)$ 次 ⇒ **LUT 需求 ×6** | §01 篇 §5.2 的方案 B 把代价压到 +20 ms（5 层）/ +120 ms（全层），但 LUT 仍然要吃 |
| 3 | SGRA 是 block-diagonal **全精度**投影（0.727 G，占全精度算力 46%） | 已计入 1.84 s；不是二值引擎的事 | 若以后想把 SGRA 也二值化，要重训——**不建议**，它是一条"对齐捷径"，二值化会破坏它存在的前提 |
| 4 | $t$ 是"可学习但在推理期是常数" | 导出一次即可；但若做**逐图在线校准**（按输入统计调 $t_q$）就要重写、且会破坏逐位可比 | 明确：**$t_q$ 在推理期只读**。在线校准留作以后的研究项 |
| 5 | 逐层自适应 $f_x$ 依赖校准集 | 引入数据依赖；换数据集要重算 | 层表里加一列 $f_x$；用 3~5 张图的 $\max\|x\|$ 的 99.9 分位，不用全量 |
| 6 | $\beta$ 的 $f_b$ 定 5 而不是事实 2 的 3 | 多 2 次 popcount（+40% gated 层开销） | 待 L2 阶段用整网 PSNR 复核：若 2.1% 的误差对 PSNR 影响 <0.05 dB，可以降回 4（3.6%）或 3（6.6%） |
| 7 | 二元激活的**量化噪声不可逆**（不像权重可以靠训练吸收） | 位翻转是硬错误 | 已在 §4.5 量化；靠"逐层标度 + 关键层加宽"缓解，不靠训练 |
| 8 | 打包沿通道 ⇒ $c_{\text{in}}<64$ 的层有 16.9% 浪费 | 只影响 45 个 `cin=32` 层（5.2% MAC） | 明确**不做** 32-bit 第二通路（§01 篇 4.4） |
| 9 | 1-bit 写回的事务数 | 一行 1 通道组只有 48 字节（$c_{\text{in}}=384$ 时）⇒ burst 够长；但 $c_{\text{in}}=32$ 时只有 4 字节 | 按"整行同通道组"打包，最小 burst = 64 像素 × 4 B = 256 B，够 |
| 10 | `beta_ste` 训练中漂到 clamp 上限（10） | 只影响反向；推理期 $\beta$ 由 MABG 的 sigmoid 给出，与 `beta_ste` 无关 | 无需处置，仅记录以免误判 |

## 7. 怎么用这份东西

```bash
# 1) 逐位正确性 + 定点误差（~10 s，纯 CPU）
/data/work/venv-torch-cu/bin/python tools/bin_ref_model.py --self-test

# 2) 位宽扫描 → §4.4 的表
/data/work/venv-torch-cu/bin/python tools/bin_ref_model.py --sweep

# 3) 指定推荐配置
/data/work/venv-torch-cu/bin/python tools/bin_ref_model.py --self-test --fx 12 --fb 5

# 4) 真实 checkpoint 上的逐层误差（~100 s / 60 层）
/data/work/venv-torch-cu/bin/python tools/bin_ref_model.py --real runs/<RUN>/net_checkpoints/checkpoint_latest.tar
```

**当作 RTL 的黄金模型用**：

```python
from bin_ref_model import Fmt, BinConvParams, BinConvInt

p = BinConvParams.from_float(weight, t, alpha, bias, zeta, gamma, slope,
                             fmt=Fmt(fx=12, fb=5), padding=1)     # 导出（PS 侧一次）
eng = BinConvInt(p)
y_q = eng.forward(x_q, beta=beta_q)        # x_q: int16 (N,C,H,W)，beta_q: int32 (N,C)
```

RTL 的 cosim 就是"同一组 `x_q`/`beta_q` 喂进去，比对 `y_q` 的每一个 int32"。**没有任何浮点参与判决**，所以差异只可能是实现 bug，不是数值容差。
