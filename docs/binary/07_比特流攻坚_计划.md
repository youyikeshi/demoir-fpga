# 比特流攻坚：当前阻塞与解决方案

## 阻塞本质（2026-10-30 诊断完成）

工程模式下 `synth_design` 综合 BD wrapper 时，9 个 BD IP **全部**被当黑盒（连 PS7 都是），
落盘 DCP 只有 23 个 cell。IPI 的 DCP 拼接依赖 Vivado GUI 的 IP Integrator 流程，
纯 batch Tcl 没有等价命令。

已排除的路：
| 尝试 | 结果 |
|---|---|
| 删混入的 `*_stub.v` | 无效 |
| `create_ip_run` / `synth_ip [get_ips]` | 报 `12-3424 IPI cores may not be directly synthesized` |
| 非工程模式读 IP RTL | 撞 IEEE-1735 加密（`Error generated from encrypted envelope`）|
| `read_checkpoint` 平铺 + `link_design` | `Netlist 29-77 Could not replace`（模块名冲突）|
| `synth_design -rtl -rtl_skip_ip` | 仍报 `module ... not found` |
| `read_checkpoint -cell` | 需要先 elaborate 成功，而 elaborate 正卡在缺模块 |

## 解决方案：**去掉协议转换器和互联，让设计只剩 3 个有 DCP 的 IP**

加密的只有 `axi_protocol_converter` / `axi_data_fifo` / `fifo_generator` / `axi_dwidth_converter`。
它们是因为 **我们的 AXI master 是 AXI4，而 Zynq HP 口是 AXI3** 才被插入的。

$$\text{若我们的 master 直接做成 AXI3} \Rightarrow \text{不需要转换器、不需要互联}$$

设计简化成：

```
ps7(DCP) ——GP0——> conv_uni_0(DCP) /s_axi          ← 控制
conv_uni_0(DCP) /m_axi ——> ps7 S_AXI_HP0          ← 数据，直连
bin_unit_0(DCP) /m_axi ——> ps7 S_AXI_HP1
rst_ps7_150M(DCP)
```

**改动量极小**（实测）：
- `m_axi_arlen` 已经是 `8'd0`（单拍读）
- `m_axi_awlen = ax_len-1`，而 `WR_BURST_MAX=16` ⇒ `awlen ≤ 15` ⇒ **4 bit 就够**
- 只需：len 端口 `[7:0]` → `[3:0]`；补一个 `m_axi_wid[5:0]` 输出恒 0；外壳标 `PROTOCOL AXI3`

$$\Rightarrow \text{顺便省掉 2 个互联 + 2 个协议转换器的 LUT/BRAM}$$

## 执行顺序

1. 改两个 wrapper 的 len 位宽 + 加 wid，改 `gen_bd_shell.py` 标 AXI3
2. **跑 xsim 复验**（TB 的 AXI 从机模型也要改 len 位宽）—— 6 形状逐字节
3. 新建 BD（只有 ps7 + rst + 2 IP），`apply_bd_automation` 连直连
4. 非工程模式：读我们的 RTL + BD 网表 + `read_checkpoint -cell` 填 3 个 IP 的 DCP
5. 出 bit，上板跑整网，量到 1 s 以内

## 目标数字（256²，1 fps）

| 部分 | 目标 |
|---|---|
| 二值 XNOR（227 层，39 G 操作）| 24 ms |
| int8 9 层（394 MMAC）| ~220 ms |
| 非卷积（RPReLU/SAM/插值）| ~200 ms |
| 调度与开销 | ~150 ms |
| **合计** | **~0.6 s** |
