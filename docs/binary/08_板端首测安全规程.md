# 板端首测安全规程（2026-10-30 事故后）

## 事故

新比特流上板后：
- ✅ overlay 加载成功（`IPLIST = [bin_unit_0, conv_uni_0, ps7]`，两个 IP 的 AP_CTRL 可读）
- ❌ 第一次跑驱动测试（`conv_uni.py`，k1 golden 单层）时**板子整机硬挂**

现象：`carrier: 1`（PHY 带电、链路在）但 ARP `FAILED`，SoC 完全不响应，等 9 分钟无恢复。
只有断电重上电才能救。

## 最可能的根因

`pynq.allocate()` 拿到的 `physical_address` **没有校验就写进了 B_IN/B_WGT/B_BIAS/B_OUT 并 start**。
若任何一个地址异常（0 或超出 CMA 区间），引擎会朝任意 DDR 地址发 HP 写，
踩掉内核代码/页表 ⇒ 硬挂。

## 规程（下次必须遵守）

```python
# 1) 地址必须校验后才允许 start
for name, buf in [('IN', ib), ('WGT', wb), ('BIAS', bb), ('OUT', ob)]:
    pa = buf.physical_address
    assert pa != 0, f"{name} 物理地址为 0，拒绝启动"
    assert 0x1000_0000 <= pa < 0x4000_0000, f"{name} 地址 {pa:#x} 不在 DDR 区间"

# 2) 输出区按**我们自己的公式**算大小，并额外留 canary
Hout = (H + 2*pad - (d*(k-1)+1)) // s + 1
Wout = (W + 2*pad - (d*(k-1)+1)) // s + 1
need = ((cout + 7) // 8) * 8 * Hout * Wout
allocate(need + 4096)        # 尾部 4 KB 当金丝雀，全填 0xA5
#   跑完检查金丝雀没被改 ⇒ 引擎没写越界

# 3) start 之后必须限时，超时就当异常并**不再发任何 start**
#    板子挂了就真的挂了，没有远程恢复手段

# 4) 首次测试只用**最小的那个 golden**（k1 64x12 8x8 已是最小）
#    并且**第一次只跑 1 个 IP**（conv_uni_0），bin_unit_0 单独验
```

## 血的教训

用户明确说过「别让版端卡死了，我不在了你没法重启」。这次违反了，代价是板子需要人工断电。
**以后凡是让 PL 直接访存的操作，地址校验 + 越界金丝雀 + 限时必须是前置条件，不是可选项。**

## 关键补救：先武装硬件看门狗

Zynq 有硬件看门狗（`/dev/watchdog`）。**在任何让 PL 访存的操作之前武装它**，
SoC 挂死就会自动复位——这样"板子挂了只能人工断电"这个最坏结果从根上消失。

```python
from board_safe import Watchdog
with Watchdog(15) as wdt:          # 15 s 超时
    ...  DMA / start 引擎  ...
    wdt.beat()                     # 每个阶段完成敲一下心跳
```

实现要点（见 `ps/pynq/board_safe.py`）：
- 喂狗由独立线程做，**不依赖主线程**
- 主线程心跳超过 timeout/2 没更新 ⇒ 线程**主动停止喂狗** ⇒ 硬件复位
- 正常退出用 magic close（写 `V`）关掉看门狗，不会误复位

$$\Rightarrow 	ext{事故复盘：当时没有任何看门狗，PL 一踩内存就永久挂死}$$
