# 备份与合并协议（2026-10-30 建立）

## 一、为什么需要这一套

`conv_int8_uni.v` / `conv_uni_axi_wrap.v` / `bin_*.v` 都是重写时**新增的文件，从来没有 `git add` 过**
（`git ls-files` 查得到 13 个老文件，但查不到这 6 个）。所以改坏了**没有 `git checkout` 可用**。

实测踩过的坑：我在子代理改完**之后**才打快照，结果快照里已经是新版，**没有改前基线**。

## 二、三个工具

### 1. `tools/snapshot.sh <tag>` —— 带 md5 校验的快照

```bash
cd pl/rtl_hand
REASON="说明" ./tools/snapshot.sh verified_addrfix
./tools/snapshot.sh --list            # 列出所有快照
./tools/snapshot.sh --verify <tag>    # 校验 md5
```

- 覆盖：`modules/` `tb/` `golden/` `tools/` `scripts/` `ps/pynq/`
- 每个快照带 `manifest.md5`，回退前强制校验
- 体积约 1.7 MB，可以随便打

### 2. `tools/restore.sh <tag>` —— 带自动快照的原子回退

```bash
./tools/restore.sh --list
./tools/restore.sh verified_addrfix --dry-run   # 先看会覆盖哪些
./tools/restore.sh verified_addrfix             # 真回退（先自动存 pre_restore_<时间戳>）
```

**关键设计**：回退前先把当前状态打成 `pre_restore_*` 快照 ⇒ **回退本身也可以再回退**。

### 3. `tools/worktree.sh` —— 并行任务的副本 + 审查合并

```bash
./tools/worktree.sh new   <task> <file>...   # 从 master 建副本
./tools/worktree.sh stat  <task>             # 看改了哪些文件、多少行、master 是否已变
./tools/worktree.sh diff  <task>             # 完整 diff
./tools/worktree.sh apply <task>             # 合并到 master（先自动快照 pre_merge_*）
./tools/worktree.sh drop  <task>             # 丢弃
```

**为什么要它**：多个子代理改同一个文件会互相覆盖。用副本 + diff + 合并，
就能像 git 分支一样并行，而且**合并前可以审查**。

`stat` 会检测"基线 md5 是否还等于 master"——如果 master 在此期间被改了，会打 ⚠。

## 三、纪律（每条都来自实际踩坑）

| # | 规则 | 踩过的坑 |
|---|---|---|
| 1 | **派活之前**先打快照 | 我派完之后才打，快照里已是新版，没有改前基线 |
| 2 | 子代理**只改副本**，不碰 master | 两个代理改同一文件会互相覆盖 |
| 3 | 每次合并**串行**，合并后立刻跑 `verify_all.sh` | 同时合并多个改动，失败了分不清是谁的 |
| 4 | 合并前 `worktree.sh stat` 检查基线是否过期 | master 被别的任务改了，直接 `cp` 会覆盖 |
| 5 | **不许**在子代理编辑期间启动综合 | 读到写了一半的文件，报出 `Synth 8-10456 \`endif without matching \`ifdef` 这种误导性错误 |
| 6 | 功能验证用 `verify_all.sh all`（5 个单元） | conv 7/7 + bin_conv 5/5 + rprelu 3/3 + sam 2/2 + interp 2/2 |
