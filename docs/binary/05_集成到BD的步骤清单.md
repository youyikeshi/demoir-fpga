# 把新引擎集成进 BD 的可执行清单

> 2026-10-29　|　目标：用 `conv_int8_uni` **一次替掉** k1/k3/k5，并加入四个二值单元
> 原则：**一次性替换，不再分三次**（今天分三次试参数、三次白跑构建的教训）

## 0. 现状盘点

BD 里现有三个 IP（都是 `module_ref`，引脚外壳是 `*_bd.v`）：

| IP | 引脚外壳 | 引擎 |
|---|---|---|
| `design_1_k1_wrap_1` | `k1_axi_wrap_bd.v` | `conv_k1_engine` |
| `design_1_k3_wrap_0` | `k3_axi_wrap_bd.v` | `conv_k3_engine` |
| `design_1_k5_wrap_0` | `k5_axi_wrap_bd.v` | `conv_k5_engine` |

$$\text{占 } 134\ \text{DSP} / 76\ \text{BRAM} / 38\text{k LUT}$$

## 1. 要新增的 IP（共 5 个）

| 模块 | 包装层 | 需要 | 状态 |
|---|---|---|---|
| `conv_int8_uni` | `conv_uni_axi_wrap` | ✅ 待写 | 引擎 6/6 已验证 |
| `bin_conv_core` | `bin_unit_axi_wrap` | ✅ 已有（4/4 通过）| 5/5 已验证 |
| `bin_rprelu` | 同上 | ✅ | 3/3 |
| `bin_sam` | 同上 | ✅ | 2/2 |
| `bin_interp` | 同上 | ✅ | 2/2 |

$$\Rightarrow\ \text{两个包装层（一个通用嵌 4 个二值单元、一个专用给 int8 引擎）} \Rightarrow \text{共 6 个 IP 实例}$$

## 2. 每个 IP 需要的三件东西（**缺一不可，顺序不能错**）

1. **引脚外壳 `*_bd.v`**（Verilog-2001，只能有 `X_INTERFACE_INFO` 属性，不能有 `logic`/`always_comb`/`parameter int`——BD 的 IP Integrator 只认 Verilog-2001 语法）
2. **`component.xml`**（Vivado 打包 IP 时生成，或者手写）
3. **BD 里的 `create_bd_cell` + 连线 + 地址分配**

$$\textbf{上一轮的坑：参数写在 } \texttt{*\_bd.v}\ \text{里才是最终生效值，改 wrapper/引擎默认值都是空操作（踩过三次）}$$

## 3. 执行顺序（脚本化，每步可单独验证）

```tcl
# ---- 步骤 1：打包 IP（每个新模块一次）----
# 用 ipx::package_project 指向 *_bd.v 作为顶层
create_ip -name <module> -vendor xilinx.com -library user -version 1.0 \
          -module_name <module>
set_property ip_repo_paths {<repo_root>} [current_project]
update_ip_catalog

# ---- 步骤 2：BD 里删旧加新 ----
delete_bd_objs [get_bd_cells design_1_k1_wrap_1]
delete_bd_objs [get_bd_cells design_1_k3_wrap_0]
delete_bd_objs [get_bd_cells design_1_k5_wrap_0]
# 新增 6 个实例、连 s_axi 到 ps 的 M_AXI_GP0、连 master 到 HP 端口
# ⚠ HP 端口数量有限：现在 3 个引擎各占一个 HP + 4 个新单元 ⇒ 建议**多个 IP 共享一个 HP 口**
#    （共享时 ARID 必须区分，否则多笔在飞会串数据）

# ---- 步骤 3：地址分配 ----
#   conv_int8_uni  0x4004_0000（沿用 k1 的窗口，PS 侧驱动只改寄存器内容）
#   bin_conv_core  0x4006_0000
#   bin_rprelu     0x4008_0000
#   bin_sam        0x400A_0000
#   bin_interp     0x400C_0000

# ---- 步骤 4：构建 ----
#   REBUILD=1 vivado -mode batch -source build_bitstream_engine.tcl
```

## 4. 重建前必须做的检查（今天的教训清单）

| 检查 | 命令 | 为什么 |
|---|---|---|
| 参数是否真的生效 | 改完看 LUT/WNS **是否变化**；一位不差就是没生效 | 四层覆盖链 |
| 子 run 是否重置 | 构建日志里应有 `reset 子 run: design_1_*_synth_1` | 陈旧 OOC 网表 |
| 静态门禁 | `check_undriven_out.py` / `check_concat_width.py` | 悬空 output 会让板上卡死 |
| 时钟门控是否合规 | 综合报告里查 `BUFGCE` / clock-gating 警告 | 包装层用 latch+AND 门控 |
| 权重 bank 是否推成 BRAM | 综合报告里查 4 块 RAMB36（**若推成 LUTRAM，128 Kbit 会撑爆**）| `conv_int8_uni` 的关键风险 |

## 5. 预期结果

$$\text{DSP}:\ 134 \to \mathbf{32}\ (\text{只有 } conv\_int8\_uni\ \text{的 } 32\ \text{个，二值单元 0 个})$$
$$\text{BRAM}:\ 76 \to \mathbf{\sim 16}\ (\text{int8 引擎 4} + \text{二值单元 4{\sim}6} + \text{互联})$$
$$\text{LUT}:\ 38.2\text{k} \to \mathbf{\sim 9\text{k}}$$

$$\Rightarrow\ \text{46.2k LUT 的板子留出 } 35\text{k} \Rightarrow \textbf{时序和后续扩展都有空间}$$

## 6. 风险与回退

- **回退点**：当前 v23 bit（`ebd5dd14`，三引擎瘦身版）已验证可上板
- **最大风险：数据侧只有一个 HP 口。** 实测 `design_1.bd` 里只有 `S_AXI_HP0`（11 处引用），
  没有 HP1/2/3 —— 现在三个引擎的数据通路**已经挤在同一个 HP0 上**（经 `auto_pc` 协议转换）。
  ⇒ 加 5 个 IP 不是"各占一个 HP"，而是要把**数据侧的 master 互联从 3 端口扩到 6 端口**，
  并让每个 IP 用不同的 ARID 前缀（否则多笔在飞会串数据）。
  ⇒ 控制侧同理：`axi_ctrl` 现在 M00/M01/M02 三个 M 端口，要扩到 6 个。

- 次大风险：`conv_int8_uni` 的权重 bank 被推成 LUTRAM（128 Kbit 会撑爆）。
  缓解：综合后先查这一项再继续。
- **次大风险**：`conv_int8_uni` 的权重 bank 被推成 LUTRAM。缓解：综合后先看这一项再继续。
