## 1. 一句话

$$\text{二值引擎}=\text{一个 XNOR-popcount 阵列}\;+\;\text{一条行缓冲}\;+\;\text{一个逐通道标量尾巴}$$

它**不碰**全精度层、**不碰** SGRA、**不碰** MABG/上采样——那些留给现有 int8 引擎与 PS。

## 2. 模块地图

```
                        PS (ARM)
        ┌───────────────────────────────────────────────┐
        │ 层表：cin/cout/k/stride/dil/pad、t_q、α_q+exp、 │
        │       bob_q、ζ/γ/slope、C_const、边界修正表     │
        │ 调度：启动 → 轮询 → 下一层；MABG 的 β 计算       │
        └───────┬───────────────────────────┬───────────┘
                │ MMIO 配置                  │ DMA (1-bit 激活 / 1-bit 权重)
   ┌────────────▼──────────────┐   ┌─────────▼─────────────────────────┐
   │  bin_conv_engine (新 IP)  │   │  DDR：packed act (1b) / w (1b)     │
   │                           │   │       + int8 act (全精度路径用)     │
   │  ① act_fetch   AXI 读      │   └─────────┬─────────────────────────┘
   │  ② binarize    加 t_q、比较  │             │
   │  ③ pack        64 通道/字   │             │
   │  ④ linebuf     3×(d·(k-1)+1) 行 │           │
   │  ⑤ xnor_win    k² 个 64bit 窗口 │          │
   │  ⑥ popcount    64→7bit 加法树   │          │
   │  ⑦ beta_acc    β 位平面加权    │           │
   │  ⑧ post        α 乘 + bob + RPReLU + 重新打包 │
   └────────────┬──────────────┘
                │ AXI 写 1-bit（+ 可选 int8 副本）
   ┌────────────▼──────────────┐
   │ conv_k1/k3/k5_engine (现有)│  ← 9 层全精度（含 SGRA 的 F.conv2d）
   └───────────────────────────┘
```

| 模块 | 归属 | 状态 |
|---|---|---|
| `bin_conv_engine` | **新建**（本文） | 设计参考 |
| `conv_k1/k3/k5_engine` | 现有，只读 | 复用，一行参数不改 |
| `bin_act_pack` / `bin_post` | 建议独立成 IP | 逐元素单元，见 §8 |
| PS `pynq/runner.py` | 现有，加一条路由分支 | 按层表把二值层指向新 IP |

**边界纪律**（沿用 `docs/rtl_hand/00_SPEC_接口契约.md` 的做法）：新 IP 不可用时 PS 自动回退到 int8 引擎，整网仍正确（只是慢 7 倍）。这样引擎可以逐层上线验收。

## 3. 数据流：八级流水

| 级 | 名字 | 输入 → 输出 | 位宽 | 延迟 | 备注 |
|---|---|---|---|---|---|
| ① | `act_fetch` | DDR → on-chip | 1 bit/元素 | — | 一笔 burst 取一整行的通道块 |
| ② | `binarize` | $x_q$ → 1 bit | int16 → 1 | 1 拍 | **$+t_q$ 逐输入通道**，$>0$ 判 +1 |
| ③ | `pack` | 64 个 bit → 一个字 | 1 → 64 | 1 拍 | 通道维，见 §4 |
| ④ | `linebuf` | 行 → k 行窗口 | 64 bit × 行 | — | 深度 $d(k-1)+1$ 行（有 dilation！） |
| ⑤ | `xnor_win` | 窗口 × 权重 → k² 个字 | 64 bit | 1 拍/组 | 每个 tap 一次 |
| ⑥ | `popcount` | 64 bit → 7 bit | 64 → 7 | 2~3 拍 | 加法树，~100 LUT6 |
| ⑦ | `beta_acc` | $pc$ → 累加器 | 7 → 17+ | — | β 见 §5；无 gate 时直通 |
| ⑧ | `post` | 累加 → int16 → 1 bit | 17 → 16 → 1 | 5 拍 | α、bob、RPReLU、重新打包 |

**关键：②③ 是"消费端"动作，⑧ 是"生产端"动作。**
因为 $t$ 是逐输入通道的常数，`binarize` 必须发生在**读取激活时**（不是产生时）——除非你确信下一个消费者也是二值卷积（见 §7 的融合写回）。

**④ 的深度容易被忽略**：SAM 的 Ghost 分支用 $d\in\{1,2,3\}$（`d_list=(1,2,3,2,1)`），k=3 时窗口要跨 $1+2\cdot3=7$ 行。所以行缓冲深度按 $\max d$ 设计成 **7 行**，而不是 3 行。

## 4. 打包格式

### 4.1 决定：**沿通道打包**，64 个输入通道一个字

$$\text{word}(y,x,g)=\sum_{j=0}^{63} a\big(y,x,\;64g+j\big)\cdot 2^{j},\qquad a\in\{0,1\}\;\mapsto\;w\in\{-1,+1\}$$

$$\text{popcount}(a\ \text{XNOR}\ w)=n_{\text{eq}},\qquad \sum_{\text{lane}}a'w'=2n_{\text{eq}}-n$$

**为什么沿通道而不是沿宽度**：

| 方案 | 优点 | 致命问题 |
|---|---|---|
| **沿通道（选它）** | 一个 popcount 直接得到"一个 (oc, tap) 对全部 cin 的内积"；累加器只有 1 个；与 C8 的"通道在内、像素在外"同构 | `cin` 不是 64 的倍数时有浪费（§4.3） |
| 沿宽度 | 对 $k=1$ 层没有浪费，边界简单 | k>1 时每个 tap 的窗口要跨字取位（相邻像素在同一个字里），要么复制 3 份移位版本要么做 66 bit 拼接；**β 逐通道而宽度维是逐像素**，门控会变成"每 lane 一个乘数"，3 bit 的 β 就退化成 64 个不同系数 |
| 沿 tap×宽度 | 省行缓冲 | 累加顺序与 $\sum_k$ 绑死，dilation 与 stride 全要重排 |

### 4.2 与现有 C8 布局的关系

现有 int8 激活是 **C8 交错**：`addr(c,y,x) = ⌊c/8⌋·H·W·8 + y·W·8 + x·8 + (c mod 8)`，一个像素 8 通道连续 8 字节，可一次 64-bit 读。

本文的打包是它的"1-bit 版本"，两处类比：

| C8（int8 引擎） | C64（二值引擎） |
|---|---|
| 通道块 8 个，块内交错在像素内 → 1 笔 burst 取 8 通道 | 通道块 **64** 个，块内**直接压进一个 64-bit 字** |
| `addr = ⌊c/8⌋·HW·8 + y·W·8 + x·8 + (c mod 8)` | `addr = ⌊c/64⌋·HW·8 + y·W·8 + x·8`（**同一个公式**，只是块内 8 字节变成了 8 字节的位图） |
| 一个像素 8 字节 | 一个像素 $\lceil c/64\rceil\times 8$ 字节 |

$$\text{于是"C8 的字节地址"与"C64 的字地址"逐位同构} \Rightarrow \text{现有的行缓冲/填充/burst 逻辑可以整段复用}$$

这是选 64 的第二个理由：**地址发生器不用重写**。`cin=544` 时 `⌈544/64⌉=9` 个字 = 72 字节/像素，正好是 C8 下 72 通道的字节数。

**注意 C8 的"通道补齐到 8 的倍数"与 C64 的"补齐到 64"是两件独立的事**：int8 路径上 `cin=48` 物理占 48（已是 8 倍数），1-bit 路径上 `cin=48` 占 64 lane（浪费 16）。两套补齐表都在 PS 的层表里。

### 4.3 补位怎么处理（**不需要额外逻辑**）

规定：**补的 lane 上激活位与权重位都置 0（编码 −1）**。于是补位恒"相等"，每个补位贡献 $+1$ 到 popcount，其虚假贡献是一个**逐层常数**：

$$\sum_{ic,k}WX=\underbrace{2\cdot\sum_{\text{tap}}\text{popcount}}_{\text{全部 lane，含补位}}-\;C_{\text{const}},\qquad
C_{\text{const}}=k^2\big(2n_{\text{pad}}+c_{\text{in}}\big),\quad n_{\text{pad}}=64\big\lceil c_{\text{in}}/64\big\rceil-c_{\text{in}}$$

推导（单 tap）：真实 lane 的贡献是 $2n_{\text{eq}}-c_{\text{in}}$，而 popcount 数到了 $n_{\text{eq}}+n_{\text{pad}}$（补位全等），所以
$$\big[2(n_{\text{eq}}+n_{\text{pad}})-64\big]-n_{\text{pad}} \;=\; 2n_{\text{eq}}-c_{\text{in}}\quad\Longleftrightarrow\quad \text{减掉}\;2n_{\text{pad}}+c_{\text{in}}$$

$C_{\text{const}}$ 是**编译期常数**（一层一个寄存器）：
- `cin=48`：$9\times(2\cdot16+48)=720$
- `cin=32`：$9\times(2\cdot32+32)=864$
- `cin=64`：$9\times(0+64)=576$（无浪费，退化成教科书公式）
- `cin=160`：$9\times(2\cdot32+160)=2016$

⇒ **补位的代价只有 16.9% 的 popcount 次数，没有额外的比较/屏蔽逻辑**（实测：64-lane 打包需 1.026 G 次 popcount，理想 $56.162/64=0.878$ G）。

### 4.4 要不要为 `cin≤32` 做 32-bit 通路？

| 判据 | 数 |
|---|---|
| `cin≤32` 的层 | 45 层（全是 Ghost 的 `cheap_operation`），占 MAC **5.2%** |
| `cin≤48` 的层 | 95 层，占 MAC 19.6% |
| 用 64-lane 的代价 | popcount 次数 +16.9% |

$$\textbf{结论：不做。}$$ 15.6% 的权重存储浪费 + 16.9% 的 popcount 浪费换掉一条第二数据通路，不值。
（如果以后要省，正确做法不是加 32-bit 通路，而是把 `cin≤32` 的层改成"两个像素塞进一个字"，但那需要累加器分半，得不偿失——记在这里免得以后再算一遍。）

## 5. β：两种实现，差 5 倍

$$\text{out}_{oc}=\alpha_{oc}\Big(\sum_{ic}\beta_{ic}\big(\underbrace{\sum_k W X}_{=\,\text{内层，纯 popcount}}\big)+\text{bias}_{oc}\Big)$$

$\beta_{ic}\in(0,1)$ **逐图像、逐输入通道**（MABG 从 DWT + 统计量算出），只有 `mabg`/`full` 档的 5 个边界层有；`base` 档完全没有 $\beta$。

### 5.1 方案 A：逐 ic 小乘（直觉做法）

$$\text{acc}_{oc}=\sum_{ic}\beta_{q,ic}\cdot\text{inner}_{oc,ic}$$

每个 $(oc,ic,\text{pixel})$ 一次"3×5 位乘 + 加"。**代价**（5 个 gated 层，320²）：

| 项 | 数 |
|---|---|
| 外层乘加 | 0.328 G MAC |
| 32 个 DSP 做 | **95 ms** |
| 全部 220 个 DSP 做 | 14 ms |
| 若 MABG 扩到全部 227 层 | 11.5 G MAC ⇒ **1.7 s（32 DSP）/ 0.25 s（220 DSP）** |

### 5.2 方案 B：β 的位平面加权 popcount（**推荐**）

$$\sum_{ic}\beta_{q,ic}\,m_{ic}=\sum_{j=0}^{f_b}2^{j}\cdot\text{popcount}\big(m\ \&\ B_j\big),\qquad B_j=\text{β 第 }j\text{ 位为 1 的 64-bit 掩码}$$

$$\Rightarrow\ \text{acc}_{oc}=\sum_{\text{tap}}\Big[2\sum_j 2^j\,\text{popcount}(m\&B_j)-B_{\text{tot}}\Big]$$

把"乘"换成了 $f_b+1$ 次 popcount。**因为 popcount 一次处理 64 个 lane，这一步是免费的**：

| 实现 | @320² 的代价 | 用 DSP | 用 LUT | 精度 |
|---|---|---:|---:|---|
| A 逐 ic 小乘 | 0.328 G MAC | 95 ms（32 DSP） | — | 3~6 bit 随取 |
| **B 位平面** | +$f_b$ 倍 popcount = **+20 ms** | **0 DSP** | 复用阵列 | 同上 |

$$\textbf{方案 B 比 A 便宜 4.7 倍，且不占 DSP。}$$

**这是本文与事实 2 的偏离点**：事实 2 说"内层纯 popcount，β 只作用在外层（每个 ic 一次乘加）"——数学上完全正确，但**硬件上外层那一次乘加可以再折叠成 $(f_b+1)$ 次 popcount**。参考模型里两条路都实现了，`--self-test` 的 T2 证明**逐位相同**（差 = 0）。

$\beta$ 的补位：$\beta$ 向量补 0 ⇒ 补位不进累加（所以 gated 通路**不需要** $C_{\text{const}}$ 修正，只有 bypass 通路需要）。

### 5.3 β 的位宽（实测，详见 02 篇 §3.2）

| $f_b$ | 2 | 3 | 4 | **5** | 6 |
|---|---:|---:|---:|---:|---:|
| 单层相对误差（均值） | 13.4% | 6.6% | 3.6% | **2.1%** | 1.5% |

$$\Rightarrow\ \textbf{建议 5 bit（而不是事实 2 提的 3 bit）}：多 2 次 popcount（+40\% 的 gated 层开销），误差从 6.6\% 降到 2.1\%；再往 6 位只再减 0.6\%，边际收益在此拐弯。$$

## 6. 空间零填充的修正表

fp32 卷积的零填充贡献 0；而 XNOR 通路把界外的激活位当成 0（编码 −1）参与计算，于是**每个越界 tap 引入一个虚假贡献** $-\sum_{ic}\beta_{ic}w_{oc,ic,t}$。修正量只依赖 $(oc,t)$：

$$W_\beta[oc,t]=\sum_{ic}\beta_{ic}w_{oc,ic,t}\qquad \text{（gated）}\qquad S_w[oc,t]=\sum_{ic}w_{oc,ic,t}\quad\text{（bypass）}$$

| 通路 | 表的规模 | 什么时候算 |
|---|---:|---|
| bypass（222 层） | $c_{out}\times k^2$ int16 = 96×9 = 864 字 | **权重量化时算好，运行期零成本** |
| gated（5 层） | 同规模 | 每图每层一次，代价 $c_{out}k^2c_{in}$ 乘加 ≈ **一个输出像素**的量，可忽略 |

```python
# forward 里的应用（tools/bin_ref_model.py）
acc = acc + (oob_mask @ W_beta.T).T          # oob_mask: (Ho·Wo, k²) bool
```

**替代方案（不用这张表）**：边界像素交给 PS 或 int8 引擎算。k=3 时边界像素占 $1-\frac{(H-2)(W-2)}{HW}\approx1.5\%$。**不推荐**——1536 个像素/P 层 × 227 层 = 35 万次 PS 侧点积，反而比预先算表贵。

## 7. 与 int8 引擎、PS 的分工（以及"1-bit 就地写回"）

### 7.1 谁能只传 1 bit

| 生产者 → 消费者 | 能只传 1 bit 吗 | 原因 |
|---|---|---|
| DenseConv(RDB/Ghost) → 下一个二值卷积 | **能** | 唯一消费者是二值卷积 |
| RDB 的 `conv_post` → `+ x`（残差） | 不能 | 要与 $x$ 做值域加法 |
| SAM 的分支输出 → `w0*y0+…` | 不能 | bilinear 重采样 + 加权在值域 |
| BoundaryConv → `+ SGRA(x)` | 不能 | SGRA 是全精度输出 |
| 二值卷积 → MABG 的 DWT/统计量 | 不能 | 需要值域（$\mu,\sigma$） |

$$\frac{\text{只传 1 bit 的二值 MAC}}{\text{全部二值 MAC}}=1-\frac{24\ \text{个值域出口层}}{56.162\ \text{G}}=1-10.3\%=\textbf{89.7\%}$$

那 24 个"值域出口层"是 6 个 RDB 的 `conv_post` + 27 个 GhostModule 的收尾 1×1 卷积里落在编码器/解码器主干上的部分（最大的是 `decoder_1.sam_blocks.0.b0.conv.conv`，1.283 G）：它们的输出要么进残差 `+x`，要么进 SAM 的 `w0*y0+w2*y2+w4*y4`，必须在值域。

### 7.2 流量账（这条比算力更关键）

现有设计的教训是"**事务数/带宽才是瓶颈**"（`docs/设计/设计_激活tiled布局_C8交错.md`：填充 90 s / 8.76 M 事务 / 有效带宽 6.3 MB/s）。

| 激活表示 | 每元素 | @320² 一帧（92.8 M 输出元素 ×0.694） | 相对 int8 |
|---|---:|---:|---:|
| int16（binarize 的输入需要） | 2 B | 129 MB | 2× |
| int8（现有 C8） | 1 B | 64 MB | 1× |
| **1-bit packed** | 0.125 B（含 lane 浪费 0.138） | **8.9 MB** | **0.14×** |

$$\Rightarrow\ \textbf{不要把 int16 落到 DDR}：\text{⑧ post 之后就地 binarize+pack，写 1-bit}$$

这样二值链上每层的 DDR 来回从 2 B/元素 降到 0.14 B/元素，**14 倍**。而 int16 只在**引擎内部**存在（acc → α → RPReLU → 比较 → 打包，全在片上）。

**但 int8 副本仍然要写**：残差/SAM 加权/SGRA 需要值域。折中：只在"有残差或 MABG 的层"写 int8 副本（5 个 boundary + 9 个 SAM 出口），其余 74% 的层只写 1-bit。

## 8. 资源与时序预算

### 8.1 单 lane 的成本（事实 3）

$$64\text{ bit XNOR}\approx32\ \text{LUT6},\qquad 64\text{ bit popcount}\approx100\ \text{LUT6}\;\Rightarrow\;\textbf{130 LUT6 / 64 op}$$

$$\text{op/拍}=64\cdot\lfloor \text{LUT}_{\text{预算}}/130\rfloor,\qquad \text{FCLK}=107.1\ \text{MHz（板上实测可达）}$$

### 8.2 三个方案

**二值 popcount 工作量：1.026 G 次（64-lane，含补位浪费）@384² ⇒ 0.712 G @320²**

| | 保守 | **均衡（推荐）** | 激进 |
|---|---:|---:|---:|
| lane 数 | 24 | **64** | 152 |
| op/拍 | 1 536 | **4 096** | 9 728 |
| XNOR+popcount LUT | 3.1 k | **8.3 k** | 19.8 k |
| 行缓冲 BRAM36 | 4（32 列条带） | **4（32 列）/ 7（64 列）** | 7 |
| 权重 BRAM36（最大层 13.1 kB） | 3 | 3 | 3 |
| DSP（α 乘，8 个） | 8 | 8 | 8 |
| **二值时间 @320²** | **277 ms** | **104 ms** | **43.8 ms** |
| **二值时间 @384²** | 399 ms | 150 ms | 63 ms |
| 加上 9 层全精度（1.84 s）与非卷积后的整网 | 10.4 s | **10.2 s** | 10.2 s |
| LUT 余量（46.2k − 25.6k 现有） | 17 k 空闲 | 12 k 空闲 | 1 k 空闲 |
| **瓶颈** | 无所谓——反正被 1.84 s 的全精度部分吃掉 | **最佳性价比点**；给后续"逐元素单元"留 12 k LUT | LUT 见底，挤掉 k3 引擎的余量；整网只比均衡快 60 ms |

$$\textbf{推荐均衡方案（64 lane / 8.3 k LUT / 104 ms）}：\text{再往上加 lane 的边际收益为零（全精度部分 1.84 s 不动）}$$

### 8.3 为什么不是"20k LUT 换 5.7 ms"

| | 数字 | 出处 |
|---|---:|---|
| 事实 3 的估法 | 5.7 ms | 用了 0.896 G（= 原始 MAC ÷ 64） |
| 用真实操作数（56.162 G）重算 | 59 ms @384² | 本文 §8.2 |
| 含补位浪费（×1.169） | **69 ms @384² / 41 ms @320²**（20k LUT） | 同 |

**结论不变**（相对 1.84 s 的全精度部分都可忽略），但**不能拿 5.7 ms 去做"二值部分可忽略"的论断依据**——真正让二值部分可忽略的是"64 个 MAC / popcount"这个比例，而不是那个绝对值。

### 8.4 Fmax 与流水

| 级 | 关键路径 | 深度 | 能否 107 MHz |
|---|---|---|---|
| ⑤⑥ XNOR + popcount | 64 位异或 + 6 级加法树（每级 2 输入） | 2~3 拍 | 是（约 6~8 ns） |
| ⑦ β 位平面累加 | popcount + 5 个加法 | 2 拍 | 是 |
| ⑧ α 乘（24×16） | DSP48（25×18） | 1 拍 | 是 |
| ⑧ RPReLU 比较 + 打包 | 16 位比较 + 移位 | 2 拍 | 是 |

**唯一的时序风险在 ⑥**：64 位 popcount 若做成单级 6 层加法树，在 7 系列上约 8~11 LUT 级联 ≈ 5~7 ns，107 MHz（9.34 ns）够用但没余量。**做成 2 拍流水**（两级各 3 层加法）就完全安全，代价是 2 个流水寄存器/ lane。

| 3 | 单个 64-lane 内核 + 行缓冲的 Verilog + cosim | 与 `bin_ref_model` 逐位相同（T1/T2 型判据） |
| 4 | 逐元素单元（RPReLU + SAM 加权 + interpolate）上 PL | 7.4 s → ≤0.3 s，3~5 k LUT |

**第 4 项才是整网最大的单点收益**（7.1 s vs 二值引擎的 1.7 s），而且它比二值引擎简单得多——只是没有二值引擎"听起来酷"。如果时间只够做一件事，做第 4 项；如果要做二值网，就必须先做二值引擎（否则 75 s）。
