## 0. 一句话结论

这份 RTL 里**没有"一个计算阵列"**，只有**四条各自独立实例化、互不复用的乘法器组**：

| | 谁在算 | 乘法器 | 每拍 MAC | II |
|---|---|---|---|---|
| k=1 快路径 | `LOOP_684_33`（+ `LOOP_730_36` 收尾） | 16（8 DSP + 8 LUT） | **16** | **1** |
| k=3 快路径 | `LOOP_764_38`（+ `LOOP_819_41` 收尾） | **72**（40 DSP48 + 32 LUT） | 36 | **2** |
| k=5 通用 | `LOOP_892_47`（收尾在顶层 FSM） | 25（20 DSP48 + 5 LUT） | 8.3 | **3** |
| 死分支 | `LOOP_849_43` / `LOOP_865_44` | 1 / 9 | — | 1 / 2 |

三条活路径的乘法器**同时存在**于同一块器件上（DSP 合计 108/160，LUT 35,520/46,200），
选路由顶层 FSM 在**每个 (pixel, ocb) 块开头**按 `ksize`（`empty_reg_7546`）做一次分支完成：

- `conv2d_engine.v:15960-15966`（state 134：`ksize==5→142`、`ksize==1→138`、否则 `→135`）
- `conv2d_engine.v:7967-8044`（各子模块 `ap_start_reg` 的置位条件，含 `empty_reg_7546` 谓词）

关键的非显然结论（后面逐条给证据）：

1. **k=1 的 16 拍收尾是"没展开的循环"，不是算法必需**——`HLS UNROLL` pragma 的直接外层作用域是 `if (ksize==1) { }` 块而不是循环体，本版 HLS 直接忽略（构建日志 `solution1.log:21` 明写）。这是 ~19 拍固定开销的主因，也是手写版最容易拿回的收益。
2. **k=3 的 II=2 不是乘法器不够，是行缓冲端口不够**：`line_buf` 每个行 bank 只有 **1 个读口**，而 3×3 窗口在同一行要读 3 个列。II = ⌈列数/2⌉。
3. **k=5 慢的根因不是 25 个抽头，而是"一次只算 1 个 oc" + 24 级串行加法链 + 每 (pixel,oc) 重启一次流水**。
4. RTL 里 k=3 是 **8 个 oc 车道（72 乘法器）**，不是"4 车道"；`K3_LANES=4` / `K3_PIPELINE_II=3` 是死宏（`conv2d_engine.h:139-160` 自己写明"grep -c = 0"）。详见 §7.1。

`mac_muladd_..._4_1` 是**真正的 DSP48 原语包装**，不是行为级乘法器：

```
conv2d_engine_mac_muladd_8s_8s_16s_17_4_1.v:7   module ..._DSP48_0(clk,rst,ce,in0,in1,in2,dout)
    a_reg/b_reg/m_reg/p_reg 四级寄存器；
    m = a_reg*b_reg;  p = m_reg + c;  dout = p_reg;      // c = in2（16 位）
```

即**一个 DSP48 = 一个 8×8 乘 + 一个 16 位加**，所以 k=3 的 9 抽头点积用 5 个 DSP48 + 4 个 LUT 乘实现
（4 个 LUT 乘的乘积作为那 4 个 DSP 的 `c` 输入，第 5 个 DSP 的 `c` 接 17 位部分和，见 §3.2）。

### 1.2 分类证据

- **k=1 快路径只被 684 引用**：`684_33:2050` `wgt1_buf_address0 = zext_ln684 = ic_5_reg_2279`，
  16 个 bank 的地址**是同一根线**（`684_33:2010,2014,...,2050` 全部 `= zext_ln684_fu_966_p1`）⇒ 同址广播。
- **k=3 快路径 = 72 个权重 bank**：`764_38` 里 `wgt3_buf, wgt3_buf_1 ... wgt3_buf_71` 共 72 个独立 LUTRAM
  （与 csynth 报告 memory 表 72 行对应，rpt:200 起），= 8 oc × 9 抽头，地址只有 `ic` 一维（352 深）。
- **k=5 只有 25 个 bank**：`wgt_buf ... wgt_buf_24`（rpt:272 起），地址 = `oc*352 + ic`
  （2816 = 8×352 深，`wgt_buf_7_U` 行 Words=2816）⇒ **一个 bank 里装着 8 个 oc，天然一次只能取 1 个 oc**。
- **累加器位宽**：所有 acc 端口都是 `[25:0]`（例如 `684_33:199` `output [25:0] acc0_15_out`）⇒ 26 位。
- **累加器奇偶双链**：`684_33:1884/1902`

```verilog
// 684_33:1884  acc0 只在 ic 偶时更新
assign select_ln694_1_fu_1274_p3 = (trunc_ln694_reg_2294_pp0_iter3_reg[0] == 1'b1)
                                   ? acc0_fu_176 : add_ln697_fu_1261_p2;   // ic 偶 → 加
// 684_33:1902  acc1 只在 ic 奇时更新
assign select_ln694_fu_1267_p3   = (trunc_ln694_reg_2294_pp0_iter3_reg[0] == 1'b1)
                                   ? add_ln695_fu_1255_p2 : acc1_fu_180;
```

`764_38:4289/4307` 是同一套（`select_ln793_1` / `select_ln793`，`trunc_ln793` = `ic&1` 延迟 4 拍）。
奇偶分链的作用：同一条链的两次更新之间隔 2 拍，26 位加法器的**循环携带依赖**从 1 拍放宽到 2 拍。

### 1.3 累加器物理位置（影响手写方案）

acc 寄存器**长在计算模块内部**，不是顶层数组：

- `684_33:373` `reg [25:0] acc0_fu_176;` …（32 个）
- `684_33:1005-1007` `if (ap_loop_init) acc0_fu_176 <= 0; else if (ap_enable_reg_pp0_iter4) acc0_fu_176 <= select_...;`
- 顶层把 684 的 32 个 `*_out` **直连**到 730 的 `acc*_reload`：
  `conv2d_engine.v:6973-7007` `.acc0_reload(grp_..._684_33_fu_3969_acc0_out)` …

⇒ 计算模块与收尾模块之间是**组合连线 + 32 根 26 位总线**（合计 832 位），中间无寄存器。
手写版如果拆成两个模块，这 832 位就是跨模块布线；更好的做法是**把收尾并进计算模块的尾部**（§6）。

## 2. k=1：十六车道、一拍内的完整数据通路

### 2.1 地址与广播（全部从 684_33 静态读出）

```verilog
684_33:1986  assign trunc_ln684_fu_962_p1 = phi_mul36_fu_172[14:0];   // phi_mul36 每拍 += 76
684_33:1764  assign add_ln688_fu_991_p2   = trunc_ln684_fu_962_p1 + zext_ln668;  // = ic*76 + base
684_33:1852  assign line_buf_address0     = zext_ln688_fu_996_p1;     // 唯一读口
684_33:2056  assign zext_ln684_fu_966_p1  = ic_5_reg_2279;            // 权重地址 = ic
```

- `76 = BWCOL_MAX`，`line_buf` 每 bank 深 26752 = 352(`CIN_MAX`) × 76（rpt:160）⇒ 布局 `[ic][col]`，ic 步长 76。
- `zext_ln668` 由顶层给（`conv2d_engine.v:6782` `.zext_ln668(mul_ln658_reg_9262)`），即本像素的列基址 `cb`。
- **每拍只读 1 个像素 `p`，广播给 16 个乘法器**；16 个权重 bank 同址（`ic`）并行出 16 个权重。
- 这就是 `conv2d_engine.h:217-219` 说的"16 个 oc 共用同一个 `p`，line_buf 每拍仍只读 1 次"。

### 2.2 一拍数据通路（单级 FSM，`ap_CS_fsm_pp0_stage0`，II=1）

```
 每拍推进 1 个 ic（5 级流水 iter0..iter4，零 stall）

 S0 发地址            S1 取数                S2 乘                S3 归约           S4 回写
 ─────────────────────────────────────────────────────────────────────────────────────────
  ic ──► lb_addr          line_buf_q0 ──► p_reg_2410 ─┐
         = ic*76 + cb                    (8b)         ├─► mul #0..7  ──► t1_reg_k[15:0]    ─┐
         (phi_mul36 += 76)                            │   (8 个 DSP 车道)                    │
                                                      └─► mul #8..15 ──► mul707_reg_k[15:0]─┤
  ic ──► wg_addr = ic     wgt1_buf_k_q0 (16 bank 同址)  ──► wgt_reg_k[7:0] ─────────────────┤
         (同一根地址线)                                                        │
                                                                              ▼
                                              ic[0]==0 ? ──► acc0[k] <= acc0[k] + sext(prod_k)   (26b)
                                              ic[0]==1 ? ──► acc1[k] <= acc1[k] + sext(prod_k)   (26b)
                                                                              │
                                                    16 车道 × 2 链 = 32 个 26 位寄存器，全展开
```

每个车道的乘法器**常量绑定**，RTL 里没有 bank 选择 mux：

| 车道 i | 权重来源 | 乘法器原语 | 累加器 | 输出 oc |
|---:|---|---|---|---|
| 0–7（`K1_DSP_LANES=8`，`cpp:690`）| `wgt1_buf[i]_q0` | `mul_8s_8s_16_1_1`（BIND_OP impl=DSP，`cpp:693`）| `acc0[i]/acc1[i]` | `ocb+i` |
| 8–15（`cpp:701`）| `wgt1_buf[i]_q0` | `mul_8s_8s_16_1_1`（留 LUT，41 LUT/个）| `acc0[i]/acc1[i]` | `ocb+i` |
| 全部 | 同一地址 `ic` | 16 个实例见 `684_33:583-775`（连续 16 段 `#(.ID(1),.NUM_STAGE(1))`，`..._U335`..`..._U350`）| 26 位 | 16 个连续 oc |

**16 个 oc 的来源**：`ocb` 仍按 8 步进，但 k=1 时奇数块整块跳过（`cpp:451` `if ((K1_BLK > 1) && (ksize == 1) && ((ocb & OC_BLOCK) != 0)) continue;`），
一个 pass 吃掉 `ocb..ocb+15`；权重装载器 `LOOP_475_16` 的循环上界就是 `ocbl1 = min(cout-ocb, 16)`（`cpp:475`）。

## 3. k=3：9 抽头是并行还是串行？为什么不是 12 MAC/拍

### 3.1 RTL 事实：9 抽头**全并行**，8 个 oc 也全并行

- 72 个权重 bank（`wgt3_buf..wgt3_buf_71`），每 bank 地址 = `ic`，一拍出 72 个字节。
- 72 个乘法器：40 个 `mac_muladd_*_4_1`（DSP48）+ 32 个 `mul_8s_8s_16_1_1`（LUT）。
  按 oc 分组正好是 **每 oc 5 DSP + 4 LUT**，对应 C++ 的两条点积：

```cpp
// cpp:781-790（3×3 快路径）
h0[i] = q0*w[0] + q2*w[2] + q4*w[4] + q6*w[6] + q8*w[8];   // 5 项：偶奇偶奇偶
h1[i] = q1*w[1] + q3*w[3] + q5*w[5] + q7*w[7];             // 4 项：奇偶奇偶
acc{0,1}[i] += h0[i] + h1[i];                              // ic 奇偶分链
```

- 每 oc 的 9 个乘积 = 5 个 DSP 乘 + 4 个 LUT 乘；4 个 LUT 乘的**乘积**作为 4 个 DSP 的 `c` 端
  （`764_38:1869-1884`：`din2(mul_ln796_1_reg_5003)`，一个已寄存的 16 位乘积），
  所以 9 个乘积的求和树被压进 DSP 的 `p = m_reg + c` 里，LUT 侧只剩下少量加法。
- C++ 的 `UNROLL factor=2`（`cpp:780`）**没有起到限制作用**：外层 `PIPELINE II=1` 约束下 HLS 把内层 8 次完全展开
  （`conv2d_engine.h:126-132` 的注释也承认这一点，只是那段讲的是 K1 的宏；K3 的 `K3_OC_UNROLL` 同理）。

### 3.2 调度（为什么是 II=2，不是 1）

`764_38` 与 `684_33` 的差别只有一处：**FSM 调度级数**

| 模块 | `ap_ST_fsm_pp0_stage*` 个数 | 结论 |
|---|---:|---|
| `684_33` | 1（`684_33:1832` 只有 `ap_block_pp0_stage0`）| 循环体 1 拍完成 ⇒ **II=1** |
| `764_38` | **2**（`764_38:4037/4039` `ap_CS_fsm_pp0_stage0/stage1`）| 循环体 2 拍 ⇒ **II=2** |
| `892_47` | **3** | ⇒ **II=3** |

`ic` 计数器的使能条件是 `ap_CS_fsm == pp0_stage0 && ap_enable_reg_pp0_iter0 && !exit`（`764_38:2763-2769`），
两拍才回到一次 stage0 ⇒ 每 2 拍推进一个 ic。

**根因是行缓冲读口，不是乘法器**：

```
line_buf 结构（rpt:160，conv2d_engine_line_buf_RAM_2P_BRAM_1R1W.v）
  7 个 bank = 7 个行（span 维被完全拆分），每 bank 26752×8，**1 读 1 写**
  ↓
k=3 窗口 = 3 行 × 3 列 ⇒ 最坏情况同一行 bank 要读 3 个不同列
  ↓  1 个读口  →  3 列读不完
HLS 的解法：给 764_38 开 **2 个读口**（address0/q0 + address1/q1，见 764_38 端口表），
            并把第 3 个列的地址**跨拍错开**（地址在 stage0/stage1 间做时间复用）：
             764_38:3136-3141  line_buf_1_address0_local = iter1 ? zext_ln768_1 : zext_ln767_1
             764_38:4153      line_buf_1_address1     = zext_ln766_fu_1926_p1
  ↓
2 读口 × 2 拍 = 4 ≥ 3  ⇒  II = 2 恰好够
k=5 同理：5 列 / 2 口 ⇒ II = ⌈5/2⌉ = 3（892_47）
```

一句话：**k=3 的 II=2 是 `line_buf` 每行 1 读口 × 3 列横向抽头的直接结果**。
拍数公式：`每像素块 ≈ 2·cin + 13（收尾）`。

### 3.3 关于"12 MAC/拍、实测 7.8"

本份 RTL 里 k=3 的**结构上限是 72 乘法器 / II=2 = 36 MAC/拍**，不是 12。
`12 = 4 车道 × 9 抽头 / 3` 对应的是 **2026-10-22 重写之前**的结构（`K3_LANES=4` + `K3_PIPELINE_II=3`），
那两个宏现在是死宏（`conv2d_engine.h:139-147`："改它们 csynth 结果一个数都不变"）。**§7.1 有更详细的出入清单。**

至于"实测 7.8 MAC/拍"：它必然包含**加权重重装载 + 收尾 + DDR 等待**，而不是计算阵列本身的能力。可核对的结构项：

| 每 (y, ocb) 块的固定/额外开销 | 拍数 | 出处 |
|---|---|---|
| 权重装载（k=3，12 字节容器）| 上界 `8 × cin` 拍；**实际更贵**：这条循环没被提成子模块，而是**顶层 FSM 里的顺序循环**，报告给的 iteration latency 是 **5~6 拍/ic 且未标 pipelined** ⇒ 可能是 `8 × 5.5 × cin` | `cpp:517-527`；rpt:76-77（`LOOP_517_20` 外层 / `LOOP_521_21` 内层）；同类 k=1 装载器 `LOOP_490_19` 在 rpt:75 给的是 **13 拍/迭代** |
| 计算 | `xn × 2·cin` | §3.2 |
| 收尾 | `xn × 13` | §4 |
| 收尾后 64 位宽写 | `xn + ~4`（**真 burst**：AWLEN=63/512 B，由顶层 FSM 发，见下方勘误）| `top:16035-16079`、`05` §1 |

按 `xn=64, cin=32` 估：

- 只算"计算 + 收尾"：`64×(64+13) = 4,928` 拍 / 该块 `64×8×32×9 = 147,456` MAC ⇒ **30 MAC/拍**；
- 加上行内装载（`8 × 5.5 × cin ≈ 1,408` 拍）⇒ `6,336` 拍 ⇒ **23 MAC/拍**；
- 要落到 7.8 还需要再差 3 倍，最可能的来源是装载循环在等 `m_axi`（本设计是 DDR-bound，
  见 `cpp:660-672` 的 "16.3 拍/字节" 记录）与行缓冲填充。

**7.8 这个数字的分解缺一份 cosim 计数，标「存疑」**；但可以确定：**大头的"固定开销"不在乘法链上**。

## 4. 累加 → 饱和链路

### 4.1 三种实现，同一套语义

| 路径 | 在哪 | 结构 | 每 (pixel,ocb) 拍数 |
|---|---|---|---|
| k=1 | `LOOP_730_36` | 16 迭代 **II=1 流水**（不是展开！）| 21 |
| k=3 | `LOOP_819_41` | 8 迭代 II=1 流水 | 13 |
| k=5 | 顶层 FSM state 144/147/148/149 | 每个 oc 走一遍状态机，**不流水** | ~4-5 × 8 oc |

### 4.2 逐级位宽（k=1 / `730_36` 为准，另两条同构）

| 级 | 表达式 | 位宽 | 在哪 | 拍 |
|---|---|---|---|---|
| ① 双链合并 | `add_ln733_1 = sext(acc0_mux) + sext(acc1_mux)` | 26+26 → **27** | `730_36:977` | S1 |
| ② 加 bias | `v = sext(acc) + bias_buf_q0` | 27+32 → **32** | `730_36:1039`（`v_fu_968_p2`）| S2 |
| ③ 移位 | `v_3 = $signed(v) >>> shift`（**算术右移，移位量运行期**）| 32 → 32 | `730_36:1035` | S3 |
| ④ ReLU | `v_4 = (v_3[31] & relu_on) ? 0 : v_3` | 32 | `730_36:1037`（`and_ln735_fu_986_p2` = `tmp_31 & empty`）| S3 |
| ⑤ 饱和到 int8 | 见下 | 32 → **8** | `730_36:1005-1033` | S4 |
| ⑥ 落行缓冲 | `wbuf_d1 = v8`，地址 = `zext_ln657`（像素号）| 8 | `730_36:1165` | S4 |

链路图（k=1，`730_36`；k=3 的 `819_41` 同构，只是车道数 16→8，mux 变 2×8:1）：

```
  acc0[i] (26b) ──┐  2×16:1 (i = 车道号)
                  ├─►[S1] 27b 加 ─►[S2] +bias(32b) ─►[S3] >>>shift ─►[S3] ReLU ─►[S4] sat8 ─► wbuf[i][px]
  acc1[i] (26b) ──┘    26+26        27+32 = 32b          32b              32b          8b
        ▲                                                                                  │
        └── 计算模块 684_33 的 32 个 26 位寄存器（组合直连，无中间寄存器）                  │
                                          bias_buf[ocb+i]  (1R1W，S0 发地址)               │
                                                                                           ▼
                                                                    wbuf（16 bank LUTRAM，同址写）
```

饱和判据（无符号/有符号混写，但语义正确）：

```verilog
730_36:645  tmp_32_reg_1140 <= v_4_fu_991_p3[31:7];              // 25 位 = v>>7
730_36:1005 icmp_ln19 = ($signed(tmp_32_reg_1140) > 25'd0);      // v > 127
730_36:1007 icmp_ln20 = ($signed(v_4_reg_1134) < 32'd4294967168);// v < -128
730_36:1015 select_ln19 = icmp_ln19 ? 8'd127 : 8'd128;           // 127 或 128(= -128)
730_36:1033 v8 = (icmp_ln19|icmp_ln20) ? select_ln19 : v_4[7:0];
```

**为什么是 26 位**（`acc_t = ap_int<26>`，`conv2d_accel.h:9`，不是 HLS 推断）：最坏 |乘积| = 127×127 = 16129，
所以 26 位（±3.35e7）能装下 `cin × taps × 16129`：

| 形态 | 最坏累加 | 26 位够吗 |
|---|---|---|
| k=1，cin = CIN_MAX = 352 | 352 × 1 × 16129 ≈ 5.7e6 | 够（17% 用量）|
| k=3，cin = 352 | 352 × 9 × 16129 ≈ 5.1e7 | 够（76%，已接近）|
| k=5，cin = 352 | 352 × 25 × 16129 ≈ 1.4e8 | **不够**（会绕回）；但 k=5 全网络只有 `conv_first`（cin=3 ⇒ 1.2e6），实际安全 |

⇒ 26 位是**按 k=3 的最坏层**定的；如果将来给 k=5 一个大 cin 层，这里会静默溢出（**存疑项，见 §7.2 第 7 条**）。

**逐级拍数**：S1 合并、S2 +bias、S3 移位+ReLU、S4 饱和+写、S0 取 bias/选 acc。
bias 走的是 `bias_buf`（192×32，1R1W，rpt:159），地址 `= ocb + i`（`730_36:1175` `add_ln733`），
所以 k=1 收尾**每拍只读 1 个 bias**——这是 16 路必须串行的又一个原因（§6.3 给出解法）。

### 4.3 "约 19 拍收尾开销"的对应物（k=1，逐拍）

`730_36` 的 RTL 是一个 **trip count = 16 的流水循环**，不是一个展开的 16 路并行：

```verilog

730_36:1011  icmp_ln731_fu_749_p2 = (zext(i) < ocbl1)                 // 谓词（不是上界）
730_36:402/462  2 × conv2d_engine_sparsemux_33_4_26_1_1                // 16 选 1 × 26 位（acc0/acc1 各一个）
```

| 相对拍 | 谁 | 干什么 |
|---|---|---|
| 0 | top state 134→**138** | 按 `ksize` 分支，置 684 的 `ap_start_reg` |
| 1 | **139** | 等 `684_ap_done`（`conv2d_engine.v:15968-15974`）|
| 1..cin | `LOOP_684_33` | 每拍 1 个 ic，16 MAC；尾部 4 拍排空 |
| +1 | **140** | 置 730 的 `ap_start_reg` |

**精确到 1 拍的分账标「存疑」**，但"16 拍来自没有展开的收尾循环"这一点没有歧义。

## 5. k=5 通用路径为什么慢

### 5.1 五个叠加的代价

| # | 代价 | 具体 | 证据 |
|---|---|---|---|
| 1 | **一次只算 1 个 oc** | 外层 `for i < OC_BLOCK` 是**顶层 FSM 的循环**（`i_6_reg_3561`，4 位，`== 8` 结束），每圈跑一次完整流水 | `rpt:83` `VITIS_LOOP_838_42 ... Trip 8`；`conv2d_engine.v:8130-8136`、`16852` |
| 2 | **II=3** | 25 抽头 = 5 行 × 5 列；每行 1 读口、2 个物理端口 ⇒ ⌈5/2⌉ = 3 | §3.2；`892_47` 有 3 个 `ap_ST_fsm_pp0_stage*` |
| 3 | **24 级串行加法链** | `part += p*wv` 是顺序归约，HLS 展开成 24 个串联加法器，位宽 17→18→19→20 递增 | `892_47:3055/3063`（`part_17`/`part_23`），其中 3 个加法器被标 `(* use_dsp = "no" *)`（`892_47:637/643/646`）|
| 4 | **25 个谓词 mux** | 每个抽头一个 2:1 mux 选"乘积 / 跳过"，26 位宽 | `892_47:3071` `part_2 = icmp_ln899_2 ? grp_fu_2209_p3 : sext_ln894_reg` |
| 5 | **每 (pixel, oc) 重启一次流水** | `142 →(启动892) 146 →(等done) 144 → 147 → 148 → 149 → 150 → 142`，一圈 7 个状态 | `conv2d_engine.v:15980-16020` |

### 5.2 拍预算（推定）

```
每个 (pixel, oc)： 3·cin（计算，II=3）+ 流水填充/排空（9 级，≈26−3·cin，cin 越大占比越小）
                 + 4（state 144/147/148/149 的收尾，不流水）
每个 pixel：      8 个 oc 串行 ⇒ 8 × 上式
每个 (y,ocb)：    权重装载 8 × cin × ~9 拍（rpt:79 给 LOOP_570_24 的 iteration latency = 9）+ xn 的宽写
```

`conv_first`（cin=3、cout=48、k=5）取 `cin=3`：每 (pixel,oc) ≈ `9 + 18 + 4 ≈ 31` 拍 → 8 oc = 248 拍/pixel
→ 48 oc 需 6 个 ocb → 每 pixel 1488 拍；256×256 = 65,536 pixel ⇒ **~9.7e7 拍 ≈ 0.65 s @150 MHz**。
再叠加行缓冲填充（k=5 → span=5，`cpp:304-330`）与 DDR 读，**3 s 量级可解释，但比例分账标「存疑」**（缺 cosim 计数）。

### 5.3 "谓词化 25 抽头"的真正代价是什么

- **不是**多乘了：`ksize==5` 时 25 个谓词恒真，乘法个数不多不少 = 25。
- **是**这三样：(a) 25 个 17~20 位 2:1 mux（约 25×19 ≈ 480 LUT）；(b) 24 级串联进位链——这是时序瓶颈，
  逼得 HLS 把一次点积拆到 3 个调度级（II=3）；(c) 25 个 bank 的权重 LUTRAM/BRAM（`wgt_buf` 深 2816×8，
  2 BRAM18/bank → **50 BRAM18**，占全设计 175 中的 28%）。
- 对比 k=3：C++ 刻意把 9 抽头**拆成 5+4 两条链再合并**（`cpp:781-790` 注释"缩短 3×3 的依赖链"），
  链深 5 而不是 9 —— 这就是 k=3 能 II=2、k=5 只能 II=3 的算法层原因。

## 6. 手写 `mac_array` + `epilogue` 规格

目标：把 §2 的路子固化成**结构上不可能退化成串行**的 RTL，并把 §4 的 16 拍收尾压成 2~3 拍。

### 6.1 模块划分

```
mac_array_k1   : 16 车道 × 1 抽头，II=1，26 位双链，累加器内部
mac_array_k3   : 8 oc × 9 抽头，II=1（靠行内移位寄存器复用，见 6.5），26 位双链
epilogue       : 16（或 8）路并行 acc→+bias→>>>shift→ReLU→sat8→wbuf
lb_bank        : 行缓冲 1 读 1 写 ×(span) 个 bank
wbuf_wide      : 8×8 → 64 位拼字 + 真 burst 写（AWLEN = xn-1）
```

### 6.2 `mac_array_k1` 端口表

| 信号 | 方向 | 位宽 | 时序/含义 |
|---|---|---:|---|
| `clk`, `rst_n` | in | 1 | 单时钟域 |
| `start` | in | 1 | 单拍脉冲；同拍必须给好 `cin`/`cb` |
| `busy`, `done` | out | 1 | `done` 单拍脉冲，与最后一个 `ic` 的 `acc` 落盘同拍 |
| `cin` | in | 16 | 迭代数（≤ `CIN_MAX`）；`cin=0` 时 `done` 在 start 后 1 拍 |
| `cb` | in | 15 | 行缓冲列基址（外层预算好，模块内只做 `+76` 递推）|
| `lb_addr` | out | 15 | `= ic*76 + cb`（由内部 38 位累加器给出，不进关键路径）|
| `lb_ce` | out | 1 | 恒 1（当 `busy`）|
| `lb_dout` | in | 8 | 行缓冲读出（BRAM 同步读，模块内已含 1 拍）|
| `wg_addr` | out | 9 | `= ic`（16 个 bank 共用一根）|
| `wg_ce` | out | 1 | 恒 1 |
| `wg_dout[15:0]` | in | 8 each | 16 个权重 bank 的同址并行输出 |
| `acc0[15:0]`, `acc1[15:0]` | out | 26 each | 16 车道 × 奇偶双链，稳定到下一次 `start` |
| `stage_vld[4:0]` | out | 5 | 调试/收尾握手用（可选）|

**吞吐承诺（硬约束，写进注释与断言）**

- `start` 之后**每 1 拍消费 1 个 `ic`**，`cin` 个 ic 用**恰好 `cin` 拍**，期间 `lb_ce`/`wg_ce` 无空拍；
- 16 个 8×8 乘 + 16 个 26 位加 **每拍全部发生**（16 MAC/拍）；
- 总延迟 `cin + 4` 拍（5 级流水，排空 4 拍），`done` 在 `cin+4`；
- **不允许**任何"按 oc 串行"的状态。

### 6.3 `epilogue` 端口表（16 路并行）

| 信号 | 方向 | 位宽 | 含义 |
|---|---|---:|---|
| `clk`, `rst_n` | in | 1 | |
| `start`, `done` | in/out | 1 | `done` 在 start 后 **3 拍**（见下）|
| `acc0[15:0]`, `acc1[15:0]` | in | 26 each | 来自 `mac_array`（组合直连）|
| `lanes` | in | 5 | 有效车道数 `= ocbl1`（≤16），**只影响写使能，不影响拍数** |
| `bias[15:0]` | in | 32 each | **16 路并行读的 bias**（见下）|
| `relu_en` | in | 1 | 旁路 ReLU |
| `shift` | in | 5 | 运行期常量（每层一次），锁存后使用 |
| `wbuf_we[15:0]` | out | 1 each | 每 bank 一个写使能 |
| `wbuf_addr` | out | 9 | 像素号 `x2`（16 bank 共用）|
| `wbuf_d[15:0]` | out | 8 each | int8 结果 |

**吞吐承诺**：16 个车道**同一拍**完成 `acc0+acc1 → +bias → >>>shift → ReLU → sat8`，
`start→done` = **3 拍**（S1 合并、S2 +bias、S3 移位+ReLU+饱和+写），
对比 HLS 现状 `21` 拍（k=1）/ `13` 拍（k=3）。

### 6.4 在 Verilog 里如何保证 II=1（五条硬规则）

1. **显式流水寄存器 + valid 移位链**，不依赖工具自动调度：
   ```verilog
   // 5 级，每级只放一件事；ce 由 valid 链控制，绝不用"等存储器就绪"的握手
   always @(posedge clk) if (ce) begin
       v1 <= v0;  p_d <= lb_dout;  w_d[k] <= wg_dout[k];   // S1
       v2 <= v1;  prod[k] <= p_d * w_d[k];                 // S2  16 个 DSP/LUT 乘
       v3 <= v2;  acc_e[k] <= acc_e[k] + prod[k];          // S3  偶链
                  acc_o[k] <= acc_o[k] + prod_prev[k];     //     奇链（错一拍）
       v4 <= v3;                                          // S4
   end
   ```
2. **bank 索引必须是常量**：第 k 个乘法器的权重输入直接接 `wg_dout[k]`（对应 `wgt1_buf_k`），
   第 k 个车道的结果直接写 `acc[k]`。**任何 `acc[i]` / `wgt[i]` 带变量 `i` 的写法都会长出 16:1 的 mux**
   （HLS 就是这么长出 `730_36:402/462` 那两个 16 选 1 的 `sparsemux_33_4_26`）——这是"收尾慢"和"面积大"的同一个根因。
3. **行缓冲每拍只读一次**（k=1）：`p` 一根线广播到 16 个乘；地址用"每拍 +76"的累加器递推
   （对应 `684_33:1185-1187`），不要把 `ic*76` 放进地址路径。
4. **奇偶双链**：`acc_e` 只在 `ic[0]==0` 写、`acc_o` 只在 `ic[0]==1` 写 ⇒ 每条链的加法器
   循环依赖是 2 拍，26 位 CARRY4 链（约 26/4 ≈ 7 级）在 6.67 ns 里有充足余量。
5. **乘法器显式用原语**，不要让综合器猜：
   - DSP 车道：`DSP48E1`（`USE_MULT="MULTIPLY"`、`AREG/BREG/MREG=1`、`PREG=1`，A/B 走 25×18 的合法位宽）；
   - LUT 车道：`(* use_dsp = "no" *)` 标注的 `a*b`（每个 8×8 ≈ 41 LUT，与 `conv2d_engine.h:226` 一致）。
   **现状的隐患**：HLS 对 k=1 的 16 个乘法器**全部**只发 `mul_8s_8s_16_1_1`（行为级 `*`），
   没有任何 `use_dsp` 属性（`grep -rn use_dsp` 只命中 3 处 `use_dsp="no"`，都在 892/364/372），
   所以"8 DSP + 8 LUT"只存在于 HLS 的资源估算表（rpt:126）里，最终由 Vivado 自己决定。
   手写版显式实例化后，DSP/LUT 划分和时序就是 RTL 的**性质**，不再是布局布线的运气。

### 6.5 k=3 / k=5 要拿到 II=1 的关键改动（当前被端口卡住）

现状 `II = ⌈横向抽头数 / 2⌉`（§3.2）。手写版用**行内移位寄存器复用**把"横向抽头"从存储器搬到寄存器：

```
每行 bank 每拍只读 1 个新像素 x[c]，横向 3 个抽头由 3 深移位链给出：
    tap0 = x[c]      tap1 = x[c-1]      tap2 = x[c-2]
    （3 行 × 2 个 8 位寄存器 = 48 个 FF，代价可忽略）
⇒ 每拍只需 3 次读（3 行各 1 次，分属 3 个 bank，各用 1 个读口）
⇒ k=3 可以 II=1：8 oc × 9 抽头 = 72 MAC/拍（DSP 预算不允许时降到 4 oc = 36 MAC/拍）
⇒ k=5 同理：5 行 × 1 读 + 5 深移位链 ⇒ 25 MAC/拍/oc，不再是 II=3
```

前提：`stride==1`。`stride==2` 的两层（`k=3 s2`）每拍跨 2 列，移位链要按 stride 抽头
（等价于链上取 `x[c], x[c-2], x[c-4]`，多一级选择），仍可 II=1，代价是每个抽头多一个 mux。

## 7. 存疑 / 与"已知事实"的出入

### 7.1 确定与已知事实不符的三处

| 已知事实 | RTL 事实 | 证据 |
|---|---|---|
| "k=3 快路径 = 4 车道 × 9 抽头，名义 12 MAC/拍" | **8 oc 车道 × 9 抽头 = 72 乘法器**，II=2 ⇒ 36 MAC/拍 | 72 个 `wgt3_buf` bank、72 个乘法器实例、16 条 acc（8×2）；`conv2d_engine.h:139-147` 自述 `K3_LANES`/`K3_PIPELINE_II` 是死宏 |
| "12 处 `BIND_OP impl=DSP`" | 源码里**只有 1 处**（`cpp:693`），在 `for i < K1_DSP_LANES` 内，展开后 = **8 个**乘法器 | `grep -c BIND_OP conv2d_engine.cpp` = 2（1 处注释 + 1 处 pragma）；csynth 给 684 的 DSP 就是 8（rpt:126）|
| "k=1 收尾 ≈ 19 拍" | 结构值是 21（收尾）+ 2（顶层状态）= 23；21 = 16 迭代 + 5 级流水 | `730_36:1009`（上界 16）、rpt:54（latency 21）；cosim 的 19 与 21 更接近 |

### 7.2 标「存疑」的推断

1. **`764_38` 的确切延迟**：csynth 给的是 `?`。按 "iter 寄存器数 × II − 1" 推是 9 拍，按 "trip×II + iter" 是 `2·cin + 5`。未仿真，不给单值。
2. **`892_47` 的 26 拍**：与 `3·n + 9` 在 `n≈5.7` 时吻合，对不上整数 trip，说明还有额外的填充/退出拍；不影响"II=3"的结论。
3. **k=1 的 DSP/LUT 8:8 划分**：RTL 无属性、无差异化原语，"8 DSP" 只是 HLS 估算；上板实际划分由 Vivado 决定（这也是 `BIND_OP` 生效后 WNS 从 −0.184 变 +0.005 却能成立的原因——它改的是 HLS 的**调度/寄存器摆放**，不是 RTL 里的乘法器种类）。
4. **7.8 MAC/拍 的分解**：需要 cosim 的 per-block 计数才能确认权重装载/收尾/DDR 各占多少。
5. **`wbuf` 深 448 的用途**：`448 = 7×64`，与 `BWCOL_MAX=76` 不匹配，怀疑是 `K1_WIDE_COLS` 的遗留形状（本构建 `line_buf` 地址是 `ic*76+cb`，说明 `wide1=0`）。不影响功能判断。
6. **`C8_LAYOUT` 的取值**：头文件写 `0`（`conv2d_engine.h:73`），但 RTL 里有 16 个 `wbuf` bank、`out_copy`（`945_50`/`967_51`）和 `WSTRB=8'd255`，**只可能来自 `C8_LAYOUT=1` 的构建**。说明构建时用了 `-DC8_LAYOUT=1` 覆盖，或头文件在构建后被改回 0。以 RTL 为准。
7. **26 位累加的溢出边界**：见 §4.2 的表；k=5 且 cin ≳ 200 时会绕回（`ap_int<26>` 截断）。当前网络只有 `conv_first`（cin=3）走 k=5，安全；但这是"运行期 k / 运行期 cin"这个设计的一个潜在静默错误面。

## 9. 结论摘要（给下一步用）

1. **不要重写"一个通用阵列"**——四条路径的乘法器组是**同时存在**的静态实例，k=1/k=3 的快路径已经是该结构下的近最优解；可动的收益只有三处，且都不在乘法器上。
2. **16 拍收尾**（`730_36`）是纯软件问题：pragma 的作用域错了（`solution1.log:21`，见 §4.3 的对照表）。手写 epilogue 或改一行 C++ 都能拿回约 16 拍/pixel。
3. **II 由行缓冲端口决定**：k=1 是 1、k=3 是 2、k=5 是 3。要突破只能改成"1 读/行 + 行内 3/5 深移位链"，这是手写 k=3/k=5 阵列唯一真正值钱的改动。
4. **k=5 的病根是"一次一个 oc"**（顶层 FSM 的 8 圈循环），不是 25 个抽头。给它 4 个 oc 车道 + 并行收尾，比优化 25 抽头本身收益大得多。
5. ~~写回仍是 1-beat 事务（AWLEN=0）~~ **勘误（以 `05_writeback_axi.md` 为准）**：`945_50:519` 的 `AWLEN=0` 是流水线的**悬空输出**（`solution1.log:766-777` 有 dangling 告警）；真正上总线的 AW 由顶层 FSM 在 `top:16035-16079` 发出，`AWLEN=63`（512 B/笔）。手写时要注意的是**AW 与 W 硬耦合**（`gmem1:2598`）而不是"没有 burst"。
