# 共存验证操作单（草稿）—— 整网 + HDMI 同时跑

> 对应 `01_第一轮优化目标与判据.md` 的目标 2。
> 拿到新位流（修过 `hdmi_fb_scan` 行握手）后，按本单执行**一次**。

---

## 0. 前提与红线

| 项 | 要求 |
|---|---|
| 板端操作者 | 只一人（当前：本代理） |
| 频率口径 | **只认真值**（读 SLCR `0xF8000170` 解 `DIV0+1`）；PYNQ 报数 = 真值 × 1.5 |
| 载位流 | 只能 sysfs 喂 **`design_1_v58.bin`**（byte-swapped），`.bit` 会被内核拒绝 |
| 改位流顺序 | **`stop` → 重载位流 → `start`**（不是 `reload → restart`：restart 的 SIGTERM 会在新 PL 上写 `0x15`，紧接 bringup 的 `0x01` 就是第二次武装） |
| 黑屏判别 | **`0x2C` 以 ~43 000/s 涨** = 扫描 FSM 死（DE 有效、像素全 0）⇒ 只能重来 `stop → reload → start` |
| 稳态判据 | `0x2C` **增量必须为 0**；`CTRL=0x01`；`init_done=1`；`FCLK0` 真值 = 目标档 |

**每次改位流前先备份**：`cp /home/xilinx/demo/design_1_v58.bit{,.prev}`、`cp /lib/firmware/design_1_v58.bin{,.prev}`，
回滚 = 换回 `.prev` 再走一次 `stop → reload → start`。

## 1. 版本核对（不做完不跑）

```sh
md5sum /home/xilinx/demo/design_1_v58.bit /home/xilinx/demo/design_1_v58.hwh
# 与交付方给的 md5 逐字相同，否则不跑

```

记录：`bit_md5 / hwh_md5 / ps_md5 / bin_md5 / 仓库 HEAD`。

## 2. A 档：整网 sha1 命中（两档频率都测）

**判据**：`out1/out2/out3` 的 sha1 与冻结基线**逐位相同**（3/3 样本）。

| 档 | 目标真值 | PYNQ 报数 | 期望 |
|---|---|---|---|
| A-50 | **50.00 MHz** | 设 75 | 整网 3/3 命中（历史值 3/3） |
| A-67 | **66.67 MHz** | 设 100 | 整网**历史上 0/7 不命中**；新位流若不改算法，允许不命中，但要记录 |

```sh
# 板上，一次进程内跑完两档（避免反复武装）
cd /home/xilinx/demoir/ps/pynq
DUMP_FCLK_MHZ=75  python3 ../tools/dump_board_int8.py --samples /home/xilinx/demo/frozen256 \
     --out /home/xilinx/demo/dump_50  --index /home/xilinx/demo/frozen256/index.json
DUMP_FCLK_MHZ=100 python3 ../tools/dump_board_int8.py --samples /home/xilinx/demo/frozen256 \
     --out /home/xilinx/demo/dump_67  --index /home/xilinx/demo/frozen256/index.json
```
> ⚠ 两档不要夹在同一个 `BinNet` 里（惰性槽会跨档残留）⇒ 分两个进程，各自 `--limit 3`。

**记录**：每档 `x0_sha1`（证明同一输入）、`out1/2/3 sha1`、`sha_ok`、`wall_s`（第 2 张起）。

## 3. B 档：HDMI 100 对轮播（66.67 真值）

**判据**：`nonblack ≥ 88%`（逐帧）、`0x2C` 增量 **0**、`CTRL=0x01`、`0x24` 逐帧推进。

```sh
sudo systemctl stop demo-player
# 位流已是新版本的话：直接 start（不清 PL）
sudo systemctl start demo-player
printf 'START\n' | nc -q1 192.168.7.2 9999      # 触发（⛔ 不要 STOP）
# 播放期间采样（另开一条 ssh）
for i in $(seq 1 10); do sh /tmp/rd.sh; sleep 5; done
tail -f /home/xilinx/demo/listen.log | grep -E "frame 0|nonblack"
```

**记录**：`nonblack` 最小值、`0x2C` 起点/终点（增量）、`0x24` 首末帧号、播放期间有无 `[warn]`。

## 4. C 档：**同进程**同时跑 A 与 B（这才是"共存"）

顺序固定（先显示后计算，避免计算期间改显示状态）：

1. `bringup()`（= `minimal_proof`）→ `CTRL=0x01`，**这一进程内只武装这一次**
2. 显示第一对图 → 读 `0x2C` 基线、`0x24=1`
3. **同一个进程里**构造 `BinConvEngine + BinNet`，跑 1 次 256² 整网（此时 HDMI 在扫）
4. 整网结束后立刻：读 `0x2C` 增量、`0x24` 是否仍在推进、再提交下一帧 → `nonblack`
5. 反向再验一次：先跑整网、中途开始显示（检验"计算完才武装"也是 0 增量）

**判据（C）**
| # | 判据 | 阈值 |
|---|---|---|
| C1 | 整网期间 `0x2C` 增量 | **0**（允许 ≤1 行/万行） |
| C2 | 整网期间 `0x24` 仍推进 | 是（每 1.0 s 至少 +1） |
| C3 | 整网 sha1 | 3/3 与 A-50 档一致 |
| C4 | 整网后第一帧 `nonblack` | ≥ 88% |
| C5 | 眼睛 | 无撕裂、无花屏、`nonblack` 稳定 |

> 现有 DSS 已经在跑 0.16 fps 的整网 + 1 fps 显示时出现过"冻结"，C 档就是把它变成**可判定的数字**。
> 若 C 档只能靠"关掉 HDMI 才准"，那本目标不达成。

## 5. 失败处置（每档独立）

| 现象 | 结论 | 动作 |
|---|---|---|
| A 档 sha1 全错 | 位流算法变了 / 频率错 | 先改回 50 MHz 真值复测，再联系交付方 |
| `0x2C` 暴涨 | 扫描 FSM 死 | `stop → reload → start`，重来 |
| `nonblack` < 88% | 写块/贴图错 | 查 `FB_ADDR/STRIDE/LATCHED`，不动位流 |
| C 档 `0x2C` 增量 > 0 | **目标 2 未达成** | 取该次 `board_dump.json` + 采样，回 RTL 方 |
| 板子失联 | AXI 挂死 | **只断电**；回来先 `cat state`，再按 runbook §0.0 两步走 |
