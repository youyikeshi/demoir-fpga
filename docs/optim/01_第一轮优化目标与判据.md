## 目标 1：PS 端输出与 PC 一致

### 症状（已实测）
板端 int8 二值网输出几乎与输入无关：

```
out ≈ 0.148·in + 0.310      R² = 0.944      σ_out/σ_in = 0.155
```

⇒ 画面发灰。旁证：`validation.json` 自报 `act_quant.rel_rms_median=0.2656`、`t_quant.rel_rms_median=0.3054`，而 `engine.rel_rms_median=0.0307` —— **引擎内部准，量化/对齐那一段崩**。

### golden 是谁
`pynq_specialized_code/ps/tools/bin_fp_ref.py`（numpy 浮点参考，语义严格照 `vendor/PDNet/model/binary_esdnet.py`）。
昨晚演示用的 100 对图对就是它生成的，**PC 侧是对的**。

### 判据（验收）
| # | 判据 | 阈值 |
|---|---|---|
| A1 | 同一 u8 映射下，int8 路径 vs 浮点参考 | max\|Δ\| ≤ 1 LSB |
| A2 | 同上 | rel_rms ≤ 0.01 |
| A3 | 样本数 | ≥ 3 张冻结样本 |
| A4 | 变异测试 | 把修复删掉 ⇒ 判据变红；恢复 ⇒ 变绿 |

## 目标 2：整网与 HDMI 同时运行（RTL）

### 硬冲突（均板端实测）
| 配置（FCLK0 真值） | 去摩尔纹整网 | HDMI 扫描 |
|---|---|---|
| 50.00 MHz | **正确**（3/3 sha1 命中） | **全黑**（`0x2C` ≈ 45000 行/秒） |
| 66.67 MHz | **错**（sha1 0/7） | 正常 |

频率口径陷阱：PYNQ `Clocks.fclk0_mhz` 报数 = 真值 × 1.5（本板 IO PLL 1000 MHz）。
文档里的 "75" 是真实 50 MHz，"100" 是真实 66.67 MHz。

### 主攻方向
`hdmi_fb_scan` 的行请求 toggle 握手（PIX 域 → AXI 域）在 $f_{aclk} < f_{pix}$ 时丢请求。
像素时钟 74.21875 MHz 固定，AXI 取 37.09 / 50.00 / 66.67 三档做 xsim 复现。

### 判据（验收）
| # | 判据 | 阈值 |
|---|---|---|
| B1 | xsim 三档丢行率 | 必须复现 50 MHz 全丢、66.67 MHz 不丢 |
| B2 | 修复后 50 MHz 档 | 丢行率 0（或 ≤1 行/万行） |
| B3 | 66.67 MHz 档 | 不许退化 |
| B4 | 整设计 LUT | ≤ 22000（当前 21709） |
| B5 | `hdmi_fb_scan` 层次 LUT | ≤ 1200 |
| B6 | FCLK0 WNS | > 0（当前 +0.100） |
| B7 | pix 三档 WNS | > 0（当前 +0.961 / +7.691 / +21.156） |
| B8 | latch / DRC | 0 / 0 |
| B9 | 变异测试 | 删掉修复 ⇒ 仿真变红 |

## 分工

| 角色 | 职责 | 边界 |
|---|---|---|
| 主代理 | 读证据、定判据、派活、归档 | 不写代码、不上板 |
| PS 数值代理 | 目标 1：定位 + 修 + 验收 | 只碰主机，不碰板 |
| RTL 代理 | 目标 2：xsim + 改 RTL + 综合实现 | 只碰主机，Vivado 经 memgate |
| 板端代理 | 上板、诊断、部署 | 唯一有板子访问权 |

## 纪律（沿用）
- 上板/长任务一律派子代理；主代理不跑板端脚本。
- Vivado 只许一个实例，必须经 `pynq_specialized_code/tools/memgate.sh`。
- 任何"已修复"必须附变异测试（删掉修复 ⇒ 判据变红）。
- 涉及画面，必须用户目视确认。
- `git add -A` 禁止；`.bit` / `.dcp` 不入库。
