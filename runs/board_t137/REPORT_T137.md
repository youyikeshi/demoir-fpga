# T-137：v54 频率阶梯（找 64² 整网"正确且可重复"的最高频率）+ 该档 256² 真实耗时

**一句话**：v54 的 64² 整网上限仍是 **83.3333 MHz（= 1500/18，读回 83.333333）**，与 v53 **完全相同**：
88.2353（1500/17）**三个 sha1 全不中**，93.75（1500/16）**连第一笔 PL 操作都不完成**（两次独立租约都是
`E1E2 等 idle 超时 30.0s`，一次 segfault rc=139），100 未测；
在 **83.3333 MHz** 上 64² 四跑三 sha1 全同且 = 冻结值，256²（T=32 ms 护栏）两跑也全中：
**墙钟 23.099 s**（PL 6.204 s、护栏睡 7.269 s = **31.5 %**、净 15.83 s），相对 50 MHz 的 23.651 s 只快 **2.3 %**；
64² 在该档 **3.823 s**，相对 50 MHz 的 3.913 s 也只快 **2.3 %**
⇒ **升频买不到时间：64²/256² 的墙钟都被 PS 侧主导（PL 只占 15 % / 27 %）**。
v54 的时序修复（WNS +0.103）**没有**换来任何频率余量（上限与 v53 分毫不差）。

## 6. 事故与取证：93.75 MHz 的 idle 挂死 + **`0x310 = 0` 不等于 PL 空闲**

**现象（`t137c`，前一跑是 PASS 的 75 MHz、跑前 AP busy 已确认 (0,0)）**

```
################ 请求 93.75 MHz（格点 1500/16 = 93.7500）
  fclk0 请求 93.75 → 读回 93.75 MHz；magic=0x50300001 0x310=0x00000000（第 119 条）
  ✗✗ 整网 @ 93.75 MHz 超时：TimeoutError('E1E2 等 idle 超时 30.0s（上一跑还在访存，不能发新 start）')
  [t137c] 探针 rc=139          ← SIGSEGV（128+11）
```

**复位前的只读取证（`t137d`，`/dev/mem` 直读，不 new Overlay）**

| 绝对地址 | 寄存器 | 读值 | 含义 |
|---|---|---|---|
| `0x40070310` | `bin 0x310 CHAIN_STATUS` | **`0x00000000`** | "空闲" |
| `0x40070010` | `bin_AP_RETURN` | **`0x00000002`** | **`busy=1`、`done=0`、`err=0`** ← 单元根本没退出 |
| `0x40050010` | `conv_AP_RETURN` | `0x00000000` | 空闲 |
| `0x40070314` | magic | `0x50300001` | 寄存器块仍在位 |

$$\Rightarrow\ \textbf{0x310 读到 0，但 bin_unit 的 AP_RETURN 是 busy=1} \Rightarrow\ \textbf{0x310 不足以判"PL 空闲"}$$
$$\Rightarrow\ \text{这就是 §2 里"93.75 起不来"的直接原因：} \text{每 op 的 pre-start 空闲门等的是 AP idle，而 AP 永远 busy}$$
$$\Rightarrow\ \textbf{处置}：\text{一次 load 复位（} \texttt{t137d} \text{）：magic } 0x50300001、0x310=0、\text{两个 AP busy=0/err=0} \Rightarrow \text{板子已回已知good状态}$$

**内核侧（`dmesg`）无 oops、无页错误**，只有一条
`coredump: 19094(apport): RLIMIT_CORE is set to 1, aborting core`
⇒ `ulimit -c 0` 生效，**没有 core 文件落到 SD**；`MemFree 780 MB`、`CmaFree 87.5 MB`、`df 34 %`、inode 6 % ⇒ 无内存/磁盘污染迹象。

> **给后续 session 的两条硬建议**
> 1. **空闲判据升级**：任何"整网后接着跑"的探针，都必须同时检查 `0x310==0` **且** 两个 IP 的
>    `AP_RETURN.busy==0`（T-137 已在 `probe_t137.py:idle_gate()` 落地并做进主机自测）。
> 2. **不要把 93.75/100 放进"先跑失败档、再往上"的序列**：一次失败就会把 bin_unit 留在 busy，
>    后面所有档位都会被 30 s idle 门挡住；要在干净 PL 上测高频，必须把它放在**换频后的第一跑**
>    （`t137c` 就是这么做的，仍然挂 ⇒ 说明是这一档本身不行，不是"没清干净"）。
