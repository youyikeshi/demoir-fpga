# v56 归档：16-lane + 写合并器 —— **仅作功能证据，不作性能候选**

首行判定：**可上板（仅功能验证，≤100 MHz）；不可作性能结论；不可替代 v152/v57**

## 是什么
`v53（16-lane, wrap 17164dfc）` + **写合并器**（10 级写串行化 → 每平面 8 深 × 104 bit FIFO + 成块轮转出口）。

## 数字
| 项 | 值 |
|---|---|
| bit | `design_1_150v56.bit` |
| WNS (10 ns) | **−0.044 ns**（4 个违例端点，TNS −0.121）；v53 是 +0.041 ⇒ 合并器吃掉 0.085 ns |
| 最差路径 | `r_h_reg[2]_replica/C → g_conv.g_wr_split2.f1_adr_reg[5][31]/D` ⇒ **合并器出口寄存器，真实数据通路** |
| LUT / FF / BRAM / DSP | 21,979（+483，+2.2%）/ 23,516（**+1,754** = 2×8×104bit FIFO）/ 43 / 126 |
| DRC / Latch | Critical 0 / 报告 0、网表 LDCE=LDPE=0（双查） |
| `.hwh` | 与 v53 同一份（BD 未动） |

## 它证明了什么
- xsim 矩阵 **96/96 PASS**（16 形状 × 6 配置），0 字节差异、0 越界
- 每 8B beat **21.40 → 3.76 拍**（判据 ≤6，达 T-99 的 3.75 口径）；beat/AW **1.01 → 7.93**（13470 → 1720 笔）
- `VLANES=8` 逐笔写日志 **16/16 逐字节相同** ⇒ 8-lane 网表未变
- **done-断言**：独立计数器在 16 形状上 `n_ub_done=0`，报 done 时"合并器非空/写侧忙/beat 未收"= 0/0/0（110 份日志）
  ⇒ 没有"为性能把 done 提前"
- T-105 的 s=2 `npix` 8 行**逐字节保留**（0 行差异）

## 为什么不作性能候选
1. **合并器只在 `VLANES>8` 的 `g_wr_split2` 里**；8-lane 走 `g_wr_direct`，**逐字节不变**
2. **8-lane 的地板本来就是 3.75 拍/beat、7.88 beat/AW**（同尺实测）⇒ 合并器只是把 16-lane 抬到 8-lane 的**既有水平**
3. 16-lane 最高只到 83.33 MHz，性能已是负的（256² 23.1 s vs v39 8.1/6.06）⇒ 已封存
