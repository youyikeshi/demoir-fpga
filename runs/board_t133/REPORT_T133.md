# T-133：把"`BE._flush` 之后 sleep 3 ms"换成**便宜且确定的 fence** —— 结论：**没有便宜 fence 存在**

**一句话**：在同一次 load 里把 9 个 fence 臂各跑 2 次（128²），**只有两种"够长的等待"能复现 v39**：
纯 sleep 3 ms（10.53 s）与 `/dev/mem` 回读**整个**输入区（12.70 s，fence 自身 6.17 s）；
而**真正的 fence 语义全部无效**——`dsb st`（0.03/0.64 ms）、只回读尾 64 B、只回读头 64 B、
只 mmap+munmap（对照）、以及**把输入区改成 `/dev/mem` device 映射、完全不 flush（F5，最快的臂 6.17 s）**。
⇒ **这不是 CPU→DDR 可见性问题**：DDR 里数据一直是对的（本探针的写回自测里"**不 flush** 对照组也 0 字节差异），
F5 直写 DDR 仍然错 ⇒ 需要的是**经过时间（≈ms 量级）**，不是任何内存屏障/回读/缓存维护。
**⇒ 推荐：保留 sleep，但只当护栏；并把下一步锁定在"最小 flush 子集 + 剂量二分"上**（见 §5，能把它从 +3.5 s 压到约 +0.7 s）。
另外 **256² 在 sleep3 下不中**（新发现），64² 中。

## 2. 第 2 步：五个候选 fence（+ 两个对照），每个 2 跑

| 臂 | 做法（都只改 PS 侧、只在 `_flush` 之后） | fence 次数 | fence 自身耗时 | 墙钟 | = v39 |
|---|---|---:|---:|---:|---:|
| **F1** `readall` | `/dev/mem` 非缓存**回读整个刚写的区** | 1135 | **6.17 s**（5.44 ms/次） | **12.70 s** | **✓ ✓** |
| **F2** `readtail` | 只回读**最后 64 B** | 1135 | 0.26 s（0.23 ms/次） | 6.51 s | ✗ ✗ |
| **F3** `readhead` | 只回读**最前 64 B** | 1135 | 0.26 s | 6.52 s | ✗ ✗ |
| **F3x** `touchonly` | **对照**：只 mmap+munmap 同一页，**一个字节都不读** | 1135 | 0.18 s | 6.45 s | ✗ ✗ |
| **F4a** `dsb` | 真 `dsb st`（板端 `cc -O2` 现场编，`rc=0`/`armv7l`），**不睡** | 1135 | 0.03 s | 6.29 s | ✗ ✗ |
| **F4** `dsb0p3` | `dsb st` + sleep **0.3 ms** | 1135 | 0.50 s | 6.77 s | ✗ ✗ |
| **F4** `dsb0p5` | `dsb st` + sleep **0.5 ms**（剂量兜底自动补跑） | 1135 | 0.73 s | 6.99 s | ✗ ✗ |
| **F5** `devmem` | 输入区改 `/dev/mem` **device 映射**，CPU 直写 DDR，**不 flush 不 invalidate** | 0（跳过 227） | 0.00 s | **6.17 s（最快）** | ✗ ✗ |
| 参照 B0 | 纯 sleep 3 ms | 1135 | 3.55 s | 10.53 s | ✓✓ |

**判据结论（逐条）**

1. **没有任何"确定的 fence"成立**：`dsb st`（完整数据同步屏障）✗、读尾 64 B ✗、读头 64 B ✗、mmap 对照 ✗。
2. **F1 之所以"成立"，是因为它贵**：整区回读 5.44 ms/次 ≈ 227 次 × 10.9 MB ≈ **2.47 GB/run**（约 400 MB/s），
   比 sleep 3 ms 还慢 **2.17 s**（12.70 vs 10.53）⇒ **F1 不是"更便宜的 fence"，是"更贵的等待"**。
3. **剂量边界被夹住**：0.2 ms（T-132）✗ → 0.3 ✗ → 0.5 ✗ → 0.64（dsb+0.5 实测）✗ → **3.13（B0）✓** → 5.44（F1）✓
   ⇒ 阈值落在 **0.6~3 ms** 之间，且**只与经过时间相关**，与做了什么完全无关。
4. **F5 最快却错（最重要的一条）**：把输入区换成 device 映射（绕开 cache、CPU 直写 DDR）后，
   **连 flush 都不需要**（跳过 227 次），墙钟反而最快 **6.17 s**，**结果仍然错，且两次互不相同**
   ⇒ **"PS→DDR 可见性"这条线被彻底否证**。不是 flush 没落地（T-132：0/908），不是缓存陈旧，不是内存序。
5. **写回自测的对照组也不敏感**：`step_flushtest` 里"只写、**不做任何 flush**"这段，`/dev/mem` 与 CPU 视角
   也 **0 字节差异**（`control_ok=False`）⇒ 这块 arena 的 CPU 写入在本机**本来就直接可见**。
   这解释了为什么所有"让写入更可见"的手段都无效，也与 F5 的负结果自洽。

## 3. 关键副产品：**1135 次 flush 只有 5 种尺寸，每种恰好 227 次**

| 尺寸 | 次数 | 是什么（据 64/128/256 三档对比定位） |
|---:|---:|---|
| **9,437,184**（9 MB） | 227 | **E1E2 程序/描述符 arena**（每 op 写 desc+cmd 后整块 flush；与分辨率无关） |
| **1,179,648** | 227（128²）/ **454**（256²） | 256² 的**每 op 输入**（max_in 1.180 MB ✓）／另有一段固定 1.18 MB 缓冲 |
| **294,912** | 227 | **128² 的每 op 输入**（= max_in 0.295 MB ✓） |
| 1,152 / 576 | 227 / 227 | desc / thr 小视图 |
| 73,728 | 227（64²） | 64² 的每 op 输入（= max_in 0.074 MB ✓） |

- **flush 本身很便宜**：1135 次合计仅 **0.22 s**（9 MB 那次约 0.19 ms，说明绝大多数行是干净的）。
  ⇒ B0 的 **+3.55 s 全是 sleep**，没有一毫秒是 flush。
- **F5 只跳过了 227 次**（arena 内那一组），其余 908 次（9 MB + 1.18 MB + 小视图）照旧 flush。
- ⇒ **"最小 flush 子集"是一个还没被利用的 5:1 杠杆**（见 §5）。

## 4. 第 4 步：最优方案（sleep3）下验 256² 与 64²

| 尺寸 | 墙钟 | fence | 三 sha1 | = v39 |
|---|---:|---:|---|---:|
| **256²** | 20.12 s | 1135 次 / 3.55 s | `7e266fc735` / `1c4becf433` / `24ff1bba4f` | **✗ 不中** |
| **64²** | 7.59 s | 1135 次 / 3.55 s | `bfa246d346` / `226bd39e52` / `762d84b961` | **✓ 全中** |

- 256² 的 arena 是 66.22 MB / 24 槽 @**0x31e00000**（`CmaFree` 报 0.385 MB 仍然分配成功 ⇒ 该字段在本机不可当额度用）；
  `run_valid=True`、`deps_closure_ok=True`、PL 前后 0x310=0、magic 在位 ⇒ **不是环境问题，是结果不中**。
- **这是新发现**：sleep3 这条护栏**只在 128² 被证明过**（T-132 + 本租约 4/4），**256² 不成立**。
  两种可能：(a) 同一个窗口在 256² 更宽（buffer 4×、PS 写 3× 时间），需要更大 settle；(b) 256² 另有独立问题。
  判别只要**一次 256² 跑**：`sleep 8~10 ms`（≈ +9~11 s）——中 ⇒ 同窗口，加剂量即可；不中 ⇒ 另一条线。

## 5. 推荐（对父代理）

1. **不推荐 F1**（12.70 s，比 B0 还慢 2.2 s，且要读 2.47 GB/run）。
2. **不推荐 F5**（虽然最快 6.17 s，但**错**）⇒ "换非缓存输入缓冲"这条路**到此为止**，别再往 RTL 之外找可见性解释。
3. **短期护栏仍是 `BIN_SETTLE_MS=3`（flush 后纯睡）**，但必须标注**只对 128² 生效**，且**不许当性能基线**（6.30 → 10.53 s，+67%）。
4. **下一步只做两件软件实验（一次 load 就够，我可以在 8 分钟内跑完）**：
   - **① 最小 flush 子集**：把 3 ms 只加在"每 op 输入"那一组（128² = 294,912 B 那 227 次）⇒ 若中，护栏从 **+3.55 s 降到 +0.68 s**（总 ~7.0 s）；
     再试"只加在 9 MB 那一组"（227 次，+0.68 s）与"只加在 1.15 KB/576 B 那组"（几乎免费），**定位窗口到底在哪个写入口**；
   - **② 剂量二分**（1.5 / 2 / 2.5 ms）+ **256² 用 sleep 8~10 ms 判别**（结论分别给"最小护栏"和"256² 是否同窗口"）。
5. **判断（为什么需要时间而不需要读）**：既然 ①DDR 内容一直正确、②直写 DDR 也错、③完整 `dsb` 也错、④只有 ≥0.6~3 ms 的时间有效
   ⇒ 这**不是 CPU→DDR 的可见性/顺序问题**，而是**PL 侧对"kick 之后多久开始读"的时间敏感**：
   最自然的读法是 **PS 侧连续的 DDR 写突发把 PL 的读事务挤在后面/重排，而 RTL 对"读数据晚到"没有正确吸收**
   （例如某级 FIFO 丢拍/错拍），以致"让 DDR 安静几毫秒"才有效、而任何 CPU 屏障无效。
   这条读法与 T-124 的形状（错在**输出尾部**、前缀逐字节正确）一致：一旦某级的输入晚到/错一拍，出口就是"从某点起往后稳定地错"。
   ⇒ **真正的修法在 RTL（输入侧握手/背压），PS 侧只能加时间。**
