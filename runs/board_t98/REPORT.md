# T-98：v51 ±1 误差 = 时序还是非确定性？（一次 load / 一个 session）

**一句话**：**是时序（频率相关），不是"硬件随机坏"**。100 MHz 下两层**连跑两次逐字节不同**（3286 B / 1310 B），
降到 **75 MHz 立刻 0/0 且两次逐字节相同、与 golden 逐字节相同**，50 MHz 同样 0/0；再回到 100 MHz 错误复现。
⇒ **"非确定"只发生在 100 MHz 这个运行点上，其根因是频率相关时序失效**；同时 STA 报的 WNS `+0.113 ns` 属于**假安全**。

跑点：位流 `design_1_150v51.bit` md5 `16766e1f…` + `.hwh` `52357646…`（跑前=跑后，成对）；
H=W=32、seed `20261031`、64 KB 越界垫子 `0xA5`、24 槽；`fclk0` 100/75/50/100 读回全精确；
**本 session 只 `download=True` 一次**（Overlay 2.493 s）；`0x40070314` magic = `0x50300001` ✓，复位 `0x40060310` = 0 ✓。
PS 闭包 `9de3d60c…`（`md5sum -c` 20/20 + `deps_closure.py --check` rc=0），`ps/pynq` 源码 md5 与主机逐个一致，
`deps_closure_ok=True`，`BIN_V50_*` 全空。**两层缓冲每个 case 只分配一次** ⇒ 跨频率/跨两次 run **物理地址恒定**
（cin112 `ob=0x30100000`，cin512 `ob=0x30126880`），地址不是自变量。

## 3. 结论（给方向性判断）

1. **不是"回炉查设计"**：75/50 MHz 下两层**逐字节等于 numpy golden**、两次运行**逐字节相同**（确定性、功能正确）
   ⇒ RTL 功能/映射/权重/PS 代码都没问题（与 T-97 的 xsim 5 层 0 差互相印证）。
2. **"两次不同"是 100 MHz 的时序失效表现**，不是独立于时钟的硬件非确定性：唯一自变量是 `fclk0`，
   100 MHz 失败的同一份缓冲/同一份数据在 75 MHz 完全正确。这类"同输入不同输出 + 频率恢复"是**亚稳态/竞争**的典型签名。
3. **STA 报的 WNS `+0.113 ns` 是不可信的"假安全"**：真实缺口下界是 > 0.113 ns（否则不会错），
   上界 ≤ 3.33 ns（75 MHz 比 100 MHz 多出的周期）；75 MHz 完全干净说明缺口量级可能在 **亚 ns 到数 ns**，而不是 0.1 ns 的抖动级。
   ⇒ 有一条**静态时序没覆盖到（或覆盖方式不对）的路径**：可能被 `set_false_path` 误切、跨时钟域、或约束的时钟源与实际
   时钟树不一致（本 build 只有 `create_clock -period 10.000 $clk_pin` + catpack false_path 三件套）。
   最差路径是 `bin_unit_0/…/win_q_reg_15/CLKBWRCLK → g_conv.u_core/s1_pc_q_reg[14][5]/D`，+0.113 ns ——
   正好是**激活字（win）寄存器**，与"错在共享激活字、同像素成簇、多通道"的错误形状吻合，值得作为首要嫌疑复核。
4. **100 MHz 下的"错误数"不是可用门禁**：T-96 同一层同 seed 记到 24 476 / 47，本轮同 session 记到 2 238 / 3 291
   （且每次 run 都变）⇒ 该指标在临界点上不可复现，只能用来定性，不能用来定阈值。
5. **可执行的取舍**：要么把运行点降到 **75 MHz**（本轮已验证该频率下这两层功能全对、确定），
   要么留在 100 MHz 就必须先找出那条 ~ns 级的未覆盖路径（查 `report_timing` 未约束端点 / false_path 覆盖面 / CDC），
   单纯再加流水而依旧按 WNS `+0.113` 验收，会在下一次 P&R 随机复现。
