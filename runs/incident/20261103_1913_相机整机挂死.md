# 事故：MaixCAM 在采集验证期间整机挂死（2026-11-03 19:13）

随后 ping 100% 丢包、SSH 无 banner ⇒ **内核级挂死**。用户手动重启后恢复。

## 五个流程缺陷（本次暴露，逐条修）

1. **服务日志 0 字节** ⇒ 挂死时零线索。必须无缓冲 + 每行 `flush`，启动先落一行带参数的 banner。
2. **没有内存看门狗** ⇒ 可用 70 MB 还一路往下跑。必须 `MemAvailable < 35 MB` 时回 `err:"lowmem"` 而不是硬撑。
3. **验证没有分档** ⇒ 一上来连发 10 张。必须先 720p×3 看内存能否回收，再 720p×10，最后 2K×2。
4. **没有先查设备占用** ⇒ 应先 `fuser -v /dev/video*` 看 launcher 有没有占相机。
5. **出事后的处置没写进流程** ⇒ "ping 丢包 / SSH 连不上 / mem<30 MB / 单次 grab>10 s" 任一出现就停手，不许"再试一次看看"。

## 补充（19:40，实现方现场日志修正了三条，其中两条推翻我当时的判断）

### 一、故障是**两阶段**的，不是"内核直接死"
| 阶段 | 现象 | 说明 |
|---|---|---|
| 19:14~19:16 | **ping 0% 丢包、RTT 1.89 ms 正常**，但 TCP 22/21/1901/7899 **accept 后不发 banner** | 内核网络栈活着、**用户态整机卡死** |
| 19:16~19:18 | ping 也开始 100% 丢包 | 内核最终失去调度 |

$$\Rightarrow\ 	ext{我最初只看到第二阶段，据此写"内核级挂死"} \Rightarrow 	extbf{不准确}$$
$$\Rightarrow\ 	ext{真实顺序是"用户态先被饿死，内核后失去调度"} \Rightarrow 	ext{这与"长时间内存回收停顿"完全吻合}$$

### 二、★ 主因假设（这次有硬数字）
$$\Rightarrow\ 	exttt{MemFree}=6.6\ 	ext{MB}、	exttt{MemAvailable}=71\ 	ext{MB}、	exttt{Cached}=55\ 	ext{MB}$$
$$\Rightarrow\ 	ext{MMF 启动要}	extbf{连续物理块}：	ext{日志 } 	exttt{PoolId 0, BlkSize 5652480, BlkCnt 3}（5.4\ 	ext{MB}	imes 3\ 	ext{连续）}$$
$$\Rightarrow\ \Rightarrow\ 	ext{可用 }71\ 	ext{MB 但}	extbf{连续块拿不到} \Rightarrow 	ext{内核必须回收 }55\ 	ext{MB page cache}$$
$$\Rightarrow\ \Rightarrow\ 	ext{长时间停顿} \Rightarrow 	ext{用户态饿死} \Rightarrow 	extbf{这就是"第一次侥幸成功、第二次挂死"的机理}$$

**佐证（可复现）**：
$$\Rightarrow\ 	exttt{sync; echo 3 > /proc/sys/vm/drop\_caches} \Rightarrow 	exttt{MemFree}\ 6.6 	o \mathbf{49\ MB}$$
$$\Rightarrow\ 	ext{紧接着那次 } 	exttt{camera.Camera(2560,1440)}\ 	ext{一次成功（}2369\ 	ext{ms）}$$

$$\Rightarrow\ 	extbf{结论（升级为"证据支持的机制"）}：	ext{绑定约束不是 } 	exttt{MemAvailable}	ext{，而是 } 	exttt{MemFree}\ 	ext{与}	extbf{连续可分配性}$$
$$\Rightarrow\ 	ext{"available 71 MB 所以没事"是}	extbf{错误推断} \Rightarrow 	ext{这条要在板上同样适用}$$

### 三、更正：MaixCAM **没有 `/dev/video*`**
$$\Rightarrow\ 	ext{相机走 MMF/VI，不是 V4L2} \Rightarrow 	exttt{fuser -v /dev/video*}\ 	ext{拿不到任何东西}$$
$$\Rightarrow\ 	ext{所以"先查占用"这条对我的建议}	extbf{不成立} \Rightarrow 	ext{占用相机的唯一标志是 } 	exttt{camera.Camera()}\ 	ext{打开失败/超时}$$
$$\Rightarrow\ 	ext{已从复跑协议里划掉，替换为"打开失败即判被占用"}$$

### 四、启动前置条件（新增，强制执行）
```
sync
echo 3 > /proc/sys/vm/drop_caches      # 把 page cache 还给伙伴分配器
# 然后要求：MemFree >= 30 MB 才允许开相机，否则不启动
```
$$\Rightarrow\ 	ext{看门狗判据也改了：}	exttt{MemFree} \ge 30\ 	ext{MB}\ 	extbf{且}\ 	exttt{MemAvailable} \ge 35\ 	ext{MB}$$
$$\Rightarrow\ 	extbf{只看 available 会漏掉连续分配这一维} \Rightarrow 	ext{这次就是这么漏掉的}$$
