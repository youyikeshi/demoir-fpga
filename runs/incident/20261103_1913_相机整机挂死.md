# 事故：MaixCAM 在采集验证期间整机挂死（2026-11-03 19:13）

## 一句话
`cam_shot.py` 首次真机验证跑到步骤 3~6（取图/连发）时，设备屏幕报 `run app failed: code:-1`，
随后 ping 100% 丢包、SSH 无 banner ⇒ **内核级挂死**。用户手动重启后恢复。

## 五个流程缺陷（本次暴露，逐条修）

1. **服务日志 0 字节** ⇒ 挂死时零线索。必须无缓冲 + 每行 `flush`，启动先落一行带参数的 banner。
2. **没有内存看门狗** ⇒ 可用 70 MB 还一路往下跑。必须 `MemAvailable < 35 MB` 时回 `err:"lowmem"` 而不是硬撑。
3. **验证没有分档** ⇒ 一上来连发 10 张。必须先 720p×3 看内存能否回收，再 720p×10，最后 2K×2。
4. **没有先查设备占用** ⇒ 应先 `fuser -v /dev/video*` 看 launcher 有没有占相机。
5. **出事后的处置没写进流程** ⇒ "ping 丢包 / SSH 连不上 / mem<30 MB / 单次 grab>10 s" 任一出现就停手，不许"再试一次看看"。
