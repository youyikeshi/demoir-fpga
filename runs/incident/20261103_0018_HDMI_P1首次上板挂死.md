## 2. 根因（高置信）

$$\Rightarrow\ \text{本 BD 里 } \texttt{MMCM.locked} \to \texttt{proc\_sys\_reset.dcm\_locked} \Rightarrow \text{MMCM 不锁则 AXI 互联被按在复位}$$
$$\Rightarrow\ \text{上板时 } \texttt{FCLK0} = 150\ \text{MHz}（\text{上一轮推理工程留下的运行点}）$$
$$\Rightarrow\ \text{MMCM 配置按 } 100\ \text{MHz 输入算：} M=11.875 \Rightarrow VCO = 150 \times 11.875 = \mathbf{1781\ MHz}$$
$$\Rightarrow\ \text{器件 } -2\ \text{的 VCO 上限 } 1600\ \text{MHz} \Rightarrow \textbf{越界} \Rightarrow \textbf{MMCM 不锁}$$
$$\Rightarrow\ \text{我们把 FCLK0 改成 } 100\ \text{MHz 后 VCO} = 1187.5\ \text{MHz 合法，但}\textbf{互联此时仍在复位/或已产生挂起事务}$$
$$\Rightarrow\ \text{随后 } \texttt{mmap} + \text{读} \Rightarrow \text{PS 主口发出一次永不完结的读} \Rightarrow \textbf{CPU 停在该事务上} \Rightarrow \text{内核死}$$

$$\Rightarrow\ \textbf{直接诱因}：\text{明知"MMCM 不锁则读寄存器会挂"仍去读} \Rightarrow \text{我在没有确认像素时钟活着的情况下做了第一次 AXI 访问}$$
$$\Rightarrow\ \textbf{结构诱因}：\text{AXI 互联被 PL 侧 MMCM 锁定门控} \Rightarrow \text{一个时钟没锁就让整块总线变砖}$$

## 3. 必须修的三件事（缺一件还会再犯）

### ① AXI 互联**绝不许**被 PL 侧 MMCM 锁定门控
$$\Rightarrow\ \text{AXI 互联与寄存器文件只用 } \texttt{s\_axi\_aclk} + \texttt{ps\_reset}（\text{PS 时钟域复位）}$$
$$\Rightarrow\ \text{像素域单独一把复位（由 } \texttt{MMCM.locked}\ \text{门控）} \Rightarrow \text{它挂了只影响出图，不影响总线}$$
$$\Rightarrow\ \textbf{这样"时钟没锁"退化成"不亮"，而不是"变砖"}$$

### ② 必须先能读到"像素时钟活没活"的心跳
$$\Rightarrow\ \text{在 AXI 时钟域放一个 } \texttt{PIX\_HB}\ \text{寄存器}：\text{像素域翻转信号用 2FF 同步过来，读它得知像素时钟是否在跑}$$
$$\Rightarrow\ \text{判据：} \texttt{PIX\_HB}\ \text{两次读必须变化} \Rightarrow \text{变了才允许读其它 PL 寄存器}$$
$$\Rightarrow\ \text{这条写进上板清单第 1 步（在 } \texttt{0x00/0x04}\ \text{之前）}$$

### ③ 上板顺序固定为"先时钟、后 load"
$$\Rightarrow\ \textbf{改（FCLK0）} \to \text{等 } \ge 100\ \text{ms} \to \textbf{load overlay} \to \text{先读 } \texttt{PIX\_HB} \to \text{再读 } \texttt{STATUS}$$
$$\Rightarrow\ \text{我这次是"先 load 再改"（因为它当时是唯一能建立 ZOCL 上下文的办法）} \Rightarrow \text{顺序错}$$

## 4. 教训（写进技能）

$$\Rightarrow\ \text{任何"新 PL 位流第一次上板"，}\textbf{第一步必须是只读一个时钟域无关的心跳寄存器}$$
$$\Rightarrow\ \text{绝不允许"load 完直接读状态"}\ \Rightarrow\ \text{MMCM/PLL 是否锁定不是我们能假设的}$$
$$\Rightarrow\ \text{子代理已经警告过我（"读 0x04 会直接挂住"）} \Rightarrow \textbf{我却做了它警告的事}$$
$$\Rightarrow\ \textbf{警告不是免责声明} \Rightarrow \text{看到"会挂"三个字，必须改成"先验活再读"}$$

## 7. 修复后的上板协议（取代事故时的顺序）

**关键认知**：上电后 `FCLK0` 由 BOOT.BIN/FSBL 决定（**大概率不是 100 MHz**），
而 MMCM 按 100 MHz 输入配置 ⇒ **一 load 就可能不锁**。
但修复后 AXI 不再被 MMCM 门控 ⇒ **不锁只是"不亮"，不再变砖**，
于是可以安全地执行下面这个顺序：

```
① load overlay（此时 MMCM 可能没锁，安全）
② 读 0x30 PIX_HB 两次（间隔 ≥5 ms）——若 [1]=0 说明没锁，继续第 ③ 步
③ 设 Clocks.fclk0_mhz = 100（这一步需要 PYNQ 设备上下文，所以只能在 load 之后做）
④ 等 ≥100 ms，再读 0x30：[0] 必须开始翻转 且 [1]=1
⑤ 才允许读 0x00（期望 0x15）/ 0x04（期望 0x03）
⑥ 若 [0] 仍不变 ⇒ 立刻停，绝不读其它寄存器
```

$$\Rightarrow\ \text{第 ④ 步是本次事故的}\textbf{制度化补丁}：\text{把"我以为它会锁"换成"我必须看到它在跳"}$$
