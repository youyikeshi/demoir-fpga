# Q1：加上 HDMI 之后，整网慢了多少？（板端实测，2026-11-04）

**运行点**：FCLK0 报数 75 → SLCR `0x00101400` → `DIV0+1=21` → 真值 **50.79 MHz**（`f_pll = 50.79×21 = 1066.6`）
**样本**：固定 `p0000`，`in_sha1 = 8d83f10019713d9d…`（5/5 一致）
**每条件**：3 个进程 × 2 次运行（第 1 次含内核 load，丢弃），`BV_FREE=1`（不开则第二跑必 OOM）

## 四行表

| 条件 | 扫描器 | 0x2C 增量 | warm（首跑，含 load） | **steady（第 2 跑）** | 中位数 |
|---|---|---|---|---|---|
| **C1** | 关（`CTRL=0x15`） | 0 | 16.88 / 17.99 / 17.01 | **10.34 / 10.26 / 10.28** | **10.28 s** |
| **C2** | 开 + 真播 | **+38 000/s**（读空） | 16.98 / 16.97 / 17.11 | 10.33 / 10.35 / 10.31 | （无效，见下） |
| **C2b** | 开 + 空扫 | **+38 000/s**（读空） | 17.12 / 16.92 / 17.15 | 10.36 / 10.30 / 10.40 | （无效，见下） |
| **C2c** | 彩条 `CTRL=0x14`（零 DDR 读） | **0** | 16.79 / 16.94 / 16.78 | **10.34 / 10.40 / 10.38** | **10.38 s** |

## 结论（一句话）

**C2c / C1 = 10.38 / 10.28 = 1.010 ⇒ 像素流本身（不读 DDR）只值 +1.0%**，
即"HDMI 出图"这件事对整网**几乎免费**；代价只可能来自 **DDR 读**（166 MB/s），而那一项
**在 50.79 MHz 下测不了** —— 该档扫描器根本取不到像素（`0x2C` 以 ~38 000/s 涨，即每行读空），
这正是本轮 RTL 要修的那个 bug。要量"真播的 DDR 争用"，只能在 **66.67 MHz**（扫描器正常）测 C3/C4，
或用 v60 修好后在新位流上测。

## 失败与作废说明（务必读）

1. **C2 / C2b 作废**：feeder 的 pairs 路径写成了 `/home/xilinx/demo/pairs100/`，实际在
   `/home/xilinx/demo/pairs100/pairs/` ⇒ 帧没载入，只有 bringup 的 `CTRL=0x01` 在扫空缓冲
   （`0x2C` +38k/s）。因此这两行测的是"扫描器开但读空"，**不是真播**。
2. **C2/C2b 里 `0x24` 始终为 0** —— 又一次独立佐证：50.79 MHz 下扫描器取不到像素。
3. 首次尝试（15:00 那轮）因 feeder 缺 `XILINX_XRT=/usr` 导致 `No Devices Found`，CTRL 一直是 `0x15`，
   四个条件全等于 C1 —— 已作废重跑。

## 复现

```sh
# C1：systemctl stop → 重载位流 → Clocks.fclk0_mhz=75 → 写 CTRL=0x15
# C2c：同上，然后 feed_display.py --mode bars（内部彩条，CTRL=0x14）
# 计时：BV_FREE=1 dump_board_int8.py --limit 1 --repeat 2 --time-only
```
