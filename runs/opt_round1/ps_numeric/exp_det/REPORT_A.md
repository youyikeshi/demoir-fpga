# REPORT A — 跨平台 `exp` 变体 canary（T-171 阶段 A）

**一句话结论：`v3 = np.float32(np.exp(x.astype(np.float64)))`（f64 上 exp → 回落 f32）在两平台
逐位稳定：`dsB` 200,000 元素 sha1 两侧同为 `bc108924cafb`、`n_diff=0`、`max|Δ|=0`。
自实现 `v5`（`ldexp` + 固定项多项式）与之**逐位相同**且不依赖任何 libm ⇒ 是"可证明稳定"的版本。
现状 `v1`（f32 上直接 `np.exp`）不稳定：`n_diff=77,900/200,000`，`max|Δ|=0.125`（≈1 f32 ulp @ 7e5）。**

## 2. 结论与机理

1. **f32 上的 `np.exp` 逐位不可移植**：numpy 在 f32 上走的是向量化/SIMD 内核（x86 有 FMA/AVX 特化，
   armv7l 只有标量 + libm `expf`），同一输入 200k 里有 **77,900 个元素不同**：
   差值中位数 **1.00 f32 ulp**、最大 **2.00 f32 ulp**（`max|Δ|=0.125` 出现在 `766277.8` 处，该处 1 ulp = 0.0625）。
   这正解释板端/host 的 `np.exp` canary 分歧（`67.1568756` vs `67.156868`）。
2. **双精度 `np.exp` 也不逐位相同**（`dsB` 300/200000 差，`max|Δ| = 7.28e−12`，相对 1 个 double ulp），
   **但回落 f32 时全部被吸收**：实测 `f32` 转换后两侧数组完全相等。
   量化裕度：`dsB` 中每个双精度结果到最近 f32 舍入中点的距离 `max = 0.4995 f32 ulp`
   （即最"危险"的点离边界仍有 5e−4 ulp），而双精度差异只有 1 个 double ulp = 2⁻²⁹ f32 ulp
   ⇒ 单个元素被翻转的概率 ≈ 2⁻²⁹ ≈ 1.9e−9。200k 元素实测 0 例。
3. **`v5` 是"可证明"而非"经验"稳定**：只用 `+ − × ÷`、`np.rint`、`np.ldexp`
   （IEEE-754 正确舍入 / 精确指数缩放），两平台同输入必同输出位模式，与 libm 无关。
   实测它与 `v3` 在两侧都**完全同一 sha1**（400k 样本零差异），说明在多花几个 ufunc 的情况下
   可以用它把"概率性吸收"换成"构造性保证"。ECA 里 `C ≤ 576`，代价可忽略。
4. `v2` 与 `v3` 都稳定；`v2` 的输入先过 f32 只是把输入量化了一次，ECU 语义上 `v3` 更直接
   （ECA 的 `z` 本身就是 f32，取 f64 后 exp 再回落）。
5. `v4 = np.exp(x32, dtype=f32)` 在本机 numpy 上**等价于 v1**（不是独立变体），没有任何改善。

## 3. 阶段 B 的落地选择

采用 **`v3` 语义 + 必要时 `v5` 兜底**：把 ECA sigmoid 的 `np.exp(−z)`（`z` 为 f32，现状在 f32 上算）
改为 **升 f64 算 `exp`、在 f64 里做 `1/(1+e)`、最后一次性 `.astype(np.float32)`**。
若阶段 B 出现"仍有个别层不一致且怀疑 exp"，则把 `np.exp` 换成 `v5` 的 `_exp64_det`
（已给出实现，与 `v3` 在 400k 样本上逐位相同）。

**判据满足 ⇒ 进入阶段 B。**
