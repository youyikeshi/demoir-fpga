# T-103：v52 在 100 MHz 下结果是否正确（"100 MHz 达标即止"的最终验收）

**一句话**：**不达标，而且比 v51 更差**。v52 @100 MHz 逐层不符 23 797/65 536 与 91 836/196 608、
同层两次差 14 629 B / 53 329 B、64² 三次 sha1 互不相同 —— 同一探针同一天跑 v51 只有 2 858/2 034（差 3 598 B），
即 **10–30× 回归**；降到 93.75 → 88.235 MHz 误差单调下降，88.235 时 cin112 已 0/0，
75 MHz 两层才 0 越界/0 不符/两次逐字节相同，**但 64² 整网在 75 MHz 仍 ≠ 冻结值** ⇒
**没有任何测试频率同时满足"逐层 + 整网"全部判据**。`WNS +0.524` 在实际数据通路上不成立。

## 4. 判定（判据由父代理任务书给定，本报告未放宽容差）

| 判据 | 100 MHz | 93.75 | 88.235 | 75 |
|---|---|---|---|---|

| 0/65 536 + 0/196 608 字节不符 | ✗✗ | ✗✗ | ✗（cin512 318/294） | ✓ |

**结论：100 MHz 不达标；95/90 MHz 也不达标；75 MHz 只救回逐层，整网仍不达标。v52 不可交付。**

## 5. 给方向性判断的三条

1. **v52 是回归，不是修复**：同一探针、同一 PS 闭包、同一缓冲地址下，v51 @100 MHz 错 2.9 k/2.8 k、
   两次差 3.6 k/2.8 k（复现 T-98），v52 错 23.8 k/91.8 k、两次差 14.6 k/53.3 k。
   ⇒ `create_clock -period 10.000` 下报的 **WNS +0.524 / 0 违例是假安全**，T-101 的 `act_q/l_qd/r2_*`
   改动把**真实数据通路的余量做差了**（不是做好）。**不要再按 WNS 验收这条路径**。
2. **T-97 的 xsim 逐字节 0 差不能覆盖这份位流**：T-97 验的是 v51 那份 core（`61568f39…`），
   v52 的 core 是 `c04302ce…`（+58/−8），T-102 只做了网表指纹（`act_q=64 / r2_vld=1 / l_qd=8`），
   **没有做逐字节功能等价**。要判"是功能错还是时序错"，需要拿 `c04302ce…` 的 16-lane 网表重跑 T-97 的 TB。
3. **整网 ≠ 冻结在 75 MHz 逐层全对的情况下依然出现** ⇒ 与频率无关的那一类差异另有其因
   （整网 227 op 里有些形状/相邻层组合是逐层 2 层探针覆盖不到的）。这条要么用 v39 同口径先复现冻结值做基线，
   要么单独开一个"整网 sha1 二分到 op"的计划，不要混在本轮频率结论里。

## 6. 板子现状 / 金丝雀

仍开机（uptime 14 h 53 m+，1 user，load ~0）；**PL = v52**（最后一次 load 保留）；**fclk0 = 75 MHz**（最后一块）；
跑后 `0x314 = 0x50300001` ✓、`0x310 = 0x00000403`（done=1 + busy=1，与 T-96/T-98 同类尾巴）；
越界垫子 **全部 0 B**、金丝雀 **0 次报警**、无段错误、无超时、无 ssh 重试；收尾只 `sync; sync`，**未 poweroff**；
bit/hwh 跑后 md5 仍为冻结值。**三次 session 共 3 次 load**（v52 两次 + v51 对照一次），每次独立租约与令牌。

# 附录 A：v52 最高安全频率（追加轮，2026-11-02 23:10–23:19）

**结论：逐层判据下的最高安全格点 = 83.3333 MHz（= 1500/18）；再上一档 88.2354 MHz（= 1500/17）就开始错。**
Zynq PL 时钟只有 1500/n 这些格点，所以"最高"是离散的，不是连续可调的。

| fclk 目标（读回） | 周期 | cin112 k3 d2 | cin512 k1 | 逐层判据 |
|---|---:|---|---|---|
| 100（100.0） | 10.00 ns | 23 797 / 23 841 不符，两次差 14 629 B | 91 836 / 91 072，两次差 53 329 B | ✗✗ |
| 95（93.75） | 10.67 ns | 4 287 / 4 238（差 2 641 B） | 16 957 / 16 822（差 11 501 B） | ✗✗ |
| 90（88.2354） | 11.33 ns | **0/0，8 次全同** | **246–296 /196 608，8 次 sha1 全不同** | ✗✗ |
| **83（83.3333）** | **12.00 ns** | **0/0，8 次全同 + 300 次 soak 全同** | **0/0，8 次全同 + 300 次 soak 全同** | **✓ 最高安全档** |
| 79（78.9474） | 12.67 ns | 0/0，4 次全同 | 0/0，4 次全同 | ✓ |
| 75（75.0） | 13.33 ns | 0/0，4 次全同 | 0/0，4 次全同 | ✓ |

**83.333 MHz 的 soak（主证据）**：两层各连跑 **300 次** ⇒ **不同 sha1 只有 1 种**、最差不符 **0/65 536** 与
**0/196 608**、越界 **0 B**、cyc 151 614–169 973 / 449 141–465 413（抖动来自轮询粒度，不是结果）。
88.235 MHz 的 8 次 cin512 **每次 sha1 都不同**（284/274/251…296）⇒ 是"刚好在临界点上"，不是偶发。

**⇒ 真实最差路径 ≈ 11.3–12.0 ns**（11.33 ns 开始错、12.00 ns 稳 300 次），而 STA 报 `10.000 − 0.524 = 9.476 ns`
⇒ **静态时序低估了约 1.9–2.5 ns**。这解释了为什么"WNS +0.524 / 0 违例"与实测完全相反：被优化/被约束漏掉的那条路径
根本不在报告的 40000 条违例清单里（清单里是 0 条）。

## A.1 必须附带的两个限定

1. **"安全"只到逐层门禁为止**：64² 整网在 100 / 93.75 / 88.235 / 83.333 / 78.947 / 75 **全部 ≠ 冻结 sha1**
   （83.333 三次互不相同、79 与 75 各三次也互不相同）⇒ 若把"整网对"算进安全定义，**没有任何频率合格**。
   这一条与频率无关（75 MHz 逐层 300 次全对时整网仍错），需要拿 v39（已知能复现冻结 sha1）在同探针同运行点做对照，
   才能判断它是 v52 的问题还是整网路径（cat/惰性反量化/形状组合）的既有问题。**未做，别当成结论。**
2. **87.5–83.3 之间没有别的格点可试**（PYNQ 只能给 1500/n）⇒ 83.333 已是"能拿到的最高且干净"的那一档；
   若要留余量，工程上取 **75 MHz**（再多 2 档余量）。

## A.2 本轮踩到的第二个顺序坑（已修）

soak 第一版排在整网之后 ⇒ 又一次读到"早到的 done"（75 MHz 上得到 65 240/195 475 不符、cyc 11 373–34 797 的**无效**数据）。
修法：把 soak 也放到整网**之前**，并在自动选频里补 `break`（否则会取到循环最后一档）。
⇒ **结论性纪律：任何"紧接着整网之后"的 PL 操作都不可信**，整网必须永远排在最后（或用 `--net-freqs=` 跳过）。
