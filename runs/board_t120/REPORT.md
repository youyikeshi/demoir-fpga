# T-120：128² 输入（unshuffle 后基分辨率 64² ⇒ 每层 npix=4096 恰好）—— **v53 在 128² 上就错，且非确定**

**一句话**：**不需要重建位流就判定了边界**。同一运行点、同一 session、两次 load：
$\mathtt{v53}$ 在 $128^2$ 上两次 sha1 **互不相同**（与 $256^2$ 同一种失效指纹），
$\mathtt{v39}$ 在 $128^2$ 上两次**逐位相同**且 $64^2$ 仍命中冻结三 sha1
$\Rightarrow$ **失效边界在 $(64^2,\,128^2]$，与"$256^2$ 独有"无关**；
而 $128^2$ 的每层像素数最大值**恰好 $=4096$**（31 个 op 命中该值）
$\Rightarrow$ **"npix $\ge 4096$ / 线缓存压力"方向得到支持**。

## 2. 判据结论（按任务书）

$$\boxed{\ \mathtt{v53}\ 128^2 \neq \mathtt{v39}\ 128^2\ \text{且 v53 两次互不相同}\ \Rightarrow\ \text{边界} \le 128^2\ (\text{npix}=4096)\ \text{，与 }256^2\ \text{无关}\ }$$

- **"npix $\ge 4096$ / 线缓存压力"方向：支持。** 失效不等到 $256^2$ 才出现，
  $128^2$ 一跨过"每层 4096 像素"就复现同一指纹（非确定 + 零 err）。
- **"$256^2$ 独有的某处"：被排除。** $128^2$ 的 `out_bytes` 最大只有 393216 B、且没有 $256^2$ 才有的
  `npix=16384` / `out_bytes>1 MB` 的量级，却照样错。
- **但这条实验不能把 npix 与 out_bytes 分开**：$128^2$ 相对 $64^2$ **同时**跨过两个 T-115 阈值
  （`npix ≥ 4096`：0→31 个 op；`out_bytes ≥ 131072`：0→31 个 op，最大 393216 B）。
  它能确定的只是**边界落在 $(64^2,128^2]$**，并排除所有 $256^2$ 独有机制。
- **线缓存的"硬 512"说法要修正**（我自己算的实际口径）：$cb\cdot HW/16$ 在
  $64^2$ 已有 **1 个 op = 576 > `LC_N=512`** 却逐位正确；$128^2$ 有 **16 个 op > 512、最大 2304（4.5×）**；
  $256^2$ 有 60 个、最大 9216。⇒ "**超过 512 就必错**"不成立，但"**超得越多才错**"与全部实测相容。

## 3. 一条旁证：v53 与 v39 在 $128^2$ 上的**时间**几乎相同

| | PL run1 / run2 | RTL 公式（@50 MHz） | 比 |
|---|---|---|---|
| v53 | 2.353 / 1.460 s | 2.262 s（113,098,752 拍） | 1.04 / 0.65 |
| v39 | 2.223 / 1.410 s | 2.262 s | 0.98 / 0.62 |

$\Rightarrow$ v53 在 $128^2$ 上**没有"少干活"**（与 T-115 对 $256^2$ 的结论一致）：
是**数据通路/地址算错**，不是丢拍或早收。
