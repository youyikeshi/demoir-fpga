## 1. 第 3 步失败：整网 64² 第 3 个 conv 卡死

```
[DEPS] q8=fast c8deq=fast bpack=fast e1e2=fast catpack=fast safe=fast  deps_closure_ok=True
[LAZY_DEQ] 24 槽
op1 encoder_1.rdb.conv_layers.0.conv  cin=48  cout=64 k=3 32×32 K=9   ✓ 收
op2 encoder_1.rdb.conv_layers.1.conv  cin=112 cout=64 k=3 32×32 K=18  ✓ 收
op3 encoder_1.rdb.conv_layers.2.conv  cin=176 cout=64 k=3 32×32 K=27  ✗ 5.05 s 未 done
    TimeoutError: bin_unit 超时 5.0s 未 done（timeout=5.047… ⇒ est=0.0118 s 正是 op3）
```
判据**按纪律停在这里**（超时 ⇒ 停、报；引擎不发第二次 start）。

进程退出后**只读**探了一次那块已挂住的 PL（不 load、不写任何寄存器）：

```
0x310 CHAIN_STATUS = 0x00000403      AP_RET = 0x2（bit1 busy=1, bit0 done=0, err=0）
cfg_cin=176 cfg_cout=64 cfg_k=3 cfg_h=32 cfg_w=32   ← 正是 op3 的配置
DBG_RD = 29,491,302（+1.0 s 后仍 29,491,302） ⇒ **核冻住，不是在慢慢算**
```

⇒ 不是"很慢"，是**死等**（busy 一直 1、读计数不涨）。而同一层单独跑 0.004 s 就完成（§2），
⇒ 卡死是**整网上下文**（arena/槽共享）里被越界写污染后才出现的次生现象。

## 2. 逐层隔离（H=W=32，只改 cin；同 PS 代码、同 100 MHz、同 blob）

`probe_t93_oob.py`：OUT 区 = `out_bytes + 64 KB` 垫子，垫子铺 `0xA5`，`verify_canary=False`
（只为量化越界，不与金丝雀判据冲突）。

| 层（真实几何） | v50 16-lane cyc | v39 8-lane cyc | 比 | **越界写** | 已写区间与 numpy 参考不符 |
|---|---:|---:|---:|---:|---:|
| cin48 k3 d1 (K=9)   | 68,665 | 116,158 | **0.59×** | **1,792 B** | **64,114/65,536** |
| cin112 k3 d2 (K=18) | 125,766 | 228,834 | **0.55×** | **3,112 B** | **63,116/65,536** |
| cin176 k3 d1 (K=27) | 183,821 | 342,512 | **0.54×** | **4,096 B** | **61,001/65,536** |
| cin240 k1 (K=4)     | 41,795 | 44,489 | 0.94× | **904 B** | **48,649/49,152** |
| cin512 k1 (K=8)     | 191,689 | 314,689 | **0.61×** | **1,600 B** | **186,553/196,608** |

**控制组（同一脚本、同一层、同一 PS 代码、只换位流 v39 `602725b8…`）**：

| 层 | v39 越界写 | v39 逐字节不符 |
|---|---:|---:|
| 全部 5 层 | **0 B** | **0 / 65,536 · 0 / 65,536 · 0 / 65,536 · 0 / 49,152 · 0 / 196,608** |

⇒ **探针与 PS 侧代码是干净的**：v39 逐字节 0 差、0 越界；同一套代码换 v50 位流后
**越界 + 错数**。故障**只能归在位流的 16-lane 数据写通路**（`§10.1 VLANES>8 的写侧
2 拍串行化` / drain 字数与地址），与 PS 代码、与"权重只装了 8 组"无关
（PRM/权重都是核自 DDR 拉，v39 同一路径 0 差）。

## 3. cyc/term 实测与"−0.56 s"的口径

本口径 `cyc/term = cyc / (cout·Hout·Wout·cb·k²)`（与 `bin_test_staged.stage5` 同一公式）：

| 层 | v39 8-lane | v50 16-lane |
|---|---:|---:|
| cin48 k3 | 0.1969 | **0.1164** |
| cin112 k3 d2 | 0.1940 | **0.1066** |
| cin176 k3 | 0.1936 | **0.1039** |
| cin240 k1 | 0.2263 | 0.2126 |
| cin512 k1 | 0.2001 | **0.1219** |

$$\Rightarrow\ \text{k}=3\ \text{层周期}\times0.54\sim0.61\ (\text{≈1.7–1.9×}\uparrow)，\text{k}=1/\text{cout}=48\ \text{层几乎不动（0.94×）}$$
$$\Rightarrow\ \textbf{"16-lane 砍一半组遍历"这条在拍数上成立；−0.56 s 的方向被证实}$$
$$\Rightarrow\ \text{但 §1.4 表里的 }54.3\ \text{用的是另一种归一化（每 64-bit term），本轮}\textbf{不做绝对对齐}$$
$$\quad\ \text{——因为位流数据是错的，整网桶级数字拿不到，宁可只报可比的}\textbf{同层周期比}$$

## 6. 未做/做不到

## 7. 给下一轮的两条硬结论

1. **v50 位流不能上板做功能验证**：16-lane 写通路越界（0.9–4 KB/层）+ 数据错（93–98 %），
   整网死锁。要先修 RTL 的 `VLANES>8` 写侧（2 拍串行化 / drain 字数与地址），
   并且**必须把"垫子 + 64 KB 越界计数 + 与 numpy 逐字节"这一层门禁做进仿真与上板脚本**
   （本轮正是靠它把"位流坏"和"PS 代码坏"分开的）。
2. **性能方向已验证**：同层 ×0.54–0.61，k=1 小层 ×0.94 ⇒ 修好写通路后 `−0.56 s` 才有意义；
   在那之前不要把它写进任何基线表。
