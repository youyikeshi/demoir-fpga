> 工作副本：`worktrees/T-161-lat/`（只改 TB 与脚本，**RTL 一个字节未动**，主线 `runs/timing_v50/rtl_v50` 未碰）
> 主机侧 xsim v2025.2.1；未上板、未 ssh；全程走 `tools/memgate.sh 5 --reserve 2.5`
> DUT：`v39` = `28375eec288f067e9235c0ecd486abb5`，`v57/刀7` = `bc28ead39b41e79f18571bff46bbd147`
> 包装层两侧相同：`0cf68b2e31ac106ed03e30bd5591504d`（⇒ A/B 只在 `bin_e1e2.v`）
> golden：106 条命令 / 6,302,720 字节（`mem.bin` `c2fc3142c901193a45ee01ea1a167841`，`cmds.txt` `70fe9306aa004d3b81a753c2535b2f14`）

## 0. bench 原来的读延迟（实测，不是推测）

| bench | 原来的读响应 | 证据 |
|---|---|---|
| `tb_bin_e1e2_desc.v`（单元级，`byteunit/`） | **恒 1 拍**（BRAM 语义 `if(mem_rd_en) mem_rd_data<=memword(addr)`），**无 valid/ready** | TB 第 76-83 行；`ab_e1e2.sh` 直接吃它 |
| `tb_bin_unit_axi_wrap_e1e2.v`（整 AXI 路径，`e1e2int/`） | 固定 **2 拍首延迟 + 1 拍拍间隔**，`ARREADY` 在 `ar_busy` 期一直拉低（一笔一笔串行）⇒ 完全确定性 | TB 第 96-150 行 |

$$\Rightarrow\ \textbf{不是 } \mathtt{RLAT}=55\ \text{类模型：原来就是 1 拍（单元）/ 2 拍（AXI），且零随机。}$$

## 1. 改成什么模型（种子写死）

**A. AXI 级（合法、有据）：** `tb_wrap_e1e2_vlat.v`
- 每笔 burst **独立**首拍延迟 `1..5` 拍，**再加"在飞笔数"作为排队惩罚**（`+QUEUE_PEN=1`，模拟 DDR 队列效应）
- 拍间隔随机 `0..1` 拍；**AR 握手后随机 0..2 拍不再 ready**（冻结后压）
- 最多 4 笔 burst 同时在飞 ⇒ **不同 ID 可乱序回拍、拍可互相穿插**
- 随机源是**自写 32 位 LFSR**（不用 `$random`），`+SEED=` 决定轨迹并打印进日志
- 实测：AR 382,040 笔，回拍 6,112,640，**首拍延迟 min=2 / max=180 / 均=30 拍**（远超真实 DDR 的 55）
- 种子：**161 / 162 / 163**（`lfsr = seed·0x9E3779B1 ^ 0x7F4A7C15`，相邻种子轨迹不同）；另加一档更狠的 `1..8 / BSTALL=2 / ARGAP=3`

**B. 单元级（合法化写法）：** `tb_bin_e1e2_desc_vlat.v` —— 因为单元 mem_rd 口**没有 ready**，
  可变延迟只能用"包装层真实做过的事"来表达：**`ap_ce` 随机冻结（读拍 30%）**，
  且**内存数据寄存器同样受 CE 门控**（与 `u_rd_data <= win_q[...]` 在 `u_ce` 下装载逐拍同构）。

## 2. 判据结果：刀 7 vs v39

| bench / 模型 | v39 (`28375eec`) | v57 刀7 (`bc28ead3`) | 逐字节 | 总拍数 |
|---|---|---|---|---|
| 单元级 BASE（1 拍） | PASS | PASS | 0 差 / 0 差 | **7,244,033 = 7,244,033** |
| 单元级 **变延迟(CE 冻结 27.3%)** | PASS | PASS | **0 / 0** | **9,960,446 = 9,960,446** |
| 单元级 非法变延迟 `1..2` 拍（无 ready） | FAIL | FAIL | 5,954,785 / **5,954,785** | 7,244,033 = 7,244,033 |
| 单元级 任意拍冻结（TB 旧写法，数据未门控） | FAIL | FAIL | 984,873 / **984,873** | 7,590,233 = 7,590,233 |
| **AXI 变延迟 seed161（1..5+排队+AR 空档）** | PASS | PASS | **0 / 0** | **6,019,388 = 6,019,388** |
| **AXI 变延迟 seed162** | PASS | PASS | 0 / 0 | 6,019,719 = 6,019,719 |
| **AXI 变延迟 seed163** | PASS | PASS | 0 / 0 | 6,019,649 = 6,019,649 |
| **AXI 更狠 seed161（1..8/BSTALL2/ARGAP3）** | PASS | PASS | 0 / 0 | 6,827,095 = 6,827,095 |

$$\Rightarrow\ \textbf{没有复现}：\text{每一个模型下两个 DUT 都逐字节 0 差，而且}\textbf{拍数、AR 笔数、AR 空档数全部逐位相同}$$

## 3. 关键机制证据（为什么"读返回对齐"不成立）

1. **包装层把数据寄存器放在 CE 里面**：
   `always_ff @(posedge clk) if (u_ce && rd_want && rd_hit) u_rd_data <= win_q[{rd_idx,rd_slot}];`
   ⇒ 冻结期**不装载**，待消费那笔数据**原样保留**；可变延迟被 `u_ce` 整拍吸收，不可能错位。
2. **逐拍检查**（新加的不变式探针，跑满 106 条命令）：
   "消费拍（`u_ce && resp_vld`）看到的 `u_rd_data` 是否等于**最后一次真正装载的地址**的数据"
   ⇒ **6,353,024 个消费拍，0 次不符**（v39 与 v57 各自都是 0）。
3. **DUT 侧逐位相同**：连"任意拍冻结"这种真实硬件不会出现、且双方都会错的病态刺激下，
   两个 DUT 的错字节数（984,873）、错位置、总拍数**完全一致** ⇒ RTL 级不存在能区分二者的刺激。
4. 顺手排除一个可疑截断：`rem <= run_len[8:0]`，`run_len=256` 时 `9'h100` **合法**（不截断）。
   探针实测：128×128 每 tile `run_len=256 / rem=256 / SWEEP=256 拍`，v39 与 v57 一致。

## 4. 一句话

$$\boxed{\text{真因}\ \textbf{不是}\ \text{"读返回对齐"——RTL 级任何内存延迟模型都区分不了 } \mathtt{v39}\ \text{与}\ \mathtt{v57}}$$

下一步只能跳出"固定延迟契约 + 整拍 CE 冻结"这层抽象：**用两版布局后的 DCP 做门级 SDF 仿真**
（同一 106 条命令 TB，看 CE/偏斜/hold），或上板读 `0x230..0x240` 现有 DBG 计数器。
