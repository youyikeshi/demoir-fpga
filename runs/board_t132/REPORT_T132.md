# T-132：128² 的错**不是** CPU 缓存陈旧（`BIN_EPI_NOINV` 无罪）；但它的**真身是一条时间竞争**——每次 `_flush` 之后多花 3 ms，v53 就**逐位等于 v39**

**一句话**：`BIN_EPI_NOINV=0` 连跑两次，三 sha1 **仍然互不相同、也不等于 v39**（缓存失效开路**不修**）；
同一时刻双通道（可缓存-不作废 vs `/dev/mem`）在所有"DDR 已稳定"的 op 上，**显式 invalidate 之后 227/227 与 DDR 一致**，
真正陈旧的只有 7~12 个小缓冲 op、且**不在首分歧 op（13/15）上**，而那条读路径上**没有任何消费者**。
⇒ **缓存一致性不予定罪。** 顺带挖到了真因方向：**每次 `BE._flush` 之后纯 sleep 3 ms（不读、不做任何 cache 维护）
⇒ 128² 三 sha1 = v39 冻结值，8 跑 8 中**；而"done 之后睡 20 ms / 等到 DDR 稳定"**全部不修** ⇒ 竞争窗口在**写入口（flush→PL）**，不在出口（done）。

## 1. 第 1 步（最硬证据）：同一时刻两条通道读同一块 —— **不是缓存**

`instr` 臂：在每个 PL conv 的 `finish()` **最前面**（消费者 `read_out` 之前）依次读：
`C1` 可缓存映射**不作废** → `U1` `/dev/mem`（device 映射 = DDR 真值）→ `U2` 再读一次 → `C2` 显式 `_invalidate()` 之后再读。

| 判据（227 个 PL conv） | 租约 1 | 租约 2 |
|---|---:|---:|
| `C1 ≠ U1`（两条通道读到不同内容） | **43 / 227** | **44 / 227** |
| 其中 `U1 ≠ U2`（**done 时 PL 还在写**，不是缓存） | **36**（84%） | **32**（73%） |
| 只剩"DDR 已稳定"的 op 上 `C1 ≠ U1`（**真·读取侧陈旧**） | **7 / 191** | **12 / 195** |
| `C2`（显式失效后）`≠ U1` | **0 / 191**（稳定组） | **0 / 195** |
| `C1` 恰好等于"上一个租客"的内容 | 0 | 0（尾巴内容也不是上一租客的） |

- **差异位置**：真陈旧的 7 / 12 个 op **全部是小缓冲**（6144 / 8192 / 12288 B），差异**从缓冲的 65~70% 处一直到末尾**（例：op51 首 5280/8192，op378 首 4352/16384）。
- **与首分歧 op 不一致**：**op13 / op15 本身两通道完全相同**（`U1==U2`、`C1==U1`、`C2==U1`）⇒ 缓存陈旧**不在**首分歧点上。
- 大缓冲那批（op2/4/6/8，262144 B）的 `C1≠U1` 全部伴随 `U1≠U2`，是**写回还没落地**，不是缓存读旧值。

**显式 invalidate 之后是否变正确**：对那 7/12 个 op **是**（`C2 == U1`，227/227 稳定 op 全一致）——
但这只证明"失效一次就读对了"，**不能证明整网错是它造成的**：这些 op 的下游消费者**根本不走这条读路径**
（`read_out(lazy=True)` 的字节只被 `materialize()` 读，而它第一行就 `_invalidate`；其余消费者都是把 PA 交给 PL）。

- **两次 NOINV=0 彼此不同**，也都不等于 v39 ⇒ 判据**未命中**；"纯环境开关的修法"**不存在**。
- 因此 256² 按任务书**没有跑**（只在 NOINV 命中时才要求跑）。
- 第 4 阶段再做了一条同义复核：`dly0p2`（每次 flush 后 0.2 ms）也不修 ⇒ 不是"多一点 CPU 时间就随便修"。

## 3. 第 3 步（被第 2 步的负结果逼出来的）：把窗口定位到**入口**而不是**出口**

第 2 阶段的 `poll` 臂给出关键数字：**done 之后 DDR 停止变化的时间 = p50 3.89 ms / p90 13.27 ms / max 47.5 ms**（225/227 收敛），
但"等到每层 DDR 稳定"的整网**仍然错**（`f6c167582f` / `a36dd3321140` / `94ea7ac003`）；`gap20`（done 之后纯睡 20 ms）两次也**都错**。

第 3、4 阶段改在**写入口**加时间（`BE._flush` 之后），结果**全中**：

| 臂 | 做法（都只改 PS，不碰 RTL） | 墙钟 | 三 sha1 | = v39? |
|---|---|---:|---|---:|
| base | 无 | 7.6 s | `b335b0860e6c` / `fc55e355ddb6` / `fc8af9f140fc` | ✗ |
| **incheck** | flush 之后**读**一遍（CPU 视角 + `/dev/mem`），不做任何 cache 维护 | 15.1 s | **`27e25cf67fda` / `b82b83f3d7eb` / `6db4e9bb19e0`** | **✓** |
| **fixflush**（共 3 跑：本阶段 ×2 + 下一阶段 ×1） | flush 之后补一次真 ARM `cacheflush(0x0f0002)`（全 arena clean+inv） | 52.1 s | 同上 | **✓✓** |
| dly0p2 | flush 之后纯 sleep 0.2 ms | 6.7 s | `ec5201aad082` / `b28e0f954c33` / `04a39d8ab7c8` | ✗ |
| dly1 | flush 之后纯 sleep **1 ms** | 7.6 s | `53e234dbbe0e` / **`b82b83f3d7eb`** / **`6db4e9bb19e0`** | **2/3 中** |
| **dly3** | flush 之后纯 sleep **3 ms**（不读、不做 cache 维护） | 9.8 s | **`27e25cf67fda` / `b82b83f3d7eb` / `6db4e9bb19e0`** | **✓** |
| **dly3 ×3（独立租约）** | 同上，连跑三次 | 9.7~11.1 s | 同上，**三次完全相同** | **✓✓✓** |

- **纯时间就够**：`dly3` 不读任何通道、不做任何 cache 维护，只 sleep ⇒ **三 sha1 逐位等于 v39，4 跑 4 中**；
  连同上表的 `incheck`(1) 与 `fixflush`(3)，**"入口加时间"共 8 跑 8 中**；而"不加"的 14 跑（base×4 / ctrl / noinv0×2 / gap20×2 / poll / dly0p2 / dly1 / instr×2）**0 中**（dly1 只中 2/3）。
- **剂量响应单调**：0.2 ms ✗ → 1 ms 中 2/3（`out1` 仍错）→ 3 ms 全中 ⇒ 不是运气，是一个**竞争窗口在变窄**。
- **`_flush` 本身没写漏**：`incheck` 里 **908 次 flush，flush 之后 CPU 视角与 `/dev/mem` 差异 0/908**（0 字节）
  ⇒ 不是"flush 没把脏线写回"，而是 flush 之后 **PL 侧还需要时间**才按新数据算。
- **窗口位置**：`done` 之后加时间（gap20、poll）**全部无效**，`_flush` 之后加时间**全部有效**
  ⇒ 竞争发生在 **PS→PL 的写入口（输入/描述符/阈值那一侧）**，不在输出侧。这与"首分歧恒在某层 conv 的**输出尾巴**、前缀逐字节正确"并不矛盾：
  只要入口处给错了一份行/组，出口就是"从某点起往后稳定地错"。
- **代价**：908 次 flush × 3 ms ≈ **+2.7 s**（6.2→9.8 s，+40%）；`fixflush` 更贵（+45 s，PL 还被拖慢 8×，不可用）。

## 4. 判据结论（对父代理）

1. **缓存一致性不予定罪**：`BIN_EPI_NOINV=0` 两次不修；`_invalidate` 之后 227/227 与 DDR 一致；
   真陈旧只在大缓冲之外的小 op 上、且**不在**首分歧 op 上；那条读路径上没有消费者。
   ⇒ T-106 提的那条"安全性论证从未被测过"——**现在测了：它是安全的**（至少在 128² 这套运行点上）。
2. **`done` 之后排空也不是根因**：等到每层 DDR 稳定（p50 3.9 ms / max 47.5 ms）与 done 后睡 20 ms 都**不修**。
3. **根因方向改为：PS→PL 写入口的时间竞争**。证据链是**剂量响应 + 位置对照 + 8/8 命中**：
   `_flush` 之后 ≥3 ms 的**纯延迟**就能让 v53 **逐位等于 v39**（4 跑 4 中，含一个独立租约的 3 连跑）。
4. **可立即使用的纯 PS 正确性护栏**（不是修法，是"取证用"）：在 `push_input`/`prepare_segments` 的 `_flush`
   之后加一个可配的 settle 延迟（默认 0，`BIN_SETTLE_MS=3` 打开）⇒ 128² 全中，+2.7 s。**不许**当性能基线。
5. **下一步该花的时间**（都能软件做、不用改 RTL）：
   - 把延迟**只**加在"PL 空闲时"或**只**加在"PL 忙时"，分离"入口握手"与"PS 与 PL 并发抢 DDR"两种读法；
   - 二分最小延迟（2.0 / 2.5 ms）与**最小 flush 子集**（只 push_input？只 prepare_segments？只 desc/thr？），把 +2.7 s 压下来；
   - 若确认是"flush 后 PL 短时间读到旧数据"，RTL 侧的正确做法是给 AXI 主口加 **读后写屏障/写回 fence**，
     或把输入侧缓冲改成 PL 可安全读的路径（不是加 sleep）。
