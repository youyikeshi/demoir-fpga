# T-96：v51 板级验证报告（2026-11-02 20:41–20:49 主机时间 / 板端 01:29–01:36）

**一句话**：v51 把 v50 的**越界写修好了（5/5 层 0 B）**，也**修掉了整网第 3 层的死锁（227/227 op 全返回）**，
但**逐字节仍然错（0.02–37 %）**，且**吞吐反而比 v39 8-lane 差（conv 拍数 1.24×）**
⇒ **`-0.56 s` 不能结算，v51 不能用于功能验证。**

跑点：位流 `design_1_150v51.bit` md5 `16766e1f…` + `.hwh` md5 `52357646…`（成对，跑前=跑后）；
`FUSE_EN=0 / VLANES=16 / BAND_ROWS=1 / HALO=0 / C_MAX=8`；fclk0 **100 MHz**；24 槽；
PS 闭包 `9de3d60c…`（20/20 `md5sum -c` + `--check` rc=0）；`BIN_V50_*` 全空。
三个 session（3 次 load）**都**得到 0 B 越界，数字可复现（±2 %）。

## 2. 第 2 步：逐层隔离（★ 核心判据：**未过**）

H=W=32、OUT 后 64 KB 垫子铺 `0xA5`、seed `20261031`、同 blob/同 PS 代码/同 100 MHz。

| 层 | v51 越界 | v51 逐字节不符 | v39 控制组（同 session 同脚本）|
|---|---:|---:|---:|
| cin48 k3 (cb=1, K=9) | **0 B** | **1 381 / 65 536** | 0 B / 0 |
| cin112 k3 d2 (cb=2, K=18) | **0 B** | **24 476 / 65 536** | 0 B / 0 |
| cin176 k3 (cb=3, K=27) | **0 B** | **18 540 / 65 536** | 0 B / 0 |
| cin240 k1 (cb=4, K=4) | **0 B** | **1 190 / 49 152** | 0 B / 0 |
| cin512 k1 (cb=8, K=8) | **0 B** | **47 / 196 608** | 0 B / 0 |

$$\Rightarrow\ \text{越界：v50 的 }904\sim4096\ \text{B} \to \textbf{0 B}（\text{修复成立}）$$
$$\Rightarrow\ \text{字节：v50 的 }93\sim98\% \to \textbf{0.02–37.3\%}（\textbf{未归零}）\ \Rightarrow\ \textbf{判据"0/65536"不成立}$$
$$\Rightarrow\ \text{v39 控制组 5/5 层 0 B / 0 字节（同一进程外同脚本）} \Rightarrow\ \textbf{探针与 PS 代码干净，错只可能来自 PL}$$

**错的空间形状**（给 RTL 侧定位；`word=(pix*ngroups+g)`，`chan`=word 内字节=组内通道）：

| 层 | 结构 | want→got 主要对 |
|---|---|---|
| cin48 k3 | 143/1024 像素受影响；列错数集中 col 6–10（88/238/312/256 334）与 col 31 | `-1→{7,3,19,-128}`，少数 `→±127/128` |
| cin112 k3 | **932/1024 像素**；`chan=2` 在**全部 8 组**都 ~750 次 | `0↔-1`、`-1↔-2`（多为 **±1**）|
| cin176 k3 | 999/1024 像素；`chan=3` 在全部 8 组 ~480 次 | `-1→{-2,6,0,-128}`、`0→127` |
| cin240 k1 | 137/1024；`chan=6` 全组 ~65 次；行 10/15/20/26/31 各 ~180 | `-6→-7`、`→±127/-128` |
| cin512 k1 | 仅 23 像素；**列只在 0/10/20**（12/16/18 次）| `0→127`、`-1→-2` 等 |

⇒ 错误**不是**随机垃圾也**不是**整段错位，而是"**每组内固定一个通道索引**系统性偏 ±1（少数饱和）"
⇒ 更像**lane→word 映射 或 per-lane PRM/shift 的残差**，而不是地址越界（越界已归零）。

## 3. 第 3 步：64² 整网（三个 sha1 **≠** 冻结值）

冻结运行点（`BIN_PACK=e1e2 BIN_LAZY_DEQ=1 BIN_LAZY_SLOTS=24 BIN_CAT_FUSION=1 BIN_BILINEAR_C=1
BIN_PRECOMP=1 Q8CACHE=1 BIN_F32DIRECT=1 BIN_CAT_ECA_FUSE=1 BIN_EPI_NOINV=1`，无任何 `BIN_V50_*`）：

| 项 | v51 | v39（同 session / 同 100 MHz）|
|---|---|---|
| sha1 out1/out2/out3 | `b8844153…` / `6a9487b8…` / `ac8a3188…` **≠冻结** | `bfa246d3…`/`226bd39e…`/`762d84b9…` **=冻结 ✓** |
| 总时间 | **3.320 s**（墙钟 3.327）| 3.443 s（3.450）|
| PL | 0.935 s（E1E2 0.624）| 0.869 s（E1E2 0.619）|
| PS | 1.295 s = prologue 0.914 + epi 0.065 + 非卷积 0.316 | 1.419 s = 0.911 + 0.063 + 0.444 |
| conv 拍数 | **31.07 M**（cyc/term 1.09）| 25.05 M（0.88）|
| **第 3 层是否挂死** | **未挂死：227/227 op 全部返回** ✓（v50 在此 5.05 s 未 done）| 227/227 ✓ |

⇒ **死锁修掉了**（这是 v51 的第二个真进展），但**数据仍错** ⇒ 三个 sha1 拿不到冻结值。
⇒ 与 5.83 s 基线**不可直接比**：5.83 s 是 **256² @150 MHz**（本 session v39 256² @100 MHz = 6.889 s，
按 PL 折算到 150 MHz ≈ 5.95 s，与 5.83 s 同档 ⇒ 口径确认）。v51 的 256² **未跑**（64² 已错，按纪律停）。
⇒ 可比的同口径量：64² conv 拍数 **v51/v39 = 1.24×**（不是 0.5×）⇒ 按此比例 `-0.56 s` 方向不成立。

## 6. 金丝雀 / 报警 / 板子现状

- 金丝雀：**0 次报警**（每次 op `fill+check_canary`；64 KB 垫子 5 层全 0 B 被写）
