# T-134：AXI 读响应「晚到/乱序」注入 —— 读鲁棒性结论

**一句话**：在 xsim 里给 `m_axi` R 通道注入**固定 0/1/4/16/64/256/1024 拍延迟、随机 0~1024、跨 16 个 ID 乱序、
burst 内变长背靠背（拍间空 0~7 拍）、在飞上限压到 1~2** —— `bin_unit_axi_wrap_v50`（VLANES=16）
在 64² 与 **128²**（板上必错几何）上**全部 524288/524288 字节逐字节 = golden**。
⇒ **读路径不存在"假定响应按时到"的 bug；本任务要定罪的读鲁棒性 bug 不存在。**
报告同时给出**门禁灵敏度证明**（故意注入两个读 bug ⇒ 立刻 FAIL，且错数随延迟单调恶化），
所以"全对"不是 TB 无能，而是被测 RTL 真的对。

运行点：xsim（Vivado 2025.2.1）、`bin_unit_axi_wrap_v50 #(.UNIT(0), .VLANES=8|16)`、
RTL = `worktrees/T-134-lat/rtl`（= `runs/timing_v50/rtl_v50` 的 `cp -a`，manifest **MATCH=35 DIFF=0** 已复核）。

## 3. 门禁灵敏度证明（"全对"不是 TB 无能）

在本副本 RTL 上故意注入两个**经典读 bug**，用同一个 TB、同一组判据：

| 变异 | 内容 | 基线 1..20 | 重延迟 |
|---|---|---|---|
| **MUT-A** | `rid_slot = m_axi_rid` → **恒 0**（忽略 RID，经典"乱序即错"bug） | DUT 自己报警 `R 数据回来但该槽无在飞请求 rid`（§9 断言抓到） | 同上 |
| **MUT-B** | `rd_hit` 去掉 **`!fill_rd`** 闸门（命中"正在回填"的线 = 响应晚到的**专属**危险） | 16² **4096/8192**；32² **16384/32768** | 16² 固定 64 拍 → **256/8192**；32² 固定 256 拍 → **1024/32768** |

**错误空间形状（MUT-B, 32² @256 拍）**：`oc=0..31 全挂 1024/1024 像素`，
`got=x`（X/Z=31744）—— 读到**没填完的槽**（板上等价于读到**旧数据**）。
⇒ 判据 R6 成立：本 TB 对"读晚到"的**检测力极强**，且**错数随延迟单调放大**
（256/8192 → 1024/32768，延迟越大错得越多）。真 RTL 在这一族压力下 0 错，所以**真的没有这个 bug**。

## 4. 根因行号 + 机制

**结论：读路径里没有"假定响应按时到"的地方，因此没有可定罪的行号。** 逐条对上任务给的四条怀疑：

| 怀疑 | 对应代码（`lane16/bin_unit_axi_wrap_v50.v`） | 为什么晚到不破 |
|---|---|---|
| ① 线缓存 fill / demand 仲裁 | **`rd_hit = tag_rd[VLD] && tag_eq && !fill_rd`（:2432-2434）**，`fill_rd` 由 16 个槽 `fs_valid[fk] && fs_idx[fk]==rd_idx` 或树算出（:2422-2426） | 任何**正在回填**的表项硬禁命中 ⇒ 单元冻结到整条线到齐；晚到只是多冻几拍，不会读到半条线（MUT-B 就是删掉这条闸门后的样子） |
| ② `r_ready`/`arvalid` 握手 | `m_axi_rready = fs_valid[rid_slot] && (fs_out[rid_slot] != PF_Z)`（**:2572**）；`m_axi_arvalid = (arq_cnt != 0)`（:2542），队头地址/ID 在 `ar_fire` 前**已预选进寄存器**（`ar_addr_sel_q/ar_id_sel_q`, :2546-2553, :2552 的 `arq_head_new`） | 收几拍由**每槽自己的** `fs_out` 计数决定 ⇒ 既不会多收也不会丢；AR 不会重发（表头只在 `ar_fire` 换） |
| ③ outstanding AR 计数 | `ARID = 填充槽号`（:2555, :2562），槽从分配占用到最后一拍（`:2662-2664` 释放在 `rid_last`） | 在飞笔数天然 ≤ NSLOT=16 = 2^AXI_ID_W ⇒ 计数不可能回绕；**同 ID 同时只有 1 笔** ⇒ 同 ID 保序自动成立，跨 ID 乱序由 RID→槽查表落对（:2562-2565） |
| ④ "响应必须 N 拍内到"的隐含超时 | 读侧**没有任何超时/兜底**；唯一的 `WR_GAP_TMO=4095`（:475/:2825）只在**写**口，读侧不依赖它 | 读侧无限期等，无兜底可误触发 |

**为什么晚到会读到旧数据（MUT-B 的机制，仅用于说明这一族 bug 长什么样）**：
线缓存按槽填、按 64 B 线对齐；若允许"正在填的槽"命中，`m_axi_rdata` 才回了 k 拍，
剩下的字还是**上一轮残留**（仿真里是 X，板上是旧数据）⇒ 卷积在这条线上算出的部分和是旧的
⇒ 误差顺着 `u_ce` 累加进整块 plane ⇒ 板上表现为"整段/连续尾巴对不上"。
**真 RTL 的 `!fill_rd` 把这个窗口彻底关死，而它的代价只是"晚到 = 多停几拍"。**

**结构性论证（为什么 xsim 加延迟不可能复现板上那条签名）**：
TB 的内存模型无论延迟多大，返回的永远是**该地址当时的正确数据**；"读到旧数据"这件事
**只能由 RTL 自己制造**（半条线 / 失效缓存 / 错误槽），而这三条在本设计里分别由
`!fill_rd`、`start` 前 512 拍全表冲 0（:1028-1060, :2726-2728，`start_fire` 那拍还有
`lc_tag[fq] !== 0` 的仿真断言 :3411-3418）、`RID→fs_idx/fs_wr` 查表堵死。
⇒ 板上"**纯 sleep 3 ms 就对**"这条决定性证据与 RTL 无关（RTL 内部状态不会因为 CPU 睡觉而改变），
它只能是 **PS→DDR 的写可见性竞态**（写还在内存控制器/缓存里没落到 PL 能读到的那份 DDR 视图）。

## 5. 修法

- **不需要改 RTL**：读路径对 1024 拍延迟 + 16 ID 乱序 + 拍间变长空闲**已逐字节正确**，
  修法"注入 256 拍仍逐字节对"这一条**基线本身就已经满足**（还有 1024 拍档）。
- 若主代理仍想要"读侧纵深防御"，唯一有意义的候选是**把半条线的 X/旧数据风险再显式化**
  （例如给 `win_q` 每个字加 valid 位、命中要求整线 valid）——**但那会多花 LUT/BRAM 且当前无 bug 可修**，
  不建议在 v50 上做。
- **主线 `runs/timing_v50/rtl_v50` 与 `pynq_specialized_code/ps/pynq` 一个字节未动**；
  所有改动都在 `worktrees/T-134-lat/`（RTL 只在 `rtl_mutA/rtl_mutB` 里被故意改坏，供门禁标定）。

## 6. 是否需要重建位流

**不需要。** 本任务没有给主线 RTL 任何改动（`rtl/` 是 `cp -a` 的只读副本），
所以位流与源码 manifest 的关系不变，**无需重综合、无需重上板**。
若主代理要走"PS 写可见性"这条线，那属于 PS/驱动侧实验（sleep / fence / 不同映射 / 分段 flush），
不产生新位流。

## 7. 副产品（给后续任务的两个坑）

1. **`runs/v94_wrpath/run.sh` 的 plusarg 键名有雷**：`shape.env` 里核大小键是 **`KK`**，
   而 TB 解析的是 **`K=%d`**，脚本 `*)` 分支原样透传 ⇒ 传给 TB 的是 `KK=3`（不匹配）。
   内置形状表覆盖了 v94 的 10 个形状所以没暴露；**任何新形状**（不在 `set_shape` 表里）
   都会拿到 **K=1**，现象是"逐字节 0/8192 全错"（我第一次跑就是这个）。
   本副本已修为 `KK) P+=(-testplusarg "K=$v")`。
2. **变异体仿真会刷爆日志**：MUT-A 让 DUT 每拍打一条 `ERROR: ... rid`，20M 拍上限下
   单文件涨到 **850 MB**（已删）。后续做变异标定请一律
   `MAXCYC=3000000` + `| head -c 4M`。
