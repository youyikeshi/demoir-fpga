# v57 验收报告

## 1. 验收对象

**v57** = v39 基线 + 一个 RTL 文件改动（时序刀 7）。

$$\text{v57} = \text{v39} + \Delta(\texttt{bin\_e1e2.v})$$

| 文件 | v39 | v57 |
|---|---|---|
| `bin_e1e2.v` | `28375eec` | **`bc28ead3`** |
| 其余 11 个构建输入 | — | **逐字节相同** |

其中 `bin_unit_axi_wrap.v` = `0cf68b2e`，**`PF_AHEAD` 保持 1**（未使用被判死的 `PF_AHEAD=2`）。

### 改动内容

v39 的 `bin_e1e2.v` 在 `ST_SWEEP` 相位每拍做一次 16 位比较：

$$\texttt{issue\_en} = (p < \texttt{run\_len})$$

这个比较器挂在整条 `u_ce`（BRAM 写使能）锥上，扇出 77，路径 11.597 ns / 16 级 / 73% 是布线。

**时序刀 7** 把它换成等价形式：在 `ST_THR` 边界装载一个 9 位倒计数器 `rem`，并用寄存使能 `sw_act_q` 驱动 CE。因为 `run_len` **每个 tile 只变一次**，这是等价改写，不是删除比较。

结果：该起点相关的 **6957 个端点（占 10 ns 违例的 97.9%）全部消失**。

**最差路径变化**

| | v39 | v57 |
|---|---|---|
| 起点→终点 | `run_len_reg[3]_replica → p_0_out__*/CEA2` | `win_q_reg_9 → u_eng/s1_pc_q[3][6]/D` |
| 延迟 / 级数 | 11.597 ns / 16 级 | 9.734 ns / 9 级 |
| 性质 | **准静态 BRAM 使能** | **真实数据通路** |

⚠ 第二行是关键：v57 的新临界路径是真实数据通路，因此**它必须真的跑在 10 ns 以内**。同一 DCP 在 6.667 ns 是 −3.07 ⇒ **100 MHz 是硬上限**。

**独立复核**（在 routed DCP 上，不依赖构建日志）

- `create_clock` 周期硬断言 = 10.000 ns
- `VIOL = 0`
- `LDCE = LDPE = 0`
- DRC：route 之后与 `write_bitstream` 之前**各一次 0 Errors**
