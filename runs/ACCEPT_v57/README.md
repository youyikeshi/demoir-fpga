# 阶段验收包：v57

**首行判定：可以接受为“时序干净”的阶段基线。10 ns 口径 WNS +0.206 / TNS 0 / 违例端点 0，功能与 v39 逐字节且逐拍一致。**

> ⚠ 运行点限制：**v57 只能按 100 MHz 跑**。它在 150 MHz（6.667 ns）口径是 −3.07，且新暴露的是**真实数据通路**（不是准静态 CE）⇒ 150 MHz 会真错数。
> 需要 150 MHz + 5.3 s 的场景仍用 v39（报告有负值，但违例性质为准静态使能，机制已查明）。两版并存，用途不同。

## 怎么用

```bash
# 上板（100 MHz）
# 注意：PYNQ 的 Clocks.fclk0_mhz 口径是真实值的 1.5 倍 ⇒ 要真实 100 MHz 就写 150
from pynq import Overlay, Clocks
ol = Overlay("design_1_150v57.bit")   # 配 v39 的 .hwh
Clocks.fclk0_mhz = 150                # 读回确认 100

# 完整验收步骤见 06_REPRODUCE.md
```

## 一句话结论

**v57 把“与 v39 功能完全相同”这件事做到了逐字节、逐拍级别，同时把 10 ns 的时序报告从 −1.998 清到 +0.206，代价是只能跑 100 MHz。**

在此之前，v39 之所以能在 150 MHz 正确工作，靠的是“违例落在准静态 BRAM 使能脚”这个机制判断；v57 把这个判断变成了不需要判断——报告本身干净。
