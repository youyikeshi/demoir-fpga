# 第二步 **阻断**：50 MHz 与 HDMI 扫描器在本位流里**互斥**（窗口为空）

**时间**：主机 2026-11-03 19:30–19:40 ｜板 192.168.7.2 ｜位流 `555c22cf…`（**未重载**）
**结论先行**：

$$\Rightarrow\ \text{去摩尔纹数值正确只到 } \mathbf{50.00\ MHz};\ \text{HDMI 扫描器在 } 50\ \text{下 }\mathbf{100\%\ 行读空},\ 66.67\ \text{起才正常}$$
$$\Rightarrow\ \Rightarrow\ \textbf{不存在同时满足两者的 FCLK0} \Rightarrow \textbf{"去摩尔纹 + HDMI 同时跑"在本位流上不可实现}$$

## 1. 判据 5：`0x24` vs 写入的 `FRAME_ID` —— **3/3 全中**（此判据与时钟无关）

| 帧 | 写入 `FRAME_ID` | `0x24` 读回 | 匹配 | `wait()` |
|---|---|---|---|---|
| noise #1 | 1 | `0x00000001` | ✅ | True |
| noise #2 | 2 | `0x00000002` | ✅ | True |
| noise #3 | 3 | `0x00000003` | ✅ | True |

`CTRL` 全程 `0x00000001`（enable=1 / **test_pattern=0**），`STATUS=0x7`（含 `[2] scan_underflow` 粘滞），
`VMODE=0`（720p60），`FB_ADDR=0x30100000`，`block_bytes=2,764,800`，`pix_alive=74.061 MHz`（期望 74.219，−0.21%）。

## 2. 判据 6：`0x2C` —— **不通过，且是"满格"不通过**

`0x2C` = `UNDERFLOW_CNT`，语义（`hdmi_out.py:83`）= **自软复位起"被读空的行数"**，RO。

| 采样点 | `0x2C` | 增量 |
|---|---|---|
| 写 `CTRL=0x01` 后 0.35 s | 14,418 | — |
| noise #1 后 | 36,669 | +22,251 |
| noise #2 后 | 263,154 | +226,485 |
| noise #3 后 | 489,639 | +226,485 |
| 20 s 保持期 5 点 | 717,561 → 1,580,887 | 每 5 s **+215,839** |

$$\text{速率} = 43{,}168\ \text{行/s} \approx 750\ \text{行} \times 60\ \text{Hz} = 45{,}000\ \text{行/s}$$
$$\Rightarrow\ \textbf{每一行都被读空} \Rightarrow \text{不是"余量不够"，是"一行都没读到"}$$

**对照（同一块帧缓冲、同一次进程、只改 FCLK0）**

| 真值 FCLK0 | `0x2C` 5 s 增量 | 行/s | `STATUS[2]` |
|---|---|---|---|
| **50.00 MHz**（写 75） | +215,836 | **43,123** | 1（粘滞） |
| **83.33 MHz**（写 125） | **+0** | **0** | 0 |

⇒ 恢复 `CTRL=0x15`（扫描器关）后 3 s 增量 **0** ⇒ 计数器只在扫描时累加，语义确认，**不是残留值**。

## 3. ★ 反向发现：去摩尔纹在 >50 MHz 上**错数**（66.67 起静默错，76.92 起越界）

同一 `BinNet(256²)`、同 `seed=1`、`CTRL=0x15`（扫描器关，**无 DDR 竞争**），只改 FCLK0：

| 写值 | 真值 | `out1` sha1 | 判定 |
|---|---|---|---|
| 75 | **50.00** | `9b1940c8955be53ccffd7905e333deffcea31f0a` | ✅ **= golden** |
| 100 | **66.67** | `88cc544544a4f343f378e3218ff9cbc1749ff4a7` | ❌ **错数，且无任何报错** |
| 115.4 | **76.92** | — | ❌ `金丝雀被写坏 24/4096` |
| 125 | **83.33** | — | ❌ `金丝雀被写坏 48/4096`（重跑 40/4096，可复现） |

$$\Rightarrow\ \textbf{66.67 MHz 是"安静地算错"}, 76.92\ \text{起是"越界写"}$$
$$\Rightarrow\ \text{这与 } \texttt{gate2\_fclk0\_wns}=+0.100\ \text{ns}@10\ \text{ns}\ \text{的结论}\textbf{冲突} \Rightarrow \textbf{10 ns 约束没有覆盖真正失效的那条路径}$$

## 4. 两侧合起来的"窗口表"（**交集为空**）

| 真值 FCLK0 | 去摩尔纹 | HDMI 扫描 | 可用？ |
|---|---|---|---|
| 50.00 MHz | ✅ golden | ❌ 100% 行读空 | ✗ |
| 66.67 MHz | ❌ 静默错数 | ✅ 0 行/6 s | ✗ |
| 76.92 MHz | ❌ 越界写 | ✅ 0 行/6 s | ✗ |
| 83.33 MHz | ❌ 越界写 | ✅ 0 行/5 s | ✗ |

**没有任何一行两列同时 ✅。** 而且两侧的失效形态都**不是"性能退化"，是"功能失效"**：
扫描器一行都读不到；去摩尔纹给的是**错数据**（66.67 时连错误码都没有）。

## 5. 为什么 §1 的 `0x24` 全中仍然有意义

`0x24 == FRAME_ID` 证明的是**帧号发布/锁存链路**（PS 写 → PL 在 vsync 边界采纳 → 回读），
它**不依赖 DDR 读取**。所以"帧号对了"不能推出"画面对了"——
这正是上一棒作废的那一轮（`CTRL=0x15` 下测真画面）踩过的同一类推理错误。

## 6. 不改 RTL 的唯一出路：**时分复用时钟**（建议方案，待批准）

两头需求在时间上其实不重叠：**算的时候不用扫，扫的时候不用算**。

```
① FCLK0 = 50.00 MHz，CTRL=0x15（扫描器关）
     跑整网（噪声 + 真图各一次）→ 结果落在 DDR / .npy
② FCLK0 = 66.67 MHz（写 100），CTRL=0x01（显式写，不是 enable()）
     把①算好的结果推 3 帧 → 0x2C 应恒 0（已实测 0 行/6 s）
③ CTRL=0x15 → 释放缓冲 → sync
```

- 用户要看的"右半屏 = 真算出来的 256² 结果"**能实现**；
- 代价：判据 6 必须改写为 **"显示期间 `0x2C` 恒 0"**，
  "去摩尔纹与 HDMI **同时**读 DDR" 这条**在本位流上做不到**，不是没测好，是设计层面互斥；
- 另有一条**更省事**的路：`out1_256_seed1.npy` 已经算好且 sha1 = golden，
  真图那张只要在 50 MHz 下跑 20 s 即可 ⇒ 上屏本身只需要②。

**根因建议（超出我的边界，交 RTL 侧）**：这是合并引入的跨时钟域问题。
`clk_pix`(74.22, 来自 Y14) 与 `FCLK0` 的相对大小在 50↔66.67 之间翻转，
两侧失效形态（一行读不到 / 静默错数）都指向 **HP 端口/异步 FIFO 只在 `FCLK0 > f_pix` 一侧成立**，
而 v57 的单设计里 FCLK0 恰好一直 ≥ f_pix，所以从没暴露。

## 7. 板子现状（安全）

```
CTRL=0x15（720p60 彩条）  VMODE=0  STATUS=0x3  FCLK0=0x00101400（真值 50.00 MHz）
UFCNT=4,289,054（历史累计，RO 不清零）  fpga0=operating  sync rc=0  无残留进程
```
⚠ `0x2C` 是 RO 累计量、**软复位才会清零**，本轮之后的读数必须减去 4,289,054 才算增量。

## 9. 时钟口径（本轮**用寄存器钉死**，不再是"1.5× 经验值"）

```
ARM_PLL_CTRL = 0x00028000  FDIV=40 → 33.3333×40 = 1333.33 MHz   （标准 Zynq-7000）
DDR_PLL_CTRL = 0x00020000  FDIV=32 → 33.3333×32 = 1066.67 MHz   （标准）
IO_PLL_CTRL  = 0x0001E000  FDIV=30 → 33.3333×30 = 1000.00 MHz   ← 父代理的 1000 说法成立
FCLK0_CTRL   = 0x00101400  DIV0=20, DIV1=1 → 1000/20 = 50.00 MHz
PYNQ：PS_CLK 当 50 MHz 用 ⇒ 30×50 = 1500 ⇒ 报 75.0 ⇒ **报数/真值 = 1.5**
```
PYNQ 源码 `pynq/ps.py` 的 `PLL_FDIV` 字段是 `bit_offset=12, bit_width=7`；
按它解，三个 PLL **同时**落在 1333/1066/1000 —— 这是唯一自洽解，概率上排除了巧合。
