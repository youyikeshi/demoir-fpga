## 第 2 档 AXI/状态
`0x00=0x15`、`0x04=0x01`、`0x08=0x03`、`0x24=0x00`、`0x2C=0x00`、`0x30=0x02`。
- 写控制项 `FB_STRIDE=0x0F00` → 读回 `0x0F00`（证明写通路真的落地）
- 写 `0x2C=0xFFFFFFFF` → 读回 `0x00`（RO；RTL 写译码 6'h0B 无分支）
- 软复位 `CTRL=0x02`（bit1 自清）→ CTRL 读回 `0x00`、`0x2C=0`、init_done 仍 1、复位后 100 ms 心跳 56 沿
  ⚠️ 复位前 `0x2C` 已是 0 ⇒ 这一条**不具判别力**；判别力来自 RTL 译码 + 写通路控制项

## 第 4 档 真画面（mode0 720p60，`CTRL=0x01` 即 test_pattern=0）—— **人眼已确认"竖条跳了三次"**

### t4 这一轮作废（`t4.json`），理由写全
`hdmi_out.HdmiOut.enable()` 是**读-改-写**（只改 `CTRL[0]`，**不清 `CTRL[2] test_pattern`**），
而第 3 档把 `CTRL` 留成了 `0x15`；RTL `hdmi_out_top.v:616` 是
```verilog
.cfg_enable (ctrl_enable && !ctrl_test),   // 彩条模式下扫描器被关掉
```
⇒ 那一轮 **扫描器根本没跑**，屏幕上是彩条，所以它的 `0x2C=0` **不是带宽证据**、`0x24` 匹配也只证明了帧号发布/锁存链路。
**作废，不作为证据引用。**

### 有效那一轮（`t5.json`）
- `CTRL=0x01`（enable=1 / test=0 / motion=0）、`VIDEO_MODE=0`、`fb_addr=0x30100000`、`block_bytes=2,764,800`
- 三帧 fid=1/2/3，`wait_ok=True`，**`0x24` 逐帧 == 写入的 `FRAME_ID`**
- `0x2C`：推帧前 / 帧1后 / 帧2后 / 帧3后 = **0/0/0/0**；40 s 保持期 8 次采样（板钟 18:55:17/22/27/32/37/42/47/52）**全 0**
- 人眼（用户确认）：主机时钟 19:19:52–19:20:37，左半彩色渐变+白竖条 / 右半 9×9 盒式模糊 / 上下各 40 px 黑边，**竖条跳三次（≈x70 → x140 → x210）**
- CMA（只认分配后的口径）：`CmaFree` 分配前 544 kB → 分配后 0 kB @ uptime 1576 s；`allocate` 一次成功、无重试

### 带宽证据（口径必须留档，之前两次算错过）
- **需求 = 3 B/pixel × 74.21875 M pixel/s = 223 MB/s，与 AXI 时钟频率无关**（由像素率决定）
- 供给 = 8 B/clk（64 位 `S_AXI_HP2`）× 83.33 MHz = **667 MB/s**
- ⇒ **3.0× 余量**；实测真扫描器连续 40 s 读 DDR，`0x2C` **零下溢**
- 两个已犯过的错：① 按 3 B × f_ACLK 算供给（那是 32 位口径，少了一半）；② 拿"需求"去跟 AXI 频率比（量纲混比）

## 时钟口径（★ 与构建声明不同）
- 板上 **IO PLL = 1000 MHz**（BOOT.BIN/FSBL 决定），PYNQ 的 `Clocks` 硬按 **1500 MHz** 计算
  ⇒ **报告值 = 真值 × 1.5**；v58 `.hwh` 里的 `1800` 只是构建期声明，**overlay 加载不重写 PLL**
- `FCLK0_CTRL = DIV0 × DIV1`（`0x170`，DIV0=[13:8]，DIV1=[25:20]） ⇒ `f_real = 1000/(DIV0×DIV1)`
- 加载后 `0x00300400` = 4×3 = 12 ⇒ **真值 83.33 MHz**（PYNQ 报 125）

| 写入 `Clocks.fclk0_mhz` | `FCLK0_CTRL` | product | 真值 |
|---|---|---|---|
| 125 | 0x00100C00 | 12 | 83.33 MHz |
| 150 | 0x00100A00 | 10 | 100 MHz |
| 75 | 0x00101400 | 20 | 50 MHz |
| 62.5 | 0x00101800 | 24 | 41.67 MHz |
| 100 | 0x00100F00 | 15 | 66.67 MHz（与 P1 台账实测 66.67 逐字吻合）|

⇒ 要真值 75 MHz：写 112.5（PYNQ 取整 product 13 ⇒ 76.9 MHz）；写 62.5 只能得 41.67。
带宽（64 位 HP2）：供给 8 B × 83.33 MHz = 667 MB/s，720p60 需求 3 × 74.21875 = 223 MB/s ⇒ 3.0× 余量，实测 0 下溢。
