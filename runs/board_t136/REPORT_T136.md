# T-136：v54 功能验证 + 干净收益测量（v54 vs v53，同探针同口径）

**一句话**：v54 **逐字节等价 v53/v39**——64² 三跑三 sha1 全中冻结值且互相同（无护栏），128² 两跑全中（6 ms 护栏），
256² 一跑全中（32 ms 护栏）；**v54 新增的 `npix_ovf ⇒ AP_RETURN[15:8]=ERR_SIZE` 在 5.6 万次寄存器读里一次都没误报**；
64² 耗时 v54 **3.913 s(min) vs v53 3.955 s(min)**（同一份探针、各 3 跑）⇒ **−1.1 %（噪声内），PL 时间 −0.4 %**
⇒ **v54 可以直接当新基线，收益是"时序红线过了、运行期一分钱没花"**。

| 2 | **3.918 s** | 0.687 s | 2.612 s | `bfa246d3…` / `226bd39e…` / `762d84b9…` | ✓ |

`762d84b9618eab8922edd6da4f07ba06de865628`）

$$\Rightarrow\ \textbf{三次三 sha1 全 = 冻结值，且三次互相同}\ \Rightarrow\ \textbf{64² 功能 PASS}$$
冻结运行点确认：`BIN_LAZY_DEQ=0`、无 `BIN_V50_*`、**零 sleep**（`flush 1135 次，睡 0 次`，睡眠次数=0 是硬证据，
不是"我们以为没睡"）。flush 尺寸与 v53 **完全一致**：`9437184×227 / 1179648×227 / 1152×227 / 576×227 / 73728×227`
（每 op 输入 73728）⇒ 同一套 PS 行为，只有位流不同。

$$\Rightarrow\ \textbf{两跑全中且互相同；墙钟 7.916 s（T-135）→ 7.688 s(min)}$$

护栏位置与 v53 判定的完全一样：**只睡 `pack_int8` 对"打包输入视图"（9,437,184 B）的那 227 次 flush 之后**，
其它 908 次一秒不睡 —— 说明护栏的必要性只跟 PS 侧写入口/排空竞态有关，**与位流版本无关**（v54 同样需要）。

## 3. 第 3 步：性能对照（64²，各 3 跑，**同一份探针**）

| 指标 | **v54** | **v53** | 差 |
|---|---:|---:|---:|
| 墙钟 3 跑 | 5.139 / 3.918 / **3.913** | 5.131 / 3.955 / **3.963** | — |
| **min 墙钟** | **3.913 s** | **3.955 s** | **−0.042 s（−1.06 %）** |
| 均值（含冷跑） | 4.323 s | 4.350 s | −0.027 s（−0.62 %） |
| PL 忙时间（3 跑合计） | 2.871 s | 2.882 s | −0.011 s（−0.4 %） |
| PL 折算拍数（稳态，@50 MHz） | 34.35 / 34.69 M | 34.25 / 34.55 M | +0.3~0.4 %（同量级） |
| PS 时间（3 跑合计） | 8.954 s | 9.021 s | −0.7 % |

$$\Rightarrow\ \textbf{v54 的时序修复是"零运行期代价"：LUT +1634（21496→23130）换来 WNS +0.103，}\textbf{墙钟与 PL 时间都在 −1 % ~ +0.4 % 的噪声带内，没有变慢}$$

**与 T-135 归档值的对照（口径差异已核）**：T-135 的 v53 64² 是 5.032 / 4.046 s（min 4.046，均值 4.539），
**没有** AP_RETURN 逐笔记账钩子；本次两个租约都带同一套钩子（每跑约 3.8k–24.6k 次额外 Python 快路径比较），
而本次 v53 = 3.955 s **比 T-135 的 4.046 s 还快** ⇒ 钩子开销在噪声内（≤0.1 s），
**因此 v54 vs v53 的差值可以直接采信**。（也说明 T-135 的 4.54 s 是"两跑含冷跑"的均值，不是稳态。）

**旁证 256²（T=32 ms 护栏，1 跑）**：墙钟 **23.651 s**（T-135 v53：23.602 s），PL 7.427 s（v53：7.366 s），
睡 227×32 ms = 7.269 s，三 sha1 全中 `9b1940c8…` / `f86a7035…` / `025757a8…` ⇒ 与 v53 同为 23.6 s 量级。

## 4. 第 4 步：`npix_ovf ⇒ AP_RETURN[15:8]=ERR_SIZE(2)` 的风险核查 —— **零误报**

做法（两层证据，都是纯读）：
1. **每跑之前/之后**各读 `bin_unit_0` / `conv_uni_0` 的 `AP_RETURN`，解 `[15:8]`；
2. **跑内钩住 `_rd`**：凡是落在 `AP_RETURN` 偏移（`0x10010`）上的读，全部记账（次数 / 非零次数 / 最大错误码 / 前 8 条非零样本）。

| 尺寸 | 跑内 `AP_RETURN` 读次数 | 非零次数 | 最大错误码 | 跑后 bin_unit_0 | 跑后 conv_uni_0 |
|---|---:|---:|---:|---|---|
| 64²（3 跑） | 12,364 | **0** | **0** | `0x00000001`（只有 done 位） | `0x00000000` |
| 128²（2 跑） | 18,518 | **0** | **0** | `0x00000001` | `0x00000000` |
| 256²（1 跑） | 24,640 | **0** | **0** | `0x00000001` | `0x00000000` |
| **合计** | **55,522** | **0** | **0** | — | — |

$$\Rightarrow\ \textbf{`ERR_SIZE` 位在 64²/128²/256² 上始终为 0，v54 新增的越界上报没有引入任何误报}$$
余量核算（**一处事实纠正**）：`NPIX_MAX = 102400`（`PIX_W = $clog2(102401) = 17`）。
按 `ps/manifest_*.json`，最大单 op 的 `Hout·Wout` 是 640² 档的 **102400**、512 档（=256² 输入）**65536**、
128² 档 **16384**、64² 档 **1024**。所以 256² 上真正的 `npix` 是 **65536（不是 16384，16384 是 128² 的值）**，
占上限 64 %；即使走到 640² 也只是刚好贴住上限 ⇒ 本网所有尺寸都在安全侧，实测 5.5 万次读零误报与这个账对得上。

## 5. 结论

| 判据 | 结果 |
|---|---|
| **64² 三跑 = 冻结值且互相同（无护栏）** | **PASS** |
| **128² 两跑 = 冻结值且互相同（6 ms 护栏）** | **PASS** |
| **256² 一跑 = 冻结值（32 ms 护栏，旁证）** | **PASS** |
| **64² v54 vs v53（各 3 跑 min）** | **3.913 s vs 3.955 s ⇒ 不变慢（−1.1 %）** |
| **`AP_RETURN[15:8]=ERR_SIZE` 误报** | **0 / 55,522 次读** |
| **RTL 主线 / `ps/` 零改动** | **PASS**（git 对两处 archive 与 `ps/` 全空） |

$$\Rightarrow\ \textbf{v54 可以作为新基线}：它把唯一没过的时序红线（WNS −x → \textbf{+0.103 / 0 违例}）修掉，$$
$$\textbf{功能与 v53 逐字节等价、运行期零代价。}\ \text{唯一"代价"是 LUT +1634（23130，仍 <26000），PS 侧护栏照旧（除 64²）。}$$
