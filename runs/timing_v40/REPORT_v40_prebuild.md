### 1.1 时序刀 7 的等价性（为什么拍数一定不变）

改前的逐拍函数：`issue_en = (p < run_len)`（仅 ST_SWEEP）。

1. **进 SWEEP**：`p = 0`（ST_LINI 与 ST_THR(ph=3) 都清 p）；`rem` 在 ST_THR 装载 `run_len`。
2. **SWEEP 每拍**：`p += 1`、`rem −= 1` ⇒ 第 k 拍 `rem = run_len − k`，且 `rem ≡ run_len − p`。
3. **值域**：ST_CHK 保证 h,w≠0 ⇒ hw≥1，`run_len = min(hw,256) ∈ [1,256]` ⇒ `p ∈ [0, run_len−1]`
   ⇒ 改前的 `p < run_len` 在 SWEEP 期**恒真为 1**，退出拍 `p = run_len−1` ⇔ `rem = 1`。

⇒ `issue_en` 用 `sw_act_q`（进 SWEEP 那条边置 1、`rem==1` 那条边清 0）与改前**逐拍相同**，
状态机转移表一字未改。⚠ 仍然**没有**"直接删比较"（时序刀 6 的教训），计数器和断言都在。

**为什么预期 WNS 会明显改善（算给审批看，不是拍脑袋）**

最差路径 `v39_at150_top30.rpt` 逐级拆分（11.597 ns 数据路径）：

| 段（到达时刻，cumulative） | v39 | v40 |
|---|---:|---|
| 时钟网 0→1.430 | 1.430 | 1.430（不变） |
| 起点 FF C→Q + 到第一级 LUT 的网 | 0.379+0.668 = **1.047** | ≈0.379+0.55 ≈ **0.93**（起点换 `sw_act_q`，扇出更小） |
| `p < run_len`（LUT4 + 2×CARRY4 + 网） | **1.460** | **0**（使能由寄存器直出） |
| 从使能到末端 DSP CEA2（u_ce→2 个千级扇出网→引擎内部 CE） | **9.09** | 9.09（本轮不动包装层 miss 协议） |
| 合计到达 | 13.027 | ≈ **11.45** |
| 要求时间（7.696 = 6.667+1.378−0.035−0.310…） | 7.696 | 7.696 |
| **slack** | **−5.331** | **≈ −3.7** |

⇒ 纯结构改动应省 **≈1.5 ns**（−5.331 → 约 −3.7~−3.9）；
再叠加"约束变诚实"本身（v39 的 P&R 是按 10 ns 目标优化的：一条 8.9 ns 的路径
slack=+1.1 等于零预算；6.667 下同一批路径变成负 slack，工具会真的去修）
⇒ **合理预期 −3.0 ~ −3.9，不承诺到 −3 以内。** 这是算术估计，必须以 P&R 实测为准。

### 4.3 下一步该动哪一块（按"收益/风险"排序）

1. **`u_ce` 这只千级扇出的组合使能网（唯一的结构性病根）**
   `u_ce = !run_active || ((!rd_want || rd_hit) && !写压力 && !(wst!=IDLE && wr_take))`，
   实测喂到 fo=367 / fo=280 两个网，**每级网 1.0~1.8 ns**，占最差路径后半 4.6 ns 里的绝大部分。
   本轮只能把它的"E1E2 那一端"（run_len/p 比较）摘掉；**网本身还是组合的**。
   要真收口必须有一步是：**让 `rd_hit` 提前一拍算出来**（E1E2 的 SWEEP 地址是线性递增，
   下一拍地址可预测 ⇒ 命中可以在 T−1 拍算好寄存），或**在 tile 边界把整趟 SWEEP 预取完**
   （之后 `rd_hit` 在 SWEEP 期恒真，`u_ce` 可以只吃一个寄存使能）。
   这是**唯一能把 20,706 这个量级整体打下来**的一刀，但涉及 miss 协议，必须单独设计+单独验收。
2. **conv_uni（4,051 / 19.6%，桶内最差 −4.137）**
   它的 CE 1,962 条 + D 1,365 条自成一套；且最差那批是
   `ps7/SAXIHP1ACLK → conv_uni/ent_out_reg[*][*]/D`（PS 的 HP 口到 PL 的落地寄存器），
   属于 **PS↔PL 接口路径**，改 PL 内部 RTL 动不到，要么加 pipeline 要么在 XDC 里按
   接口真实频率分开约束（需你定口径）。
3. **bin_unit 写口（2,989 / 14.4%，CE 1,840）**
   `p_addr / be_word / p_merge / bf_*` 那一族；它的起点是 `run_unit_q`/`start_fire`，
   本轮只是复制降路由，**逻辑深度没动**。下一轮可以按"写口入口寄存器再拆一拍"做
   （v38 时序刀 5 已经拆过一次，还有一层可拆）。
4. **读侧 linecache（2,836 / 13.7%，WADR 1,406 条是 BRAM 写地址）**
   `WADR` 是 BRAM 的写地址端口，属于**线缓存填充**那条路 —— 与第 1 条是同一个病根的另一面。

**优先级判断（我的建议）**：先看 v40 实测把哪一桶顶上来；
若 WNS 落在 −3 以外，**下一步就做第 1 条（`rd_hit` 提前一拍 / SWEEP 预取）**，
而不是继续在写口上做小刀 —— 因为 CE 占 51.6%，不解决使能锥，端点数量级不会变。
